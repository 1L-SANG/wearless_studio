# 호리존 세트의 촬영 구성과 배경 정책을 분리한다

상태: Accepted (사용자 결정 2026-09-26; 구현·배포 상태는 별도 검증 기록)

## 제품 동작

촬영 구성과 배경색을 섞은 제목은 무엇을 선택하는지 불명확하다. 카드는 짧은 특징 이름·사진·컷 수로 구성한다. 세트 클릭은 추가 상세/확정 단계 없이 즉시 교체하고 목록·스크롤·포커스를 유지한다. 교체는 되돌릴 수 있다. 개별 컷을 누르면 기존 방향·대상 색상 인스펙터를 유지하고 소속 세트와 세트 설정 진입점만 짧게 표시한다. 대표 사진 아래에는 실제 추가 컷을 최대 4개까지 보여준다.

배경은 세트 선택 인스펙터 위쪽의 `기존 배경` / `옷 색에 맞춤` 두 글자 버튼으로 선택한다. 시각적인 라디오 원은 숨기되 키보드/보조기술의 선택 의미는 유지한다. 선택 범위는 해당 인스턴스 전체 컷이다. 기본값은 기존 배경이다. 새 선택지는 여성 상의의 파란 벽 예시에만 묶지 않고 상의·하의·아우터·원피스에 공통으로 제공한다. 카탈로그에 같은 세트를 복제하지 않는다. 같은 카탈로그 세트라도 두 번 배치하면 서로 다른 인스턴스다. 같은 인스턴스의 멤버는 함께 변경·저장·되돌린다. 새 멤버는 그룹 설정을 이어받고 그룹 밖으로 나온 컷은 세트 설정을 제거한다.

`horizonBackgroundMode`는 선택 의도만 저장한다. 임의 HEX, 색상명, 13개 스와치의 대표값은 배경 계산 근거로 쓰지 않는다. 측정이 유효하고 서버 발행 카탈로그에서 해당 세트가 호리존일 때 적용한다. 선택 목록의 19세트와 저장된 콘티 호환을 위한 교체 전 린넨 세트 1개를 모두 지원한다. 스타일링 장소 세트와 미등록 세트는 제외한다. 사진이나 출처가 없거나 손상·변경됐으면 기존 배경으로 돌아가며 요청/실제 적용/이유를 결과 기록에 남긴다.

## 대표색을 읽는 단계

사진 분석은 정밀 색 측정을 하지 않는다. AG-01의 기존 13개 스와치 색 분석은 그대로 두며 색상 칸 자동 채움과 매칭 의류 순위에만 쓰고 벽색 근거로 쓰지 않는다. 기존 AG-01·AG-08·입력 일관성의 기준색 최대 4장과 인덱스는 변경하지 않는다.

정밀 측정은 셀러가 콘티보드를 저장하고 마네킹컷으로 넘어갈 때, 필요한 경우에만 서버가 한다. 필요한 경우란 `옷 색에 맞춤`을 고른 호리존 세트 멤버가 있고, 그 멤버들이 쓰는 색상 중 아직 측정 결과가 없는 색이 있을 때다. 대상은 그 세트들이 실제로 쓰는 색상(최대 4색)의 첫 Front와 첫 Back 사진뿐이고, 필요한 색상을 한꺼번에 측정한다. 콘티보드는 로그인한 뒤에만 들어갈 수 있으므로 서버가 프로젝트에 저장된 원본 사진을 직접 읽는다. 측정 요청은 저장이 끝난 뒤 보내고 마네킹컷 이동을 기다리게 하지 않는다. 관찰은 기존 부가 분석 시간 상한을 넘기면 중단한다. 관찰이 실패하거나 시간을 넘기면 아무것도 저장하지 않으므로 다음 이동 때 다시 시도한다. 이동 시점의 측정이 끝나지 않은 채 상세페이지 생성이 시작되면 생성 작업이 같은 조건으로 한 번 더 측정하고, 그래도 근거가 없으면 해당 컷을 기존 배경으로 만든다. 한 번 저장된 색상별 결과는 가능과 불가를 가리지 않고 사진이나 의류 종류가 바뀔 때까지 그대로 쓴다.

관찰 모델은 판매 의류의 안쪽 영역과 종류·품질 플래그만 제안하고 HEX를 추측하지 않는다. 가디건 등은 서비스 분류에 맞게 아우터로 구분한다. EXIF 방향을 바로잡고, 관찰용은 긴 변 1024px, 측정용은 긴 변 512px로 먼저 줄인 다음 sRGB로 변환한 픽셀에서 색을 계산한다. 큰 사진을 원본 해상도 그대로 색 변환하고 다시 인코딩하지 않기 위해서다. 영역 좌표는 0과 1 사이 비율이라 비율을 유지한 축소와 어긋나지 않는다. 배경·피부·코디 의류·라벨·단추·깊은 그림자·반짝임을 피한 여러 패치를 사용한다. 흰 원단의 구김, 줄무늬, 워싱, 앞뒤 패널 차이도 대략적인 색 계열을 읽을 수 있으면 측정 근거를 만든다. 패치 간 차이와 반짝임·유색조명은 불확실성으로 기록하되 일괄 제외하지 않는다. 판매 의류 자체를 식별할 수 없거나 상품 종류가 다르면 제외한다. 측정값은 정밀 측색이 아니라 배경의 낮은 채도 색 계열 제안이다.

측정 계약은 상품 종류, 색상 ID, Front와 Back, 원본 파일의 SHA와 길이에 묶고 서버 소유 analysis에 저장한다. 측정은 줄인 픽셀로 하지만 근거는 원본 바이트에 묶으므로 생성 시점의 재검증과 그대로 맞는다. 비회원 분석을 로그인 뒤로 넘기는 인계 경로는 두지 않는다. 사진 또는 상품 종류가 바뀌면 무효화하며 생성 시점에 선택 색상의 현재 원본 바이트도 재검증한다. 한 색상이 측정 불가로 나와도 다른 색상의 측정 결과는 버리지 않는다. 클라이언트가 보낸 측정값은 저장하지 않는다. 저장 직전에 현재 상품 사진과 의류 종류를 다시 대조하고, 측정하는 사이 저장된 근거가 바뀌었으면 저장하지 않는다. 그래서 늦게 끝난 측정이 최신 근거를 덮어쓰지 않는다. 분석 결과를 다시 저장할 때도 그 사이 저장된 측정 근거를 잃지 않는다.

공개 요약은 현재 정책으로 계산한 backgroundStatus와 backgroundPolicyVersion도 제공한다. 인스펙터는 지원 세트의 배경 선택을 대기, 준비, 불가의 세 상태로 보여 준다. 측정 결과가 없거나, 결과가 현재 의류 종류나 정책 버전과 맞지 않거나, 세트가 쓰는 색 중 결과가 없는 색이 있으면 대기 상태다. 대기 상태에서도 `옷 색에 맞춤`을 고를 수 있고 이 값은 선택 의도로만 저장한다. 이때 다음 단계로 넘어갈 때 옷 색을 확인해 벽 색을 맞추고, 맞추기 어려운 색이면 기존 배경으로 만든다고 안내한다. 아직 측정하지 않은 상태를 근거 없음으로 보고 선택을 막거나 기존 배경으로 되돌리지 않는다. 세트가 쓰는 모든 색이 측정됐고 배경 계산도 가능하면 준비 상태다. 측정 결과 옷 색을 확인하지 못했거나 배경으로 바꿀 수 없는 색이 있으면 불가 상태로, 맞춤 선택지를 끄고 이유를 보여 주며 저장된 선택을 기존 배경으로 되돌린다. 불가 상태는 측정이 끝난 뒤 콘티보드로 돌아왔을 때 보인다. 관찰, 디코딩, 측정 실패는 해당 그룹을 기존 배경으로 생성하게 할 뿐이고 마네킹컷 이동이나 생성을 막지 않는다. v1 색 근거는 아직 이 PR 안에서만 생성되므로 기존 운영 데이터 이관은 필요하지 않다.

## 생성·검수 계약

의류색 맞춤은 벽 표면의 색 계열에 한정된 명시적 예외다. 정책 v3는 관측한 의류 색을 30도 색상 구간의 낮은 채도 벽색 제안으로 바꾼다. 이 HEX는 정확한 최종 벽 밝기 지시가 아니며 실제 벽 밝기·명암 기울기·무드는 해당 세트의 완성 예시가 결정한다. 원단이 여러 색이면 작은 포인트색 하나에 배경을 맞추지 않고 전체적으로 차분한 색 계열을 고른다. 노란색 계열은 탁한 올리브로 보이지 않게 채도를 더 낮춘다. 정책 수치는 서버의 버전 있는 JSON으로 관리한다. Oklab 변환은 [원 저자의 공개 수식](https://bottosson.github.io/posts/oklab/)을 사용한다. 수학적 색상 좌표와 실제 의류 사진의 품질을 동일시하지 않는다.

기존 스튜디오의 벽/바닥 구조, 바닥색, 광원 방향, 그림자의 방향·길이·퍼짐·가장자리 부드러움, 노출·화이트밸런스·명암 기울기·무드, 구도와 포즈 권한을 그대로 유지한다. 상품색·소재·구조가 최우선이며 이미지 전체에 색 필터를 씌우지 않는다. 사용자 정정(2026-09-26)에 따라 기존 실서비스의 모델 선택·보정·검수·재시도 흐름을 유지하고, 선택한 호리존 세트에 유효한 측정값이 있을 때만 벽색 예외를 추가한다. Flare 모델을 강제하는 별도 생성기는 제품 경로에 추가하지 않는다.

**완성 예시 직접 참고(2026-09-17 결정, 2026-09-26 재확인):** 호리존은 최종 생성예시 `all`을 잘라내지 않은 원본 그대로 입력으로 참고한다. 포즈 전용 마네킹이나 크롭한 pose로 바꾸지 않는다. `all`은 구도·호환되는 포즈·배경·조명의 근거이고, 실제 상품 사진과 선택한 모델 입력은 의류·정체성의 근거다. 결과의 프레이밍은 샷에 따라 다르다. 중간샷은 고른 예시의 자르는 위치와 인물 크기를 따른다. 풀샷은 기장과 밑단을 보는 컷이므로 예시를 따르더라도 머리부터 발끝까지 담고 발, 굽, 밑단을 자르지 않는다. 큰 촬영 구성은 유지하되 상품 표현에 필요한 작은 손·발·시선 차이는 허용한다. 세트 밖 낱장 호리존 컷에서 같은 예시를 다른 색상으로 반복하면 두 번째 색부터 ADR-0011의 미세 포즈 변주를 스타일링과 똑같이 적용한다. 공간 세트 멤버에는 적용하지 않는다. 핏 확인 섹션의 자동 포즈 돌려 넣기는 세트 멤버와, 방향이 맞는 완성 예시가 포즈를 정하는 컷에 넣지 않는다. 그런 컷에 이미 저장된 자동 포즈 문장은 auto로 되돌린다. 셀러가 직접 고른 포즈와 명시한 방향·샷 변경은 예시보다 우선한다. 이 입력 결정은 호리존 공통이며 배경 맞춤 선택 여부와 별개다. 배경 맞춤을 끄거나 측정이 불가능하면 같은 완성 예시의 기본 배경을 유지한다. 스타일링 세트의 pose/plate 격리는 바꾸지 않는다. 기존 포즈 자산은 호환 기록으로 남길 수 있으나 신규 호리존 릴리스의 필수 요건으로 삼지 않는다.

생성 프롬프트, CutPlan, 독립 검수와 공간 검수 모두 같은 벽 색 예외를 받아야 한다. 배경색이 달라졌다는 이유만으로 실패시키거나 전체 공간 유지 규칙을 끄지 않는다. 상품에 배경색이 번졌는지, 옷 윤곽이 배경에 묻히는지, 조명·바닥이 바뀌었는지 검사한다. 검증되지 않은 1% 위치 차이·IoU .98 같은 수치를 실제 이미지의 강제 실패 조건으로 쓰지 않는다.

호리존 공용 템플릿의 일반적인 `균일하고 부드러운 조명` 지시는 배경 맞춤을 켠 컷에서 예시의 강한 방향성 그림자를 평탄화할 수 있다. 배경 맞춤 컷에만 완성 예시의 벽·바닥 경계, 명암 기울기와 그림자 배치를 우선하는 문구를 사용한다. 기본 배경과 스타일링 컷의 템플릿은 그대로 둔다. 독립 컷 검수가 경계나 명암을 놓칠 수 있어, 벽색을 바꾼 경우에는 예시의 좌우 명암과 바닥 경계를 구체적으로 비교하고 실패 시 고정된 복원 문구로 원본 근거에서 재생성한다.

## 한계와 범위

Flare 4장과 MASTER 전용 검수 실험은 배경 맞춤 가능성을 본 연구 자료다. 그 실험에서 나온 니트 질감 의견·숨은 손 위치 오판을 기존 실서비스의 결함으로 일반화하거나 기존 QC를 전면 교체하는 근거로 사용하지 않는다. 미세 원단 질감에 대한 검수 의견 차이는 별도 연구 항목이다. 별도 S14 운영 모델 1컷 실험에서는 초기 프롬프트가 바닥 경계와 강한 명암을 잃었다. 배경 맞춤 전용 문구를 넣은 2차 1컷은 방향성·경계를 더 잘 유지했지만 20세트 전체 품질을 증명하지는 않는다. 알려진 초기 실패 이미지는 강화 전 독립 검수에서 통과했고 강화 후 검수에서 경계 손실로 실패했다. 실제 운영 `CUT_OUTPUT_QC_MODE` 기본값은 off이므로 이 실험의 검수 결과를 운영 자동 차단으로 표현하지 않는다.

측정값은 사진에서 관측한 색이지 보정된 실물 원단 측색값이 아니다. AI가 일관되게 잘못 잡은 영역이나 모든 사진에 동일하게 들어간 색조명까지 검출한다고 보장할 수 없다. 잘못 입력된 색이나 여러 색의 외곽 윤곽까지 팔레트 계산만으로 보장하지 않는다. 초기 명도·채도 값은 운용 가설이며 다른 의류의 실제 생성 결과로 보정할 수 있다. 참고 예시 사진에는 임의 틴트를 씌우지 않는다. 옷 색은 다음 단계로 넘어갈 때 확인하고 벽색은 생성할 때 적용된다는 점을 인스펙터 안내로 알린다.

이 결정은 호리존 세트의 벽색에만 적용된다. 스타일링·제품컷·디테일컷의 모델·정책을 바꾸지 않는다. 신규 8세트와 수정 원본의 자산 등록은 이 PR의 발행 카탈로그에 반영됐으며, 실제 운영 배포와 그 뒤의 생성 품질 관찰은 별도 상태로 확인한다.
