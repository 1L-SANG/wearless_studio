# 호리존 세트의 촬영 구성과 배경 정책을 분리한다

상태: Accepted (사용자 결정 2026-09-26; 구현·배포 상태는 별도 검증 기록)

## 제품 동작

촬영 구성과 배경색을 섞은 제목은 무엇을 선택하는지 불명확하다. 카드는 짧은 특징 이름·사진·컷 수로 구성한다. 세트 클릭은 추가 상세/확정 단계 없이 즉시 교체하고 목록·스크롤·포커스를 유지한다. 교체는 되돌릴 수 있다. 개별 컷을 누르면 기존 방향·대상 색상 인스펙터를 유지하고 소속 세트와 세트 설정 진입점만 짧게 표시한다. 대표 사진 아래에는 실제 추가 컷을 최대 4개까지 보여준다.

배경은 세트 선택 인스펙터 위쪽의 `기존 배경` / `옷 색에 맞춤` 두 글자 버튼으로 선택한다. 시각적인 라디오 원은 숨기되 키보드/보조기술의 선택 의미는 유지한다. 선택 범위는 해당 인스턴스 전체 컷이다. 기본값은 기존 배경이다. 새 선택지는 여성 상의의 파란 벽 예시에만 묶지 않고 상의·하의·아우터·원피스에 공통으로 제공한다. 카탈로그에 같은 세트를 복제하지 않는다. 같은 카탈로그 세트라도 두 번 배치하면 서로 다른 인스턴스다. 같은 인스턴스의 멤버는 함께 변경·저장·되돌린다. 새 멤버는 그룹 설정을 이어받고 그룹 밖으로 나온 컷은 세트 설정을 제거한다.

`horizonBackgroundMode`는 선택 의도만 저장한다. 임의 HEX, 색상명, 13개 스와치의 대표값은 배경 계산 근거로 쓰지 않는다. 측정이 유효하고 해당 촬영 세트가 허용 목록에 있을 때만 적용한다. 불확실하거나 오래된 근거는 기존 배경으로 돌아가며 요청/실제 적용/이유를 결과 기록에 남긴다.

## 대표색을 읽는 단계

사진 분석 요청에서 기준색 및 다른 색의 첫 Front/Back을 별도의 선택적 관찰 작업으로 병렬 처리한다. 기존 AG-01·AG-08·입력 일관성의 기준색 최대 4장과 인덱스는 변경하지 않는다. 추가 색상은 최대 4장, 실제 UI의 최대 3색 범위 안에서 수집한다. 기존 60MiB 요청 상한 안에 들어가지 않는 추가 색상은 통째로 생략하고 핵심 분석을 막지 않는다. 관찰은 기존 부가 분석 시간 예산으로 제한한다.

관찰 모델은 판매 의류의 안쪽 영역과 종류·품질 플래그만 제안하고 HEX를 추측하지 않는다. 가디건 등은 서비스 분류에 맞게 아우터로 구분한다. EXIF 방향과 ICC→sRGB를 맞춘 원본 픽셀에서 색을 계산한다. 배경·피부·코디 의류·라벨·단추·깊은 그림자·반짝임을 피한 여러 패치를 사용하고, 패치/앞뒤 사진의 불일치와 다색·무늬·투명/광택·불확실성을 검사한다. 구김의 자연스러운 명암과 다른 색을 구별하기 위해 색 비교에서 명도 변화의 가중치를 낮추되, 원래 명도 범위를 보존하여 배경 선택에 반영한다.

측정 계약은 상품 종류·색상 ID·Front/Back·원본 SHA/길이에 묶고 서버 소유 analysis에 저장한다. 게스트 인계는 용도별 서명과 만료를 검증한다. 사진 또는 상품 종류가 바뀌면 무효화하며 생성 시점에 선택 색상의 현재 원본 바이트도 재검증한다. 다른 색상이 용량 때문에 제외되어도 이미 검증한 색의 근거를 버리지 않는다. 임의 클라이언트 측정값을 저장하거나 오래된 서명으로 새 측정을 덮어쓰지 않는다.

측정 성공과 배경 변경 가능 여부는 별개다. 공개 요약은 현재 정책으로 계산한 backgroundStatus/backgroundPolicyVersion도 제공한다. 인스펙터는 세트의 모든 선택색과 세트 허용 목록을 확인하며, 애매한 색에서는 맞춤을 가능하다고 표시하지 않는다. 관찰/디코딩/측정/서명 승격 실패는 기존 배경 선택으로 수렴하고 콘티 진입 자체를 차단하지 않는다.

## 생성·검수 계약

의류색 맞춤은 벽 표면색에 한정된 명시적 예외다. 색 계열은 유지하되 채도를 낮추고 옷과 배경의 밝기를 구분한다. 흰색·연한 색은 한 단계 어두운 벽, 어두운 의류는 밝은 벽으로 윤곽을 드러낸다. 노랑 계열을 어둡게 할 때는 탁한 올리브색처럼 보이지 않도록 채도를 더 줄인다. 정책 v2는 유한한 30도 색상 구간과 낮은 채도의 밝은/중간 벽 색을 사용한다. 밝고 어두운 벽 중 어느 쪽이 안정적인지 명암 범위가 경계에 걸리면 기존 배경을 유지한다. 수치와 허용 세트는 서버의 버전 있는 정책 JSON으로 관리한다. Oklab 변환은 [원 저자의 공개 수식](https://bottosson.github.io/posts/oklab/)을 사용한다. 이 수학적 색상 좌표와 실제 의류 사진의 품질을 동일시하지 않는다.

기존 스튜디오의 벽/바닥 구조, 바닥색, 조명 방향·부드러움, 그림자, 구도, 포즈 권한을 그대로 유지한다. 상품색·소재·구조가 최우선이며 이미지 전체에 색 필터를 씌우지 않는다. 사용자 정정(2026-09-26)에 따라 기존 실서비스의 모델 선택·보정·검수·재시도 흐름을 유지하고, 선택한 호리존 세트에 유효한 측정값이 있을 때만 벽색 예외를 추가한다. Flare 모델을 강제하는 별도 생성기는 제품 경로에 추가하지 않는다.

**완성 예시 직접 참고(2026-09-17 결정, 2026-09-26 재확인):** 호리존은 최종 생성예시 `all`을 원본 크롭 그대로 참고한다. 포즈 전용 마네킹이나 크롭한 pose로 바꾸지 않는다. `all`은 구도·호환되는 포즈·배경·조명의 근거이고, 실제 상품 사진과 선택한 모델 입력은 의류·정체성의 근거다. 큰 촬영 구성은 유지하되 상품 표현에 필요한 작은 손·발·시선 차이는 허용한다. 명시한 방향·샷·포즈 변경은 예시보다 우선한다. 이 입력 결정은 호리존 공통이며 배경 맞춤 선택 여부와 별개다. 배경 맞춤을 끄거나 측정이 불가능하면 같은 완성 예시의 기본 배경을 유지한다. 스타일링 세트의 pose/plate 격리는 바꾸지 않는다. 기존 포즈 자산은 호환 기록으로 남길 수 있으나 신규 호리존 릴리스의 필수 요건으로 삼지 않는다.

생성 프롬프트, CutPlan, 독립 검수와 공간 검수 모두 같은 벽 색 예외를 받아야 한다. 배경색이 달라졌다는 이유만으로 실패시키거나 전체 공간 유지 규칙을 끄지 않는다. 상품에 배경색이 번졌는지, 옷 윤곽이 배경에 묻히는지, 조명·바닥이 바뀌었는지 검사한다. 검증되지 않은 1% 위치 차이·IoU .98 같은 수치를 실제 이미지의 강제 실패 조건으로 쓰지 않는다.

## 한계와 범위

Flare 4장과 MASTER 전용 검수 실험은 배경 맞춤 가능성을 본 연구 자료다. 그 실험에서 나온 니트 질감 의견·숨은 손 위치 오판을 기존 실서비스의 결함으로 일반화하거나 기존 QC를 전면 교체하는 근거로 사용하지 않는다. 미세 원단 질감에 대한 검수 의견 차이는 별도 연구 항목이다.

측정값은 사진에서 관측한 색이지 보정된 실물 원단 측색값이 아니다. AI가 일관되게 잘못 잡은 영역이나 모든 사진에 동일하게 들어간 색조명까지 검출한다고 보장할 수 없다. 잘못 입력된 색이나 여러 색의 외곽 윤곽까지 팔레트 계산만으로 보장하지 않는다. 초기 명도·채도 값은 운용 가설이며 다른 의류의 실제 생성 결과로 보정할 수 있다. 참고 예시 사진에는 임의 틴트를 씌우지 않고 ‘배경 설정은 생성 시 적용’이라고 명시한다.

이 결정은 호리존 세트의 벽색에만 적용된다. 스타일링·제품컷·디테일컷의 모델·정책을 바꾸지 않는다. 신규 8세트의 운영 자산 등록, 기존 원본 수정본 발행, 운영 배포는 이 결정이나 로컬 시안만으로 완료되지 않는다.
