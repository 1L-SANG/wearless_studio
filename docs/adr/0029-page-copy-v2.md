# ADR-0029: 페이지 카피를 한 번에 쓰고 컷과 함께 만든다

상태: Accepted
결정일: 2026-11-19 오너 승인. 후기 별점은 2026-11-18 결정.
근거: 카피 작업지시서 B 승인판, COPY_SPEC 7절, TO_PO 22~27절.

## 맥락

상세페이지의 판매 특징과 디테일 설명만 만들던 경로를 페이지 전체 카피에 연결한다. 2회차부터 2.2판 시험과 오너 비교에서 별도 다듬기 호출의 이득이 작아 다듬기를 접었다. 카피 때문에 이미지 생성 시작을 늦추지 않으며 크레딧 단가는 유지한다.

## 결정

1. `page_copy.generate`가 섹션 글, 판매 특징, 부위 설명을 같은 모델 요청으로 쓴다. 방식은 `single`뿐이다. `draft`, `draft+polish`, 초안 공유와 다듬기 검사를 제거한다. 검사에 실패한 칸과 꼭 채워야 하는 누락 칸은 성공한 같은 경로로 한 번 고쳐 쓸 수 있다. 셀러 MD 코멘트를 다듬는 것도 최초 페이지 요청에 포함되며 별도 다듬기 단계가 아니다.
2. 페이지 경로 설정은 `PAGE_COPY_ROUTES`다. 코드 기본값은 `gemini:gemini-4-argon,gemini:gemini-4-hydrogen`이며 역순도 설정할 수 있다. 앞 경로의 오류, 시간 초과, 응답 꼴 오류는 다음 경로로 한 번만 넘어간다. 운영 순서는 템플릿 총괄의 추가 시험 뒤 배포 설정으로 확정한다. 모델별 생각 단계와 출력 상한은 `settings_v2.json`을 읽는다.
3. 새 경로 설정이 있으면 옛 `MODEL_ORDER_PAGE_COPY`, 모델별 페이지 설정보다 우선한다. 새 설정이 없으면 옛 공통 순서와 모델 이름을 읽어 경로 목록으로 바꾸고 경고한다. 옛 섹션별 경로는 한 번에 쓰기와 맞지 않아 무시하고 경고한다. 다듬기 전용 설정은 제거한다. 프롬프트 기본 판은 v2이고, 에디터 `feature_copy.generate`는 기존 A 구현의 모델 생성 후 누락 칸 사전 보완 순서를 보존하고 `feature_*_v1`을 고정한다.
4. 워커는 컷 시작 전에 카피 작업을 따로 띄운다. 컷에는 시작 시점 분석과 빈 `copy_results`를 전달하고 새 카피는 최종 조립 직전에만 기다린다. `PAGE_COPY_TIMEOUT_SECONDS` 기본 90초는 준비, 경로 전환과 한 번의 고쳐 쓰기를 모두 포함하며, 조립 시 이미 흐른 시간을 뺀다. 잡 실패나 취소 시 카피 작업도 취소하고 회수한다.
5. 카피는 생성의 통과 조건이 아니다. 키가 없으면 호출하지 않고 빈 결과로 조립한다. 실패나 시간 초과는 경고만 남긴다. 일부 성공은 사용하고 기존 설명의 빠진 항목은 보존한다. 끝날 때 `copy_ready` 진행 이벤트를 한 번 보내며 당시 최신 진행 값을 그대로 실어 막대가 뒤로 가지 않는다.
6. 응답 섹션 키는 콘티 저장 순서상 해당 섹션 첫 블록 ID로 바꾼다. 조립 입력은 `[{blockId,texts:[{role,text}]}]`다. 분석 JSON의 `pageCopy`에 `copyResults`, `promptVersion`, `model`, `createdAt`을 저장한다. `partDescriptionCopy`와 `featureCopy`도 기존 분석 키 병합으로 저장한다. DB 열이나 콘티 블록 필드는 추가하지 않는다. 카피 입력을 생략한 조립은 저장된 `pageCopy`를 쓸 수 있고 명시적 빈 목록은 저장값을 쓰지 않는다.
7. `label`은 두 설명 목록의 선택 필드이며 화면용 이름표다. 공백 제외 8자 이하, 봉제 용어와 과장어가 없는 값만 받는다. 실패하면 `label`만 버리고 설명은 유지한다. 짝 맞추는 `point`, 그림 지시문과 컷 생성의 이름표는 분석 원문이다. 디테일 후보나 `aiSuggestedPoints`로 분석 출처가 확인될 때만 화면 이름을 바꾸며 셀러 원문과 출처 불명은 보존한다.
8. 상품 소개 본문은 생성 카피가 있으면 먼저 쓰고 없으면 셀러 원문을 쓴다. 셀러 글이 있으면 초안 표시가 없다. 셀러 글이 없으면 AI 본문 또는 강조 특징과 옷 종류로 만든 사실 한 문장을 초안으로 넣는다. 한 문장도 만들 수 없으면 본문과 감성형 아바타, MD 이름표를 숨기고 높이를 다시 계산한다. 대기 화면은 다듬은 본문으로 원문을 바꾸되 대기 중 수동 편집은 보호한다.
9. 궁금한 점 답, 원단 제목과 본문, 사이즈 팁은 `aiDraft`다. 추천 대상은 `ai`다. 후기와 SNS 본문의 초안 표시는 유지한다. 후기마다 글 위에 고정 별 다섯 개를 강조 색 토큰으로 표시하며 셀러가 편집할 수 있다. 쇼룸형은 후기 섹션을 추가한 경우에만 표시한다.
10. 후기의 요가 아닌 말끝 강제는 없애고 명사형 끝을 막는다. 오버핏과 세미오버핏의 FAQ 답에서만 단정하지 않는 한 사이즈 작게 권유와 실측표 안내를 함께 허락한다. 레귤러, 슬림, 크게 권유, 다른 칸의 권유는 막는다. 따뜻함은 기모, 퀼팅 충전재, 패딩 충전재, 울 혼방 사실이 있을 때만 허락하고 절대 보온과 다른 성능 주장은 계속 막는다.
11. 호출마다 모델, 토큰, 경과 시간, 고쳐 쓰기 여부를 기록한다. 이미지와 같은 `image_usage` 계측 경로를 사용하고 `page_copy_call` 구조화 로그도 남긴다. 단가표에 없는 텍스트 모델의 금액은 추측하지 않는다. 크레딧 단가는 바꾸지 않는다.
12. 시험 틀만 `GEMINI_API_KEY_NEXT`를 읽는다. 잔액 또는 할당량 소진이면 한 번 예비 키로 전환하고 그 호출부터 이어 한다. 일시적인 초당 제한은 전환하지 않는다. 실행과 호출 기록에는 `primary`, `next`만 남기고 키 값은 남기지 않는다. 운영 키 설정과 `vision_llm` 키 정책은 바꾸지 않는다.

## 검증과 한계

가짜 공급자로 생성, 실패, 부분 성공, 동시 실행, 마감 시간과 취소를 검증한다. 두 조립 엔진은 같은 고정 입력을 비교한다. 실제 모델 호출과 화면 확인은 이번 구현 범위에 없다. 지시문 본문과 운영 모델 최종 순서는 담당 총괄이 확정한다.

컷 저장 중 글자 대비 계산은 기존처럼 카피가 없는 분석으로 동작한다. 그 계산 직전에만 기다리는 대안도 있으나 컷을 늦추지 않는 결정을 따른다. 업로드 FAQ의 최종 대비 계산은 조립 직전 카피를 사용한다.
