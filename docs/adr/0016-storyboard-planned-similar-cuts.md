# 콘티에서 비슷한 컷을 예약하고 완성된 원본으로 생성한다

상태: Accepted, 사용자 승인 2026-10-09. 2026-10-10 세트 포함 개정, 오너 결정

에디터 현재 이미지 수정은 기준 사진과 `비슷한 컷 생성` 한 버튼으로 제공한다. 수동 방향·포즈·표정 선택은 제거한다. 기존 요청의 변경값 처리는 이전 클라이언트 호환 계약으로만 남는다(2026-10-10 대체됨, 아래 개정).

콘티에서는 일반 AI 착용 카드에서 `비슷한 컷 추가`로 후속 카드를 만든다. 후속 카드의 `similarSourceBlockId`는 원본 카드 ID이며 원본의 상품·예시 설정을 상속한다. 방향별 분류나 새로운 생성예시가 필요하지 않다. 개별 호리존 예시와 장소세트 데이터는 유지한다. 후속 컷은 어떤 경우에도 후킹 프레임 슬롯 후보가 되지 않고 구성 뒤에 남는다. 구성 변경으로 원본이 삭제되면 함께 삭제한다.

후속 컷의 세트 소속은 원본에서만 온다. 원본의 `spaceGroupId`와 `spaceVariation`, 배경 설정을 상속하고 세트 장수에 포함한다. `spaceSetMemberOrder`는 없으며 예비 멤버를 쓰지 않는다. 세트에서는 원본과 기존 후속 컷의 마지막 카드 바로 뒤에 추가한다. 후속 컷의 복제도 최초 원본에 한 장 더 추가한다. 세트 밖 원본은 기존처럼 사진 행 뒤에 추가한다.

세트 교체와 섞기는 후속 컷을 뺀 원본 멤버 수와 순서로 대체한다. 원본 ID가 남으면 후속 컷도 원본 바로 뒤에 남아 새 설정과 소속을 상속한다. 원본이 사라지면 함께 정리하고 장수를 알린다. 원본 삭제는 후속 컷도 삭제하며 남은 세트는 한 장이어도 유지한다. 후속 컷만 삭제하면 그 카드만 사라진다. 후속 컷은 같은 세트 안에서만 옮길 수 있다. 원본이 세트 밖으로 이동하면 후속 컷도 바로 뒤로 함께 이동해 세트에서 빠진다. 세트 전체 이동은 후속 컷도 포함한다. 교체 되돌리기는 이전 보드 전체를 복원하고, 삭제 되돌리기는 다른 조작 뒤의 재삽입도 세트 소속과 연속 순서를 복원한다.

콘티의 예시 사진은 촬영 계획 미리보기다. AI 실행은 상세페이지 생성 작업에서 원본의 실제 생성 사진이 나온 뒤 이뤄진다. 같은 작업 내 서버가 소유한 원본 바이트로 먼저 후속 컷을 만들 수 있으며, 공개 에디터 API는 저장된 프로젝트 소유 사진만 받는 기존 규칙을 유지한다. 화면 진입·새로고침은 생성 책임을 갖지 않는다.

여러 후속 컷은 모두 최초 원본을 사용한다. 계획은 생성 호출 전 서버에 저장하며 재시도에 재사용한다. 원본 실패 시 후속 컷을 일반 예시 생성으로 대체하지 않는다. 결과의 원본 계보는 이후 에디터 비슷한 컷 생성에서도 유지한다. 일반 카드 복제의 동일 사진 재사용은 유지하고 후속 컷은 별도 생성 장수·기존 단가로 정산한다. 원본 삭제는 후속 카드 삭제를 포함하며 되돌리기를 지원한다.

표시는 기존 사진 비율·서체를 유지하고 작은 무채색 라벨과 원본 번호·썸네일로 연결을 표현한다. 긴 설명은 인스펙터에만 둔다. 색상 배지·장식 연결선·방향 분류는 추가하지 않는다.

## 2026-10-10 개정, 옛 수정 경로 정리

오너 결정(2026-10-10)으로 이전 클라이언트 호환으로 남겼던 수정 경로를 서버에서도 없앴다.

- 현재 이미지 수정 요청은 두 가지만 받는다. 착용 사진의 `비슷한 컷 생성`(`variationMode='similar'`)과, 원본 검수 레시피가 있는 디테일컷의 `같은 부위 다시 촬영`이다.
- 변경값(방향, 포즈, 표정, 배경)과 배경 참조는 받지 않는다. 비어 있지 않은 `changes`, `refBg`, `refBgAssetId`가 오면 거절한다.
- 제품컷 결과 사진 한 장을 원본 확인 없이 다시 그리던 AG-07 경로(빈 변경의 `이미지 수정`)는 없앴다. 고스트샷 같은 제품컷은 `새 이미지 추가`에서 원본 사진을 골라 만든다(ADR-0008 2026-10-10 개정).
- AG-07 실행기는 비슷한 컷 계획을 실행하는 용도로만 남는다.

## 2026-10-15 개정, 조건 표로 계획하고 자세 변화를 허용한다

오너 결정(2026-10-15). 근거는 실험 세 번이다(로컬 `.scratch/similar-cut-lab-20261014/HANDOFF.md`). 지금 방식은 6컷 중 2컷에서 손이 세 개가 되거나 잘려 있던 얼굴이 드러났고, 대부분 원본과 거의 같은 작은 동작이었다. 아래 방식은 14컷에서 그런 결함이 없었고 원본 대비 변화가 약 네 배였다.

- 비슷한 컷은 같은 촬영의 다음 셔터처럼 보이는 새 자세를 만든다. 사람, 옷, 장소, 빛, 카메라, 앉고 선 상태, 몸이 바라보는 방향은 유지한다. 등을 보이거나 자리를 옮기지 않는다. 이 범위 안에서 다리 풀기와 꼬기, 상체 기울이기, 지지물에 기대기와 떨어지기, 한 걸음, 발목 교차, 골반 이동 같은 자세 변화를 허용한다. 손가락이나 체중만 조금 바뀌는 변화는 새 사진으로 치지 않는다.
- 계획 AI는 먼저 원본 상태 장부를 채운다. 자세, 지지물, 바로 옆 지지물, 촬영 방식, 구도, 얼굴, 머리, 다리, 상체, 화면 기준 양손의 상태와 쥔 물건, 시선, 소품, 보이는 옷 부위다. 그다음 서버 동작 표에서 조건이 모두 맞는 동작 하나를 고르고, 시선이나 표정 한 가지를 보조로 더할 수 있다. 서버가 조건을 코드로 검사하고, 어긋나면 기존 1회 재계획으로 돌려보낸다.
- 동작 표와 조건은 서버 코드가 정본이다. 프롬프트에 경우별 예외 문장을 늘리지 않고, 표에 동작과 조건을 더한다.
- 손이 쥔 물건은 그 물건에 관한 동작이 아니면 계속 쥔다. 물건을 더하거나 없애거나 다른 손으로 옮기지 않는다. 셀카에서 휴대폰을 쥔 손은 움직이지 않는다. 얼굴이 잘린 사진에서는 얼굴이 필요한 동작을 고르지 않는다. 상의, 아우터, 원피스 상품은 팔짱처럼 상품 앞면을 가리는 동작을 고르지 않는다.
- 계획은 새 자세에서 셀러 옷의 주름이 어떻게 바뀌는지 적는다. 그림 단계는 옷의 디자인, 색, 길이, 폭, 디테일을 유지하고 주름만 새 자세에 맞게 새로 그린다.
- 바꾸지 않는 부위는 서버가 상태 장부로 "그대로 둘 것" 목록을 만들어 그림 단계에 넘긴다. 그림 단계에 보내는 손은 좌우 대신 쥔 물건이나 놓인 곳으로 부른다. 거울 사진에서 좌우를 뒤집어 읽는 오류가 실험에서 실제로 나왔기 때문이다.
- 반복 판정은 같은 원본의 이전 계획과 동작, 손, 보조 시선의 조합이 같은지로 한다. 쓰지 않은 동작이 있으면 그것을 우선한다. 조건을 통과하는 새 동작이 없으면 예전 동작을 다른 손이나 다른 보조 시선으로 다시 쓸 수 있다.
- 계획 AI는 전용 설정 `MODEL_ROUTING_TEXT_GEMINI_SIMILAR`(기본 `gemini-3.8-flash`, 생각 수준 low)을 쓴다. 공용 text 모델은 출고 검수가 함께 쓰므로 바꾸지 않는다.
- 두 부위를 동시에 움직이는 방식과 몸 방향 30도 틀기는 이번 범위가 아니다. 실험 3판의 확대 검사 뒤 따로 정한다.

바꾸지 않는 것: 가격(8크레딧), 최초 원본 재사용, 생성 전 계획 저장과 재시도 재사용, 실패 미차감, 장소세트 규칙, 그림 모델과 크기, DB 스키마. 저장 계획의 모양은 계약 문서(`documents/common_data_contract.md`)의 비슷한 컷 계획 절을 따른다.
