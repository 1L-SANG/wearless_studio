# 컷 생성은 세 계열로 컴파일하고 QC는 독립 워크플로우로 실행한다

상태: Accepted
결정일: 2026-08-03

## 결정

서비스의 컷 생성은 다음 세 상위 계열만 쓴다.

1. `styling` — 생활 공간 스타일링컷. 기존 `mirror`는 이 계열의
   `captureMode='mirrorSelfie'` 하위 방식으로 컴파일한다.
2. `horizon` — 중립 호리존 스튜디오컷.
3. `product` — 사람 없는 제품컷. `productVariant='ghost'|'detail'`을 반드시 구분한다.

`all|pose|bg`는 생성 계열이 아니라 **생성예시가 맡는 범위**다. 공간 세트도 별도
생성 계열이 아니라 styling 또는 horizon 컷 여러 장을 한 촬영 세션으로 묶는
`SeriesPlan`이다. 따라서 화면과 상위 프롬프트 계열은 세 가지이지만, 실행기는
거울 반사, 배경 플레이트 편집, 포즈 제어, 공간 세트 멤버, 고스트, 디테일처럼
물리적으로 다른 하위 작업을 구분해 실행한다.

## 항목별 정본과 우선순위

하나의 전체 우선순위 문장으로 모든 이미지를 경쟁시키지 않는다. 결과의 항목마다
정본을 하나만 둔다.

| 결과 항목 | 정본 |
|---|---|
| 상품 구조·실루엣·소재·무늬·봉제·부자재·상품에 인쇄된 텍스트와 로고 | 셀러 상품 사진 |
| 목표 색상 | 콘티보드의 `colorId`와 그 색상의 셀러 상품 사진 |
| 모델 얼굴·체형 | 프로젝트에서 선택한 모델 |
| 매칭 의류 | 사용자가 선택한 `matchIds` |
| 컷 계열·샷·방향·얼굴 노출·아우터 여밈 | 현재 콘티보드 카드 값 |
| 포즈 | 사용자가 직접 고른 포즈 > 공간 세트/생성예시 포즈 > 계열 기본값 |
| 선언된 핏·길이 축 | 핏 설정이 명시한 축에 한해서만 핏 프로필 |
| 장소 | 공간 세트 대표 공간 > `bg` 빈 플레이트 > `all` 예시 > 계열 기본값 |
| 조명·색감·촬영 분위기 | 장소 정본과 같은 시각 근거. 활성 근거가 없을 때만 무드/기본값 |

사용자가 콘티보드에서 색상·방향·샷·포즈·얼굴 노출·여밈을 바꾸면 저장된 생성예시보다
현재 사용자 값이 우선한다. 프롬프트에 상반된 두 지시를 함께 적어 해결하지 않는다.
컴파일 단계에서 생성예시가 맡던 충돌 항목을 제거하고, 더 이상 권한이 없는 이미지도
모델 입력에서 제외한다. 예를 들어 방향을 바꾼 `all` 예시는 새 방향과 양립하는
장소·조명·색감·촬영 분위기만 맡고, 예시의 원래 방향은 더 이상 맡지 않는다.

`No text`는 금지한다. 대신 결과에 새 캡션·워터마크·오버레이를 추가하지 말라고 지시하고,
상품 자체의 텍스트와 로고는 철자·모양·색·위치·방향·개수를 상품 사진과 같게 유지한다.
상품 사진에서 확인할 수 없는 텍스트·로고·부자재는 지어내지 않는다.

## 하위 방식의 불변 조건

- `styling/direct`: 생활 공간의 촬영 문법과 선택 예시의 스냅/화보 촬영 등급을 유지한다.
- `styling/mirrorSelfie`: 반사 방향, 휴대폰, 거울 프레임, 얼굴 가림을 별도로 검사한다.
- `horizon`: 중립 스튜디오, 요청 방향과 샷, 의류 실루엣을 우선한다.
- `product/ghost`: 사람·신체가 없어야 하고 상품 전체가 보여야 한다.
- `product/detail`: 실제 Detail 근거가 필수이며 보이는 구조만 재현한다. 근거가 부족하면
  생성하지 않는다. 다른 색상의 Detail을 쓰는 경우 구조는 고정하고 허용된 색상만 바꾼다.
- 공간 세트: 대표 공간은 세트의 장소 정본이지만 각 멤버의 카메라 위치·구도·포즈·광원
  결과는 독립 컷으로 생성한다. 단순 크롭이나 동일 배경 복제는 허용하지 않는다.

## 독립 QC 워크플로우

생성 모델의 자기평가를 통과 근거로 쓰지 않는다. 생성과 분리된 판정기가 다음 단계를
순서대로 실행하고, 각 단계는 `PASS|FAIL|NA|UNJUDGEABLE`과 관찰 근거를 구조화해 남긴다.

1. **생성 전 검사** — 스펙 조합, 이미지 역할, 발행 자산, 항목 정본의 충돌 여부를 확인한다.
2. **상품 동일성** — 색상, 구조, 실루엣, 소재, 무늬, 봉제, 부자재, 텍스트, 로고를 확인한다.
3. **사용자 의도·예시 범위** — 계열, 하위 방식, 샷, 방향, 포즈, 얼굴 노출,
   `all|pose|bg` 범위가 현재 콘티보드 값과 맞는지 확인한다.
4. **사진 물리성** — 인체 비대칭과 원근, 손·관절, 옷의 장력·주름·처짐, 광원 방향,
   인물과 옷의 명암·반사, 접지·투영 그림자, 노출·화이트밸런스·심도, 합성 경계를 확인한다.
5. **모델 동일성** — 비교 가능한 얼굴·체형이 선택 모델과 같은지 확인한다.
6. **재시도** — 실패 항목을 사실 형태의 교정 패치로 같은 CutPlan에 넣고 독립 판정기가
   다시 본다. 현재 서비스의 시도 횟수와 채택 규칙은 아래 실행 계약을 따른다.
   `UNJUDGEABLE`은 통과가 아니다.
7. **페이지·세트 검사** — 모든 컷이 같은 SKU와 목표 색상으로 보이는지, 같은 모델과
   고정된 매칭/이너를 유지하는지 확인한다. 같은 공간 그룹 안에서만 같은 촬영 세션으로
   보이는지도 검사한다. 페이지 전체가 하나의 장소일 필요는 없다.

자동 판정은 먼저 `shadow`로 실제 좋은/나쁜 표본에 보정하고, 오탐률을 확인한 뒤에만
출고 차단에 사용한다. 생성예시 제작 때 쓰던 독립 Codex 검수의 유효한 원칙—제작자와
판정자 분리, 블라인드 시도 비교, 불변 해시, 재검수 이력, 사람이 보는 HTML—은 오프라인
골든셋과 릴리스 검수에 재사용한다. 실시간 서비스는 데스크톱 Codex 세션에 의존하지 않고
동일한 판정 계약을 구현한 독립 비전 판정기를 사용한다.

현재 구현은 독립 컷 QC를 `off|shadow|repair`, 페이지/세트 QC를 `off|shadow`로 제공하며
코드 기본값은 `off`다. `shadow`에서는 결과를 바꾸지 않고 판정만 작업 메타데이터에 저장한다.

2026-08-17~18 오너 결정으로 프로덕션 콘티 생성은 `repair`를 명시적으로 사용한다. 블록은 서로
병렬로 실행한다. `styling/direct`, `direction='front'`, `shot='full'|'medium'`,
`refScope='all'`, `pose='auto'`, `spaceGroupId` 없음, 생성예시 방향 호환이며 서비스 생성예시를
선택한 블록은 **확정 GPT exact 프로필을 요청한 것**으로 본다. 실제 실행에는 기준 색상, 선택된
resolved 마네킹컷, 대체되지 않은 선택 가상모델과 큐레이션된 서비스 생성예시가 모두 필요하다.
요청 뒤 이 실행 조건을 충족하지 못했다고 generic 경로로 바꾸지 않는다.

이 경로는 `GPT Image 2 Stage 1 → 독립 QC → 조건부 Stage 2 → 독립 재검수` 순서다.
`anatomyPerspectiveAsymmetry`와 `lightingShadowReflectionDrape` 실패만 Stage 1 이미지를 같은
GPT로 직접 편집한다. 프레이밍·방향·얼굴·포즈와 의류·모델·공간처럼 정본을 다시 봐야 하는
실패는 같은 CutPlan, exact 입력 패킷과 고정 프롬프트에 실패 축만 추가해 처음부터 다시
생성한다. Stage 2는 정확히 한 번만 시도하며, 통과하거나 실패 축이 줄고
기존 통과 축의 회귀가 없을 때만 채택한다. `UNJUDGEABLE`, QC 불능, Stage 2 실패·회귀에는 추가
호출 없이 Stage 1을 보존한다. 이 `repair`는 출고 차단 모드가 아니며, 모든 후보가 실패했을 때
`HOLD`하는 별도 `enforce`는 골든셋 보정 뒤에 연다.

exact 프롬프트는 과거 선호 실험에서 확정한 기존 iPhone 기본 Photo 계약과 Adjacent V4 문구를
`cut_generate_confirmed_gpt_v1.txt`에 그대로 고정한다. 모델은
`gpt-image-2-2026-04-21`, 품질은 `medium`, 출력은 PNG다. 서비스의 `4K` 요청은 GPT가 허용하는
정확한 2:3 최대 크기 `2336x3504`로 변환한다. 이것만 과거 실험의 `1024x1536`에서 의도적으로
바꾼 provider-level 조건이다. PL-4의 exact가 아닌 블록도 generic 입력·프롬프트는 유지하되
`detail_cut` GPT를 사용한다. 첫 시그니처 컷은 별도 `image_signature`, 에디터와 AG-07의 공유
`image_high`는 기존 Gemini 경로를 유지한다.

exact 프로필을 요청한 뒤에는 필수 모델 시트의 SHA-256·길이, AG-01 셀러 근거 계약과 현재
원본 바인딩, 생성예시/연출 카탈로그 및 해당 바이트 중 하나라도 없거나 불일치하면 그 컷을
실패시킨다. generic 입력이나 프롬프트로 조용히 강등하지 않는다. 반대로 처음부터 exact 프로필의
구조적 범위에 들지 않는 블록이 기존 generic 경로를 쓰는 것은 폴백이 아니라 정상 라우팅이다.

## 현재 런타임 이미지 입력 계약

프롬프트의 역할 목록과 실제 첨부 순서는 항상 함께 만든다. 텍스트 핏 프로필과 콘티보드
설정은 이미지가 아니며 아래 목록에 포함하지 않는다.

- 확정 GPT exact 착용컷: 선택 resolved 마네킹컷 → `grid_face_direction` →
  `grid_fullbody` → 셀러 상품 사진 1~4장을 합친 **라벨이 픽셀에 렌더된 근거 그리드 한 장**
  → 선택 매칭 의류 최대 한 장(있을 때) → 서비스 생성예시 순서다. 각 모델 시트는 manifest의
  SHA-256·길이와 실제 R2 바이트를 두 장 모두 확인한 뒤에만 원자적으로 첨부한다. 셀러 그리드는
  AG-01이 같은 분석 호출에서 만든 근거 계약과 현재 원본의 순서·SHA-256·길이가 같을 때만 만든다.
- 그 밖의 상세페이지 착용컷(`styling`, `horizon`)은 기존 generic 계약을 사용한다: 선택
  마네킹컷(있을 때) → 선택 모델의 `face_front`·`body_front` 쌍(그 방식을 쓸 때) → 현재 선택 색상의 셀러 상품 사진
  (Front→Back→Detail→Fit) → 첫 번째 매칭 의류 → 레거시 라이선스 얼굴(그 방식을 쓸 때)
  → 무드 최대 3장 → 생성예시 순서다.
  선택 마네킹컷은 기준색으로 생성된 자산이라 기준색 컷에만 첨부한다. 사용자가 다른 색을
  고른 컷에는 색상 충돌을 막기 위해 빼고, 해당 색상의 셀러 상품 사진을 정본으로 쓴다.
  다만 `bg` 플레이트는 편집 대상이라 항상 맨 앞에 둔다.
- `all`이나 `bg` 예시가 장소·조명을 맡거나 공간 세트 대표 플레이트가 있으면, 서로
  경쟁하는 무드 이미지는 첨부하지 않는다. `pose`만 참고하고 별도 플레이트가 없을 때는
  무드 이미지를 유지한다.
- 공간 세트는 대표 플레이트 한 장(있는 세트만)과 해당 멤버의 포즈 컨트롤 한 장을
  첨부한다. 플레이트는 장소 연속성만, 포즈 컨트롤은 해당 컷의 동작만 맡는다.
- 제품컷(`product/ghost|detail`): 선택 색상의 셀러 상품 사진 → 필요할 때 무드 → `all`
  생성예시만 첨부한다. 마네킹·모델 얼굴·매칭 의류는 구조적으로 첨부하지 않는다.
  디테일은 목표 색상 Detail을 우선하고, 없으면 목표 색상 일반 사진과 다른 색상의 Detail을
  함께 써서 허용된 색상만 바꾼다. 미세 무늬의 같은 색상 Detail 원본은 생성하지 않고 그대로 쓴다.
- 에디터의 단건 새 이미지도 같은 계열/정본 규칙을 쓰지만, 현재 UI 계약상 선택 마네킹과
  매칭 의류를 받지 않으므로 모델 참조 → 셀러 상품 사진 → 조건부 무드 → 생성예시만 첨부한다.

## 영향

- 기존 저장값 `cutType='mirror'`는 깨지지 않게 읽되 실행 시
  `recipeFamily='styling'`, `captureMode='mirrorSelfie'`로 컴파일한다.
- `refScope`와 공간 세트는 상위 계열 enum에 합치지 않는다.
- 프롬프트는 활성 계열·하위 방식·참고 범위에 필요한 규칙만 렌더하고, 권한이 없는 이미지는
  첨부하지 않는다.
- 컷 결과에는 적용된 CutPlan, 이미지 역할 목록, 프롬프트·스키마 버전, 후보별 QC와
  페이지 QC를 감사 가능한 메타데이터로 저장한다.
