# 에디터 캔버스에서 고른 사진의 AI 일은 왼쪽 여백의 오브 메뉴로 한다

상태: Accepted
결정일: 2026-10-12, 사용자 승인(시안 g1 확정). 시안 `mockups/editor_ai_concepts_20261011/g1-place-rule/index.html`(로컬 전용)

## 배경

에디터 왼쪽 AI 탭에는 "새 이미지 만들기"와 "현재 이미지 수정" 두 칸이 있었다. 고른 사진으로 할 일(비슷한 컷, 색상, 열림 정도, 디테일)이 사진에서 멀리 떨어진 패널에 있어 찾기 어려웠고, 결과가 나오면 의류 탭으로 넘어갔다. 사용자는 사진을 고르면 그 사진 가까이에서 할 일을 고르게 하자고 정했다(2026-10-10). 시안을 열여섯 차례 고쳐 g1을 확정했다(2026-10-11~12).

## 결정

### 1. 입구는 오브 하나

- 이미지 요소 하나를 골랐을 때만 오브가 뜬다. 여러 개 선택, 글자 편집, 자르기, 끌기, 크기 조절, 회전, 영역 선택, 화면 끌기 중에는 숨기고 끝나면 다시 계산한다.
- 모양은 유리 키캡(보이는 지름 30px, 누르는 영역 40px). 바깥 흰 테두리와 안의 글자는 없다. 회전은 안쪽 빛만 12초와 17초로 돌고 크기는 변하지 않는다. 올리면 그림자와 하이라이트, 누르면 1px 내려간다.
- 자리는 사진이 아니라 블록 기준이다. 가로는 블록 왼쪽에서 32px 바깥(화면 좌표), 세로는 고른 사진의 위 끝. 사진이 2열, 3열, 2×2의 어느 칸이어도 좌우로 뒤집지 않는다. 화면 위아래 끝이면 여백 안에서 높이만 맞춘다. 확대로 왼쪽 여백이 156px보다 좁으면 캔버스 왼쪽 위 고정 자리로 간다.
- 이렇게 하는 이유: 사진 기준으로 두면 2열 오른쪽, 3열 가운데에서 이웃 사진을, 2×2 아래 줄에서 윗줄을, 오른쪽에서는 빠른 도구를 가린다. 여백은 어느 배치에서도 비어 있다.
- 메뉴, 생성 중, 결과 액자가 떠 있는 동안에도 오브는 제자리에 있다. 오브를 다시 누르거나 메뉴 밖을 누르거나 Esc를 누르면 메뉴가 닫힌다.
- 알리는 방법: 오브에 올리거나 키보드 초점이 오면 오브 왼쪽에 한 줄 "이 사진으로 새 컷을 생성해요". 이름표와 자동 펼침은 쓰지 않는다. 온보딩에서 한 문장으로 알린다.

### 2. 메뉴는 두 단계, 세로 한 줄

- 오브를 누르면 오브 아래 10px부터 갈래가 세로로 선다. 오른쪽 끝은 오브의 오른쪽 끝과 같은 선이다. 아래 공간이 모자라면 위로 펼치되 선택지의 위아래 순서는 지킨다.
- 갈래 알약은 모두 같은 검정(`--cta-bg`)에 흰 글자와 흰 아이콘(20px, 글자와 8px)이고 폭이 같다. 바로 만드는 갈래("비슷한 컷", 디테일컷의 "같은 부위 다시", 빈 칸의 "원래 콘티대로 다시"와 "AI로 채우기")만 더스티 블루 회전 테두리(`--ring-flow-stops`)이고 누르면 바로 만든다. 펼치는 갈래(색상, 열림 정도, 앞뒷면, 디테일)는 오른쪽 끝에 작은 꺾쇠가 있다.
- 갈래를 누르면 나머지 갈래는 접히고 그 갈래 알약 아래 12px부터 선택지만 선다(한 단계에 한 종류). 선택지는 평소 불투명도 0.62, 올리거나 초점이 오면 1이다.
  - 색상: 흰 원(36px) 안 상품 색 원(24px), 원 왼쪽에 색 이름. 원이 오른쪽 끝 선에 서고 이름은 오른쪽 정렬.
  - 열림 정도: 흰 알약에 옷 아이콘(지퍼 손잡이 점으로 단계를 구분하는 그림)과 단계 이름. 위가 전체 닫힘, 아래가 전체 열림. 칸 수는 `outerClosureRange`를 따른다(다섯 칸, 두 칸, 여밈 없는 옷은 갈래를 숨긴다).
  - 앞뒷면과 디테일: 흰 알약 왼쪽에 그 면이나 그 부위의 작은 원형 사진(22px), 내용만큼의 폭, 오른쪽 정렬. 디테일 부위는 분석이 사진에서 찾은 것만 보인다(ADR-0012).
  - 지금 값(원본 사진의 색, 면, 열림 정도)은 체크로 표시하고 누를 수 없다. 지금 값을 모르면(직접 올린 사진 등) 체크를 그리지 않는다.
- 설명과 금액은 무언가에 올렸을 때만, 오브 왼쪽 한 곳에 두 줄(설명 13px, 금액 12px 회색)로 보인다. 펼치기만 하는 갈래에는 설명이 없다. 문구: "지금 이미지와 비슷한 컷을 생성해요", "블랙으로 생성해요", "반만 열림으로 생성해요", "뒷면을 생성해요", "포켓 디테일을 생성해요", "같은 부위를 다시 생성해요", "원래 콘티대로 다시 생성해요", "빈 칸에 어울리는 컷을 생성해요". 둘째 줄은 착용컷·직접 올린 사진의 색상과 열림 정도는 "5 크레딧", 비슷한 컷은 "8 크레딧", 고스트·디테일·빈 칸을 포함한 그 밖의 생성은 "19 크레딧"이다(2026-10-12 오너 결정). 내 사진 넣기는 "내 컴퓨터에서 사진을 넣어요" / "무료".

### 3. 사진 종류별 갈래

| 사진 | 갈래 |
|---|---|
| AI 착용컷, 셀러가 직접 올린 사진 | 비슷한 컷, 색상, 열림 정도(아우터) |
| 제품 전체컷(고스트) | 색상, 앞뒷면, 디테일 |
| 디테일컷 | 같은 부위 다시(바로), 다른 부위 |
| 종류를 모르는 옛 제품컷 | 디테일 |
| 계획된 빈 칸(`editorSlotKind` planned) | 내 사진 넣기, 원래 콘티대로 다시(바로, 회전 테두리) |
| 계획 없는 빈 칸(unplanned) | 내 사진 넣기, AI로 채우기(바로, 회전 테두리, ADR-0019) |

종류와 지금 값은 서버의 `asset_recipe.resolve_asset_recipes`(ADR-0019 11절)로 읽는다. 칸에 남은 `sourceBlockId`로 추정하지 않는다.

### 4. 만드는 방식

- **비슷한 컷**: 기존 AG-07 경로 그대로. 직접 올린 사진도 연다(사용자 결정, 묻지 않는다). 사람이 없어 계획이 실패하면 크레딧을 받지 않는다.
- **착용컷과 직접 올린 사진의 색상, 열림 정도**: 고른 사진을 고쳐 만든다. 사람, 자세, 장소, 구도는 그대로 두고 옷의 색이나 열림 정도만 바꾼다. 그래야 AI 사진과 직접 올린 사진이 똑같이 동작하고 "현재 이미지와 교체"가 자연스럽다.
  - 모델: 에디터 새 컷과 같은 `gpt-image-2.5-flare`, 출력은 원본 비율(`similar_cut.openai_source_size`).
  - 색상 입력: 고른 사진 + 그 색으로 올린 상품 사진.
  - 열림 정도 입력: 고른 사진 + 단계별 몸 기준 문구(가슴: 쇄골 아래 손 한 뼘, 반만: 명치, 배까지: 배꼽 위 주머니 윗선, 전체 닫힘, 전체 열림: 밑단까지). 화면의 단계 이름과 지퍼 그림은 예시이며, 실제 지시는 `outer_closure.front_closure_of`가 읽은 옷의 여밈에 맞춘다. 값은 `outer_closure.effective_state`로 옷에 맞춘 뒤 쓴다(오너 2026-10-12).
    - 지퍼와 모르는 여밈(`unknown`)은 품질 시험을 통과한 기본 문구를 그대로 쓴다. 지퍼 손잡이는 하나, 손잡이 아래는 밑단까지 맞물리고 전체 닫힘은 깃까지다. 10/10 전 프로젝트는 모두 시험 프로젝트이므로 `unknown`을 따로 바꾸지 않는다.
    - 단추와 스냅은 실제 있는 것만 채운다. 중간 단계에 해당하는 높이에 여밈이 없으면 가장 가까운 실제 여밈까지 채워 요청한 깊이에 가까운 자연스러운 V를 만든다. 그 높이 아래에 여밈이 하나도 없으면 앞을 다 연다. 여밈을 만들거나 옮기지 않는다. 전체 닫힘은 깃 아래에서 끝나더라도 맨 위 실제 여밈까지 모두 채운다. 스냅에는 단춧구멍을 지시하지 않는다. 보조 여밈(`secondary`)이 있으면 같은 높이까지 같은 방식으로 여미는 문장을 덧붙인다.
    - 열림 고쳐 만들기의 목표가 전체 닫힘이 아닐 때만 이너를 보존하는 문장을 덧붙인다. `resolve_asset_recipes`의 `origin`이 `editor_color` 또는 `editor_closure`이고 `sourceAssetId`가 있으면 같은 사용자·프로젝트 소유 사진으로 거슬러 올라간다. 업로드, 페이지 생성, 비슷한 컷 등 다른 출처에서 멈추고, 순환이나 10단계에 닿으면 마지막으로 확인한 소유 사진에서 멈춘다.
    - 찾은 사진이 고른 사진과 다르고 읽을 수 있으면 두 번째 이미지로 보낸다. 고른 사진에 이미 보이는 이너를 우선 보존하고, 가려졌던 이너는 참고 사진의 종류·색·목선에 맞춘다. 참고 사진의 재킷 색·열림·자세·배경은 따르지 않는다. 어느 사진에서도 이너가 보이지 않을 때는 재킷 색과 무관하게 무지 흰 크루넥 티(인쇄·글자 없음)를 쓴다. 참고 조회나 파일 읽기에 실패하면 한 장으로 계속 만든다. 색상, 전체 닫힘, 상의·하의·원피스에는 이 처리를 적용하지 않는다.
  - 근거: 2026-10-12 최소 품질 시험 14장(`.scratch/editor-ai-tab-20261010/g6_quality_test_20261012/README.md`). Gemini(AG-07 `image_high`)는 중간 단계에서 지퍼 손잡이가 둘이 되거나 아래가 벌어졌고, `gpt-image-2.5-flare`와 몸 기준 문구는 재킷 두 벌에서 다섯 단계 순서를 지켰다. 색상은 두 모델 모두 통과.
  - 한계: 표본이 작고 단추, 벨트 아우터는 시험하지 않았다. 상품 사진 대조 검수는 없다. 출시 뒤 실서버에서 단추 아우터로 확인한다.
- **고스트의 색상과 앞뒷면**: 고쳐 만들지 않고 기존 제품 전체컷 생성 경로로 새로 만든다(색은 그 색 상품 사진, 면은 고른 원본 사진의 면, ADR-0008 개정). 레시피는 원본의 생성 설정에서 색이나 방향만 바꾼다.
- **디테일**: 기존 디테일 경로(`detailTargetId`, ADR-0012, ADR-0014). 같은 부위 다시는 기존 다시 찍기.
- **빈 칸**: 계획된 칸은 기존 다시 만들기(`failedCutRetry`), 계획 없는 칸은 ADR-0019의 `fillEmptySlot`.

### 5. 누른 뒤 2초 취소

바로 만드는 버튼이나 선택지를 누르면 요청을 2초 늦춘다. 그동안 결과 자리에 옅은 웨어리스 로고, "취소" 알약, 줄어드는 가는 선이 보인다. 취소하면 요청을 보내지 않으므로 크레딧이 나가지 않는다. 서버 변경은 없다. 움직임 줄이기 설정이어도 2초는 그대로 기다린다.

### 6. 생성 중과 도착

- 결과 자리는 메뉴와 같은 왼쪽 여백이다. 폭 150px(1280 화면 148px), 원본 비율, 위 끝은 고른 사진 위 끝보다 28px 아래, 오른쪽 끝은 오브와 같은 선.
- 생성 중: 앱 생성 대기 칸의 언어(`#f3f5f6` 바탕, 로고 마스크 `#707985` 20%)에 로고 안이 아래에서 위로 차올랐다 빠지는 움직임(2.4초 왕복). 회전 표시는 쓰지 않는다. 다른 사진을 골라도 작업은 이어지고, 그 사진을 다시 고르면 결과 자리가 다시 보인다.
- 도착: 액자가 새 사진으로 채워지고 왼쪽 위 "새 컷" 표시, 오른쪽 위 닫기(×). 바로 아래 같은 폭 알약 두 개: "현재 이미지와 교체"(흰 바탕, `--cta-bg` 글자, 1px `rgba(44,44,44,.55)` 테두리), "새 블록에 추가"(검정). 크게 비교 화면은 두지 않는다.
- 교체는 요청 때 기록한 요소가 남아 있고 사진 주소가 요청 때와 같을 때만 된다. 아니면 교체 버튼을 막고 "새 블록에 추가"만 남긴다. 교체는 프레임 자리, 크기, 둥글기를 지키고 사진만 바꾸며 자르기 값은 처음으로 돌린다. 되돌리기는 툴바 Undo 한 단계.
- 닫기는 액자만 접는다. 결과는 의류 탭에 남는다.
- 모든 결과는 의류 탭에도 들어가고 탭은 넘어가지 않는다. 툴바 의류 아이콘의 점은 기존 `genDot` 그대로(만드는 중 `#e6b800`, 끝나면 `var(--link)`, 의류 탭을 열면 사라짐).
- 빈 칸의 결과는 그 칸에 바로 들어가고 교체, 추가 버튼이 없다(ADR-0019 9절).

### 7. AI 탭

왼쪽 AI 탭에는 "새 이미지 만들기"만 남는다. 두 칸 탭과 현재 이미지 수정 패널을 지운다. 생성 뒤 의류 탭으로 넘어가는 동작을 지운다. 실패 컷 다시 만들기 안내는 빈 칸 메뉴로 옮긴다.

### 8. 크레딧과 중복 방지

- 착용컷과 직접 올린 사진의 색상·열림 정도 고쳐 만들기는 한 장 5크레딧(`credit_cost_editor_edit`), 비슷한 컷은 8크레딧(`credit_cost_editor_similar`)이다(2026-10-12 오너 결정). 그 밖의 에디터 새 이미지, 고스트 색상·앞뒷면, 디테일 같은 부위 다시·다른 부위, 빈 칸 다시 만들기·AI로 채우기는 19크레딧(`credit_cost_editor_image`)을 유지한다. 상세페이지 생성은 장소세트 컷을 포함해 장당 19크레딧, 최소 5컷으로 그대로다.
- 서버가 검증·복원한 요청으로 가격을 고르고 작업에 저장한 예약액 그대로 확정·해제한다. 원장 `action_key=editorImage`와 멱등키 계약은 유지한다. 실패는 미차감이다.
- 표시 키는 `editorImage`, `editorEdit`, `editorSimilar`다. 화면은 서버 견적의 새 키가 없으면 `editorImage`로 표시하고 로컬 5·8 기본값을 합치지 않는다. 메뉴의 선택지와 결과 액자에 올리거나 초점을 두었을 때 기존 설명 자리에서 가격을 보여 준다. 완료 결과는 서버 `creditsCharged`를 우선한다.
- 중복 방지 키는 (사진, 갈래, 값)마다 하나. 같은 요청을 진행 중에 또 누르면 같은 작업을 가리킨다. 접수가 불명확할 때만 키를 보존하고, 성공이나 확정 실패로 끝나면 키를 버려 다시 누르면 새 작업을 만든다(같은 사진의 비슷한 컷 여러 장).
- 같은 중복 방지 키에 다른 내용이 오면 옛 작업을 돌려주던 동작을 409 `idempotency_key_reused`로 거절한다.

### 9. 기록

ADR-0019 11절의 `assets.metadata.generation`을 따른다. 색상은 `origin: "editor_color"`, 열림 정도는 `origin: "editor_closure"`, `sourceAssetId`는 고른 사진, `recipe`는 원본 설정에서 그 값만 바꾼 것(원본 설정을 모르면 바꾼 값만 담는다). 의류 탭 색 그룹은 색상이면 목표 색, 그 밖은 원본의 색 그룹. 상세페이지 생성 경로의 `page` 기록은 후속으로 미룬다(ADR-0019의 대체 경로로 읽힌다).

### 10. 디자인 규칙 예외

- DESIGN.md 6절(오브는 배경 자산): 에디터의 고른 사진 AI 입구 오브만 예외로, 30px 누르는 버튼으로 쓴다. 고른 사진이 있을 때 화면에 하나뿐이고, 빛 색은 구슬 안에서만 쓴다.
- DESIGN.md 9절(아이콘 무채색): 캔버스 AI 메뉴의 색상 갈래 아이콘과 색상 선택지는 상품 색을 보여 준다(색은 상품 내용에서만 온다는 원칙과 같다).
- DESIGN.md 15.11절, ADR-0018(열림 정도는 지퍼 레일 하나, 옷 그림 금지): 캔버스 AI 메뉴는 누르는 순간 크레딧이 나가므로 끄는 레일 대신 누르는 목록을 쓰고, 단계를 구분하는 옷 아이콘을 이 메뉴에서만 쓴다. 값 다섯 개와 칸 수 규칙은 그대로 공유한다.

## 버린 안

- 사진 안 아래 알약 막대, 블록 왼쪽 검정 세로 아이콘 줄과 검정 캡슐, 색상 사진 타일, 지퍼 레일 팝오버, "착용 사진인가요?" 질문, 오브 안 "생성" 글자, 랜딩 오브, 고른 사진 작은 미리보기, 크게 비교 화면, 곡선 배치. 모두 사용자가 시안에서 거절했다.
- 사진 기준 자리(사진 왼쪽 변, 사진 안 모서리): 이웃 사진, 손잡이, 상품명, 빠른 도구와 부딪힌다.
- 2열 오른쪽 사진의 결과를 왼쪽 사진 위에 겹쳐 띄우기: 바로 아래 "현재 이미지와 교체"가 왼쪽 칸으로 읽히고 짝 사진을 가린다.
- 색상, 열림 정도를 원래 설정으로 새로 찍기: AI 사진에만 되고 장면과 자세가 바뀌어 교체가 어색하다.
- 사진을 고를 때 메뉴 자동 펼침, "AI 새 컷" 이름표: 옮기고 크기를 바꿀 때마다 방해하고, 사용자가 별로라고 했다.

## 바꾸지 않는 것

blocks 저장 계약, 섹션과 행 구조, 상세페이지 생성 요금, 콘티보드(G8), ADR-0019의 판단 규칙.

## 검증

- 시험: 오브 자리 함수(1440과 1280, 확대 40, 60, 100%, 2열, 3열, 2×2 아래 줄, 화면 끝, 여백 156px 미만), 메뉴 위로 펼침, 2초 안 취소 시 요청 없음, 교체 가능 조건(사진 주소 같음), 종류별 갈래, 지금 값 체크, 중복 방지 키 내용 불일치 409, 색상과 열림 정도 요청 모양과 기록.
- 화면: 1280px, 1440px, Chromium과 WebKit, 키보드 경로(오브 Enter, 화살표, Esc), 단어 중간 줄바꿈과 가로 넘침 자동 검사.
