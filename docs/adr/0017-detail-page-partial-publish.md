# 상세페이지는 만든 컷만으로 내보내고 만든 만큼만 받는다

상태: Accepted, 오너 결정 2026-10-10. #420의 결정 B(한 컷이라도 실패하면 페이지를 내보내지 않고 예약 전액 해제)와 #441 부분 실패 화면을 새 작업에 대해 대체한다. 실패 이유의 갈래와 빈 칸 문구는 아래 2026-10-11 개정이 대체한다.

## 배경

지금은 AI 컷이 한 장이라도 실패하면 페이지를 내보내지 않고 예약 크레딧을 모두 풀어 준다. 완성 컷은 24시간 보관되어(#394) 다시 시도할 때 실패한 컷만 새로 만든다(#441).

이 규칙은 일시 오류에는 맞지만, 재료가 없어 다시 해도 같은 컷이 계속 실패하는 경우에는 셀러가 완성된 컷까지 영영 받지 못한다. 예: 확정 GPT 경로는 기준 색이 아닌 정면 착용컷을 거절한다(`confirmed_gpt_runtime.py` `resolve_profile_request`).

오너 원문(2026-10-10): "10장 만드는데 9장만 성공하면 1장값은 돌려주고 9장값은 받으면서 내보내준단 의미잖아. 이럼 되는거아냐?" 세부 확정: 못 만든 장은 최소 요금 계산에서도 뺀다. 빈 칸 다시 만들기는 그 한 장 값만 받는다.

## 결정

1. **일부만 실패하면 페이지를 내보낸다.** 작업과 프로젝트는 완료(`done`)가 된다. 실패한 자리는 빈 칸으로 남고, 서버가 그 이미지 요소에 `genFailed: true`, `genFailReason`(이유 코드), `genFailRetryable`(다시 만들기 가능 여부)를 적는다. 새로고침이나 나중 방문에도 같은 빈 칸과 이유가 보인다.
2. **전부 실패하면 지금처럼 내보내지 않고 전액 해제한다**(`all_cuts_failed`).
3. **정산은 "견적에서 못 만든 장 값만 뺀다".** 예약 때 남긴 스냅샷(`aiCount`, `minCuts`, `perCutCost`)으로 계산한다.
   ```
   quote_cuts   = max(requested, minCuts)          (requested > 0)
   failed_units = max(0, requested - completed)
   charge_cuts  = 0 if completed == 0 else max(completed, quote_cuts - failed_units)
   charge       = min(charge_cuts * perCutCost, reserved)
   ```
   스냅샷이 없는 옛 작업은 `completed * 단가`로 정산한다.

   | 요청 | 완성 | 정산 장수 | 크레딧(19 기준) | 돌려준 값 |
   |---|---|---|---|---|
   | 14 | 14 | 14 | 266 | 0 |
   | 14 | 13 | 13 | 247 | 19 |
   | 6 | 4 | 4 | 76 | 38 |
   | 5 | 3 | 3 | 57 | 38 |
   | 3 | 3 | 5 | 95 | 0 |
   | 3 | 2 | 4 | 76 | 19 |
   | 1 | 1 | 5 | 95 | 0 |
   | n | 0 | 0 | 0 | 전액 |

   돌려주는 값은 언제나 "못 만든 장 수 × 단가"다. 부분 정산과 빈 칸 다시 만들기 값을 더하면 원래 견적과 같다. 정산은 `finalize_detail_page_success` 한 번으로 끝난다. 이 함수는 이미 예약 전액을 풀고 계산한 값만 차감하므로(`_consume_buckets`) 따로 환불 경로를 만들지 않는다.
4. **모든 실패에 이유 코드를 남긴다.** `cut_failed` 이벤트와 건너뛴 컷 모두. 세 갈래로 나눈다(2026-10-11 개정으로 "셀러 조치 필요" 갈래는 없어졌다).
   - 다시 만들기 가능: 일시 오류, 생성 공급자 오류, 얼굴 처리 불가, 장면 검수 실패, 예시 자산 일시 불가, 확정 경로 거절(`confirmed_gpt_*`).
   - 셀러 조치 필요: 옷 근거 사진 없음, 매칭 의류 자산 없음, 각도 사진 없음, 모델 범위 밖, 디테일 대상 없음 등. 빈 칸에 고치는 방법을 한 줄로 안내하고 다시 만들기는 띄우지 않는다.
   - 다른 컷에 달림: 비슷한 컷의 원본 실패(`similar_cut_source_failed`), 같은 사진 복제의 원본 실패. 원본 칸이 채워지면 다시 만들 수 있다.
5. **빈 칸 다시 만들기는 에디터 이미지 작업으로 한 장씩 한다.**
   - 값은 에디터 새 이미지 한 장 값(`credit_cost_editor_image`, 지금 19)이다.
   - 서버가 `retryBlockId`로 저장된 콘티에서 그 블록의 설정을 다시 만든다. 지금 호리존 세트에만 있는 복원(`horizon_background.restore_failed_retry`)을 모든 블록으로 넓힌다. 그 `sourceBlockId`의 빈 칸이 에디터에 실제로 있을 때만 받는다. 클라이언트가 고른 필드 목록에 기대지 않는다(지금은 `sideStyle`이 빠진다).
   - 같은 `retryBlockId`로 진행 중인 작업이 있으면 새로 만들지 않고 그 작업을 돌려준다. 새로고침 뒤 두 번 결제되는 일을 막는다. 중복 클릭은 기존 Idempotency-Key가 막는다.
   - 비슷한 컷 후속 칸은 원본 칸이 채워진 뒤, 그 사진을 기준으로 비슷한 컷 변형으로 만든다. 원본 칸이 비어 있으면 "원본 컷을 먼저 만들어 주세요"로 안내한다. 일반 예시 생성으로 대체하지 않는다(ADR-0016).
   - 확정 경로가 거절한 컷을 다시 만들면 에디터 경로(일반 생성)로 만들어진다. 확정 경로는 고치지 않고 의류컷 고도화가 대체한다(오너 2026-10-10). 그 전까지의 차이로 기록한다.
6. **보관 체크포인트.** 부분 완성으로 끝나면 완성 컷은 자산이 되므로 보관본을 모두 정리한다(`discard_all`). 리스 상실, 작업자 종료, 예외로 끝나는 경로는 지금처럼 오류로 끝나고 보관본을 남겨 다음 작업이 이어 쓴다. 배포 전에 만들어진 `incomplete_cuts` 작업의 보관본 미리보기는 그대로 둔다.
7. **실제 모델(REAL).** 라이선스 재확인과 정산은 지금 규칙 그대로다. 완성된 REAL 컷이 1장 이상일 때만 정산한다. AI 표기는 완성 컷 기준으로 만든다.
8. **화면 사실.** 완료 때 "N장 중 M장을 만들었어요. 못 만든 K장 값은 받지 않았어요." 수준의 짧은 알림을 띄운다. 빈 칸은 이유와 다시 만들기 또는 고치는 방법을 보여 준다. 빈 칸의 시각 디자인과 캔버스 위 조작은 에디터 AI 탭 개편(G6)이 정한다. 이 ADR은 데이터, 정산, 문구의 사실만 정한다.

## 바꾸지 않는 것

예약 금액 계산(최소 5컷), 전부 실패 처리, 오류 종료 경로의 보관과 이어 쓰기, 저장 계약(blocks)의 모양(이미지 요소에 필드만 더한다), 비슷한 컷의 원본 우선 생성 순서.

## 결과와 위험

- 셀러는 일부가 실패해도 완성분을 바로 받고, 못 만든 장 값은 내지 않는다.
- 내려받기는 지금도 빈 칸을 건너뛴다. 빈 칸이 남은 채 내려받을 때의 안내는 후속 과제다.
- 시그니처 제목처럼 사진 위에 얹는 요소가 빈 칸 위에 남을 수 있다. 구현 때 화면으로 확인한다.
- 보관함에서 빈 칸이 있는 페이지도 완료로 보인다.

## 2026-10-11 개정, 셀러에게 사진 업로드, 촬영, 재선택을 요구하지 않는다

오너 원문(2026-10-10 밤): "셀러한테 귀찮게 더 찍게 하는 일은 웬만하면 없어야되긴해. 그럼 우리가 만들어서 줘야지, 뭘 사용자한테 올리라고해." 세부는 2026-10-11에 확정했다.

이유별 도달 경로 조사(파일:줄 근거)는 `.scratch/g10-no-seller-action-20261011/survey.md`에 있다.

1. **실패 이유는 두 갈래다.** 다시 만들기 가능, 다른 컷에 달림. 위 4번의 "셀러 조치 필요" 갈래를 없앤다. 그 갈래에 있던 14개 이유 코드는 이름을 그대로 두고 다시 만들기 가능으로 옮긴다. 이름은 기록과 CS 추적에 쓴다.
2. **재료가 없거나 조건이 맞지 않으면 서버가 대체 경로로 칸을 채운다.** 빈 칸은 대체 경로까지 실패한 경우에만 남는다. 대체로 채운 컷은 자산 메타데이터 `fallback` 목록에 무엇을 대체했는지 남기고, 채워진 컷이므로 정상 차감한다. 셀러 화면에는 지금 알리지 않는다.
3. **빈 칸 다시 만들기도 같은 대체 규칙을 쓴다.** 다시 만들기는 저장 콘티의 설정을 그대로 복원하므로, 생성 작업에만 대체 경로를 넣으면 같은 이유로 다시 실패한다.
4. **이유별 처리**

   | 이유 | 셀러 화면에서 생기는가 | 처리 |
   |---|---|---|
   | `matching_asset_unavailable` | 아니다. 우리 쪽에서 매칭 사진 파일을 잃었을 때만 | 같은 프로젝트의 매칭 추천 목록(분석의 `matchClothing`, 저장된 순서)에서 사라진 매칭과 세부 종류(`category`)가 같은 다음 후보, 없으면 종류(`clothingType`)가 같은 다음 후보로 바꿔 만든다. 그 컷이 이미 쓰는 다른 매칭과 겹치지 않고, 한 페이지에서 같은 매칭이 빠지면 모두 같은 대체 매칭을 쓴다. 원래 매칭에 맞춘 핏 조정(`matchCut`, `matchingFit`)은 대체 매칭에 쓰지 않는다. 후보가 없거나 모두 불러오지 못하면 빈 칸이다. 위의 "셀러가 확정한 매칭은 한 벌의 진실이라 일부만 붙이지 않는다" 규칙을 대체한다(오너 2026-10-11) |
   | `pose_direction_incompatible` | 아니다. 서버 정규화(`content_roles.canonicalize_storyboard_block`)가 이미 같은 종류 예시의 등록 방향과 옆모습 갈래(`sideStyle`)를 따른다(ADR-0015). 예시 종류가 카드와 달라 정규화가 방향을 덮지 않을 때(거울 예시와 스타일링 카드 등)만 남는다 | 생성은 지금처럼 예시 방향으로 한다. 저장된 카드 방향이 실제로 다른 그림이면 그 사실을 `fallback`에 남긴다. 예시 종류가 맞지 않으면 빈 칸이다 |
   | `no_garment_photo`, `detail_reference_required` | 사진이 없는 추가 색을 디테일 카드에서 고를 때만 | 상품 입력에서 막는다(5번). 색 옮기기 같은 대체 생성은 하지 않는다. 남은 경우는 빈 칸이다 |
   | `invalid_cut_spec` | 아니다. 우리 코드나 저장 데이터 문제 | 빈 칸. 작업 하나에 운영 알림(CRITICAL 로그, 슬랙 중계) 한 줄을 남긴다. 디테일컷에서 이름 없는 일반 ValueError도 이 이유로 닫는다 |
   | `no_angle_photo`, `identity_scope_mismatch`, `real_model_studio_only` | 아니다. 셀러 앱의 실제 모델 생성은 2026-10-07에 닫혔고 `real_model_studio_only`는 조건이 성립하지 않는다 | 분류와 문구만 바꾼다 |
   | `detail_target_unavailable`, `invalid_detail_region`, `detail_color_reference_required`, `detail_source_unavailable`, `detail_target_color_changed`, `detail_target_source_changed` | 아니다. 화면에서 그 상태를 만들 수 없거나 코드상 성립하지 않거나 데이터 이상일 때만 | 분류와 문구만 바꾼다. `detail_target_unavailable`로 닫을 때 하위 원인을 로그에 남긴다 |

5. **상품 입력에서 추가 색의 정면 사진을 받는다.** 추가한 색에 정면 사진이 한 장도 없으면 "AI 분석하기"와 "저장하고 PC에서 이어하기"를 누를 수 없다. 버튼 옆에 파란 글씨로 "추가한 색상의 정면 사진을 올리거나 색상을 지워 주세요"를 보인다(오너 2026-10-11). 칸에 이미 적힌 "정면 필수"와 같은 규칙이다. 이 안내는 2026-08-14 결정(사진 요구 문구를 버튼 옆에 두지 않는다)과 DESIGN.md 색 예산 규칙(글로우 화면은 무채색)의 예외다. 생성 뒤의 빈 칸에서 셀러에게 사진을 요구하지 않는다는 이 개정의 원칙과는 다른 단계다.
6. **빈 칸 문구.** 다른 컷에 달린 칸("원본 컷을 먼저 만들어 주세요")을 빼고 이유 줄은 모두 "저희 쪽에서 다시 만들 수 있어요"이며 다시 만들기를 띄운다. 화면은 저장된 `genFailRetryable` 값 대신 이 두 갈래 규칙으로 판단한다. 2026-10-10에서 이 개정 배포 전 사이에 저장된 빈 칸의 `false`도 다시 만들기를 띄운다.
7. **바꾸지 않는 것.** 정산 공식, 저장 계약(blocks)의 모양, 비슷한 컷의 원본 우선 순서(ADR-0016), 디테일 검수와 최선 후보 발행(ADR-0012, ADR-0014), 확정 GPT 경로(오너 2026-10-10, 의류컷 고도화가 대체), 실제 모델 생성 닫힘(2026-10-07).
8. **기록만 하는 것.** 에디터 "비슷한 컷"은 2026-10-07 실제 모델 스위치를 거치지 않는다. 그러나 실제 모델 사진이 새로 생길 길이 닫혀 있고 지금 프로젝트는 모두 테스트라 실제 모델이 쓰인 적이 없다(오너 2026-10-11). 이번에 막지 않는다. 실제 모델 생성을 다시 열 때 함께 본다.
