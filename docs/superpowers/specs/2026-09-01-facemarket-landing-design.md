# FaceMarket 랜딩페이지 — 설계

날짜: 2026-09-01
상태: 구현 완료 · 출시 게이트 없음 · 이 문서는 **현행 코드 기준으로 갱신됨**(2026-09-01, 마감 라운드 감사 후)

> 이 문서는 원래 착수 전 설계였다. 구현이 다섯 라운드의 감사·수리를 거치며 여러 곳에서
> 갈라졌고, 갈라진 자리를 코드 쪽으로 맞춰 다시 썼다. 갈라짐의 목록과 사유는
> 문서 끝 [§감사에서 나온 것](#감사에서-나온-것-2라운드--3라운드--4라운드)에 모아 뒀다.
> 이 문서가 코드보다 세게 말하면 다음 사람이 속는다 — 고칠 때 같이 고쳐라.

## ✅ 한때 출시 게이트였던 것 — 해소됨 (2026-09-01)

이 자리에 "prod api 가 us-east-1 이라 RaonSecure OACX 가 한국 IP 방화벽에 막혀 등록 STEP 2
에서 전원이 차단된다, 그러니 랜딩을 공개하지 마라"는 게이트가 적혀 있었다. **사실이 아니었다.**

출처는 `documents/FACEMARKET_PRD.md` §12 표였고, 그 표가 배포 설정보다 오래된 상태였다.
실제로는 `copilot/api/manifest.yml` 이 **서울 리전 프록시**로 이미 우회한다:

```
CX_TRANS_BASE_URL: https://93vhif0l14.execute-api.ap-northeast-2.amazonaws.com
                   (fm-cx-proxy — API GW → Lambda → cx.raonsecure.co.kr:18543 forward)
```

서버는 `config.py` 의 `cx_trans_base_url` 로 그 값을 읽고 `facemarket.py` 의 `_fetch_trans`
가 그 base 로 나가므로, 컨테이너가 us-east-1 에 있어도 CX 에는 한국 IP 로 도착한다.
prod DB 의 2026-08-30·08-31 신원확인 2건이 실제로 통과한 것으로 실증했다.

**그래서 "일곱 단계면 끝납니다"는 원래부터 맞는 말이었고, 랜딩 카피는 손댈 필요가 없다.**

### 다만 이 우회는 env 값 하나에 매달려 있다

`CX_TRANS_BASE_URL` 이 지워지면 기본값(`https://cx.raonsecure.co.kr:18543` 직접 호출)으로
떨어지고, us-east-1 egress 는 방화벽에 막혀 ConnectTimeout → `cx_verify_failed`
"본인확인에 실패했어요." 로 **2단계가 다시 전원 차단**된다. 그때는 이 랜딩의 완주 약속이
거짓이 되므로, 그 값을 건드리려면 `RegisterSection.jsx` 도 같이 봐라(그 파일 머리말에
같은 경고가 있다).

> **교훈 — 이 문서가 남기는 진짜 항목.** 게이트 자체보다 이게 중요하다: 네 라운드의 감사가
> PRD 표 한 줄을 근거로 major finding 을 만들고, 그게 스펙·계획서·소스 주석 세 곳에 복제됐다.
> 아무도 `manifest.yml` 을 열어보지 않았다. **"문서에 그렇게 적혀 있다"는 근거가 아니다** —
> 배포 설정과 코드가 정본이다.

## 목표

`facemarket.wearless.kr` 루트에 **모델을 대상으로 하는 랜딩페이지**를 만든다. 이 작업 전까지
그 루트는 랜딩 없이 곧장 `/model/register` 로 리다이렉트됐다(`src/App.jsx` 의 `RootRedirect`
안 `IS_FACEMARKET` 분기 두 곳 — 이번 작업에서 제거됐다). 처음 온 사람이 "이게 뭐고 내 얼굴이
어떻게 되는지" 알기 전에 로그인 벽과 7단계 KYC 위저드를 맞는 순서였다.

디자인 원본은 `~/Documents/Codex/2026-09-01/new-chat/outputs/spotlight-webgl-gallery`
(spotlight WebGL 갤러리 프로토타입)이고, 라이선싱 섹션의 정보 구조는 Mirror Mirror AI 의
라이선싱 페이지를 참조한다.

## 성공 기준

- facemarket 도메인 루트가 랜딩을 띄운다. **로그인 복귀 플래그가 없는 평범한 방문은
  인증 상태와 무관하게 즉시 랜딩이다.** 플래그를 들고 온 진입만 인증 부트스트랩이
  끝날 때까지 잠깐 기다린다(아래 라우팅 참고).
- 랜딩이 `/` 를 가져가도 이 도메인에서 OAuth 로그인이 완성된다(`?code=` 파괴 금지).
- spotlight 원본의 오목 아크 캐러셀(가운데 카드가 가장 멀고 양끝이 카메라로 밀려나오는)이
  육안으로 같은 인상으로 재현된다. 바깥 카드의 기울기 방향이 원본과 **좌우 같아야** 한다.
- 드래그·스와이프·좌우 화살표 키·이전/다음 버튼·점 선택이 모두 동작하고 무한 루프한다.
  **데스크톱 마우스 클릭으로 카드를 고르는 것도 포함**이다(포인터 캡처 함정, 아래 참고).
- 상단바 세 항목(라이선싱 · 모델 등록 · 모델 정보)이 같은 페이지 안 섹션으로 스크롤한다.
  비로그인 방문자가 눌러도 로그인 모달이 뜨지 않는다.
- 신규 npm 의존성이 0개다. `pnpm build` 가 통과한다.
- 캐러셀 이미지가 실제 등록 모델이 아니라는 표기가 화면에 있다.
- `prefers-reduced-motion: reduce` 에서 관성 없이 즉시 스냅한다.
- **페이지의 사실 주장이 코드보다 세지 않다.** 생체정보를 넘기라고 설득하는 페이지라,
  구현이 안 하는 일을 약속하면 그건 디자인 흠이 아니라 거짓말이다.

## 범위

### 포함

- 랜딩 라우트 1개와 그 안의 섹션 6개(히어로·캐러셀·라이선싱·모델 등록·모델 정보·푸터).
- spotlight 캐러셀의 CSS 3D 재구현.
- 캐러셀 수학(`carouselMath`·`sceneLayout`·`cssProjection`) 의 JSX 이식과 그 순수함수 테스트.
- 라이선싱 섹션은 정산을 **설명만** 한다.

### 제외

- three.js · @react-three/fiber · React 19 · TypeScript 도입.
- **`getJobSettlement` 실호출.** 착수 시점 스펙은 "이 랜딩에서 처음으로 화면에 붙인다"고
  적었지만 계획 승인 단계에서 축소했고, 구현도 부르지 않는다(`LicensingSection.jsx` 는
  `@/lib/brandUseCategories.js` 외에 아무 API 도 import 하지 않는다). 이유: 랜딩 방문자는
  정의상 미등록이라 조회할 `jobId` 가 없고, 로그인한 모델에게도 랜딩은 설명 화면이지
  조회 화면이 아니다. 실제 정산 영수증 UI 는 `/model` 허브나 라이선스 화면의 몫이다.
  (근거: 계획서 `docs/superpowers/plans/2026-09-01-facemarket-landing.md` §Self-Review
  "스펙과 어긋난 곳 — 의도적".) **랜딩에 정산 조회를 다시 붙이지 마라. 없는 회귀다.**
- `/model/license` 발급 폼, 등록 7단계 위저드, `/model` 허브의 UI 수정.
- 셀러 카탈로그(`listModels`) 실데이터 연동. 캐러셀은 정적 가상모델 이미지만 쓴다.
- 셀러 대상 카피. 셀러는 `ai.wearless.kr` 를 그대로 쓴다.
- 카드에 붙는 메타데이터 설계. 이번엔 번호만 붙이고, 무엇을 어떻게 붙일지는 **사용자가 따로
  지시한다**. 임의로 이름·연도·평점을 지어내지 않는다.

## 결정과 근거

### 왜 CSS 3D 인가

원본은 React 19 + `@react-three/fiber` v9 인데 v9 는 React 19 를 요구한다. 메인 앱은 React
18.3 이고, 올리려면 `react-moveable`(에디터)·`@aws-amplify/ui-react-liveness`(생체등록)·
`@tanstack/react-query` 를 전부 재검증해야 한다. 랜딩 하나 때문에 제품 전체를 흔드는 거래다.

동시에, 원본 셰이더(`ArtworkCardMesh.tsx`)가 하는 일을 뜯어보면 **둥근 모서리 마스크와
opacity 곱하기**뿐이다. 그림자는 별도 plane 에 블러 텍스처, 라벨은 캔버스에 그린 글자.
WebGL 이 아니면 못 하는 연산이 하나도 없다. `layoutForOffset` 이 뱉는 `{x, z, rotationY}` 도
CSS 3D 변환에 1:1로 대응한다.

CSS 3D 가 오히려 나은 지점도 있다. 캔버스 텍스처로 굽던 카드 라벨이 진짜 DOM 텍스트가 되어
선명하고, 스크린리더와 검색엔진이 읽고, 폰트 로딩 타이밍에 안 흔들린다.

### 왜 상단바가 섹션 앵커인가

`/model/license` · `/model/register` · `/model` 세 라우트가 전부 인증 필요다
(`src/App.jsx` 의 `RequireAuth` 아래). 랜딩 방문자는 정의상 아직 등록 안 한 사람이라, 상단바를 실제 라우트에
걸면 첫 클릭이 곧바로 로그인 모달이다. 설명을 읽기 전에 가입을 요구하는 순서가 된다.

### 왜 "모델 정보"가 프라이버시 섹션인가

방문자는 미등록 모델이다. 이 사람이 등록 전에 가장 알고 싶은 건 자기 상태가 아니라 **내 얼굴이
어떻게 취급되는지**다. PRD 프라이버시 하드룰 7개(`documents/FACEMARKET_PRD.md` §10)는 내부
개발 규칙이지만, 모델 입장에서는 그대로 신뢰 근거다.

착수 시점 스펙의 트리에 없던 파일이 여섯 붙었다. `FacemarketRoot.jsx` ·
`facemarketRootTarget.js` 는 로그인 복귀 경로 소비를 `RootRedirect` 에게서 넘겨받느라
(아래 라우팅), `cssProjection.js` 는 좌표 변환을 순수 함수로 떼어 테스트로 못 박느라,
`registerCta.js` 는 상태별 CTA 판정을 렌더에서 떼어내느라 생겼다. `GallerySection.jsx` 와
`CarouselStage.module.css` 는 원래 트리가 빠뜨린 것 — 캐러셀 섹션과 스테이지 스타일이다.

원본의 `GalleryStage` · `ArtworkScene` · `ArtworkCardMesh` · `CssGalleryFallback` 네 파일은
`CarouselStage.jsx` 하나로 합쳐진다. WebGL 이 없으니 WebGL 감지·에러 바운더리·CSS 폴백 전환이
전부 불필요하다.

### 라우팅

랜딩은 **`ChromeLayout` 밖의 독립 surface** 다. 기존 `TopNav`(`src/features/shell/shell.jsx`)는
크레딧 배지·요금제 배지·플로우 스테퍼 같은 셀러 스튜디오 물건을 달고 있어서, 랜딩에 재사용하면
숨김 분기만 늘어난다. `verify/:licenseId` 와 `editor/:id` 가 이미 chrome 밖 라우트라 선례가 있다.

```
App.jsx
  // 신규 — facemarket 호스트에서만, ChromeLayout 밖
  {IS_FACEMARKET && <Route index element={<FacemarketRoot />} />}
  // ChromeLayout 안의 기존 인덱스는 ai 도메인 전용이 된다
  {!IS_FACEMARKET && <Route index element={<RootRedirect />} />}
  // 제거 — RootRedirect 의 facemarket 분기 (target 삼항, useEffect 조기 반환)
  // catch-all 도 도메인별로 나눈다 — facemarket 의 모르는 경로가 셀러 입력 화면으로
  // 떨어지면 안 된다
  <Route path="*" element={<Navigate to={IS_FACEMARKET ? '/' : '/create/input'} replace />} />
```

`LoginGate` 는 `AuthProvider` 가 직접 렌더하므로 chrome 밖에서도 `openLogin()` 이 그대로
동작한다. 다만 이 랜딩 때문에 인증 쪽 계약이 다섯 바뀌었다(전부 다른 도메인과 공유하는
코드다). **다섯 다 ai 도메인이 같이 쓰는 코드라, 고칠 때 셀러 쪽 회귀를 먼저 세어라** —
감사가 이 브랜치에서 잡은 회귀의 절반이 이 다섯 계약에서 나왔다.

- **`openLogin` 은 `useCallback` 으로 identity 가 고정돼야 한다.** 렌더마다 새 함수면 이걸
  effect deps 에 둔 쪽이 매번 재실행된다 — `App.jsx` 의 `FacemarketLoginPrompt` 가 실제로
  그래서 "닫으면 즉시 다시 열리는" 모달이 됐다.
- **`closeLogin({ cancelled })` — 취소일 때만 복귀 플래그를 버린다.** "성공 경로는 여기를
  지나지 않는다"는 단정은 틀렸다. 로컬 이메일 로그인 성공은 페이지 이동이 없어 이 함수로
  닫고, `Modal` 의 Escape 리스너는 `window` 에 붙어 있어 프로바이더 리다이렉트가 커밋되기
  전 Esc 도 여기를 지난다. 둘 다에서 플래그가 지워지면 ai 도메인의 콘티 승격이 스킵된다.
- **`wl_postLogin` 에 맨손으로 접근하는 코드를 새로 만들지 마라.** 사파리 프라이빗·쿠키
  차단·일부 인앱 웹뷰에서 `sessionStorage` 는 **접근 자체가 던진다.** 그래서 접근은
  `AuthProvider` 가 export 하는 `readPostLogin()` · `forgetPostLogin()` 두 헬퍼만 쓴다
  (심는 쪽은 `openLogin(redirect)` 안에서 같은 규율로 감싼다). **키 이름과 예외 처리의
  주인은 `AuthProvider` 하나다** — 다른 파일이 `sessionStorage` 를 직접 부르면 같은 키의
  주인이 둘이 되고, 한쪽만 하드닝된 '반쪽' 상태가 라운드마다 되살아난다. 현재 소비자는
  셋 — `App.jsx` 의 `RootRedirect`(ai), `FacemarketRoot`(facemarket), `AuthProvider` 자신.
  **이게 반쪽이면 안 되는 이유:** 두 라우트 소비자(`RootRedirect`·`FacemarketRoot`) 모두
  읽기가 `useState` 초기화 함수라 **렌더 중에** 돌고, 이 레포에는 `ErrorBoundary` 가 하나도 없다(`componentDidCatch` ·
  `getDerivedStateFromError` 0건). 렌더에서 던지면 React 18 `createRoot` 가 트리를 통째로
  언마운트해 그 도메인 루트가 **흰 화면**이 된다. 실제로 한 라운드가 facemarket 쪽만 감싸
  "모델 도메인은 살고 매출이 도는 셀러 도메인만 죽는" 상태를 만들었다. 실패하면 복귀
  목표만 포기하고(=`null`) 기본 경로로 떨어진다 — 복귀는 편의 기능이라 그래도 된다.
- **모달 카피가 `IS_FACEMARKET` 으로 세 곳 갈린다.** `LoginGate` 는 셀러 스튜디오 문구를
  달고 있었다("Studio" 접미, "마네킹컷 생성으로 이어가세요"). 랜딩의 유일한 전환 버튼이
  여는 화면이 그것이면, 이 랜딩이 고치려던 실패 — **모델에게 셀러 제품을 보여주는 것** —
  이 CTA 한 번 만에 재현된다. 갈리는 건 ① 브랜드 락업 접미(`Studio` / `FaceMarket`),
  ② 부제(`마네킹컷 생성으로` / `모델 등록을 이어가세요`), ③ 약관 고지 한 줄 셋뿐이고,
  **셀러 쪽 문자열은 한 글자도 건드리지 않는다**(법적 문구를 약화시키지 않는다). ③ 의
  근거는 §6 푸터에 있다. `host.js` 의 `IS_FACEMARKET` 은 `App.jsx`·`shell.jsx` 가 이미
  쓰는 검증된 분기점이라 여기서도 같은 걸 쓴다. 문구를 손볼 때 이 분기를 지우지 마라.
- **모달은 "열릴 때 없던 세션이 도착하면" 스스로 닫는다 — 그 가드를 빼지 마라.** 페이지
  이동이 없는 성공 경로(다른 탭 로그인, 로컬 이메일 폼)에서 모달이 남지 않게 하는
  장치다. 조건이 "세션이 있으면"이 아니라 **"열릴 때는 없었는데 지금 생겼으면"** 인 이유:
  Editor 의 401 '다시 로그인' 모달은 만료 토큰이라 **세션이 살아 있는 채로** 뜬다 —
  가드를 빼면 토큰 갱신 한 번에 그 모달이 사라져, 사용자가 아무것도 안 했는데 재인증이
  끝난 것처럼 보인다(ai 도메인 회귀). 그리고 이 자동 닫기는 **성공**이므로
  `cancelled: false` 다. 여기서 `cancelled: true` 로 바꿔 남은 플래그를 치우고 싶어질
  텐데(아래 항목이 그 유혹의 출처다) 바꾸지 마라 — 그러면 ai 도메인의 콘티 승격이
  스킵된다. **남은 플래그 정리는 심는 쪽이 아니라 소비하는 쪽(`FacemarketRoot`)의 몫**
  이고, 거기서 한 번 튕긴 뒤 스스로 낫는다(1회성).

`RootRedirect` 의 나머지(draft 승격·프로젝트 부트스트랩)는 create 플로우 전용이고 facemarket
분기는 이미 그 로직을 타지 않게 조기 반환하고 있었다. 그 조기 반환 자리를 라우트 분기로
올리는 것이라 create 플로우 동작은 바뀌지 않는다.

#### 복귀 경로(`wl_postLogin`)를 넘겨받는다

`wl_postLogin`(로그인 후 복귀 지점)의 유일한 소비자가 `RootRedirect` 였다. 랜딩이 `/` 를
가져가면 그 소비도 같이 가져와야 한다 — 안 그러면 "모델 등록 시작 → 로그인 → **다시 랜딩**"
이 된다. `FacemarketRoot` 가 소비하고, 판정은 순수 함수 `facemarketRootTarget` 이 한다.

판정은 두 겹이다.

1. **앱 밖으로 새는 값 차단.** `sessionStorage` 는 같은 오리진의 다른 스크립트도 쓸 수
   있어서, 거르지 않으면 로그인 복귀가 그대로 오픈 리다이렉트가 된다. 절대경로만 받고
   `//`·역슬래시·인코딩된 슬래시·제어문자·과대 길이를 막는다.
2. **도메인 화이트리스트(`/model`, `/verify`).** 플래그를 *심는* 쪽 대부분에 도메인 가드가
   없다 — `ProductInput` 은 `/create/storyboard` 를, Editor 는 `/editor/:id` 를 심고,
   그걸 심는 `TopNav`·화면들은 facemarket 에서도 렌더된다. 통과시키면 등록 전용 도메인에
   셀러 스튜디오가 열린다. 랜딩 도입 전 `RootRedirect` 는
   `if (IS_FACEMARKET) { setDest('/model/register'); return; }` 로 복귀 의도를 통째로
   무시해 이 문이 아예 없었다 — 그 봉쇄를 화이트리스트로 이어받는다.

   **화이트리스트는 마지막 방어선이지 설계가 아니다.** 걸리는 순간 사용자는 랜딩으로
   떨어지고 원래 가려던 곳을 잃는다. 그래서 심는 쪽도 도메인을 봐야 한다 —
   `shell.jsx` 의 TopNav 로그인은 `IS_FACEMARKET ? '/model/register' : '/create/input'`
   으로 갈랐다. 새 CTA 를 만들 때 이 짝을 같이 챙겨라.

#### `FacemarketRoot` 의 순서 계약 — 첫 렌더에 이동하지 않는다

**이게 이 라우트에서 가장 조용하고 가장 치명적인 자리다.**

`supabase` 는 `detectSessionInUrl: false` 라 `?code=` 교환처가 `AuthProvider` 한 곳뿐인데,
`AuthProvider` 는 `BrowserRouter` 의 **조상**이다(`main.jsx`). React 의 passive effect 는
자식 → 부모 순으로 돈다. 그래서 `FacemarketRoot` 가 첫 렌더에서 `<Navigate>` 를 반환하면
그 `history.replaceState` 가 `AuthProvider` 의 부트스트랩 effect보다 **먼저** 돌아
쿼리스트링을 통째로 지운다 — code 를 읽기도 전에. 그러면 이 도메인에서는 아무도 로그인할
수 없다. `RootRedirect` 가 `if (loading && …) return;` 으로 지키던 계약이 정확히 이것이다.

그래서 이동 조건은 "플래그가 있다"가 아니라 **"부트스트랩이 끝났고(`!loading`) 세션이
있다"** 이다. 두 번째 조건도 필요하다 — 세션 없이 이동하면 `/model/register` 의
`RequireAuth` 가 로그인 프롬프트를 띄우고 그게 `openLogin` 으로 플래그를 **다시 심어서**,
그 탭에서는 랜딩을 영영 못 본다. 세션이 없으면(=로그인을 취소했다) 플래그를 버리고 랜딩을
그린다.

부수 규칙 셋:

- 플래그 **읽기**는 렌더에서(`useState` 초기화), **지우기**는 커밋 뒤 effect 에서 한다.
  dev StrictMode 는 마운트 렌더를 두 번 돌리고 두 번째 결과를 커밋하므로, 렌더에서
  지우면 두 번째 렌더가 빈 값을 읽어 복귀 목표가 사라진다.
- 플래그가 **없는** 평범한 방문은 인증을 기다리지 않는다 — 성공 기준이 "루트는 로그인
  여부와 무관하게 랜딩"이기 때문. 기다리는 건 플래그를 들고 온 진입뿐이다.
- **지우기는 "내가 마운트에서 집어온 그 값"에만 건다.** 조건은 `settled` 하나가 아니라
  `settled && target` 이고, 지우기 직전에 저장소의 현재 값이 아직 `target` 과 같은지
  대조한다. 이유는 아래.

> **⚠️ `FacemarketRoot` 의 정리 effect 를 "부트스트랩 끝나면 무조건 삭제"로 넓히지 마라.
> 그러면 자식이 방금 심은 복귀 목표를 부모가 먹는다.**
>
> 순서를 그대로 따라가면 이렇다. 플래그 없이 들어온 평범한 방문은 `loading` 중에도
> 랜딩이 그려진다(위 두 번째 규칙). 그 창에서 사용자가 CTA 를 누르면 클릭은
> `pendingPrimary` 에 담기고, `loading` 이 내려가는 순간 자식(`FacemarketLanding`)의
> 이펙트가 `openLogin('/model/register')` 로 **플래그를 심는다.** 그런데 같은 커밋에서
> 부모(`FacemarketRoot`)의 `settled` 이펙트도 돈다 — effect 는 자식 → 부모 순이므로
> 부모가 **나중에** 돌아 그 새 플래그를 지운다. 로그인을 마치고 돌아온 사용자는 등록
> 위저드가 아니라 **랜딩으로 되돌아온다.** 랜딩의 유일한 전환 경로가 조용히 끊긴다.
>
> `target` 가드 한 줄이 이 경합을 완전히 닫는다. `target` 이 null 인 방문은 지울 대상이
> 애초에 없고, `target` 이 있는 진입은 `!settled` 동안 스피너만 그려 `FacemarketLanding`
> 이 마운트조차 안 되므로 보류 클릭이 존재할 수 없다. 값 대조는 그 위의 벨트다.
>
> **이건 2·3라운드 수리가 서로를 잡아먹은 자리다.** 자식의 보류함과 부모의 묵은 플래그
> 정리는 둘 다 옳은 수리인데, 삭제 범위를 좁히지 않으면 둘이 같은 커밋에서 상쇄된다.
> 한쪽을 지워서 풀지 말고 범위로 풀어라.

#### 탭 제목·설명 교체 — facemarket 에서는 **되돌리지 않는다**

`index.html` 의 정적 head 는 셀러 스튜디오 것이다("Wearless — AI 상세페이지 스튜디오").
빌드 산출물이 한 벌이라 도메인으로 못 가르므로(§열린 항목), `FacemarketLanding` 이 마운트
때 `document.title` 과 `meta[description]` 을 갈아 끼운다.

**언마운트 복원은 `IS_FACEMARKET` 으로 가른다 — 이 도메인에서는 복원하지 않는다.**
복원하면 랜딩을 떠나는 순간 탭 제목이 셀러 제목으로 돌아가고, **모델 전용 도메인의 나머지
화면 전체가 새로고침 전까지 그 상태로 남는다** — 생체정보를 넘기는 등록 7단계 내내 탭에
셀러 제품 이름이 뜨고, 그 상태로 북마크하면 셀러 제목으로 저장된다. 복원의 원래 근거였던
"같은 문서에서 셀러 화면으로 이동할 수 있다"는 이 도메인에서 사실상 성립하지 않는다:
catch-all 이 `/` 로 돌려보내고(`App.jsx`) TopNav 도 셀러 탭을 숨긴다(`shell.jsx`) —
주소창에 직접 치는 경우에만 도달한다. **그 예외를 위해 흔한 경로를 망가뜨리는 거래는 맞지
않는다.** 분기는 지우지 말고 남겨 둔다 — ai 도메인에서 이 컴포넌트를 재사용하게 되면
그때는 복원이 옳다.

이건 근본 해결이 아니라 그 전의 최소 조치다. 근본은 호스트별 정적 head 분리(§열린 항목)
이고, **JS 를 실행하지 않는 크롤러의 공유 미리보기(`og:*`)는 이 교체로 바뀌지 않는다.**

### 캐러셀 — 좌표 변환

원본 카메라는 `fov 24°`, `position z = 8.6`. z=0 평면에서 세로로 보이는 world 높이는

```
visibleHeight = 2 · 8.6 · tan(12°) = 3.656 world units
```

스테이지 DOM 의 실제 픽셀 높이를 `H` 라 하면 변환 계수는 `k = H / 3.656` 하나로 닫힌다.

| three | CSS |
|---|---|
| camera z **11** (원본 fov-24 카메라의 z=0 가시 높이 3.656 은 유지) | `perspective: 11·k px` (스테이지에 지정) |
| `metrics.cardWidth/Height` | 카드 px 크기 = `cardWidth·k` × `cardHeight·k` |
| `layout.x` | `translateX(x·k px)` |
| `layout.y` (양수 = 위) | `translateY(**-**y·k px)` — 부호 반전 |
| `layout.z` (양수 = 카메라 쪽) | `translateZ(z·k px)` |
| `layout.rotationY` | `rotateY(θrad)` — 그대로 |
| `layout.rotationZ` | `rotateZ(**-**θrad)` — 부호 반전 |
| `layout.opacity` | `opacity` |
| 셰이더 `uRadius 0.055` | `border-radius: 5.5%` |
| 그림자 plane + 블러 텍스처 | `box-shadow` — 단, **카드 아래에만**(음수 spread). 사방 그림자는 사용자가 뺐다 |
| 캔버스 라벨 텍스처 | 카드 위 `<span>` (번호 + '예시' 고지) |

**부호가 왜 항마다 다른가 — 두 좌표계는 y 축으로 손대칭이다.** three 는 +y 가 위,
CSS 는 +y 가 아래라 `F = diag(1, -1, 1)` 만큼 어긋나 있고, CSS 행렬은 `M_css = F·M·F`
로 옮겨야 한다. 풀면:

- 이동 y → 부호 반전 (F 가 y 성분을 뒤집는다)
- `rotateZ` → 부호 반전 (`F·Rz(θ)·F = Rz(-θ)`)
- `rotateY` → **그대로** (`F·Ry(θ)·F = Ry(θ)`)
- 이동 x·z → 그대로 (F 가 손대지 않는 축)

이걸 놓치면 배율 불변식 테스트는 멀쩡히 통과하면서 화면의 부채꼴만 좌우 반전된다
(offset +2 카드가 화면상 시계방향이어야 하는데 반시계로 기운다). `rotateY` 까지 같이
뒤집으면 카드가 반대쪽을 보며 오목 아크가 볼록으로 뒤집힌다. 그래서 배율 테스트와는
별도로 `facemarket-css-projection.test.mjs` 에 손대칭 테스트 넷을 따로 뒀다.

깊이 정렬도 CSS 로는 공짜가 아니다. `perspective` 만으로는 브라우저가 카드를 깊이순으로
정렬하지 않는다(`transform-style: preserve-3d` 가 아니면 각 자식이 개별 평탄화된다).
그래서 `z` 를 `z-index` 로 직접 번역한다 — 안 하면 카메라 앞으로 나온 카드가 뒤 카드에
가린다.

`metricsForAspect(aspect)` 의 aspect 는 원본에서 three viewport 비율이었다. CSS 에서는
스테이지 엘리먼트의 `clientWidth / clientHeight` 를 `ResizeObserver` 로 관측해 넣는다.
브레이크포인트 세 구간(`<1.1`, `<2.3`, 그 이상)은 원본 값을 그대로 쓴다.

### 캐러셀 — 애니메이션

원본은 `useFrame` 안에서 `MathUtils.damp(current, target, lambda, delta)` 로 감쇠하고 그 값을
React state 에 매 프레임 넣는다. 이건 지수감쇠 한 줄이라 그대로 옮긴다.

```
current += (target - current) · (1 - exp(-lambda · delta))
lambda = isDragging ? 18 : 9
delta 는 50ms 로 상한 (백그라운드 탭에서 돌아올 때 한 프레임에 다 감쇠하지 않게)
```

다만 매 프레임 `setState` 로 14장을 재렌더하는 대신, `requestAnimationFrame` 루프에서 카드
ref 의 `style.transform` / `style.opacity` 를 직접 쓴다.

**재렌더가 없다고 오해하지 마라 — 두 상태를 구분해야 한다.** idle(관성으로 미끄러지는
구간 포함)에서는 활성 인덱스가 실제로 바뀔 때만 재렌더한다(카드 하이라이트·점 표시용).
반면 **드래그 중에는 컨트롤러가 `pointermove` 마다 `target` 을 `setState` 하므로
(`useCarouselController.js` 의 `setTarget(startTarget - deltaX / DRAG_PIXELS_PER_ITEM)`)
프레임마다 재렌더가 실제로 일어난다.** 그게 아래 wake 계약의 대가다 — `target` 이 React
state 라서 rAF 루프가 다시 깨어난다. 여기서 줄일 수 있는 건 ref 콜백을 인덱스별로 캐시해
14개 ref 재부착만 막는 정도이고(`CarouselStage.jsx`), 재렌더 자체를 없애려면 `target` 을
ref 로 돌려야 하는데 그건 캐러셀을 통째로 멈춘다(바로 아래 경고).

`prefers-reduced-motion: reduce` 면 **감쇠를 아예 건너뛰고 그 프레임에 `position = target`
으로 확정한다.** 착수 스펙은 원본처럼 lambda 를 24 로 올리는 안이었는데, 그러면 원근 회전이
여전히 160ms 동안 재생된다 — "동작 줄이기"를 켠 사용자에게 3D 슬라이드를 보여주지 않는다는
목적을 lambda 조정으로는 달성할 수 없다.

**rAF 루프는 목표에 닿으면 스스로 멈춘다.** 안 멈추면 아무도 안 만지는 랜딩에서도
초당 14장×스타일 4개를 영원히 덮어쓴다(캐러셀이 화면 밖으로 스크롤돼도 마찬가지다).

> **여기서 계약이 하나 생겼다.** 잠든 루프를 다시 깨우는 건
> `useEffect(…, [controller.target, controller.isDragging, reducedMotion])` 뿐이다. 즉
> `controller.target` 이 **렌더마다 새 값으로 보이는 React state 여야** 루프가 켜진다.
> 드래그 중 재렌더를 줄이겠다고 `target` 을 ref 로 돌리면 이 wake 이펙트가 영영 발화하지
> 않아 캐러셀이 통째로 안 움직인다. 옮기려면 컨트롤러가 (a) 이동을 알리는 정수 tick state
> 를 함께 내보내거나 (b) `subscribe(listener)` 를 주고 스테이지가 그걸로 깨어나야 한다.

### 캐러셀 — 입력

`useCarouselController` 를 JSX 로 옮긴다. 8px 수평 의도 임계값, `DRAG_PIXELS_PER_ITEM = 170`,
속도 기반 스냅(`snapTarget`)은 원본 상수 그대로다.

`touch-action: pan-y` 를 스테이지에 유지해 세로 스크롤을 뺏지 않는다 — 랜딩은 한 장 스크롤
페이지라 캐러셀이 페이지 스크롤을 삼키면 그 아래 섹션에 도달할 수 없다.

원본에서 바꾼 곳이 넷 있다. 전부 감사에서 실제로 터진 것들이라 되돌리지 마라.

- **포인터 캡처를 `pointerdown` 이 아니라 `pointermove`(가로 의도 확정 시점)에 건다.**
  `pointerdown` 에서 걸면 이후 `pointerup` 이 캡처 대상(`.stage`)으로 리타깃되고,
  `click` 은 down/up 타깃의 최근접 공통 조상에 발화하므로 공통 조상이 `.stage` 가 된다 →
  자식인 카드 `button` 의 `onClick` 이 영영 안 불린다. **데스크톱 마우스 클릭만 죽고
  터치 탭은 살아서 QA 에서 놓치기 쉽다.** 단순 클릭은 8px 임계를 못 넘으므로 캡처가 아예
  걸리지 않고, 드래그일 때만 스테이지 밖 추적이 유지된다.

  **이 지연에는 대가가 있고, 그 대가를 갚는 탈출구가 함께 있어야 한다.** 캡처가 걸리기
  전(=8px 을 넘기 전) 구간에는 `pointerup` 을 스테이지로 끌어올 장치가 없다. 그 사이에
  포인터가 스테이지 밖에서 떨어지면 `releasePointer` 가 영영 안 불려
  `pointer.current.id` 가 살아남고, **그다음부터는 버튼을 누르지 않은 맨 호버가 드래그로
  인식된다**(마우스는 hover 만으로도 `pointermove` 가 계속 온다). 캡처를 `pointerdown`
  으로 되돌리는 건 이 문제의 해법이 아니다 — 데스크톱 클릭이 다시 죽는다.

  그래서 **무장하는 곳은 `onPointerDown` 하나지만 무장을 푸는 길은 셋이고, 셋 다
  `resetPointer` 로 모인다.** 하나라도 지우기 전에 "그 경로로 무장이 남지 않는가"를 먼저
  답해야 한다.

  1. `onPointerMove` 첫머리의 사장 상태 가드 — `pointerType === 'mouse' && buttons === 0`.
     마우스에만 적용한다: 터치는 접촉마다 `pointerId` 가 새로 발급돼 스스로 낫고, 펜은
     호버에서도 `buttons` 가 0 이라 `pointerType` 을 같이 안 보면 정상 동작이 취소로
     오인된다. 이미 가로 의도가 섰던 경우에는 관성 0 으로 스냅해 마무리하되 드래그 표식은
     세우지 않는다(그 click 은 이미 스테이지 밖에서 지나갔다).
     *테스트에서 드래그를 흉내 낼 땐 `pointermove` 에 `buttons: 1` 을 반드시 넣어라 —
     합성 이벤트 기본값이 0 이라 여기서 걸러진다.*
  2. `window` 의 `pointerup`/`pointercancel` — 스테이지 밖 릴리스. 리스너는 무장 중에만
     붙였다 떼지 않고 **상시로 둔다**: `releasePointer` 는 첫 줄에서 `pointerId` 를 대조해
     무장 중이 아니면 즉시 빠져나오므로 비용이 없고, 반대로 붙였다 떼는 방식은 그 떼기를
     놓치는 순간 같은 종류의 구멍이 하나 더 생긴다.
  3. `.stage` 의 `onLostPointerCapture` — 캡처 상실.

  같은 릴리스가 둘 이상 도착해도 안전한 건 `releasePointer` 첫 줄의 `pointerId` 대조 한 줄
  덕분이다. 먼저 온 쪽이 id 를 -1 로 돌려놓으므로 뒤따르는 쪽은 거기서 끝난다. **그 한 줄을
  지우면 한 번의 릴리스가 `snapTarget` 을 두 번 먹인다.**
- **드래그 끝의 compat click 을 `consumeDragClick` 이 한 번 삼킨다**(수명 500ms).
  안 그러면 드래그가 끝나는 카드로 캐러셀이 한 번 더 점프한다. 호출부는 click 이벤트를
  **반드시 넘긴다** — 키보드 활성화(Enter/Space)는 `event.detail === 0` 으로 걸러 드래그
  표식과 무관하게 통과시켜야 하기 때문. `pointercancel` 에는 뒤따르는 click 이 없으므로
  표식을 세우지 않는다(세우면 아무도 소비하지 않고 남아 다음 활성화를 삼킨다).
- **속도 측정의 dt 하한을 1/60 → 1/240 초로 낮췄다.** 원본 값을 그대로 두면 120Hz 기기
  (`pointermove` 간격 ≈8.3ms)의 플릭 속도가 정확히 절반으로 측정돼 같은 손동작이 60Hz 의
  절반만 넘어간다. 그리고 마지막 move 뒤 100ms 넘게 있다가 뗐으면 속도를 0 으로 본다
  (끌다가 멈춰서 맞춘 위치가 관성으로 밀려나지 않게).
- **누적 위치(`target`)는 자르지 않는다.** 원본에 있던 `rebaseTarget`(한 바퀴 단위로
  되돌리기)은 이식하지 않았다 — 스테이지의 렌더 위치는 `target` 을 감쇠로 쫓아가는
  연속값이라, `target` 만 705 → 5 로 접히면 화면이 그 700칸(=50바퀴)을 실제로 훑고
  내려간다. layout 상 "같은 위치"인 것과 애니메이션이 같은 건 다르다. 정밀도가 상하려면
  `|position|` 이 1e15 근처여야 하는데 한 칸이 170px 이라 현실 위험이 아니다.

접근성 쪽으로 하나 더: 카드는 **로빙 탭인덱스**(활성 카드만 `tabIndex 0`)이고, 활성 인덱스가
바뀌면 포커스도 따라간다. 포커스를 쥔 카드는 절대 `visibility: hidden` 으로 만들지 않는다 —
숨기는 순간 브라우저가 포커스를 body 로 회수해 방향키 조작이 통째로 죽는다.

### 1. 히어로 — 첫 화면은 한 뷰포트다

**첫 화면 = 상단바 + kicker + 두 줄 세리프 제목 + 캐러셀 + 메타 바**, 원본 spotlight 의
한 뷰포트 구성 그대로다(2026-09-02 사용자 지시 — "첫 화면이 이런 식으로 나와야 해 …
밑에 있는 것도 안 나오고 좀 다르지?"). 구현은 `FacemarketLanding.jsx` 의 `.screen` 그리드
(행: 히어로 auto / 스테이지 `minmax(하한, 1fr)` / 메타 바 auto, `min-height: 100svh −
상단바`)다. 남는 높이가 전부 스테이지 행으로 가고, 메타 바(힌트·고지·점·인덱스·화살표)가
스크롤 없이 첫 화면 바닥에 선다. 스테이지 자체는 `max-height: 34rem` 으로 큰 모니터에서
카드가 뷰포트의 37% 까지 커지는 걸 막는다(원본은 22~23%).

히어로에는 **kicker(`—— FACEMARKET ——`, 헤어라인)와 제목만** 온다. 제목은 원본
"Selected works, / framed in *light*" 의 리듬대로 두 줄 + 마지막 단어 이탤릭
(`Your face, / your *terms*.` — 문구는 그대로, 조판만). 이탤릭은 Cormorant Garamond 500
Italic 라틴 서브셋(24KB)을 **랜딩 모듈 전용 패밀리명**으로 얹는다 — `tokens.css` 의
"Cormorant" 에 이탤릭 face 를 더하면 셀러 에디터의 이탤릭 토글 결과가 바뀐다(백엔드
page_assembler 와 어긋남).

리드문("얼굴을 등록하고, 어떤 품목에 …")과 주 CTA 는 **첫 화면 아래**(`IntroSection`)로
내려갔다. 첫 화면에 끼우면 캐러셀이 밀려 내려가 메타 바가 잘린다 — 그게 사용자가 잡은
증상이었다. 카피는 "내 얼굴을 내 조건으로 빌려준다"는 모델 관점. 셀러·브랜드 관점 문구는
넣지 않는다.

폰(< 48rem)은 원본처럼 히어로 왼쪽 정렬·헤어라인 접음·스테이지 78vh 고정이라 한 화면에
안 들어가고 스크롤한다(원본도 같다).

CTA 는 상태별 CTA 와 같은 핸들러를 쓴다(상단바·등록 섹션·모델 정보 섹션과 넷 다 공유).
세션이 있으면 `registerCta` 가 준 경로로 이동하고, 없으면 `openLogin('/model/register')`
로 로그인 모달을 연다. **인증 부트스트랩 중(`loading`)에는 아무 분기도 태우지 않는다** — 그때의
`session === null` 은 '비로그인'이 아니라 '아직 모름'이라, 이미 로그인한 사람에게 로그인
모달을 띄우고 복귀 플래그까지 심어 다음 `/` 진입을 엉뚱한 곳으로 보내게 된다.

> **⚠️ 부트스트랩 중에 CTA 를 `disabled` 로 잠그지 마라. `aria-busy` 도 마찬가지다.
> 이 자리에서 두 라운드가 반대 방향으로 왕복했다 — 이 문단이 그 왕복을 끝낸다.**
>
> 분기는 미루되 **의도는 버리지 않는다.** `loading` 중에 눌린 클릭은
> `LandingShell.jsx` 의 보류함 `pendingPrimary` 에 담겼다가, `loading` 이 내려가는
> 이펙트에서 **한 번만** 실행된다(연타해도 boolean 하나라 이동·모달은 한 번). 넷 다
> 같은 `onPrimary` 를 받으므로 상단바·리드(IntroSection)·등록 섹션·모델 정보 섹션 어느
> 버튼을 눌러도 같다.
>
> **보류함은 `useState` 다. `useRef` 로 되돌리지 마라.** ref 면 재렌더가 없어 눌린 사실이
> 화면에 하나도 안 남고(라벨도 안 바뀐다), 느린 회선에서 "버튼이 고장 났나" 하며 연타하다
> 몇 초 뒤 맥락 없이 모달이 떠오르는 게 실제 증상이었다. state 라서 대기 표시를
> **라벨로만** 돌려줄 수 있다 — `primaryLabel` 이 `'확인 중이에요…'` 로 바뀌고, 네 버튼이
> 같은 prop 을 받으므로 넷이 함께 따라온다. 클릭은 계속 들어오므로 보류함은 그대로 산다.
>
> `disabled` 를 걸면 **그 클릭이 DOM 에 아예 도달하지 않는다.** 보류함이 채워질 길이
> 사라져 `pendingPrimary` 경로가 통째로 도달 불가능한 죽은 코드가 되고, 토큰 갱신이 긴
> 회선에서는 사용자가 눌리지도 않는 버튼을 몇 초간 마주한다. 즉 "고장 난 버튼처럼
> 보인다"는 걱정을 `disabled` 로 풀면, 걱정하던 그 고장을 **진짜로** 만든다.
> 이 결정은 **세 곳에 못 박혀 있다** — 이 문단, `LandingHeader.jsx` 의 헤더 주석
> (+`FacemarketLanding.jsx` 의 `primaryLabel` 주석), 그리고 계획서 Task 7 의
> `[구현과 다름]` 블록. **한쪽만 고치지 마라.** 계획서의 옛 요구("대기를 `disabled` +
> `aria-busy` 로 드러내라")는 그 블록에서 명시적으로 폐기됐다.
>
> 대기 표시를 더 손보고 싶다면 **버튼을 잠그지 않는 방법으로만** 한다(스피너 아이콘,
> `aria-live` 안내 등). 클릭이 계속 들어오는 한 보류함은 산다. `aria-busy` 도 `disabled`
> 와 같은 취급으로 금지한 이유는 이 자리를 오간 두 라운드가 그 둘을 **한 쌍으로** 요구했기
> 때문이다 — 한쪽만 남기면 다음 사람이 나머지를 "빠진 것"으로 읽고 다시 채운다.

### 2. 캐러셀

`public/models` 의 가상모델 14장(women `w1`~`w11`, men `m1`~`m3`)을 카드로 돌린다.
데스크톱 첫 화면에 보이는 건 **5장**(가운데 + 양옆 2장씩, `edgeFade: 3`) — 원본은 ±3 이 화면
양끝에 잘린 조각으로 걸려 7장이었는데 사용자가 5장으로 줄였다(2026-09-02). 넘길 때 들어오는
카드는 3→2 로 움직이며 페이드인한다. **그 5장이 폭을 채운다**("자연스럽게 화면을 꽉"):
world→px 계수를 높이만이 아니라 폭에서도 재서(`cssProjection.js fillScale`) ±2 카드의 바깥
가장자리가 좌우 3% 여백에 닿게 한다. 낮고 넓은 창에서는 바깥 카드가 스테이지 행을 14% 넘는
지점이 상한이라 폭을 다 못 채우고(1280×720: 76%), 좁고 높은 창에서는 높이 기준보다 작아져
5장이 잘리지 않는다. 폰·태블릿 버킷은 높이 기준 그대로다.
카드에 붙는 사람 정보는 **번호(01~14)뿐**이고, 그 옆에 '예시' 고지 배지가 함께 박힌다
(이미지만 잘려 공유돼도 가상 모델이라는 사실이 같이 나가야 한다 — 배지는 메타가 아니라
고지다). 이름·연도·평점 같은 메타는 지어내지 않는다.

"위 이미지는 전부 가상 모델 예시입니다. 실제 등록된 모델이 아닙니다." 고지는 **메타 바
안, 조작 힌트 바로 밑** — 원본에서 작품명·연도가 서던 자리다. 예전엔 스테이지 위에 뒀다
(폰에서 스테이지가 78vh 라 아래 두면 첫 화면 밖으로 밀린다는 이유). 지금은 카드마다 '예시'
배지가 박혀 있어 사진과 같은 화면에 고지가 있다는 조건은 배지가 지키고, 이 문장은 한 번 더
못박는 역할이다. 이 고지가 없으면 방문자가 이미 등록된 실존 모델 목록으로 읽는다.

**메타 바**(`.galleryMeta`, 첫 화면 3행): 위에 `DRAG · SWIPE · ARROW KEYS` 힌트와 고지
(가운데), 아래 줄에 좌 큰 인덱스(세리프 `01 / 14`) · 가운데 점 14개 · 우 원형 화살표.
원본의 작품명·연도·평점 줄은 **없다** — 가상 모델이라 채울 게 없고 지어내면 실재 정보로
읽힌다. 원본의 `position: fixed` 인덱스는 정적으로 둔다(첫 화면 아래 리드·푸터 위로
떠다니면 안 된다).

**3D 프로파일은 코덱스 포트가 아니라 사용자가 준 원본 캡처(녹화 `화면 기록 2026-09-01
오후 4.10.02.mov` → 스크린샷 `이미지-1.jpg`)를 잰 값이다.** 세 번 고쳤다.
(1) 코덱스 포트의 `sceneLayout.ts` 상수는 위치·크기는 맞았지만 회전이 1/3(offset 1: 4.6°,
2: 15°)이라 카드가 종이처럼 납작했다("카드가 딱 입체적으로 보여야 한다"). (2) 녹화 프레임
피팅으로 회전은 살렸지만 카드 크기가 가운데부터 커져 이웃 사이(gap)에서 실루엣이 계단처럼
꺾였다("라인 따라서 안 가고 울퉁불퉁") — 코덱스가 덧붙인 rotateZ 기울기(±2 에서 1.6°)가
윗변을 눕혀 그걸 키웠다. (3) 지금은 **접선 현(tangent chord)** 원칙: 카드는 곡면의 한
조각이라 안쪽 가장자리 높이 = 더 안쪽 이웃의 바깥 가장자리 높이. 원본 실측(가운데 = 1)
offset 1 안 0.99·바깥 1.08 / 2 안 1.11·바깥 1.28 / 3 안 1.37 에서 깊이와 회전을 역산하면
θ ≈ 30° / 54° / 72°, 카메라는 **z 11**(z=0 가시 높이 3.656 은 유지해 카드/스테이지 비율
불변), rotateZ 는 ≈ 0.3°. 검증: 1668px 뷰포트에서 귀퉁이 좌표가 원본과 ±2%.
`sceneLayout.js`·`cssProjection.js` 머리말이 정본이다. 워터마크('SPOT' → 'FACE')는
옮겼다가 사용자 지시로 뺐고, 카드 그림자는 사방 → **아래에만**(사용자 지시 둘: "그림자
효과 다 없애" → "카드 밑에만 그림자 있으면 되겠다").

**자동 회전**(2026-09-02 사용자 지시): 평소에는 8초에 한 장 속도로 계속 흐르고, 사용자가
카드를 만지면(포인터 다운·드래그·카드/점/화살표 클릭·방향키) 멈췄다가 **마지막 조작 3초 뒤**
다시 흐른다. 목표값을 10Hz 로 0.0125칸씩 밀고 스테이지의 감쇠가 그 사이를 메우는 방식이라
정지 상태가 없다 — 매 프레임 setState 를 피하면서 연속 이동으로 보이게 하는 타협이다
(`useCarouselController.js` 머리말이 정본).

다음 넷 중 하나라도 걸리면 돌지 않는다. 뒤 셋은 타이머가 아니라 조건이 풀리는 즉시 재개한다.
| 조작 | 3초 뒤 재개 |
| 스테이지 안에 **키보드** 포커스 | 포커스가 나가면 재개 — 안 그러면 자동 회전이 키보드 사용자의 포커스를 다른 카드로 끌고 간다. 마우스 클릭도 버튼에 포커스를 남기므로 **직접 센 입력 모달리티**(마지막 입력이 키보드였나)로 가른다. `:focus-visible` 로 가르면 안 된다 — 브라우저 휴리스틱이라 답이 갈리고, 틀리는 쪽으로 기울면 마우스 사용자에게 자동 회전이 영영 안 돌아온다(실제로 그 증상이 났다) |
| 캐러셀이 화면 밖(IntersectionObserver) | 다시 보이면 재개 — 아무도 안 보는 rAF 루프를 돌리지 않는다 |
| `prefers-reduced-motion: reduce` | 아예 안 돈다. 속도를 늦추는 것으로 대신하지 마라(WCAG 2.2.2) |

스테이지는 세로로 자르지 않는다(`overflow: visible`) — 아크 바깥 카드가 원근으로 1.68배까지
커져 행을 살짝 넘는데, 자르면 수평선이 생긴다. 가로 클립은 셸의 `overflow: clip` 이 뷰포트
가장자리에서 한다. 카드는 `position: absolute` 라 스테이지 내재 높이에 안 잡히고, 그래서
1fr 행이 카드 크기를 따라 커지는 되먹임이 없다.

`-face` 접미 파일과 `pose/` · `physique/` 는 쓰지 않는다. 등록 위저드 안내용 소재라
랜딩의 편집 톤과 맞지 않는다. 이 목록 계약은 `facemarket-landing-models.test.mjs` 가
지킨다 — 경로 한 줄만 바꿔도 걸리게(프라이버시 하드룰 1).

### 3. 라이선싱 (`#licensing`)

Mirror Mirror AI 라이선싱 페이지의 정보 구조를 빌린다: 카드 6장 그리드 + 그 아래
"확인할 수 있는 기록" 블록. 내용은 우리 것으로 채운다.

**이 섹션의 문장은 전부 구현 눈금으로 낮춰져 있다.** 생체정보를 넘기라고 설득하는
페이지라, 코드보다 세게 말하면 디자인 흠이 아니라 거짓말이 된다. 아래 표의 "근거" 칸이
문장의 상한이다 — 구현이 바뀌기 전에는 되돌리지 마라.

카드 6장:

| 카드 | 근거 / 상한 |
|---|---|
| 조건을 모델이 정한다 | `ModelLicense.jsx` · `facemarket.py _clean_uses`. 조건은 **넷뿐**(허용 품목·금지 품목·건당 단가·유효기간). **채널 조건은 제품에 없다** |
| 허용 품목을 고른다 | `src/lib/brandUseCategories.js` (개수는 상수에서 읽는다). 금지 품목 나열의 구분자는 `', '` — 품목명 자체가 `속옷·란제리` 처럼 `·` 를 품어서 `·` 로 이으면 2개가 4개로 읽힌다 |
| 기간이 정해져 있다 | `ModelLicense.jsx` `VALIDITY` — **90일 · 1년 · 2년** 셋 |
| 서명된 자격증명으로 발급된다 (W3C VC) | PRD §7.2 |
| QR 하나로 누구나 확인한다 | `/verify/:licenseId`, 무인증 |
| **해지**하면 즉시 무효가 된다 | PRD §7.5 파이프라인. **단어는 '폐기'가 아니라 '해지'다** — 아래 어휘 규칙 |

> **어휘 — 랜딩은 '해지'라고 쓴다. '폐기'로 되돌리지 마라.** 제품 화면의 말이 전부
> '해지'다(`ModelLicense.jsx` 의 버튼 "해지" · 확인창 "이 라이선스를 해지하면…" · 상태
> "해지됨", `PublicVerify.jsx` "해지된 라이선스예요"). PRD 는 '폐기'를 쓰지만 **PRD 는
> 사용자 대면 문자열이 아니다.** 랜딩만 '폐기'라고 부르면, 되돌릴 수 없는 조치를 앞둔
> 모델이 `/model/license` 에서 그 단어를 못 찾고 멈춘다. 통일 방향을 뒤집고 싶다면
> **제품 버튼부터** 바꿔라 — 랜딩이 신규 표면이라 랜딩을 맞추는 쪽이 싸다.
> 이 규칙은 §5 모델 정보의 '그만두고 싶을 때' 문단에도 그대로 적용된다.

"확인할 수 있는 기록" 블록은 Mirror Mirror 가 C2PA 로고를 놓은 자리다. **네 칸**이다 —
착수 스펙은 "VC → 체인 앵커 → 공개 검증" 세 칸이었는데 정산 칸이 하나 붙었고, 이름도
사실에 맞게 내려갔다.

| 칸 | 구현 눈금 |
|---|---|
| VC 발급 | 그대로 |
| **체인 기록** ("앵커" 아님) | 체인에 올라가는 건 사용 1건짜리 `recordSettlement` 뿐이다(`facemarket_chain.py`). 라이선스 자체의 지문을 올리는 코드는 없다. **그리고 무조건이 아니라 best-effort 다** — 아래 참고 |
| 공개 검증 | `GET /v1/facemarket/verify/{id}` 는 `fm_licenses` 화이트리스트 SELECT 한 방이다. **VC 서명 대조도 체인 조회도 없다** — 문장에 "지금은 Wearless 기록 조회"라고 남긴다 |
| 사용 기록이 남는다 | 온체인 정산은 record-only(`facemarket_chain.py` "코인 이동 없음"). 지급 코드도, 모델이 자기 사용 기록을 보는 화면도 없다. 그리고 단위가 **컷이 아니라 잡(상세페이지) 1건**이다 — `workers/detail_page_job.py` 가 `payment_key=f"job:{job_id}"`, `total=unit_price` 로 잡 하나에 1건만 남긴다. 컷 수 비례로 곱해지는 건 셀러 과금뿐이다 |

> **체인 기록을 무조건형("…마다 남습니다")으로 되돌리지 마라.** `facemarket.py` 의
> `record_license_settlement` 는 docstring 부터 "best-effort(생성 흐름 비파손)"이다.
> `app.state.fm_chain` 이 없으면 즉시 `return None`(`settlement_skipped_no_chain`), RPC 뒤
> 조회까지 실패해도 `return None`(`settlement_record_failed` /
> `settlement_record_unresolved`). 그리고 DB 미러(`fm_settlements` 삽입)는 **온체인 성공
> 경로에서만** 불리므로, 실패하면 체인에도 DB 에도 **아무 행이 안 생긴다.** 호출부
> (`workers/detail_page_job.py`)는 잡을 성공 종결·과금한 **뒤에** 이 훅을 부르고 예외를
> 삼키므로, 컷은 배달되고 셀러 크레딧은 차감된 채 기록만 없는 상태가 실재한다.
> 그래서 문장에 "올리기가 실패한 건은 기록이 남지 않습니다"라는 상한이 함께 붙는다 —
> 같은 표의 '공개 검증' 칸이 "지금은 Wearless 기록 조회라…"로 상한을 적는 것과 같은
> 규율이다. 이 상한을 지우려면 카피가 아니라 **코드**를 바꿔라(실패 시
> `chain_status='failed'` 미러 행을 남겨 "기록은 반드시 남는다"를 참으로 만드는 쪽).

이 섹션은 어떤 facemarket API 도 호출하지 않는다(`getJobSettlement` 축소는 §범위>제외 참고).

라이선스 발급 자체는 이 섹션에서 하지 않는다. CTA 가 `/model/license` 로 보낼 뿐이고, 그 폼은
건드리지 않는다.

### 4. 모델 등록 (`#register`)

7단계 레일(`동의 · 신분증 · 사진 · 체형 · 대표 · 라이브 · 완료`)을 미리 보여준다. PRD 리뉴얼
유의점 1번이 "진행 레일은 장식이 아니다" 인데, 랜딩에서 미리 보여주는 것도 같은 이유다 —
순차 KYC 라 몇 단계인지 미리 알면 이탈이 준다. 체형·대표 이미지가 건너뛸 수 있는 선택 단계라는
것도 여기 표기한다. 레일의 순서·라벨은 `ModelRegister.jsx` 의 `FLOW_STEPS` 가 정본이고,
각 단계에 붙는 설명은 그 단계가 **실제로 하는 일**이어야 한다 — 예: prod 는
`FM_LIVENESS_ENABLED=false` 라 '라이브' 단계에 카메라 라이브니스가 돌지 않으므로 "실제
본인인지 확인"이라고 적으면 하지 않는 검사를 약속하는 셈이다(실제 본인 방어는 모바일
신분증과 사진↔신분증 초상 매칭이 한다).

CTA 문구는 상태에 따라 바뀐다. 비로그인/미등록은 "모델 등록 시작", 등록 진행 중은 "이어서
등록하기", 완료된 모델은 "내 모델 정보". 상태 조회는 `listMyModels` · `getCurrentEnrollment`
로 하되, **조회 실패나 지연이 랜딩 렌더를 막지 않는다** — 기본 문구로 먼저 그리고 결과가 오면
교체한다. 판정 자체는 순수 함수 `registerCta(ownedModel, enrollment)` 로 떼어 테스트한다.
조회는 `session` 객체가 아니라 **사용자 id** 로 묶는다 — `session` 은 토큰 갱신마다
(기본 1시간) 새 객체가 되는데 같은 사람이면 CTA 도 같다.

### 5. 모델 정보 (`#model-info`)

PRD 프라이버시 하드룰 7개를 모델이 읽을 언어로 옮긴다.

| 하드룰 | 모델에게 |
|---|---|
| 얼굴은 공개 URL 을 갖지 않는다 | 내 얼굴 사진 주소를 아무나 열 수 없다 — **단, 대표 이미지는 예외** |
| 공개 검증 페이지에 생체정보 0픽셀 | QR 을 스캔한 사람은 내 얼굴을 못 본다 — **조건·유효 여부에 더해 마스킹 이름과 나이가 함께 뜬다** |
| 업로드 사진은 격리 상태로 저장 | 검사를 통과하기 전에는 어디에도 쓰이지 않는다 |
| 신분증 초상은 메모리에만 | 신분증 사진은 저장하지 않는다 |
| CI 는 HMAC 해시로만 저장 | 본인 확인값은 원본이 아니라 해시로만 남는다 |
| QC 로그에 이미지·파일명·랜드마크 금지 | 검사 기록에 내 사진이 남지 않는다 |
| 동의문은 버전 계약 | 동의한 문서가 무엇이었는지 그대로 보존된다 |

**하드룰을 그대로 옮기면 거짓이 되는 자리가 둘 있다. 예외를 문장 안에 적는다 — 지우면
랜딩이 코드보다 세게 말한다.**

- 하드룰 1 은 등록 사진(`face_front` 등)에 대해서만 참이다. **대표 이미지는 의도적 예외**
  — 셀러 카탈로그에 얼굴이 보여야 모델을 고를 수 있어서, `coverImageUrl` 은 비공개 R2 의
  presigned GET(1시간)이라 카드 HTML 에 무인증 주소가 그대로 실린다. 대표 이미지가
  건너뛸 수 있는 선택 단계라는 것도 같이 적는다.
- 하드룰 2 의 원문은 "생체정보 0픽셀"이지 "조건과 유효 여부만"이 아니다. 공개 검증 응답은
  마스킹 이름(`홍*동`)과 만 나이도 싣는다(`facemarket.py` → `PublicVerify.jsx`).

여기에 **라이선스 해지**(`/model/license`)를 탈출구로 적는다(단어는 §3 의 어휘 규칙 —
'폐기'가 아니다). 경로는 **텍스트로만** 적고 링크로 걸지 않는다 — 그 라우트는
`RequireAuth` + 소유 모델 가드 뒤라 비로그인 방문자가 누르면 로그인 모달로 튕긴다
(상단바를 앵커로 둔 것과 같은 이유).

> **⚠️ `/model/withdraw` 를 이 섹션에 적지 마라. 3라운드 감사의 유일한 critical 이 이거다.**
> 착수 스펙은 철회 경로로 그 화면을 지목했지만, `ModelWithdraw.jsx` 는 **개인화
> (personalization) 도메인 전용**이다 — `GET /v1/personalization/status` 를 보고
> `personalization_profiles` 행이 없으면 "등록된 데이터가 없어요." 한 줄만 그린다.
> FaceMarket 7단계 위저드는 그 테이블에 행을 만들지 않으므로(`facemarket.py` 가 쓰는 건
> `personalization_identity_verifications` 뿐), **FaceMarket 모델에게 그 화면은 빈 화면**
> 이고 `POST /v1/personalization:withdraw` 도 404 다. facemarket 라우트에도 등록 철회·삭제는
> 없다(있는 건 `/licenses/{id}/revoke` 와 진행 중 등록 `cancel`).
>
> 그래서 이 문단은 **라이선스 해지까지만 약속하고, 등록 자체를 지우는 화면은 아직 없다고
> 밝힌다.** 등록 파기 진입점이 생기면 그때 이 문단과 이 스펙을 함께 고친다.

하드룰 7번(동의문 용어는 임의로 못 바꾼다)에 따라 `생체정보 처리 동의` 라는 표현은 그대로 쓴다.

**이 섹션이 페이지의 마지막 CTA 를 든다.** 프라이버시 규칙 7개 + '그만두고 싶을 때'로
끝나면 페이지의 마지막 인상이 부정문 연속이고, 끝까지 읽은 사람이 전환하려면 스크롤을
되돌려 올라가야 한다(3라운드 판정). **고지를 줄여서 풀지 않는다 — 고지는 그대로 두고
누를 자리를 그 뒤에 놓는다.** prop 은 `RegisterSection` 과 **같은 둘**(`ctaLabel` ·
`onPrimary`)이다. 새 이름을 만들면 같은 버튼이 파일마다 다른 계약을 갖는다. 두 prop 이
없으면 버튼을 그리지 않는다 — 이 섹션은 랜딩 밖에서도 재사용될 수 있고, 핸들러 없는
버튼은 눌러도 아무 일이 없어 더 나쁘다. 지우려거든 섹션 순서부터 바꿔라.

### 6. 푸터

법무 문서 현황, `ai.wearless.kr`(셀러) 링크. 그리고 **예시 이미지 고지는 여기 없다** —
아래 참고.

**개인정보처리방침·이용약관 링크를 걸 곳이 없다.** 레포에 해당 페이지가 없고
(`/legal/…` 라우트가 `App.jsx` 에 존재하지 않는다), 서버 `NOTICE_URIS` 도 "법무 확정 URI
자리"라고 적힌 플레이스홀더라 지금 걸면 catch-all 로 튕긴다. 없는 주소를 지어 걸지 마라.

**다만 "약관이 없다"고 단정하지도 않는다.** 문장은 "공개 문서가 준비되면 여기에 겁니다"
까지다. 이 랜딩 CTA 가 여는 로그인 모달이 두 클릭 거리에 있어서, 한쪽이 부재를 단정하고
다른 쪽이 "계속하면 서비스 약관에 동의하는 것으로 간주됩니다"라고 말하면 두 화면이 서로를
부정한다 — 분쟁 시 '어떤 약관에 동의했는지' 특정도 안 된다. 그래서 **모달의 facemarket
분기도 같은 말로 맞췄다**(§라우팅의 모달 카피 분기 ③): 실제로 일어나는 일 —처리 내용 고지와
동의는 등록 STEP 1 에서 명시적으로 받는다— 만 적는다. 셀러 도메인 문구는 그대로 둔다.
**둘 중 한쪽만 고치지 마라.** 법무 문서가 공개되면 푸터와 모달의 그 줄을 **같은 링크로
함께** 잇는다.

근거로 `ModelConsent.jsx` 를 들지 마라 — 그 컴포넌트는 **어디에도 마운트되지 않는다**
(`/model/consent` 는 `Navigate` 로 대체됐고 import 하는 파일이 0개다). 죽은 화면을 살아
있는 고지로 세면 안 된다. 같은 이유로 **푸터에서 보관 기간을 약속하지 마라** — STEP 1 이
실제로 그리는 건 처리 안내 5줄과 동의 체크박스뿐이고, FaceMarket 서버에는 보관기간 상수도
고지 URI 도 없다(`GET /v1/facemarket/config` 는 `livenessRequired` 하나만 돌려준다).
`RETENTION_DAYS`·`NOTICE_URIS` 는 개인화 도메인 것이다. 사업자 정보도 값을 확인할 소스가
레포에 없어 비워 뒀다.

**예시 이미지 고지의 사본은 둘이고, 푸터 사본은 지웠다.** 남은 둘은 (1) 캐러셀 바로 위
(`GallerySection` 의 `.galleryNotice`)와 (2) 카드 안 배지(`CarouselStage` 의
`.badgeNotice` "예시")다. 그 둘은 지우지 마라 — (1)은 스테이지보다 위라 폰에서도 사진과
함께 보이고, (2)는 이미지만 잘려 공유돼도 가상 모델이라는 사실이 같이 나간다. 푸터 사본은
스크롤 끝이라 캐러셀과 한 화면에 있지도 않아 고지로서 하는 일이 없었다. PRD §13-5
("예시 사진과 내 사진의 구분 장치가 사라지면 안 된다")는 (1)+(2)로 지켜진다 — **셋째
사본이라서 지운 것이지 사실이 아니라서가 아니다.**

문의 창구는 넣지 않았다 — 확인할 수 있는 주소가 레포에 없다.

## 스타일

기존 토큰(`src/styles/tokens.css`)을 베이스로 쓰고, 랜딩 루트에만 스코프 오버라이드를 얹는다.
spotlight 의 `#edf3f8` 배경과 `#2d63ff` 블루는 앱 토큰(`--bg-1: #ffffff`,
`--link: #0099ff`)과 다르므로 `.shell { --fm-page-bg: … }` 처럼 `--fm-*` 접두로 랜딩
안에서만 재정의한다. 앱 전역 토큰은 건드리지 않는다.

원본 값을 그대로 못 쓴 곳이 둘 있다.

- **`--fm-muted`.** 원본 `#727c86` 은 이 페이지 배경에서 명도비 3.8:1 로 WCAG AA 4.5:1
  에 못 미친다. 리드·카드 본문·고지·푸터가 전부 이 토큰이라 한 단계 어둡게 잡았다.
- **스테이지 높이.** 원본 `styles.css` 의 미디어쿼리 세 개를 그대로 가져온다. 값이 예쁘라고
  있는 게 아니다 — 스테이지의 폭/높이 비가 `metricsForAspect` 의 버킷(폰 <1.1 / 태블릿
  <2.3 / 데스크톱)을 고르기 때문에, 기본값 한 줄만 두면 폰에서 태블릿 버킷이, 태블릿에서
  데스크톱 버킷이 잡혀 카드 크기·간격·페이드가 한 단계씩 어긋난다. `sceneLayout.js` 상수를
  원본 그대로 보존한 의미가 여기서 난다.

폰트는 신규 추가가 없다. `Cormorant`(디스플레이 세리프)와 `Pretendard`(한글 본문)가 이미
셀프호스팅되어 있다(`src/fonts/`). 원본의 DM Sans 자리는 Pretendard 가 받는다 — 한글 카피가
대부분이라 어차피 DM Sans 로는 못 그린다.

CSS Modules 를 쓴다. `ModelLicense.module.css` · `ModelPersonalization.module.css` 처럼
features 폴더의 기존 관례다.

## 확인 방법

로컬은 `?facemarket=1` 로 호스트 분기를 강제한다(`src/lib/host.js`). `pnpm dev` 후
`http://localhost:5173/?facemarket=1`.

육안 확인 항목: 오목 아크 형태(가운데가 가장 작고 양끝이 커짐), **바깥 카드 기울기 방향이
원본과 좌우 같은지**, 드래그 관성과 스냅, 루프 경계 통과, **데스크톱 마우스로 옆 카드 클릭 →
그 카드로 이동**, 앵커 3개 스크롤, 좁은 화면에서 카드 1장 중심 + 양옆 살짝, 비로그인 상태에서
로그인 모달이 안 뜨는 것, `prefers-reduced-motion` 켠 상태.

로그인 왕복은 따로 확인한다 — 콘솔에서
`sessionStorage.setItem('wl_postLogin', '/model/register')` 를 심고 `/?facemarket=1` 을
새로고침하면 (세션이 있을 때) 등록으로 가고, 세션이 없으면 플래그를 버리고 랜딩이 떠야 한다.
`'/create/input'` 을 심으면 화이트리스트에 걸려 랜딩이 떠야 한다.

## 열린 항목

- ~~**⛔ OACX 지역 차단 — 출시 게이트.**~~ **닫힘 — 애초에 존재하지 않았다.**
  PRD §12 표가 낡아서 생긴 유령이고, prod 는 서울 리전 프록시로 이미 우회한다.
  문서 맨 위 §해소됨 절 참고. **출시를 막는 항목은 이제 없다.**
- ~~**부트스트랩 중 CTA 의 대기 표시.**~~ **닫힘.** 보류함이 `useState` 라 눌리면 네 CTA
  의 라벨이 함께 '확인 중이에요…'로 바뀐다. 더 손보더라도 **`disabled`·`aria-busy` 로 푸는
  건 여전히 금지**다 — §1 히어로의 경고 블록 참고.
- **카드 메타데이터.** 이번엔 번호 + '예시' 고지뿐. 무엇을 어떻게 붙일지는 사용자 지시 대기.
- **호스트별 공유 미리보기.** `index.html` 에 `og:*` 와 `meta[description]` 이 들어갔지만
  **두 도메인 공통(중립)** 값이다. 빌드 산출물이 `dist/index.html` 한 벌이고 `vercel.json`
  이 전 경로를 그리로 rewrite 하며, 도메인 분기는 `src/lib/host.js` 의 **런타임** 분기라
  정적 head 에 닿지 않는다 — facemarket 전용 문구를 박으면 `ai.wearless.kr` 미리보기가
  대신 틀려진다. 호스트별로 가르려면 (a) `rollupOptions.input` 으로 `facemarket.html` 을
  추가해 산출물을 두 벌 내고 (b) `vercel.json` rewrites 에 host 조건을 걸어야 한다
  ((a) 없이 (b) 만 넣으면 facemarket 루트가 404 다). 또는 Edge Middleware.
  정식 1200×630 OG 이미지도 아직 없다.
- **모델용 사용 내역·정산 화면.** 라이선싱 섹션이 "실제 지급 기능은 준비 중"이라고 말하는
  근거다. 지급(payout) 코드와 모델이 자기 기록을 보는 화면이 생기면 그 문장부터 고친다.
- **법무 문서.** 개인정보처리방침·이용약관 페이지와 사업자 정보(§6 푸터).
- **FaceMarket 등록 파기 진입점.** 지금 모델이 쓸 수 있는 중단 수단은 라이선스 해지뿐이고,
  랜딩도 딱 거기까지만 약속한다(§5 의 경고 블록). 화면이 생기면 그 문단부터 고친다.
- **히어로·섹션 카피 최종본.** 구조는 이 문서가 고정하고 문구는 구현 중 조율한다.

## 감사에서 나온 것 (2라운드 · 3라운드 · 4라운드)

(이 절은 마감 라운드까지 포함한다.)

구현 뒤 감사가 다섯 라운드 돌았다. 2라운드까지 45건이 수리됐고, 3라운드 재감사에서 27건이
더 나왔다(critical 1 · major 5 · minor 21). 4라운드에서 critical 은 0 이 됐지만 major 9 ·
minor 15 가 남았고, 마감 라운드가 그것을 닫았다. **뒤로 갈수록 앞 라운드의 수리가 새로
만든 결함의 비중이 커졌다** — 카피의 과장을 걷어내다 다른 문장이 사실과 어긋나고, 옳은
수리 둘이 같은 커밋에서 서로를 상쇄했다. 그래서 마감 라운드의 규율은 **"새 결함을 만들지
않는 게 고치는 것보다 중요하다"** 였다. 아래는 다음 사람이 되풀이하면 안 되는 것만 추린
것이다.

**되풀이 금지 함정 열하나**

1~5 는 2·3라운드에서, 6~8 은 4라운드에서, 9~11 은 마감 라운드에서 나왔다. **6 이후는 전부
"앞 라운드의 옳은 수리가 다른 옳은 수리를 잡아먹은" 종류다** — 한쪽을 되돌려 풀지 말고
범위·조건으로 풀어라.

1. **`FacemarketRoot` 가 첫 렌더에 `<Navigate>` 를 반환하면 OAuth `code` 가 죽는다.**
   effect 는 자식 → 부모 순으로 돌고 `AuthProvider` 는 라우터의 조상이라, 그 `replaceState`
   가 code 교환보다 먼저 쿼리스트링을 지운다. 이 도메인에서 아무도 로그인할 수 없게 된다.
   (계획서 Task 4 Step 5 의 예시 코드가 바로 이 형태였다 — critical 로 잡혀 고쳐졌다.)
2. **스테이지에 `pointerdown` 캡처를 걸면 데스크톱 카드 클릭이 죽는다.** 터치 탭은 살아 있어
   QA 에서 놓치기 쉽다. 캡처는 가로 의도가 확정되는 `pointermove` 로 미룬다.
3. **CSS 는 +y 가 아래라 three 의 `rotationZ` 를 그대로 쓰면 기울기가 거울이 된다.**
   배율 불변식 테스트는 그대로 통과하므로 테스트가 안 잡아 준다 — 손대칭 테스트가 따로 있다.
4. **`perspective` 만으로는 깊이 정렬이 안 된다.** `z` 를 `z-index` 로 직접 번역해야 한다.
5. **공용 인증 코드(`AuthProvider`·`Login`·`shell`)를 고칠 땐 ai 도메인부터 확인하라.**
   이 랜딩을 고치려고 `closeLogin` 에 플래그 삭제를 넣었더니, "성공 경로는 여기를 지나지
   않는다"는 그 주석의 전제가 두 경로에서 거짓이어서 셀러 도메인의 콘티 승격이 조용히
   스킵됐다. **주석이 주장하는 사실은 실제 호출부를 세어 확인하고 넣어라** — 감사가
   이 브랜치에서 잡은 회귀의 절반이 이 종류다.
6. **`FacemarketRoot` 의 플래그 삭제를 "부트스트랩 끝나면 무조건"으로 두면, 부트스트랩
   중에 눌린 CTA 가 방금 심은 복귀 목표를 부모가 먹는다.** effect 는 자식 → 부모 순이라
   자식(`FacemarketLanding`)이 심고 부모(`FacemarketRoot`)가 나중에 지운다. 로그인하고
   돌아온 사용자가 등록 위저드가 아니라 랜딩으로 되돌아온다 — 랜딩의 유일한 전환 경로가
   조용히 끊긴다. 삭제는 `settled && target` + 값 대조로 좁힌다(§라우팅 참고).
   **`pendingPrimary` 보류함을 지워서 풀지 마라. 그건 다른 실패를 되살린다.**
7. **포인터 캡처를 8px 뒤로 미룬 대가를 안 갚으면 맨 호버가 드래그가 된다.** 캡처 전
   구간에서 스테이지 밖으로 손을 떼면 `pointerup` 이 안 들어와 `pointer.current.id` 가
   사장되고, 그 뒤로는 버튼을 안 누른 마우스 이동까지 드래그로 인식된다. 그래서 무장을
   푸는 길이 **셋 다 있어야 한다** — `pointermove` 첫머리의 `buttons === 0` 가드 ·
   `window` 릴리스 리스너 · `onLostPointerCapture`(§캐러셀 — 입력). 하나로 줄이지 마라.
   **캡처를 `pointerdown` 으로 되돌리는 건 해법이 아니다 — 함정 2 가 그대로 돌아온다.**
8. **카피를 낮추다 편익을 전부 지우면 페이지가 목적을 잃는다 — 이 자리는 양방향으로
   실패한다.** 코드가 안 하는 일을 약속하면 거짓말이고, 코드가 하는 일까지 지우면
   생체정보를 넘기라고 설득해야 하는 페이지에 설득이 없어진다. 실제로 한 라운드가 편익
   문장을 전부 지워 마지막 CTA 뒤에 부정문만 남긴 상태를 만들었다. 규칙은 §섹션 내용
   머리말에 있다 — **문장을 지우지 말고 눈금만 내려라.**
9. **랜딩만 다른 단어를 쓰면 사용자가 버튼을 못 찾는다.** 랜딩이 '폐기'라고 부르던 조치를
   제품 화면은 전부 '해지'라고 부른다(`ModelLicense.jsx` · `PublicVerify.jsx`). PRD 의
   용어는 내부 문서 용어지 **사용자 대면 문자열이 아니다.** 되돌릴 수 없는 조치를 앞둔
   모델이 화면에서 그 단어를 못 찾고 멈춘다 — 신규 표면(랜딩) 쪽을 맞추는 게 싸다.
10. **`Login.jsx` 의 두 줄(`hadSessionOnOpen` 가드, 자동 닫기의 `cancelled: false`)을
    되돌리지 마라.** 둘 다 앞선 라운드가 정반대로 왕복하다 못박은 자리다. 가드를 빼면
    Editor 의 401 재로그인 모달이 토큰 갱신 한 번에 사라지고, `cancelled: true` 로 바꾸면
    ai 도메인의 콘티 승격이 스킵된다. **facemarket 에 남은 플래그를 여기서 치우고 싶어지는
    게 그 유혹의 출처인데, 정리는 소비하는 쪽(`FacemarketRoot`)의 몫이다** — 여기서 고치면
    두 도메인이 같은 플래그에 반대 요구를 하게 된다.
11. **탭 제목 복원을 호스트로 안 가르면 모델 도메인 전체가 셀러 제목이 된다.** 랜딩을
    떠나는 순간 되돌아가고 새로고침 전까지 안 돌아온다 — 생체정보를 넘기는 등록 7단계
    내내 탭에 셀러 제품 이름이 뜬다. 복원의 근거("같은 문서에서 셀러 화면으로 갈 수 있다")
    가 이 도메인에서는 성립하지 않는다(§탭 제목·설명 교체).

**문서가 코드보다 세게 말했던 자리 (이번에 맞춤)**

- `getJobSettlement` 화면 노출 — 계획 승인 단계에서 축소됐는데 스펙에만 남아 있었다.
- `rebaseTarget` — 계획서가 정의·테스트·호출까지 실었으나 이식하지 않았고, 2라운드에서
  잔재까지 지웠다.
- 유효기간 "90일 / 1년" — 실제 선택지는 90일·1년·2년.
- "검증 가능한 기록" 세 칸 / "체인 앵커" — 실제는 네 칸이고 라이선스 지문을 체인에 올리는
  코드가 없어 "체인 기록"이다.
- 프라이버시 하드룰 1·2 — 대표 이미지 예외와 공개 검증의 마스킹 이름·나이가 빠져 있었다.
- 정산 기록 단위 — "컷마다"가 아니라 **잡(상세페이지) 1건마다**.
- 체인 기록의 무조건형 — `record_license_settlement` 는 best-effort 라 실패하면 체인에도
  `fm_settlements` 에도 행이 없다. 문장에 그 상한이 붙는다(§3).
- 푸터 "법적 고지, 문의" — 걸 문서도 확인된 문의 주소도 없다.
- 푸터가 **약관 부재를 단정한 것** — 두 클릭 거리의 로그인 모달이 "서비스 약관에 동의한
  것으로 간주"한다고 말해 두 화면이 서로를 부정했다. 지금은 양쪽 다 "공개 문서가
  준비되면"으로 맞췄다(§6).
- 법무 URI 의 근거로 `ModelConsent.jsx` 를 든 것 — 그 화면은 어디에도 마운트되지 않는다.
- 푸터의 예시 이미지 고지 — 셋째 사본이라 지웠다. 남은 둘(캐러셀 상단 + 카드 배지)이 정본.
- 라이선스 해지의 어휘 — 스펙이 '폐기'라고 썼지만 제품 화면은 전부 '해지'다(함정 9).
- **철회 경로로 `/model/withdraw` 를 지목한 것**(critical) — 그 화면은 개인화 도메인 전용이라
  FaceMarket 모델에게는 빈 화면이다. 랜딩은 라이선스 해지까지만 약속하는 것으로 바뀌었다.
- **히어로 CTA 를 `disabled` + `aria-busy` 로 잠그라고 요구한 것**(4라운드 major) — 구현은
  정반대를 **의도적으로** 골랐다(보류함 `pendingPrimary`). 스펙대로 따르면 보류 클릭
  기능이 통째로 죽는다. **이 자리에서 두 라운드가 반대 방향으로 왕복했으므로**, §1 히어로에
  근거를 붙인 경고 블록으로 못 박았다. 다시 뒤집기 전에 그 블록부터 읽어라.
- **"React 는 활성 인덱스가 바뀔 때만 재렌더한다"**(4라운드 minor) — idle 에서만 참이다.
  드래그 중에는 `pointermove` 마다 `setTarget` 이 돌아 프레임마다 재렌더된다. 이 문장을
  믿고 `target` 을 ref 로 옮기면 wake 이펙트가 안 발화해 캐러셀이 통째로 멈춘다.

**아직 그물이 없는 곳**

렌더 테스트 인프라가 없어서 캐러셀의 포인터·포커스 동작과 라우팅 게이트는 전부 육안 확인에
기댄다. 이 영역을 손대는 변경은 §확인 방법의 항목을 손으로 다시 밟아라.
