## B. 오너 신규 발견 (N1 ~ N9)

- **N1 [수정]** 섹션 접힘(덱 커버) 썸네일과 펼친 후 카드 이미지의 표시 크기가 다르다 → 동일하게.
  (접힘 상태 커버 크기를 펼침 카드와 같은 규격으로 — CSS 정렬, 레이아웃 재계산 최소화.)
- **N2 [설명+1-02]** 스타일링 7번째 회색 컷 = 자동 배정이 그 조합(거울샷 등)의 예시를 카탈로그에서
  못 찾은 상태. 코드 결함 아님 — 오너가 예시 추가 예정. 1-02 문구가 이 상태를 자명하게 만든다.
- **N3 [수정]** 실행 취소(되돌리기) 토스트가 상단 네비 아래 '마네킹컷 생성 중' 리본(job-ribbon)에
  가려짐 → 토스트 스택 위치를 리본 아래(리본 유무에 따라 offset)로.
- **N4 [수정]** 사용자가 '컷 추가'로 만든 컷은 생성예시 **자동 배정 금지** — "예시를 골라주세요"
  빈 카드 상태로 두고 인스펙터를 열어 사용자가 선택. 구현: 사용자 추가 컷에 플래그(예:
  `exampleChoice:'manual'`)를 남겨 `assignGenerationExamples`가 건너뛰게. 진입 시 초기 보드
  자동 배치는 기존대로. 저장 계약과의 호환(신규 필드 1개)은 서버가 payload 통짜 저장이므로 안전하나
  Codex가 계약 문서와 대조 확인할 것.
- **N5 [수정]** 생성예시 드래그 → 카드 사이 드롭 시 양옆이 살짝 밀리며 "여기에 추가" 표시.
  드래그 소스(MoodGuide draggable :919-926)와 드롭존(sb-addzone .drop-on :219)이 이미 있으므로
  ① 드롭존 활성 조건·히트 영역 점검 ② 양옆 카드 translateX 밀림 + 삽입선 하이라이트 스타일 복원
  ③ 갤러리(인스펙터)에서 캔버스로의 드래그 경로가 실제로 발화하는지 검증.
- **N6 [수정]** 매칭 의류를 바꾼 뒤 생기는 변형 표시(기존 컷들을 좌측으로 밀며 최우측에 노란 배경으로
  들어가는 요소)를 **최좌측** 배치로 바꾸고, 스타일은 노란 배경 → **흰 배경 + 검정 테두리**.
  (해당 요소의 정확한 렌더 지점은 구현 시 특정: 캡션 변경 칩(sb-val-changed 계열)·트레이 예약 카드
  중 실제로 오너가 본 것을 mock 재현으로 확인 후 적용.)
- **N7 [수정]** 색상 라벨 불일치: 입력에서 '핑크' 스와치를 골라도 컷 라벨이 '블랙'.
  콘티 colorOpts는 `product.colors[].name`(:1503)을 읽는데 스와치 선택(swatchId)과 name이
  동기화되지 않는 경로가 있다. 수정: ① 라벨 우선순위 = 스와치 라벨(swatchId→카탈로그 라벨) >
  color.name > '색상 N' ② 스와치 미선택 색상은 자동 배정(대표색 추정 또는 '색상 1/2') —
  입력 저장 경로(ProductInput/saveRouting)에서 name을 스와치와 동기화하는 쪽이 근본 수정이면
  그쪽으로(단 분석·서버 계약 필드 의미는 불변). Codex가 mock·http 양쪽 흐름 추적 후 확정.
- **N8 [수정]** 인스펙터 '매칭 의류 바꾸기' 목록: 수직 나열 → 생성예시 갤러리처럼 **수평 스크롤**,
  그리고 **단일 선택**(현재 matchIds 복수 토글 :1384) — 마지막 선택 하나만 유지(matchIds=[선택 1개]).
  저장 shape(matchIds 배열)는 유지하되 UI가 1개만 담는다.
- **N9 [수정]** 되돌리기 토스트 문구 간소화: "생성예시를 바꾸며 방향·색상 등 설정을 초기화했어요 ·
  N건" → **"N건 변경"** + [되돌리기]. 사라질 때 페이드아웃 애니메이션(기존 토스트 소멸에 opacity
  transition, prefers-reduced-motion 시 즉시).

## C. 공간세트 단순화 설계 (1-03 + N10, 오너 방향 확정)

오너 결정: "구분 자체는 기존처럼 하되, 그냥 구분만. 개별컷이 들어오면 경계가 사라지게."
+ 세트 안/밖 '컷 추가' 버튼 이원화가 UX를 해친다(없애는 쪽 추천 → 채택).

설계 원칙:
1. **데이터 불변**: spaceGroupId 의미·저장 계약 그대로(생성 파이프라인의 공간 일관성 계약 유지).
2. **시각 구분만 남긴다**: 세트 묶음은 얇은 테두리/헤더 라벨("동네 편의점 앞" 등) 정도의 표시로.
   트레이(전용 컨테이너)와 일반 카드의 이질적 UI 차이를 줄인다.
3. **컷 추가 단일화**: 세트 내부 전용 '이 컷 추가'(:2610 트레이 버튼)와 외부 '＋ 컷 추가'를
   **하나의 추가 어포던스**(카드 사이 addzone)로 통일. 삽입 위치가 세트 내부면 세트 소속으로
   (기존 targetSpaceGroupId 로직 재사용), 경계면 밖이면 개별컷으로.
4. **경계 유연화**: 개별컷(또는 '내 이미지' 컷)이 세트 멤버 사이로 이동/삽입되면 그 지점에서
   세트 묶음이 분리된다. **[합의 정정]** 서버가 같은 spaceGroupId의 전역 연속성을 강제하므로
   (space_set_assets.py:545-575 `space_set_members_not_contiguous`, 테스트 고정) "ID 유지 +
   시각 run 분리"는 저장이 거부된다 → **끊긴 뒤쪽 run은 같은 세트 ID의 새 인스턴스 ID로 재키**
   (`spaceSetGroupId(setId, uniqueId)`, storyboardSpaceSetCatalog.js:251-268). 첫 run은 기존 ID
   유지. 순수 helper `detachSpaceMembership`·`rekeySeparatedSpaceRuns`를 storyboardSpaceSets.js에
   신설하고, 모든 보드 mutation이 저장 전에 서버-유효 배열을 만들게 한다. 별도 '장소 세트 묶음
   풀기' 메뉴는 제거(경계 조작이 곧 풀기), '다시 묶기'는 만들지 않는다.
5. **삭제되는 것**: '장소 세트 묶음 풀기' 액션(:earlier sb-deck-collapse 메뉴), 트레이 전용
   추가 버튼, 예약(reservation) 카드 UI 중 단일화와 충돌하는 부분.
6. **지키는 것**: 세트 멤버의 pose refScope 강제(:172-173, :246), 세트 호환 예시 게이트
   (addBlock :2091-2097), '장소 세트 변경' 액션(세트 단위 교체)은 유지.

수용 기준(브라우저 재현):
- 세트가 있는 섹션에서 컷 추가 어포던스는 카드 사이 addzone 한 종류만 보인다.
- 세트 한가운데에 '내 이미지' 컷을 삽입하면 세트 표시가 두 묶음으로 갈라져 보인다(데이터는
  spaceGroupId 유지 — 렌더 run만 분리).
- '묶음 풀기' 메뉴가 더는 없다. 저장/새로고침 후에도 보드가 동일하게 복원된다.

## F. Codex 계획 합의 반영 (2026-08-13, 상세는 2026-08-13-storyboard-qa-codex-plan-notes.md)

- **§C 전제 정정**: 위 4항 재키 방식으로 확정. 수용 기준의 "데이터는 spaceGroupId 유지" 문구는
  "세트 종류는 유지, 인스턴스 ID는 재키"로 대체. React key는 `spaceGroupId+첫 block.id`.
- **N7 수정 지점 확정**: ProductInput 저장부가 아니라 **prepareStoryboardEntry 의 allColorOpts
  라벨 파생 한 곳**(Storyboard.jsx:1501-1505) — 우선순위 `swatchColors[swatchId].label → name →
  색상 N`. 이 방식만이 기존 불일치 저장 데이터까지 복구한다(swatchId=색 정체성, types.js:86-91).
- **N6 지점 확정**: 캡션의 `sb-match-chip`(Storyboard.jsx:258-280, flex:none·#f6f2ea) —
  JSX에서 최좌측으로 이동 + 흰 배경·검정 테두리(features.css:2383-2394).
- **1-01 정정**: pickRefImage 앵커는 httpAdapter.js:733-749. **Editor 의류 업로드는 이미
  실경로(Editor.jsx:1265-1309)** — 코드 변경 아님, 회귀 테스트만.
- **N4 안전 확인**: `exampleChoice:'manual'` 필드는 서버 canonicalizer round-trip 안전
  (content_roles.py:161-188). 예시 선택 시 generationExampleSelectionPatch 가 `exampleChoice:null`
  로 종료. 초기 진입 자동배정 2개 호출은 유지.
- **1-04/1-07 정정**: sbPending 은 "재시도 체인"이 아니라 보관만 한다 → persistence 모듈에
  **silent retry scheduler**(프로젝트별 backoff, online 이벤트 즉시 재시도, atomic rollback 후
  no-op) 신설. httpAdapter `http()`에 keepalive 옵션 추가해 saveStoryboard 가 전달(1-07 실배선).
  상단 saveError 배너는 **배경 자동저장 실패만 조용히** — '다음' flush 실패는 이동 차단+토스트,
  atomic picker·세트 변경 실패는 기존 inline 에러 유지(경로 분리).
- **1-05 보강**: 적용 순서 = 보드 flush → composeMode PATCH → 성공 시에만 reload/모달 닫기.
- **1-09**: Toggle 을 실제 button role="switch"로, setCopywriting 이 PATCH promise 반환하도록.
- **1-10**: 카드 폭 초과 방지 위해 액션 2×2 grid + 44px 히트영역(시각 크기 유지).
- **N1**: `.sb-stack` 고정 200×258 → `width:var(--sb-card-w); aspect-ratio:3/4`(펼침과 동일 규격).
