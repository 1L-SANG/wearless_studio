# 움직이는 썸네일(GIF) 설계 (2026-10-13, 라운드 4 오너 확정)

## 1. 목적
스타일링컷 여러 장을 모아 돌아가는 대표이미지(썸네일) GIF를 에디터에서 바로 만들어 내려받는다. 완성된 GIF 파일도 보관함에 첨부할 수 있다. 모든 처리는 브라우저 안에서 하고 서버·크레딧·DB를 건드리지 않는다.

근거: 카톡방 썸네일 GIF 고통(용량, 색 빠짐, 화질, 목록 로딩), 에이블리 공식 권장(대표이미지 GIF, 640×768, 전환 1.7초, 5장 이상), 카페24 썸네일 GIF 5MB 한도. 조사 정본 `.scratch/gif-20261013/PLAN.md`.

## 2. 범위
- 포함: 의류 안 이미지와 GIF 밑줄 탭, 사진 2~8장의 GIF 제작과 완성 GIF 첨부, 원본 비율과 고정 규격 3종, 저장과 캔버스 삽입, GIF 인스펙터, 정지 이미지와 GIF 원본 내보내기.
- 제외: 크레딧, 서버와 DB 변경, 글자 얹기, 손실 압축.

## 3. 화면 (라운드 4 확정)
의류 패널은 `UnderlineTabs`의 이미지와 GIF 탭을 쓴다. 별도 툴바 GIF 탭은 없다.

1. 이미지 탭은 색상 묶음마다 3열 그리드 첫 칸에 3:4 점선 “＋ 사진 추가”를 둔다. 빈 등록 색상에도 표시하며 색상이 없으면 기타 묶음을 둔다. 업로드 대기와 완료 사진은 해당 `colorId`에 속한다. 한 장도 자동 삽입하지 않고 사진 클릭으로 넣는다. GIF는 제외한다.
2. GIF 탭은 보관함이다. 맨 위 검정 block 버튼 “GIF 생성하기”, 아래 “보관한 GIF” 개수와 점선 “＋ GIF 첨부”를 둔다. 최근 저장한 GIF부터 poster, 호버와 초점 재생, 왼쪽 아래 GIF·용량 배지, 오른쪽 위 다운로드와 X를 표시한다. 저장 직후 기존 `fresh` 강조를 쓴다. 타일 클릭은 캔버스 삽입, 사용 중 삭제는 기존 규칙을 따른다.
3. “GIF 생성하기”는 탭 안의 별도 화면이다. 제목과 취소, “사진 2~8장을 고르세요 · 고른 순서로 돌아가요 · 3/8” 안내를 둔다. 색상별 스타일링컷을 먼저 보여 주고 클릭 순서를 번호로 표시한다. 마우스로 타일을 드래그하면 지나간 순서대로 선택하며 이미 선택한 사진은 건너뛰고 8장까지만 고른다. 클릭 선택과 해제는 유지한다. GIF와 삭제는 없다.
4. 사진 영역은 위쪽에서 스크롤하고 규격과 “GIF 만들기”는 패널 하단 고정 영역에 둔다. 고정 영역은 위쪽 1px `--ring-strong` 경계선과 `--bg-2` 배경을 쓴다. 규격은 원본 비율 기본, 5:6, 3:4, 1:1의 틀 아이콘 네 개다. 원본은 첫 사진 기준 폭 640px, 짝수 높이, 높이 최대 1200px다. 고정 규격은 640×768, 800×1067, 800×800이다. 장당 1.5초 하드컷, `anchorY: 0.08`을 쓴다. 선택 사진의 `cropLossRatio`가 25%를 넘으면 “많이 잘려요” 배지를 표시하며 제작은 허용한다.
5. “GIF 만들기”는 진행률을 보여 준 뒤 `saveWardrobeGif`로 바로 저장하고 보관함으로 돌아간다. 결과 화면과 별도 저장 버튼은 없다. 성공 토스트는 “보관함에 담았어요”, 실패는 제작 화면의 오류 한 줄이다. 5MB 초과 제작 결과는 저장하지 않고 “용량이 커서 담지 못했어요. 사진 수를 줄여 주세요”를 표시한다.
6. GIF 첨부는 형식, 가로·세로 4000px, 25MB 순서로 검사한다. 일반 이미지 재인코딩 경로를 거치지 않는다. 5MB 초과는 확인 줄에서 “줄여서 담기”와 “그대로 담기”를 고르게 하고 카페24 경고를 유지한다.

한국어 어절 중간 줄바꿈 금지, CSS Modules와 기존 토큰, 나란한 버튼의 `.modal-actions`, 짧은 안내를 따른다. 시각 기준은 `mockups/gif-ui-20261013/round4.html`의 ①, ③④, ④-b, G-1, G-2이며 G-3은 제외한다.

## 4. 인코딩 규칙
- 라이브러리: `gifenc`(npm, MIT). Web Worker(`new Worker(new URL('./gifEncodeWorker.js', import.meta.url), { type: 'module' })`)에서 인코딩. 메인 스레드는 프레임 추출(canvas)만.
- 프레임마다 팔레트: `quantize(rgba, maxColors, { format: 'rgb565' })`로 프레임별 256색. 전역 팔레트 금지(색 빠짐 원인).
- 디더: Floyd–Steinberg(직접 구현, 쇼필공 도구와 같은 식). 켜짐 고정.
- 피부·입술 보정(colorBoost): 양자화 입력 샘플에 피부·붉은 기 픽셀(r>95&&g>40&&b>20&&r>g&&r>b&&|r-g|>15&&r-b>15, 또는 r>110&&r-g>45&&r-b>35&&g<140)을 3배 더 넣어 팔레트 칸을 확보한다. 함수로 분리해 테스트한다.
- GIF: loop 0, delay = 1500ms 고정(사진), 첨부 축소는 원본 프레임 delay 유지. 첫 프레임은 JPG(품질 0.92)로도 만든다.

## 5. 용량 사다리 (순수 함수 `planLadder` + 실행 루프)
- 하드 상한 5MB(5,000,000바이트), 소프트 목표 1.5MB(목록 로딩).
- 사진 모드 단계: [256색], [192색], [폭 ×0.8, 256색], [폭 ×0.8, 128색], [폭 ×0.64, 128색].
- 소프트 목표는 처음 256색과 192색 단계까지만 시도한다. 128색과 폭 축소는 하드 상한을 위해서만 쓴다. 하드 판정은 인덱스 2부터다.
- 각 단계마다 실제 바이트를 재고 하드 상한 이하였던 첫 결과를 기억한다. 소프트 목표를 통과하면 그 결과를 쓰고, 소프트 시도가 끝나도 목표에 못 미치면 기억한 첫 통과본을 쓴다. 하드 통과본이 없으면 사다리를 계속 실행하며, 하드 판정에서 멈췄을 때도 소프트 목표를 못 맞췄으면 기억한 첫 통과본을 쓴다. 마지막 단계도 하드 상한을 넘으면 저장을 막고 사진 수를 줄이라는 오류를 표시한다.
- 결과 객체: `{ blob, width, height, frames, delayMs, bytes, colors, scale, stepIndex }`.

## 6. 이미지 읽기
보관함 사진 `src`가 `/v1/assets/{id}/file`이면 `editorExport.js`의 `toBytesUrl`로 `/bytes`로 바꾸고 `img.crossOrigin='anonymous'`를 src 대입 전에 세운다(내보내기와 같은 근거). 목 어댑터의 로컬 경로는 그대로 쓴다.

## 8. 테스트 기준(통과해야 함)
1. `planLadder('photo')` 단계 순서와 종료 조건이 위 표와 같다.
2. cover 크롭: 세로 긴 사진을 5:6, 3:4, 1:1로 자를 때 기본 가운데와 anchorY 0.08의 위쪽 기준 좌표가 맞고 결과 크기가 정확히 640×768, 800×1067(짝수 보정 허용), 800×800이다.
3. 인코더(워커 없이 순수 함수 경로): 합성 프레임 6장(800×1067, 노이즈 포함)을 넣으면 올바른 GIF(헤더 `GIF89a`, 프레임 6, loop 0, delay 150)가 나오고 바이트가 5MB 이하다.
4. colorBoost: 피부색 배경에 0.2% 붉은 영역을 가진 합성 프레임에서, boost 적용 팔레트의 붉은 영역 평균 색 오차가 boost 없는 팔레트보다 작거나 같고, 양쪽 모두 256색 기준으로 계산한다(ΔE는 간단한 Lab 변환으로 테스트 안에서 계산).
5. 기존 테스트 전부 통과, `pnpm build` 통과.

## 10. 저장, 첨부, 인스펙터와 내보내기

### 저장과 첨부
- 기존 `uploadWardrobeGif`로 원본 GIF blob과 첫 프레임 JPG를 올리고 두 업로드가 성공한 뒤 한 항목을 등록한다. `kind`, `posterSrc`, `gifMeta`와 프로젝트별 브라우저 저장소 계약은 유지한다. 서버·DB 계약은 바꾸지 않는다.
- `gifMeta`는 frames, 평균 delayMs, width, height, 원본 bytes를 담는다. 첨부 GIF는 `gifuct-js`의 `parseGIF`, `decompressFrames`로 읽고 dispose 2와 3, 투명 패치를 완전한 프레임으로 합성한다. 첫 프레임은 캔버스로 JPG를 만든다. 확장자로 허용한 파일은 바이트를 유지하고 blob MIME만 `image/gif`로 맞춘다.
- 5MB 초과 원본 저장은 사용자가 “그대로 담기”를 누른 경우에만 허용한다. 25MB 한도는 항상 유지한다. “줄여서 담기”는 4초로 제한하고 프레임이 많으면 10fps로 샘플링한 뒤 사진과 같은 색·폭 사다리를 사용한다. 샘플링하지 않는 프레임은 원본 delay를 유지한다.
- 메모리 보호를 위해 축소 합성 버퍼는 폭 800px 이하로 먼저 만든다. gifuct-js는 압축 해제 전 리사이즈를 지원하지 않으므로 원본 인덱스 패치를 한 장씩 해제하고 작은 RGBA 버퍼에 직접 합성한다. 원본 크기 RGBA 프레임 배열을 누적하지 않는다.
- 캔버스에 넣지 않은 일반 업로드 사진의 재접속 복원은 기존과 같이 제공하지 않는다. 이 작업에서 새 사진 저장 계층을 추가하지 않는다.
- 실패하면 목록에 불완전 항목을 보이지 않고 현재 화면에서 재시도한다. 삭제는 목록에서만 하며 원본 또는 poster가 사용 중이면 막는다. GIF는 저장 후 자동 삽입하지 않는다. 미삽입 목록의 기기 간 동기화와 새 asset 정리 API는 추가하지 않는다.

### 캔버스와 인스펙터
- 기존 이미지 요소의 GIF 필드는 삽입, 프레임 채우기, 정보 카드 재편집, 보관함 복원에 유지한다. 사진 교체와 비우기는 GIF 필드를 지운다. GIF에는 AI 요청을 제공하지 않는다.
- 인스펙터 제목은 “이미지”와 작은 GIF 표식, 아래 정보는 “4장 · 0.4MB”다. 크기·비율 잠금·레이어는 기본 노출한다. 회전·모서리·채우기·투명도·자르기는 기본 닫힌 “캔버스 모양”에 넣고 펼치면 “모양을 바꿔도 GIF 원본은 그대로예요”를 표시한다.
- 맨 아래 텍스트 버튼 “첫 장을 정지 이미지로 사용”은 기존 `convertGifToStill`을 호출한다. Undo로 GIF를 복구할 수 있다. 인스펙터 다운로드와 큰 전환 알약은 없다.

### 내보내기
- 캔버스는 원본 GIF를 재생하고 캡처 복제 DOM만 poster로 바꾼다. 크롭은 유지한다.
- GIF 없는 블록은 PNG 한 장을 받는다. GIF가 있으면 다운로드 아이콘에서 “블록 이미지와 GIF 받기 (ZIP)”을 기본 첫 항목으로, “GIF 원본만 받기”를 둘째 항목으로 제공한다.
- 블록 ZIP은 해당 블록 첫 프레임 PNG와 `gif_01.gif` 등의 중복 없는 원본들이다. PNG만 기존 `block_png` 공증을 적용하고 이후 GIF와 함께 포장한다. 원본만 받기는 한 개면 `.gif` 직접, 여러 개면 ZIP이다. 숨긴 GIF는 제외한다.
- 전체 다운로드 창은 유지한다. 분할 ZIP은 정지 이미지 ZIP 공증 뒤 원본 GIF를 추가한다. 단일 이미지 모드의 별도 GIF ZIP은 공증하지 않는다. 원본 읽기에 실패하면 누락 ZIP을 성공으로 내려받지 않는다.
