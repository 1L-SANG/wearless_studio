# 후킹 첫 화면 스타일 — 확정 설계 (2026-08-14)

> 정본. 시안 이력·인터랙션 데모: `mockups/hooking-first-screen/hooking-uiux-directions.html` (v7, 로컬 전용).
> 오너 확정 대화: 2026-08-13(방향)·2026-08-14(5차 피드백까지). "다 구현 들어가면 될 것 같아"로 구현 승인.

## 1. 무엇인가

후킹 섹션에만 붙는 **첫 화면 스타일** — 상세페이지 첫 화면을 어떤 프레임으로 시작할지 셀러가 고른다.
스타일은 **틀(슬롯 수·샷 역할)만** 정하고, 각 슬롯의 그림은 그 컷의 생성예시가 정본이다(랜덤 초기 배정 → 컷에서 변경).

| 스타일 | 값 | 구성 | 진입 노출 조건 |
|---|---|---|---|
| **시그니처 컷** (디폴트) | `signature` | 확대 미디움샷 1장 + 제품명 중앙(흰색) | 항상 |
| **두컷 프레임** | `pair` | 미디움샷 2장(왼 스타일링 · 오른 호리존), 완전 밀착 | 항상 |
| **네컷 프레임** | `moodGrid` | 2×2 **항상 4칸** — 색상 2개↑: 등록 색상이 1번씩 + 남는 칸은 기준색 추가 컷(자동) / 단색: 같은 색 다른 4컷(자동). **선택 토글 없음** | 항상 (내용만 색상 수로 자동 분기) |

- GIF 제외(범위 밖). 합성 이미지는 저장하지 않는다 — 저장 정본은 개별 컷, 프레임은 참조·순서만.
- 제품명 오버레이(시그니처)는 **생성 이미지에 넣지 않는다** — 콘티·에디터가 얹는 텍스트(에디터 텍스트 슬롯 트랙과 연결).

## 2. 저장 계약 (blocks 위에 얹기 — 서버 계약 무변경)

컬러웨이 페어(`colorwayGroupId`+`layoutRowId`) 선례를 그대로 따른다. 신규 필드는 후킹 프레임 소속 블록에만 붙는다.

```
block += {
  hookFrameId: 'hookframe__<uid>',    // 같은 프레임 묶음 (섹션 내 연속 run)
  hookStyle: 'signature'|'pair'|'moodGrid',
  hookFrameVersion: 1,
}
```

- **pair**: 프레임 2컷은 기존 `layoutRowId` + `sectionLayout:'twoColumn'`을 함께 갖는다(조립·렌더 재사용).
- **moodGrid**: 4컷 = `layoutRowId` 2행(위 2컷·아래 2컷) + `sectionLayout:'twoColumn'` — 접힘 시트에서만 2×2로 붙여 그린다.
- **signature**: 단일 컷 + `hookTitleOverlay: true`(표시 계약 — 실제 텍스트는 카피 파이프라인).
- **핀(고정)**: 신규 필드 없음 — 기존 `exampleSelectionOrigin === 'user'` 가 곧 고정. 셔플·재배정은 `'auto'`만 교체.
- 프레임 밖의 후킹 컷은 일반 컷 그대로(펼침에서 '구성 미사용') — 프레임 뒤에 이어서 발행된다.
- 서버는 미지 필드를 저장 통과시킴을 실측 확인(2026-08-14, prod PUT 200). `canonicalize_storyboard`가 이 필드들을 보존하는지 P1에서 재실측 후, 누락되면 서버 화이트리스트에 추가(그때만 서버 변경).

### 컷 수·크레딧 (2026-08-14 2차 정정 — 오너)

- **후킹 시드는 스타일이 필요로 하는 컷만 둔다: 시그니처 = 1컷**(호리존 미디움 + 제품명 오버레이). 구 "2컷 유지" 계약은 폐기 — "후킹에 기존처럼 2장 배치되게 하면 안 된다"(오너).
  - contentRole 은 위치 규칙(후킹 첫 AI 카드 = hero, PRD §8)이 정본.
- **pair 전환 = 컷 +1**(왼쪽 스타일링 미디움은 기존 컷 재사용, 오른쪽 호리존 미디움은 부족분 생성). moodGrid = 항상 4칸(+3). 컷 수 증가 = 크레딧 증가는 확장형 컬러웨이와 동일 원리 — 콘티 상단 컷수·크레딧 표기(기존 동적 로직)가 그대로 반영.
  - 시드 경로의 부족분 팩토리는 `applySeededHookStyle`(shapes.js) 하나로 통일 — 기본 지문(isDefault)·사진 양 재시드(http/mock) 세 경로가 같은 팩토리를 쓰고, UI 전환(applyHookStyleChoice)의 createBlock 과 지문 필드가 일치해야 한다(테스트 가드 있음).
  - 구 '오프닝 2단 행' 보드는 pair 전환 기본 보드와 구조가 같아져 **기본(pair 변형)으로 인정** — 진입 승격(adoptHookFrame)과 사진 양 재시드가 자연스럽게 흡수한다.
- **스타일 전환 = 정확한 컷 구성(2026-08-14 3차 정정)**: 슬롯에 안 쓰인 후킹 AI 컷은 **삭제**한다 — "잔여 컷 남기지 말고 각 스타일에 맞는 컷 구성·개수로 그때그때 배치"(오너). 셀러가 직접 올린 '내 사진'만 프레임 뒤에 남긴다. 구 "보관" 규칙 폐기.
- **발행 조합 폴백**: 슬롯 사양은 발행된 생성예시가 있는 조합만 쓴다(`hookSlotPlan`의 `isCutAvailable` 체인 — 닫힌 조합으로 컷을 만들면 예시 미배정 빈 칸이 되는 사고 방지). 네컷 프레임의 호리존 풀샷은 후보 후순위로 밀리고, 부족분은 방향(뒷면) 변형으로 서로 다른 4컷을 채운다.

## 3. UI (콘티보드)

- **접힘(후킹만 예외)**: 스택 대신 흰 페이지 시트(13px 여백, 내용 크기에 맞춤, radius 10) 위에 실형태 — 타일 **완전 밀착**(gap 0), 기존 스택 이미지 크기(카드 폭; 시그니처 단독 타일만 1.15배 확대 — v4 목업 확정). 시트 태그·헤더 모드 뱃지 없음. **시트 클릭 = 섹션 펼침**(패널 열기 아님). 색상 그리드 추가색 타일에는 색상 칩 + '자동 생성' 뱃지.
- **펼침**: 기존 개별 컷 카드 그대로 — **후킹 슬롯 뱃지·'구성 미사용' 뱃지·'첫 화면 · 스타일명' 프레임 태그는 붙이지 않는다**(2026-08-14 2차, 오너: "'첫 화면 왼쪽/오른쪽' 이런 거 뜨게 하지 마"). 컷 클릭 = 기존 인스펙터(생성예시 선택) — 고르면 origin='user'로 고정.
- **'첫 화면 스타일' 섹션(2026-08-14 2차 — 상시 우측 패널 폐기)**: 후킹 섹션 AI 컷을 클릭했을 때 그 **컷 인스펙터의 맨 위**에만 뜬다. 구성 = 라벨 '첫 화면 스타일' + **미리보기 버튼**(흰 시트 미니어처 + 현재 스타일 이름·설명 + 힌트 '미리보기를 눌러 스타일 바꾸기') → 누르면 아래로 **스타일 카드 3종**이 펼쳐진다(다시 누르면 접힘). 스타일을 골라도 선택 컷·인스펙터는 유지된다.
  - signature: "의류 위주로 확대한 이미지 중간에 제품명을 강조해서 넣었어요."
  - pair: "의류 위주로 표현된 미디움샷 이미지 2개를 붙여서 보여줘요."
  - moodGrid(색상별): "여러 분위기의 이미지를 색상별로 한번에 보여줘요."
  - moodGrid(단색): "같은 색의 서로 다른 네 컷을 모아 무드를 풍성하게 보여줘요."

## 4. 예시 셔플 (전 섹션 공통)

- 모든 섹션 콘텐츠 하단에 **'예시 셔플'** 버튼(셔플 SVG 아이콘 = 검정, pill, 호버 리프트) — 스택 섹션은 부채꼴에 겹치지 않게 아래로(+20px).
- 동작: 그 섹션에서 `exampleSelectionOrigin !== 'user'` 인 컷들의 생성예시를 **같은 컷 종류·샷 후보군 안에서만** 재추첨. 공간 세트는 **세트 단위**로 같은 조건의 다른 세트로 교체. 고정 컷 제외.
- 구현: `assignGenerationExamples` 후보 풀에 재추첨(reroll) 모드 추가 — 현재 배정과 다른 후보 우선.

## 5. 구현 단계

1. **P1 계약 lib** — `src/lib/storyboardHookFrame.js`: 스타일 상수·파생(`deriveHookFrame`)·적용(`applyHookStyle`)·그리드 내용 자동 분기, 순수 함수 + 테스트. 서버 필드 보존 실측.
2. **P2 시드·전환** — defaultStoryboard 후킹 시드에 signature 프레임 표식, 스타일 전환 로직(블록 보관·추가), normalizeBoard/normalizeRows 상호작용 정리(§7 나열규칙 준수).
3. **P3 콘티 UI** — 접힘 시트 렌더 예외, 스타일 선택 패널, 슬롯 뱃지, 셔플 버튼(전 섹션).
4. **P4 조립** — 에디터/발행 조립에서 프레임 렌더(pair·grid는 layoutRow 조립 재사용, signature 오버레이는 텍스트 슬롯 트랙과 접점).
5. **P5 검증** — 프론트 테스트·빌드 + 헤드리스 스모크(접힘/펼침/전환/셔플).

확정(2026-08-14, '네컷 프레임' 네이밍과 함께): 그리드는 항상 4칸 — 2~3색의 남는 칸은 기준색 추가 컷으로 채운다.
