# 마네킹 품질 기준과 최종 한 장 구현 계획

**Goal:** 중요한 상품 오류를 개수로 상쇄하지 않고 후보를 선택하며, 해결되지 않으면 서비스 부담 최종 한 장만 재검증한다.

**Architecture:** 순수 정책 모듈이 구조화된 항목별 판정과 선택 이유를 소유한다. 기존 scored QC 호출에서 판정을 함께 받으며 워커의 선택, 보정 되돌리기, 저장 전 최종 재생성에서 사용한다. 품질 실패 코드를 기존 job result에 실어 화면의 자동 재시도를 멈춘다.

**Tech Stack:** Python, FastAPI, pytest, Vite와 JavaScript.

**Spec:** `documents/mannequin_quality_selection.md`

## 제약

- PR 252의 기존 worktree에서 작업한다. 현재 사용자 작업 트리는 수정하지 않는다.
- 구현 단계에서는 커밋과 푸시를 하지 않았다. 이후 사용자가 승인한 머지 전 준비 단계에서 커밋과 푸시, CI 확인과 Draft 해제를 진행한다. 머지, 운영 배포, 유료 이미지 API 호출은 수행하지 않는다.
- 기존 생성 예산 외 추가 이미지 요청은 최종 1회뿐이다. 사용자 크레딧 추가 차감은 없다.
- 공유 비채점 QC, 기존 모델 선택, 이미지 크기는 유지한다. 후속 P1 수정에는 합류 요청 연결을 저장하는 전진 마이그레이션 한 개만 추가한다.

## 작업

- [x] `mannequin_quality.py`에 항목별 심각도 검증, 후보 비교, 보정 악화, 재생성 지시를 추가한다. 로고 critical과 여러 minor 비교, 동일 심각도 교환, 중복 문장, 불명확한 근거를 테스트한다.
- [x] `image_qc.py`의 scored 요청에만 항목별 근거를 붙인다. 응답 검증과 생성 이미지 해시를 기록하고 공유 3필드 요청이 유지되는지 검사한다.
- [x] `mannequin_job.py`의 후보 선택과 모든 최종 저장 경로를 정책에 연결한다. 중요한 오류가 남으면 최종 1회 생성, 재검수, 실패 종료와 크레딧 해제를 실제 워커 하니스에서 확인한다.
- [x] 품질 종료 코드를 job result와 어댑터에 전달한다. 최초 생성과 재생성 화면의 자동 시도는 중단하고 명시적 재시도는 새 멱등 키를 만들도록 테스트한다. 결과 불명인 요청은 기존 키로 재합류한다.
- [x] 변경 관련 테스트, 비DB 서버 전체 검사, 프런트 전체 검사와 빌드를 수행한다. 독립 리뷰에서 나온 유효한 문제를 수정하고 관련 검증을 다시 한다.

## 후속 P1 수정

사용자는 독립 리뷰의 1번만 수정을 승인했다. 2번은 확정된 상품 정보의 재진입 차단으로 정상 UI 도달 경로가 성립하지 않아 철회했으며, 이번 수정에서 화면 코드는 바꾸지 않는다.

- 변경: `repo.create_job`의 마네킹 요청 키 조회와 합류 기록을 프로젝트별 트랜잭션 잠금 안에서 처리한다. `mannequin_job_requests`에 합류 키도 영속 저장한다.
- 수정 전 재현: 별도 임시 Postgres에서 실제 생성 라우트, 작업 생성 SQL, 예약 SQL로 4 failed, 2 passed. 응답을 잃은 합류 키가 원래 작업 종료 후 새 작업을 만드는 것을 확인했다.
- 수정 후: `MANNEQUIN_REQUEST_TEST_DATABASE_URL`로 명시한 격리 로컬 DB에서 `tests/test_mannequin_request_aliases.py`, 9 passed. 실패·완료·취소 후 재합류, 8개 동시 합류, 트랜잭션 롤백, 사용자 격리, 기존 작업 키 보존, 다른 작업 종류 비개입과 접근 권한을 검증했다.
- 독립 재리뷰: P1 해결 확인, 추가 결함 없음. 검증에 사용한 임시 컨테이너는 운영 데이터나 볼륨을 공유하지 않았고, 테스트 후 컨테이너와 임시 DB를 제거했다.
