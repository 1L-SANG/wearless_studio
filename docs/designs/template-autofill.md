# 목적 기반 템플릿 자동 채움 설계

상태: **구현 전 검토용 초안**
대상: 에디터의 A안 상세페이지 템플릿
이 문서는 설계와 후속 구현 범위를 정리한다. 자동 채움 기능 구현, 새 모델 학습, PRD·ADR 개정은 포함하지 않는다.

## 해결할 문제와 목표 동작

사용자는 앞 단계에서 상품 정보를 확인하고 필요한 이미지 생성을 마친 뒤 에디터에 들어온다. 템플릿을 적용할 때 이미 준비한 사진과 상품 설명을 다시 하나씩 입력하는 부담을 줄인다.

목표 흐름은 **템플릿 적용 → 기존 결과와 상품정보로 자동 구성 → 사용자가 확인·편집**이다. 공통 영어 표제와 디자인은 유지하고 상품별 사진·문구를 채운다. 사용자 수정 내용은 자동으로 덮어쓰지 않는다.

이 설계에서 프레임의 목적은 ‘사진 2장’ 같은 배치 모양과 다르다. 같은 2장 구성도 상품 소개인지 컬러 비교인지에 따라 입력 자료와 문구가 달라진다. 목적은 템플릿 제작자가 지정하며 일반 사용자에게 내부 역할 분류를 먼저 요구하지 않는다.

## 대화에서 정리된 기준

- 도입부는 사진 2장 아래에 상품 소개를 자동 작성한다.
- 영어 섹션 표제는 기본 유지한다. 실제 편집기에서 사용자의 제목 수정을 금지한다는 뜻은 아니다.
- 두 큰 착용 사진 구역에는 별도 제목·설명·캡션을 추가하지 않는다.
- 제품 단독 앞면·뒷면 컷은 Size Guide 앞에 놓는다.
- **디테일 행 수는 앞 단계에서 확정하고 정상 생성한 디테일 항목 수를 따른다.**
- 디테일 1개가 생성됐다면 1개가 필요했던 것이므로 1행을 구성한다. 템플릿 예시의 3칸을 채우기 위해 다른 항목을 만들지 않는다.
- 상품 소개 전용 작성 규칙을 사용하되, 이를 위해 별도 AI 모델을 새로 학습시키는 것을 전제로 하지 않는다.

## 자동 채움 방식 비교

| 방식 | 장점 | 한계 |
|---|---|---|
| 정해진 자료 연결 | 빠르고 예측 가능하다. 상품명·컬러·실측에 적합하다 | 자연스러운 상품 소개와 사진 맥락에 맞춘 표현은 보완이 필요하다 |
| **목적 안에서 AI가 선택·작성 — 추천** | 디자인을 유지하면서 상품별로 내용을 맞출 수 있다 | 사진·문구·확인된 사실의 연결과 결과 검증이 필요하다 |
| AI가 전체 배치까지 자유 구성 | 큰 구성 변화가 가능하다 | 디자인 일관성·재편집·기존 수정 보존의 부담이 크다 |

규칙 기반 자료 연결을 기본으로 하고 표현이 필요한 곳에 AI를 사용한다. AI가 상품 사실이나 필요한 디테일 개수를 다시 결정하는 구조로 만들지 않는다.

## A안 프레임별 목적과 입력

| 프레임 | 목적 | 사진 및 정보 | 문구 처리 |
|---|---|---|---|
| Opening | 상품 식별과 첫인상 | 대표 착용컷, 상품명, 대표 컬러, 선택 브랜드 정보 | 입력값 연결. 영문명이 없으면 원래 상품명 사용 |
| The Everyday Edit | 상품의 전체 매력과 핵심 특징 소개 | 도입 사진 2장, 확정된 특징·핏·상품정보 | 도입부 전용 규칙으로 자연스럽게 작성 |
| Color Selection | 등록된 컬러 비교 | 컬러별 사진·컬러명·스와치를 같은 colorId로 연결 | 등록 이름 연결 |
| Fabric Notes | 소재의 외관과 확인된 소재 정보 설명 | 소재 사진, 확인된 혼용률·특징, 필요한 확대 안내 | 사진으로 보이는 내용과 확인된 사실을 구분해 작성 |
| Detail Notes | 앞 단계에서 확정·생성한 디테일 설명 | 생성된 디테일 항목 목록 | 항목별 사진·특징·설명을 한 묶음으로, 개수만큼 반복 |
| Full Image 01 | 기장과 착용 실루엣 확인 | 확정된 착용 사진 | 새 문구 없음 |
| Full Image 02 | 뒷모습의 착용 실루엣 확인 | 확정된 뒷면 착용 사진 | 새 문구 없음 |
| Product View | 제품 단독 앞면 확인 | 같은 상품·컬러의 제품 앞면 | FRONT 기본 표기 |
| Back View | 제품 단독 뒷면 확인 | 같은 상품·컬러의 제품 뒷면 | BACK 기본 표기 |
| Size Guide | 실제 치수 확인 | 입력된 실측값·단위·사이즈명 | 사실 연결. 숫자나 사이즈명을 추정하지 않음 |
| Care & Composition | 소재 구성과 관리 안내 | 확인된 혼용률·케어라벨·사용자 안내 | 입력값 우선. 규칙형 초안은 확인된 상품 사실과 구분 |

프레임 목적은 기존 사진의 contentRole, cutType, 방향 등의 정보를 활용하지만 기존 콘티 분류를 대체하지 않는다. 동일한 ‘제품 사진’ 필드도 Product View와 Back View에서는 다른 방향 조건을 갖는다.

## 디테일은 생성 결과 개수에 맞춰 반복

정상 완료된 생성 결과에서 현재 사용할 디테일 항목 목록을 읽는다. 이 목록은 앞 단계에서 확정한 항목과 대응해야 하며, 재시도 이력의 이전 파일들을 별도 디테일로 중복 계산하지 않는다.

아래 detailItems는 구현할 논리적 입력 목록을 설명하는 이름이며, 이미 존재하는 API 필드라고 가정하지 않는다.

```text
행 수 = detailItems.length

1개 확정 → 1개 생성 → 사진·설명 1행
2개 확정 → 2개 생성 → 사진·설명 2행
3개 확정 → 3개 생성 → 사진·설명 3행
```

현재 Figma의 3행은 예시이지 고정 정원이나 상한이 아니다. 기본 행을 재사용해 유효한 생성 결과의 N개 항목만큼 구성한다. 각 행에는 해당 항목의 사진과 확정된 특징, 그 항목을 설명하는 문구가 함께 들어간다.

템플릿 적용 시 디테일을 새로 선별해 개수를 줄이거나, ‘세 번째 칸이 비었다’며 보충을 요구하지 않는다. 생성 대기·실패 복구는 기존 생성 흐름의 책임이며 이 정상 자동 채움 규칙에 새로운 기획 단계로 섞지 않는다.

## 상품 도입부 작성 규칙

The Everyday Edit 아래의 소개 문구는 자동 작성 대상이다. 같은 AI에 도입부 전용 지시를 주며, 소재·디테일 작성 지시와 역할을 구분한다.

### 입력

- 확인된 상품명, 핵심 특징, 핏 및 관련 상품정보
- 함께 배치할 도입 사진과 해당 사진의 알려진 맥락
- 현재 사용자가 작성·수정한 소개 문구
- 카피라이팅 ON/OFF와 공통 섹션 제목
- 프레임의 글자 크기와 사용 가능한 폭

### 작성 지시

- 상품의 전체 인상과 주요 매력을 자연스럽게 소개한다.
- 확정된 특징 중 도입부에 적합한 핵심을 골라 **2~3문장 정도**로 쓴다. 이는 목표 길이이며 사용자 문구를 강제로 자르는 제한이 아니다.
- 함께 배치된 사진과 어울리게 작성한다.
- 뒤의 디테일 설명을 전부 나열하거나 반복하지 않는다.
- 확인되지 않은 촉감·기능성·소재·효능을 추가하지 않는다.
- 공통 영어 제목을 다시 쓰거나 상품명을 임의로 만들지 않는다.
- 카피라이팅 OFF에서는 새로운 AI 소개를 작성하지 않는다.
- 사용자가 편집한 소개는 일반 템플릿 재적용으로 다시 쓰지 않는다.

출력은 소개 본문과 사용한 상품정보·사진의 참조다. 확인된 정보가 적으면 그 범위 안에서 짧게 작성한다. 별도 모델 학습보다 전용 지시와 실제 상품 예시 평가부터 진행한다.

## 자료 연결과 사용자 편집 보존

1. 현재 문서와 상품정보·생성 결과를 읽어 적용 계획을 만든다.
2. 사진은 같은 상품·컬러·사진 종류·방향 조건을 우선한다. 적합한 후보 안에서만 구도·선명도·다양성을 비교한다.
3. 디테일은 확정·생성된 항목별 묶음을 그대로 소비한다. 다른 문구 영역도 선택한 사진과 확인된 사실을 함께 근거로 삼는다.
4. 고정 기본 표제, 사실 연결, AI 작성 대상, 사용자 수정 문구를 구분한다.
5. 프레임 크기·글자 폭·내용 길이를 확인해 배치한다. 사용자 문구를 임의로 요약하거나 작은 글자로 눌러 넣지 않는다.
6. 한 번의 적용 작업으로 반영하며 되돌릴 수 있게 한다. 늦은 AI 응답이 최신 편집을 덮지 않도록 요청과 문서 버전을 확인한다.

컬러는 전체 최대 3개라는 현재 상품 입력 계약을 따른다. 사진과 컬러명은 같은 등록 컬러를 가리켜야 한다. 등록되지 않은 선택 컬러 자리는 숨기고, 등록 컬러에 맞는 사진이 없으면 해당 컬러와 사진 선택 필요 상태를 유지한다. 제품 단독 뒷면에 착용 뒷모습이나 앞면을 자동 대체하지 않는다. Full Image 02의 뒷면 착용컷도 앞·옆면으로 자동 대체하지 않는다.

사용자 문구의 보존과 그 문구의 사실 검증은 별개다. 혼용률·실측·케어는 사진 인상만으로 추론하지 않는다. 케어라벨의 입력값을 우선하고, 기존 규칙형 제안은 확인이 필요한 초안으로 표시하고, 확인된 입력값과 구분한다.

템플릿 변경으로 자리를 잃은 기존 배치 사진은 보존한다. 라이브러리의 모든 미사용 사진을 새로 붙이지 않는다. 사용자가 만든 수동 순서와 자유 편집 구역을 자동으로 재기획하지 않는다.

새 이미지 생성은 기존 생성 기능을 사용한다. 추가 문구 호출의 비용·대기·취소 정책은 구현 전에 기존 서비스 정책과 맞춘다.

## 현재 기반과 후속 구현

현재 main에는 사진 자동 배치와 상품정보·특징 문구를 불러오는 기반이 있다. 이 문서의 A안 전체 자동 구성이나 도입부 작성기를 구현했다는 뜻은 아니다.

- [Editor.jsx](../../src/features/editor/Editor.jsx)의 addFrame, overwriteDetailPageTemplate, buildInfoCtx, draftFeatureCopy
- [autofill.js](../../src/features/editor/templates/autofill.js)의 역할별 사진 후보와 배치
- [infoPresets.js](../../src/features/editor/presets/infoPresets.js)의 정보 연결과 특징 문구 재사용
- [PRD](../../documents/PRD.md) §10.12, §10.14, §11의 프레임·정보·카피 정책
- [ADR-0005](../adr/0005-storyboard-content-taxonomy.md)의 사진 목적과 촬영 방식 구분

후속 기능 PR의 구현 순서는 다음과 같다.

1. A안의 실제 프레임 정의와 목적·입력 항목 연결을 코드화한다.
2. 생성 결과를 읽어 디테일 N행을 만들고 사진·상품정보를 연결한다.
3. 도입부·소재·디테일의 목적별 문구 작성을 기존 서비스/어댑터 계층을 통해 연결한다.
4. 내용 길이에 따른 배치, 사용자 수정 보존, 카피 OFF, 재적용·취소·되돌리기를 검증한다.

확인 상태와 입력 자료의 출처, 사용자 수정 여부를 연결할 필요가 있다. 기존 일반 텍스트 요소가 모두 이런 메타데이터를 가진다고 가정하지 않는다. Figma의 자동 레이아웃도 실제 에디터의 배치 로직으로 따로 옮겨야 한다.

## 기능 PR에서 검증할 결과

| 입력·행동 | 기대 결과 |
|---|---|
| 디테일 항목 1개 확정·생성 | 1행만 구성. 3행을 맞추는 보충 요구 없음 |
| 디테일 항목 2개 확정·생성 | 2행만 구성하며 각 사진·특징·설명이 대응 |
| 디테일 항목 3개 확정·생성 | 3행 구성. 기존 재시도 파일을 중복 항목으로 계산하지 않음 |
| 확인된 상품정보와 도입 사진으로 적용 | 관련된 핵심을 2~3문장 정도로 소개. 뒤의 설명 전체를 반복하지 않음 |
| 큰 착용 사진과 제품 앞뒤 배치 | 큰 착용컷에 불필요한 문구 없음. 제품 앞뒤는 Size Guide 앞 |
| 등록 컬러 1~3개로 적용 | 실제 등록 컬러 수에 맞추고 사진·컬러명 일치 |
| 등록 컬러 사진 누락 또는 뒷면 사진 불일치 | 해당 목적에 맞는 사진 선택 필요. 다른 컬러·방향으로 억지로 채우지 않음 |
| 사용자 문구 수정 후 재적용 | 원문을 보존하고 필요한 만큼 배치 높이 조정 |
| 카피 OFF 또는 적용 후 문구 수정 | 새 AI 문구를 강제로 채우지 않고 늦은 응답으로 수정 내용을 덮지 않음 |
| 적용 후 실행 취소 | 적용 전 사진·문구·배치 복원 |

위 표는 후속 구현의 수용 기준이다. 이번 문서 PR에서 기능 테스트를 실행해 통과한 결과가 아니다.
