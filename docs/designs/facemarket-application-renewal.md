## Vision

### 10x Check
MirrorMirror 완전 패리티(모델 요율·프로젝트별 승인·모델 프로필 페이지)가 12개월 이상향.
이번 플랜은 그 첫 관문인 "큐레이션된 공급": 아무나 즉시 생체등록하는 현재 구조를
지원 → 관리자 검토 → 검증된 모델만 입장으로 바꾼다. 차별화 서사 = MirrorMirror는
지원서가 self-report로 끝나지만, 우리는 지원서 주장(이름·생년월일)을 신분증 인증으로
검증하고 VC로 봉인한다. "지원 → 검토 → 검증 → VC" 루프가 심사위원 앞에서 라이브로 돈다.
**데모 기본 = 두 브라우저 라이브 관리자 검토 시연. auto-approve는 리허설·비상용.**

## 아키텍처: 분리 테이블 (T1-A — 코덱스 외부 검증 후 B→A 전환)

`fm_model_applications` 신설 (생체 enrollment와 별개 aggregate):
- 상태: `under_review → approved / rejected / cancelled`. 제출 즉시 under_review(draft 없음).
- 지원서 필드: 이메일(연락·승인 메일 수신처 — auth엔 이메일 없음, 카카오 무이메일 계정 대응)·이름·생년월일·지역·성별·키(cm)·에이전시 계약 여부·카테고리 4종(다중)·포트폴리오·SNS·자기소개·프로필 사진 1장(application id 귀속 R2 키).
- 유저당 활성 지원서 1개 partial unique index (터미널 제외 → 재지원 가능).
- 승인된 지원서 → `create_enrollment` 게이트 통과 근거. enrollment 머신(2,345줄)은 **무수정** — TTL 재장전·NOT NULL 충돌·sweep 제외·상태 호환 문제 전부 비발생.
- enrollment가 만료·실패해도 승인 지원서는 유효 → 상태 허브에서 **새 enrollment 생성으로 재개** (원클릭, decision 리셋·unique 충돌 없음).
- 전환 이유 기록: 두 모델(Claude 리뷰 원권고 + Codex 독립 검증)이 합의 — 통합(B)의 함정 6개(TTL·NOT NULL·sweep·롤백 상태 호환·재개 충돌·사진 키 소유권)가 전부 aggregate 경계 오류의 증상. 단일 여정 UX는 프런트에서 동일하게 구현됨.

## 리뷰 확정 결정 (구현 구속력)

- **1A 딥링크**: 승인 메일 링크 = 권한 없는 딥링크. 로그인 필수, 세션 유저 = 지원서 유저 검증.
- **2A 메일 실패**: 상태 전이 항상 커밋(진실원천). 메일 발송은 **타입별 로그**(승인/거절/자동거절 구분), 실패 시 대시보드 '미발송' 뱃지 + 재발송 버튼. ModelHub 상태 허브가 메일과 무관한 진실.
- **T2-A 수신처**: 지원서 이메일 필드가 유일한 발송 주소(검증 메일 불요 — 오타 시에도 앱 내 상태가 진실이라 데드엔드 없음).
- **3A PII**: 거절·취소 30일 후 PII 익명화+R2 사진 삭제(재지원 프리필은 30일 내 사진 포함). **승인 경로**: 활성 모델의 지원서 = 운영 데이터 보존, 계정 삭제·라이선스 폐기 시 기존 purge에 지원서 PII·사진 포함(영구 잔존 없음). 승인/거절 감사 로그(admin id·시각·사유). **sweep 구현은 데모 후 PR**(TODOS P1).
- **4A 대조**: cx_identity 계약 수정 — raw 이름 **비교 순간만** 노출(저장·로그 금지 명시). 이름 전체+생년월일 전체 in-flight 대조. 라틴 문자 대소문자 무시+공백 제거. **year-only 엣지**(`cx_identity.py:308` 실존): 성인 게이트 통과자에 한해 이름 전체+연도 일치 시 통과(약한 보장 로그), 경계 연령 minor_blocked는 기존 유지.
- **5A 불일치**: 3회 상한 → 자동 거절('정보 불일치') → 재지원 프리필 교정. 새 상태 없음.
- **6-1B 스펙 위치**: 지원서 = 경량(성별·키 포함). 컴카드 스펙은 승인 후 프로필 단계 — 상태 전이 무관·스킵 가능·photos 안 막음. 기존 모델 행 freeze(역산 fallback 잔존). 지원서 키(cm) → height_bucket 파생 저장, 정확값은 지원서 보존.
- **9-1A 롤아웃**: `FM_APPLICATION_REQUIRED` env — off = 구 경로가 지원서 테이블을 아예 안 봄(진짜 클린 롤백), on = 신규 등록은 승인 지원서 필요. 기존 모델·진행 중 등록 grandfathered.
- **11-1A 화면**: /model/apply 분리 페이지 + ModelHub 상태 허브(검토중/거절 사유·재지원/승인 '계속하기'/만료 재개). admin = **admin.wearless.kr 서브도메인** (2026-09-02 사용자 최종 명세 — 같은 SPA에 Vercel 도메인 알리아스 + `host.js` 도메인 분기 추가, 별도 앱 아님. facemarket 호스트 리다이렉트는 그대로). ⚠️ 선행 ops: DNS 레코드 + Vercel 도메인 추가. admin 지정 절차(SQL/스크립트) 문서화.
- **T3-A 데모·순서**: 구현 순서 = 최소 루프(지원→검토→대조→상태 허브) 먼저 → 메일 → admin 품질 → Slack → 컴카드 → 랜딩. 데모 = 라이브 관리자 검토, auto-approve는 비상용(ON이면 제출 즉시 승인 전이, 메일 실패 무시).
