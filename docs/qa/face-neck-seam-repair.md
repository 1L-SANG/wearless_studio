# 목·옷깃 경계 수리 — 시각 판단과 마스크 자동화

2026-09-17 사용자 선택 1~4만 구현한다. 기존 PR #331의 off/shadow/on, Qwen 폴백, 목 크롭만 보관, 신원 하락 ≤0.02, 범위 밖 변경 0, 비용·메타 배선은 유지한다. 실제 API 사용은 사용자 허락 후에만 수행한다. 이번 수정의 실제 API 호출은 아직 0회이며 사진 품질 통과를 주장하지 않는다.

## 처리 흐름

1. 기존 Qwen 생성 경계 띠에서 목 크롭을 준비한다. 정사각형을 크게 잡아도 얼굴 전체가 들어가지 않도록 윗변을 얼굴 박스 0.55h 아래로 제한한다. 기본 여유 0.3, 빈틈 관찰 시 0.6이며, 확대된 크롭으로 좌표를 정확히 재매핑한다. 원본 RGB 전체는 후처리 context에 보관하지 않는다.
2. 비전 `FACE_SEAM_VISION_MODEL`(기본 gpt-5.4, reasoning high/detail high)이 현재/원본 목 크롭에서 결함, 복원 문장, `damage_polygons`를 함께 만든다. 좌표는 1024 크롭 기준이며 파일명·컷별 수동 좌표는 사용하지 않는다. 수리 영역에는 결함과 자연스럽게 연결하기 위한 정상 주변부도 포함한다.
3. 좌표 개수·범위·유한성·자기 교차·크롭 가장자리·얼굴 보호 구역을 검사한다. 유효한 수리 다각형 안을 투명하게 만든 RGBA 마스크와 현재 목 크롭 한 장을 Sunburst `images/edits`에 보낸다. 원본 베이스는 이미지 편집 API에 보내지 않는다. 모델 gpt-image-2.5-sunburst, high, 1024×1024, PNG, n=1이다. 프롬프트 HEAD/TAIL은 처음 성공한 `repair.cjs`의 surgical restoration 문구를 옮겼다.
4. 별도 비전 호출이 입력/생성 목 크롭을 비교해 `composition_polygons`를 만든다. 손상 수리 영역을 감싸고 정상 질감에서 경계가 이어지는 연속된 영역을 선택한다. blob/API 차이/Qwen 차이로 조각 마스크를 만들지 않는다. 손상 다각형이 합성 영역 밖에 있으면 거절한다.
5. 합성 영역을 확장해 제외한 정상 주변에서 양방향 LK 추적과 RANSAC으로 작은 이동·회전·크기 변화를 추정한다. 양방향 일치, 기준점 분포, 추정에 쓰지 않은 점의 오차, 변환 한계, 주변 픽셀 오차 감소를 확인한 경우만 정렬한다. 움직임이 없으면 생략하고 신뢰할 수 없으면 기존 Qwen 결과로 돌아간다. 이는 작은 전역 유사변환이며 과거 수작업의 DIS 국소 변형을 그대로 복제한 것은 아니다. 국소 비틀림은 이번 정렬의 검증 범위 밖이다.
6. 원본 해상도에서 sigma 7로 경계를 부드럽게 한 뒤 `alpha=clip((soft−128)/110,0,1)`을 적용한다. 다각형 밖 alpha는 정확히 0이며 원본 RGB를 그대로 보존한다. 마스크는 정상 연결 주변부도 포함하므로 가장자리 전체에 alpha=1을 강제하지 않는다. alpha가 모두 사라지는 작은 영역은 거절한다.

두 마스크의 역할은 다르다. API 마스크는 생성 모델의 편집 지시이고, 합성 마스크는 최종 원본에 실제 붙이는 범위다. 생성 모델이 마스크 밖을 바꾸어도 최종 합성 범위 밖 픽셀은 원본에서 복사한다.

## 유지한 동작과 클로드 인계

사용자가 클로드에 맡긴 5~8번(톤 보정 정책, 추가 수리 횟수, 외관 합격 게이트, 정상 사진 처리 정책)은 변경하지 않았다.

- `FACE_SEAM_REPAIR=off`, `FACE_TONE_FIX=off` 기본값 유지.
- 기존 tone 함수·플래그를 유지한다. 이 구현의 품질 확인은 톤 off로 1~4를 분리해 볼 수 있다.
- Sunburst 자동 재시도는 추가하지 않았다.
- 기존 `verify_repair`는 관찰 메타만 남긴다. 불합격이어도 수치 게이트를 통과하면 기존 정책대로 채택한다.
- 정상 여부에 따른 새 제품 정책은 추가하지 않았다. 다각형을 얻지 못하거나 공간 검증에 실패하면 기존 오류 폴백으로 돌아간다.
- `finish_repair`는 합성/정렬 이후 기존 tone을 적용한다. 클로드는 tone 변경 시 이 순서와 합성·톤 전체 support 밖 0 계약을 유지해야 한다.
- 운영 메타에 다각형·프롬프트·사진을 넣지 않는다. 계획/합성 계획 사용량, 정렬 수치, 실패 단계, 신원·변경 픽셀·이미지 비용만 보존한다. 이미지 호출 이후 합성 실패가 나도 확보한 이미지 사용량은 남긴다.

API 호출 수는 완료 컷당 계획 비전 1 + Sunburst 1 + 합성 계획 비전 1 + 기존 관찰 비전 1, 최대 4회다. 중간 실패 시 후속 호출은 하지 않는다. 정상 6장·재수리·품질 정책 검증은 이번 1~4 구현의 완료 근거로 포함하지 않는다.

## 검증

로컬 합성 이미지 테스트로 API 마스크 투명도, 두 계획의 호출 순서, gap 크롭 좌표 변환, 얼굴 보호, 범위 밖 RGB 일치, 정렬 성공/무이동/불확실 거절, off/shadow/신원 폴백, API 본문·키 비노출, 실패 후 비용 보존을 확인한다. 실제 얼굴 사진을 테스트 픽스처로 추가하지 않는다.

최종 관련 테스트: 129개 통과, 30개 건너뜀(레포 밖 실제 사진·모델·참조 파일이 필요한 기존 테스트). Python 컴파일과 `git diff --check` 통과. 독립 코드 검토에서 회전량 누락과 저장 응답의 마스크/프롬프트 검증 누락을 수정한 뒤 추가 차단 결함이 없음을 확인했다. 실제 OpenAI 호출은 사용자가 보류했으므로 0회다.

실사진 12컷에서 API 없이 크롭 준비만 실행했고 12컷 모두 성공했다. 이것은 수리 품질 검증이 아니다. 로컬 산출물은 `output/face-neck-repair-20260917/visual-mask-local-prepare`에 있으며 Git에 포함하지 않는다.

`server/scripts/evaluate_face_seam_repair.py`는 아래 로컬 평가 모드를 제공한다.

- `--prepare-only`: 크롭만 준비, API 0회.
- `--plan-only`: 비전 수리 영역·문장 및 API 마스크 준비.
- `--live`: 계획 → 마스크 편집 → 합성 계획 → 조건부 정렬/합성 → 기존 수치·관찰 검사.
- `--responses-dir`: 동일 목 입력, 마스크, 프롬프트로 생성된 저장 응답과 합성 계획만 재생한다. 요청 지문이 없거나 다르면 거절한다.
- `--plans-dir`: 같은 입력/베이스의 수리 계획을 재사용한다. responses-dir와 동시 사용 금지.

이 도구는 공유 함수를 평가하며, 실제 `repair_after_face_pass` 진입점 검증과 구분한다. 실제 운영 진입점 검증에서는 관찰용 저장 훅만 사용하고 결과·계획·마스크를 수정하지 않는다. 모든 새 실제 API 평가에는 사용자의 허락이 필요하다.
