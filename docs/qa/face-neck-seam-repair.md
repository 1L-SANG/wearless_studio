# 목·옷깃 경계 수리

Qwen 얼굴 패스가 성공한 뒤 목 주변을 따로 잘라 Sunburst로 편집하고, 온전한 주변을 기준으로 정렬한 다음 목·옷깃 부분만 원본에 다시 합성한다.

## 처리 흐름

1. 기존 FacePlan과 패딩 정보를 사용해 최종 Qwen 이미지에서 목 주변 정사각형을 자른다.
2. 얼굴 위치로 목·옷깃 편집 범위를 정하고 얼굴은 보호한다. 별도 비전 모델, 손상 분류, 컷별 건너뛰기는 없다.
3. 모든 컷에 같은 자연어 요청을 보낸다. 끊긴 목·칼라·나시 띠·여밈을 자연스럽게 잇고, 멀쩡한 얼굴·옷감·배경·구도를 유지하도록 요청한다.
4. `images/edits`를 한 번 호출한다. `gpt-image-2.5-sunburst`, `high`, `1024x1024`, PNG, `n=1`. 전송하는 것은 목 주변 크롭 한 장과 같은 크기의 투명 마스크뿐이다.
5. 생성 결과를 원래 크기로 축소하고, 편집 범위 밖의 이동량으로 정렬한다. DIS medium, 이동량 ±48, 1/4 해상도에서 내부 이동량 보간 1600회, Gaussian sigma 5를 사용한다.
6. 마스크 안쪽으로 부드럽게 합성한다. 범위 밖 alpha는 정확히 0이다. 원래 전체 이미지를 바탕으로 수정 영역의 픽셀만 바꾼다.
7. 범위 밖 변경 0, 유효한 SFace 점수 하락 ≤0.02, PNG 저장·디코딩 일치를 확인한다. 실패하면 기존 Qwen 성공 결과를 유지한다.

최초 수작업의 컷별 마스크와 합성 범위는 사람이 정했다. 서버에서는 얼굴 위치로 제한된 목·옷깃 범위를 정해 같은 편집 흐름을 실행한다. 동일한 API 응답이나 완전히 같은 결과를 보장하는 것은 아니므로 실사진 결과를 별도로 검증한다.

## 배선·관측

공유 `apply_face_pass` 성공 경로와 `test_cut_build.render_variant`의 직접 얼굴 패스 성공 경로에 연결한다. 기본 `FACE_SEAM_REPAIR=off`는 기존 경로를 유지한다. `shadow`는 후보를 검증하되 Qwen 바이트를 그대로 반환하고, `on`은 검증을 통과한 후보만 채택한다. 이미지 API 재시도는 없다.

이미지·키·응답 본문·서명 URL은 로그나 Git에 남기지 않는다. 이미지 사용량은 기존 `image_usage`의 `face_seam_repair` 단계로 기록한다. 결과 메타에는 상태, 크롭, 프롬프트 해시, 변경 픽셀 수, 신원 점수, 비용·지연 등만 남긴다. 모델 설정은 `FACE_SEAM_REPAIR_MODEL`이며 이 경로는 Sunburst만 허용한다.

## 로컬 검증

평가 스크립트는 `server/scripts/evaluate_face_seam_repair.py`다. 원본·Qwen 출력·신원 참조·로컬 모델 경로를 명시적으로 받고 운영 DB에 연결하지 않는다. 결과는 Git 바깥 또는 Git이 무시하는 폴더에만 저장한다. `.env`에서는 OpenAI API 키만 읽는다.

- `--prepare-only`: 목 크롭과 편집/합성 마스크를 로컬에 저장한다. API 호출은 없다.
- `--live`: 모든 컷을 같은 경로로 편집한다. 이미 응답이 저장된 출력 폴더에서는 중복 호출하지 않는다.
- `--responses-dir`: 저장한 목 크롭이 같은 입력인지 확인하고 응답을 재사용해 로컬 합성만 검증한다.
- `--replay-dir`: 최초 수작업의 로컬 작업 정보와 응답으로 합성 코드를 비교한다.
