# 목·옷깃 경계 수리

Qwen 성공 결과 뒤에 `목 경계 띠 크롭 → 결함 문장 → 무마스크 Sunburst → blob 합성 → tone_v4`를 연결한다. 기본값은 `FACE_SEAM_REPAIR=off`, `FACE_TONE_FIX=off`다. 이번 수정은 이전 다각형·마스크·DIS 정렬 경로를 대체한다.

## 처리 흐름

1. 실제 Qwen 생성 마스크의 `unlocked_cells` 경계 ±56px(@1024)에서 얼굴 0.55h~2h 행만 취한다. 이 띠를 감싸는 정사각형에 여유 0.3을 적용한다. 마스크 잠금 미지원 백엔드에서는 기존 Qwen 입력 크롭으로 띠 마스크만 재구성하며 `seam_mask_source`에 구분한다. Qwen 렌더링·합성에는 영향을 주지 않는다.
2. 같은 좌표의 현재/원본 목 크롭을 1024로 확대해 `FACE_SEAM_VISION_MODEL`(기본 gpt-5.4, reasoning high, detail high)에 보낸다. 결함 서술·빈틈 여부·편집 문장만 받고 공간 다각형은 받지 않는다. 결함 0개이고 빈틈도 없으면 지시서의 공통 수리 문장을 쓴다. 빈틈 예이면 결함 목록이 비어도 목 전용 지시를 유지한다.
3. 빈틈이면 여유 0.6, 가로폭 W=3.0을 적용하고 목만 기존 칼라까지 연결하도록 지시한다. 나머지는 여유 0.3, W=0.85다. 파일명 분기나 neck_offset 판정은 없다. neck_offset은 메타로만 남긴다.
4. 지시서 2-3절 HEAD·TAIL을 그대로 사용한다. `images/edits`는 현재 크롭 한 장을 `image[]`로 받으며 **mask와 원본 베이스 이미지를 보내지 않는다**. 모델 gpt-image-2.5-sunburst, high, 1024×1024, PNG, n=1이다.
5. 결과를 원래 크롭 크기로 LANCZOS 축소한다. v8_blob의 큰 API 차이 덩어리와 Qwen 변경부의 합집합을 합성한다. opening으로 얇은 윤곽 잔상을 제거하고 얼굴 피부·크롭 가장자리·가로폭 제한 및 선형 alpha를 적용한다. 흐름 정렬은 없다.
6. tone_v4는 얼굴·귀·목 안의 `피부 ∩ 변경부`만 Lab 이동한다. 원본 몸 피부가 충분하면 그 중앙값, 아니면 원본 얼굴·목 피부를 기준으로 쓴다. L +12/−4, a·b ±2 상한을 적용한다. 톤 범위 밖은 Lab 왕복 변환도 하지 않고 원본 RGB를 그대로 복사한다.
7. 수리 범위 밖 0과 톤까지 포함한 범위 밖 0을 각각 검사한다. 최종 SFace 하락 ≤0.02, PNG 저장·디코딩 일치를 검사한다. 최종 비전은 **메타 기록만 하며**, 부정적 답이나 호출 실패가 수치 통과 후보를 거절하지 않는다.

후처리 context에는 최대 여유 0.6의 목 RGB 크롭만 보존한다. 톤에는 전체 RGB 대신 변경부 boolean 마스크와 Lab 통계만 보존한다. 신원 참조 사진은 로컬 SFace 측정용이며 외부에 보내지 않는다.

## 배선과 폴백

공유 `apply_face_pass` 성공 경로와 `test_cut_build.render_variant` 직접 경로를 사용한다. context 준비·비전 계획·편집·합성 실패 시 성공한 Qwen 결과를 유지한다.

- off: 추가 크롭·API 호출 없음.
- shadow: 후보와 메타를 만들되 Qwen 바이트 반환.
- on: 범위 밖 0·신원·PNG 검사 통과 후보 반환. 최종 비전은 관찰값이다.

정상 완료는 계획 비전 1회 + Sunburst 1회 + 관찰 비전 1회다. 자동 재시도는 없다. 운영 경로는 수치 실패 시 관찰 비전을 생략한다. 이미지 비용·사용량은 기존 `image_usage`의 `face_seam_repair` 단계로 기록한다. 숫자 사용량·지연, 빈틈 판단, 크롭, 프롬프트 해시, 픽셀 수, 신원, 톤 이동을 메타에 남긴다. 사진·키·프롬프트·비전 원문·응답 본문을 운영 로그나 Git에 넣지 않는다.

## 로컬 평가 도구

`server/scripts/evaluate_face_seam_repair.py`는 원본·Qwen·참조·모델 경로를 명시적으로 받는다. `.env`에서는 OpenAI 키만 읽고 DB 기록은 끈다. 이미지 출력은 Git 바깥 또는 Git이 무시하는 폴더만 허용한다.

- `--prepare-only`: 같은 위치의 목 크롭 준비, API 없음.
- `--plan-only`: 12컷 결함·빈틈·문장 사전 평가.
- `--live`: 계획 → Sunburst → blob/tone → 수치 검사 → 관찰 비전.
- `--plans-dir`: 동일한 현재/원본 크롭의 계획 재사용.
- `--responses-dir`: 동일 입력·계획·응답으로 로컬 재합성, API 없음. plans-dir와 동시 사용 금지.
- `--masks-dir`: 저장된 m0 사용. 없는 마스크는 원본에서 재구성하고 출처를 기록한다.
- `--tone`: 로컬 평가에서 tone_v4 활성화. 운영 기본값을 바꾸지 않는다.

응답·계획 덮어쓰기와 출력/캐시 경로 중복을 거절한다. 실제 편집 후에는 원본 해상도의 `before-after-native.png`, 후보, 범위 마스크, 채택 결과를 로컬에 저장한다.

## 이번 12컷 평가 — 사전 조건 미통과

비전 **12회(성공 9, 실패 3), Sunburst 0회**. 그레이 전신·나시 전신·청자켓2 결함을 서술하고 나시 전신은 빈틈 아니오로 판단했다. 그러나 **그레이셔츠_호리존_2도 빈틈 예**여서 “그레이셔츠_호리존만 예” 조건을 위반했다. 스트라이프 3컷은 약 182초 후 `vision_provider_error`로 끝나 문장을 얻지 못했다. 재시도하지 않았다.

위 표는 모델 관찰 결과이며 사람이 확인한 정답이 아니다. 정상 컷에서도 결함을 서술하므로 정상 보존 역시 입증되지 않았다. 저장된 m0는 10컷에 사용했고 스트라이프_1·청자켓1의 마스크는 재구성했다. 성공 9회만의 사용량은 입력 28,935·출력 23,734 토큰이다. 실패 3회의 사용량/비용은 확인할 수 없다.

지시서 4-2·5절의 중단 조건에 따라 **이번 편집·톤 결과, 12컷 수치 게이트, 원본 해상도 결과 검토는 미실행**이다. 사진 없는 [평가 JSON](face-neck-seam-blob-2026-09-17.json)에 세부 수치를 남겼다. 생성 문장 전체 표와 입력 목 크롭은 로컬 평가 폴더에만 있다.

## 검증과 활성화 조건

합성 이미지 기반 회귀: 관련 56개 통과. 백엔드 5,753개 통과·83개 건너뜀(마지막 톤 통합·빈틈 문장 회귀 추가 전); 이후 추가/수정은 관련 56개로 재확인했다. 로컬 PostgreSQL이 필요한 `test_personalization.py`는 제외했다. Python 컴파일·diff 검사 통과. 독립 코드 리뷰에서 발견한 누락 마스크 경로·캐시 출처 혼합·빈틈 문장 누락도 보완했다.

PR은 **Draft, 기본 off**를 유지한다. 아직 시각적 수리 성공이나 새 사진에 대한 일반화를 주장하지 않는다. 사전 조건 통과 → Sunburst 12회 → 원본 해상도 사람 검토 → 실서비스 shadow 20컷 이상 관찰 후 활성화한다. 운영 DB·SSM·매니페스트와 main 병합은 변경하지 않는다.
