# 처리 용량 계산표 + 읽기 경로 부하 실측 (2026-09-22)

발표 Q&A 용 한 장. "동시에 N 명이 컷을 만들면 어떻게 되나" 는 **계산**으로, "그동안 다른 사람 화면이 버티나" 는 **k6 실측**으로 답한다. 돈 드는 경로(컷 생성)는 부하테스트로 치지 않았다 — 병목이 우리 서버가 아니라 프로바이더 한도라 실측해도 답이 안 바뀐다.

## 1. 생성 잡 — 지금 값 (prod, 최근 30일, `scratchpad/job_stats.py` 읽기 전용 SELECT)

| 잡 | n | 완료 | 에러 | p50 | p90 | p95 | 큐 대기 p50 |
|---|---|---|---|---|---|---|---|
| 마네킹컷(컷 5장) | 34 | 25 | 9 (26%) | **66s** | 136s | 156s | 0s |
| 상세페이지(12~15컷) | 23 | 17 | 6 (26%) | **341s** | 433s | 470s | **49s** (Spot 워커 콜드스타트) |

- 30일간 **동시 실행 최대 1** — 사용자가 겹친 적이 없다(하루 1명, 전부 팀 E2E).
- 에러 26% 의 대부분은 `마네킹컷 생성에 실패했어요` 9건 = 얼굴 렌더 파드가 안 뜨던 9/15·9/20 구간(#346 에서 자동 기동 복구). 그 이틀을 빼면 에러 4/47 = 8.5%.
- 운영값: `JOB_CONCURRENCY=1`, `DETAIL_CUT_CONCURRENCY=5`, `DETAIL_WORKER_MAX_TASKS=1`. OpenAI 계정 Tier 1 = **이미지 분당 5장**이라 잡을 병렬로 돌려도 처리량이 안 늘고 서로 뺏는다(8/28 실측, 14컷 중 4컷 429 유실).

## 2. N 명이 동시에 누르면 — 마지막 사람이 결과를 받는 시각

FIFO, 잡 동시성 1. 마지막 사람 ≈ N × p50 (최악은 N × p90).

| 동시 N | 마네킹컷 (지금) | 상세페이지 (지금) | 마네킹 (한도↑·잡 3) | 상세 (한도↑·컷 8·워커 2) |
|---|---|---|---|---|
| 1 | 1.1분 | 6.5분 | 1.1분 | 3.1분 |
| 3 | 3.3분 | 17.9분 | 1.1분 | 6.2분 |
| 5 | 5.5분 | 29.2분 | 2.2분 | 9.3분 |
| 10 | 11.0분 | 57.6분 | 4.4분 | 15.5분 |
| 20 | 22.0분 | 114.5분 | 7.7분 | 31.0분 |

- "지금" 열: 마네킹 66s, 상세 341s + 콜드스타트 49s(첫 사람만).
- "한도↑" 열: OpenAI Tier ≥3 키로 8/27 실측한 값 — 상세 14컷 **186s**(컷 동시성 8), 잡 3개 병렬, 상세 워커 2대. 코드는 다 들어가 있고 env 두 줄(`DETAIL_CUT_CONCURRENCY=8`, `JOB_CONCURRENCY=3`, `DETAIL_WORKER_MAX_TASKS=2`)로 복귀한다. 티어는 누적 결제액으로 자동 상승.
- 한 줄 답: **지금은 실질 동시 사용자 1명. 처리량의 병목은 서버가 아니라 프로바이더 계정 한도이며, 한도가 오르면 코드 변경 없이 3~4배.**

## 3. 읽기 경로 — 잡이 도는 동안 다른 사람 화면이 버티나 (k6 실측)

8/26 장애 유형(동기 이미지 작업이 이벤트루프를 얼려 ALB 헬스체크까지 실패)이 재발하는지 보는 테스트. 비용 0 — GET 만.

```bash
brew install k6
# 무인증 경로만 (healthz · readyz · pricing-plans · 401 경로)
K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=loadtest-report.html k6 run tools/loadtest/read-paths.js
# 셀러 폴링 경로까지 (계정 · 프로젝트 · 마네킹 목록) — 심사용 이메일 계정의 Supabase access_token
TOKEN=… k6 run tools/loadtest/read-paths.js
# 같은 시간창의 서버 쪽 지표 (ECS CPU/메모리 · ALB 응답시간 · 5xx)
tools/loadtest/cloudwatch.sh 2026-09-22T11:00:00Z 2026-09-22T11:05:00Z
```

기본값 3분, 공개 읽기 20 rps + 401 경로 5 rps (+ 인증 폴링 10 rps). `RPS_PUBLIC`·`RPS_AUTH`·`DURATION` 으로 조절. 실행 중 http://127.0.0.1:5665 에 실시간 그래프, 끝나면 HTML 리포트.
