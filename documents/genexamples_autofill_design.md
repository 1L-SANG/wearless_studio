# 콘티보드 생성예시 자동 배정 — 최종 설계 (구현 전 확정본)

> 2026-07-21. 오너 7단계 기준 → Claude·Codex 독립 설계 → 상호 반박 → 통합.
> 상태: **확정** — 오너 결정 4건 반영(2026-07-21), 구현 착수.
> 정본 관계: ADR-0005~0009, documents/genexamples_release_contract.md, 저장 계약 §3.4.

## 1. 화면 동작 (비개발자용)

1. 콘티보드에 들어오면 모든 AI 카드에 **실제 생성예시 사진이 이미 채워져** 있다. 회색 칸 없음. 재진입·새로고침·순서 변경·다른 카드 삭제에도 같은 사진이 유지된다.
2. 카드의 예시를 바꾸는 방법은 두 가지: **갤러리에서 직접 선택**, 또는 **'다른 예시 보기'**(현재 조건 최대 6장 안에서 다음 장으로 순환, 6번째 다음은 1번째, 즉시 저장). 한 장뿐이면 버튼 비활성 + "이 조건에는 다른 예시가 없어요".
3. 사용자가 한 번이라도 만진 카드(직접 선택·다른 예시 보기·참고 범위 변경·샷 변경)는 그 뒤로 시스템이 절대 덮어쓰지 않는다.
4. **풀샷↔중간샷** 변경은 예시 사진을 바꾸지 않는다 — 화면 범위만 바뀐다는 안내와 함께 현재 예시를 '현재 선택'으로 고정 표시하고, 아래 후보 목록만 새 샷 기준으로 갱신한다.
5. **컷 종류 변경**(컷 탭 / 제품의 고스트↔디테일): 카드를 먼저 바꾸지 않는다. 새 컷의 예시 목록을 선택창으로 먼저 보여주고, 사용자가 한 장을 고르는 순간 컷·샷·예시가 **한 번에** 바뀐다. 예시 없는 카드 상태는 어떤 중간 단계에도 존재하지 않는다. (예시 재클릭으로 선택을 해제해 빈 상태로 만드는 기존 동작은 제거.)
6. 오류는 정직하게: 카탈로그·썸네일·저장 실패 시 "…하지 못했어요" + [다시 시도]. 'AI 자동 포즈' 등 자동 배정을 위장하는 문구 금지. 공개 예시가 없는 조합(예: 원피스)은 컷·샷 선택지 자체를 비활성화한다.

## 2. 블록 저장 상태값 (저장 계약 §3.4 확장)

- `exampleId`(기존): 자동 배정 완료 후 `source='ai'` 블록에서 사실상 필수.
- **신규 `exampleSelectionOrigin: 'auto' | 'user' | null`** (명명: `source`와 혼동 방지)
  - 자동 배정 시 'auto'. 다음 4가지 행위 시 'user': 직접 선택 / 다른 예시 보기 / 참고 범위 변경 / 샷·컷(제품 고스트↔디테일 포함) 변경 확정.
  - 소급: exampleId가 있는데 origin이 없는 저장분은 **'user'로 간주**(절대 안 덮어쓰는 방향으로 오판).
  - 서버 canonicalize: enum 검증, exampleId 없으면 null 강제. **exampleId를 지우는 모든 기존 경로(레시피 정규화·섹션 이동 등)에서 origin·thumb도 동반 정리**(고아 값 금지).
- **기본 콘티 지문(fingerprint) 규칙**: `origin='auto'`인 exampleId는 기본값으로 간주(지문 제외), `'user'`만 사용자 수정으로 취급 — 자동 배정만으로 "수정된 콘티"로 오판돼 사진 양 전환 재시드가 막히는 것 방지. mock의 storyboardDirty도 동일 규칙(자동 배정 저장은 dirty 아님).
- 선택창의 임시 상태(pendingCutType·후보 목록·저장 중·오류)는 화면 로컬 — 블록·스토어에 저장하지 않음.
- 구조 필드(sectionId·sectionLayout·layoutRowId·배열 순서)는 자동 배정이 절대
  변경하지 않는다. `spaceGroupId`는 발행된 정식 촬영 세트를 선택하거나 기본
  콘티가 정식 세트를 시드할 때만 별도 세트 로직이 만든다.

## 3. 자동 배정 알고리즘

**후보 자격**(방향은 조건이 아님 — 방향은 카드 설정이 생성에 적용):
```
eligible(block, product, gender):
  카탈로그 존재(= 공개) && variants에 'all'
  && cutType == block.cutType && shot == block.shot   # 최초 배정 시점 기준
  && product.clothingType ∈ applicableClothingTypes
  && (제품컷 ? example.gender == null : example.gender == 분석 성별)
  && (정식 촬영 세트 멤버 ? pose variant 발행 && 방향 호환 : true)
```

**배정**(결정적 — 같은 입력이면 항상 같은 결과):
```
1패스: 기존 블록 집계 — origin='auto'이고 ID가 현 상위3 안이면 해당 슬롯 사용량 +1
2패스: 문서 순서대로, source='ai' && exampleId 없음 && origin 없음 인 카드만
  seq  = 현행 갤러리 표시순(무드·디테일부위 라운드로빈 — selectGenerationExamples 재사용)
  pool = seq 앞 3장 (3장 미만이면 있는 만큼)          # '품질 상위 3'의 임시 정본 — 하단 결정 C
  slot = 조건키(cutType:shot:의류:성별 — 무드 제외)별 사용량 최소 슬롯(동률이면 1→2→3)
  배정: exampleId=pool[slot], origin='auto', thumb=카탈로그 썸네일
  후보 0장이면 미배정 — 해당 조합은 UI 비공개 대상(§5)이므로 정상 흐름에선 발생하지 않아야 함
저장: 전용 await 저장(1.5초 자동저장 재사용 금지 — 지연·실패무시 부적합). 표시는 낙관적으로 즉시,
  저장 실패 시 카드 위 배너 "변경 내용을 저장하지 못했어요" + 재시도(배정이 결정적이라 재계산해도 동일 값).
실행 계기: 진입 시 1회 + 새 블록 추가 시 그 블록만. 재렌더·순서변경·삭제·재진입은 계기 아님.
```

## 4. 컷·샷 변경 상태 흐름

- **샷(full↔medium)**: `{shot 변경, exampleId 유지, origin='user'}` 단일 패치. 현행 코드의 exampleId:null 두 경로(onShotChange의 초기화 + 후보 밖 ID를 지우는 effect)는 **제거**. 서버도 착용컷 예시 shot과 카드 shot 불일치를 거부하지 않음(프레이밍은 카드가 정본 — ADR-0009).
- **컷(탭) / 제품 고스트↔디테일**: 2단계 — ①pendingCutType만 로컬로 들고 새 조건 최대 6장 제시(블록 불변) ②선택 시 `{cutType, shot, 파생 contentRole, exampleId, refScope, origin='user', thumb}` 단일 블록 패치 → blocks 전체 1회 PUT(현행 저장이 원자적 — 신규 엔드포인트 불필요). 실패 시 기존 카드·선택창 유지 + 오류·재시도.
- **참고 범위**: '포즈만' 전환 시에만 방향 호환 게이트(#34) 적용(기존 구현). 자동 배정은 all이므로 무관(같은 공간 제외 — §3 자격에서 처리).
- **섹션 이동**: 이동 후에도 cutType이 대상 섹션에서 허용되면 예시 유지, 컷이 바뀌어야 하면 컷 전환 흐름으로.
- **삭제 취소**: 삭제 전 스냅샷의 exampleId·origin 그대로 복원.

## 5. 공개 전 누락 검사 (커버리지)

- 정본 도구 = release_genexamples.py에 커버리지 검사 추가. 검사 축: 구조(컷×샷×적용의류) + 착용 실사용(＋성별). 방향은 어느 게이트에도 불포함. 'all' 발행분만 집계.
- **게이트 규칙(절충 확정)**: 릴리스 매니페스트에 **공개 선언 조합표**를 포함하고, ①선언된 조합이 0장이면 hard fail(오너 1단계 — 데이터 결함) ②미선언 조합은 리포트만 + **UI에서 해당 컷·샷 선택지 비활성**(= "서비스에 공개하지 않는다"의 구현). 전 조합 hard fail은 현 실측(실사용 56조합 중 29개 0장, 상위3 미달 6개)에서 릴리스 자체가 불가하므로 기각.
- CI: 커밋된 카탈로그·레지스트리 두 JSON에 같은 커버리지 검사 pytest 추가(기존 parity 테스트 옆).
- 현 실측 기준 공개 선언 1안: 착용 top·bottom(여·남) + 제품 ghost·detail(top·bottom) — 아우터·원피스·거울 일부는 미선언(비활성). 시드 필수 조합이 미선언에 걸리는 카테고리는 상품 등록 단계에서 안내.

## 6. 기존 프로젝트 처리

- 마이그레이션 배치 없음(위험: 사용자 선택 오인·임의 교체). 진입 시 처리만:
  ①ensureSections 정규화 → ②mine 제외 → ③exampleId 있는 카드는 절대 재배정(origin 없으면 'user' 소급) → ④exampleId·origin 모두 없는 AI 카드만 현 cutType·shot 기준 배정 → ⑤전용 저장.
- 저장된 exampleId가 카탈로그·레지스트리에서 사라진 경우: 자동 대체 금지(안정 ID 영구 계약) — "저장된 예시를 불러오지 못했어요" + 재선택 유도. 서버 저장 검증은 `unknown` ID를 허용하지 않음(존재·적용 의류·컷 일치·성별 검증, 방향·샷 불일치는 허용).
- HTTP 최초 시드가 배정 전에 PUT되는 순간의 "예시 없는 콘티" 공백: 시드 생성 시점에 배정을 포함(시드→배정→첫 PUT 순서)으로 봉합.
- 상품 의류·성별이 이후 단계에서 바뀌어 기존 예시가 부적용이 되는 경우: 자동 교체하지 않고 카드에 "조건이 바뀌어 예시를 다시 골라주세요" 표시(서버는 생성 시 기존 규칙대로 안전 생략+경고).

## 7. 테스트·예외 목록 (필수)

- 후보 필터: 컷·샷·의류·성별·공개만 작용, 방향 무영향, matchIds 무영향, 제품=성별 null
- 순환: 동일 조건 6카드 1,2,3,1,2,3 / 기존 auto 배정 사용량 포함 집계 / 조건키 독립 / 1~2장 조건은 N장 순환 / 스타일링 무드 분산(조건키 무드 제외 확인)
- 고정성: 재진입·재렌더·순서변경·삭제 후 ID 불변 / 삭제 취소 복원 / 배정 결정성(같은 입력=같은 결과)
- 사용자 보호: 4가지 행위 각각 origin='user' / 재클릭 해제 경로 부재 / 이후 자동 배정 제외
- 지문: auto 배정만 있는 콘티 = 기본 콘티 판정(사진 양 전환 재시드 정상) / user 선택 있으면 수정 판정 / mock storyboardDirty 동등 규칙
- 샷·컷 전환: 샷 변경 예시 유지(기존 null 경로 2곳 제거 회귀 테스트) / 컷 전환 원자성·중간 상태 부재 / 저장 실패 시 원상 유지
- 정식 촬영 세트: pose+방향 호환 후보만 배정 / 0이면 미배정+명시 표시 /
  무음 all 강등 금지 / 임의·미등록 group ID 거부
- 커버리지: 선언 조합 0장 hard fail / 미선언 리포트·UI 비활성 / CI 커버리지·parity
- 서버 저장 검증: 미존재·부적용·컷 불일치 거부, 방향·샷 차이 허용, 원자 PUT
- 오류 표시: 카탈로그/썸네일/저장 실패 각각 오류+재시도, 'AI 자동 포즈' 문구 전무(grep)
- 구조 회귀: 배정·전환 전후 구조 필드·run 불변
- 프론트 로직은 순수 모듈로 분리해 node --test로 검증(상호작용은 브라우저 스모크)

## 오너 결정 (2026-07-21 확정)

- **A. 복제 카드 = 예시 유지** (원본의 exampleId·origin 그대로 복사 — 복제 의도 존중).
- **B. '품질 상위 3' = 현행 갤러리 표시순 앞 3장을 임시 정본으로 시작.** 릴리스 계약의 공식 자동 배정 순위 필드는 후속(생성 세션 합의 시).
- **C. 공개 선언 조합표: 메커니즘 구현 + 1안(착용 top·bottom 여·남, 제품 top·bottom)으로 시작.** 목록 확장은 오너가 직접 편집(선언표는 오너가 고치기 쉬운 데이터 파일로).
- **D. 같은 공간 = 방향별 pose 자산이 존재한다는 전제로 설계·구현.** 부족분은 166 확장에서 방향 커버 우선 생산(생성 세션 전달). UI에는 예시의 방향 표기(예: '뒷모습')를 라벨로 노출해도 좋음 — 갤러리 예시 셀·현재 선택에 방향 뱃지 표시 채택.
