# 협찬 법무 개정 실행 계획

> 법률 검토 전 초안이에요. 기준 작업지시서는 `documents/facemarket_sponsorship_legal_brief_20260922.md`이고, 지정 워크트리의 기준 커밋은 `8c802365`예요. 실행은 이 세션에서 직접 진행해요.

목표는 제품 사실을 바꾸지 않고 선택 협찬의 동의, 개인정보, 계약 경계를 정하고 검토 가능한 문서와 코드 초안을 만드는 것이에요.

## 작업 단위

1. 문서와 판단 근거를 작성해요. 00 조건표, 01·03·04·06 본문, 02·05 v3 델타, 공개 FAQ를 정리하고 커밋을 시도해요.
2. 동의 유형과 버전은 `DRAFT_` 상수로 분리해요. 자동 적용 디렉터리 밖에 새 SQL 초안을 두고 실제 등록·프로필·VC 배선은 하지 않아요. 테스트가 없는 상수와 발행 동작은 실패를 먼저 확인한 뒤 구현해요.
3. 발행기로 공개 검토본을 만들어요. 02·05 v1과 v2는 보존하고 v3 델타는 별도 공개 검토 파일로 만들어요. 협찬 개정본은 초안 표시, 미확정 시행일, 별도 버전을 유지해요. B-1·B-2 손 이식 공개본은 내용이 바뀌지 않으므로 유지해요.
4. 지정한 pytest로 서버 전체를 검사하고 발행 관련 테스트와 broken_bold 검사를 실행해요. 결과 원문을 마지막 보고서에 넣고 작업 단위별 커밋 결과를 기록해요.

## 설계 판단

- E-2 안에서 참여 토글, 수집·이용 체크, 협찬 프로필 제공 체크, 요청별 배송정보 제공 체크를 구분해요. 마지막 체크는 실제 셀러가 정해지는 후속 요청 단계에서 받아요. 배송 동의는 요청 수락이 아니에요.
- 화면 지시서의 협찬 프로필 노출에도 제3자 제공 근거가 필요해요. 비로그인 대중에게 인스타 계정·팔로워·사이즈를 공개하는 것은 이번 동의에 포함하지 않아요. 화면 트랙과 통합할 때 범위를 확인해요.
- 토글을 끄면 신규 요청이 중단되고 협찬 프로필은 내려가요. 기본 프로필 정보는 파기하며 진행 중 계약 이행에 필요한 최소 정보와 법정 증빙은 구분해요. 화면 지시서의 `off면 저장값 유지`와 충돌하므로 이 법무 초안 기준으로 조정이 필요해요.
- 협찬은 현금이 없지만 게시 의무와 교환되는 현물이에요. 비과세·순수 증여라고 단정하지 않고 세무 검토를 남겨요.
- 광고 표시 근거는 2026년 개정 지침의 Ⅴ.6이에요. 종전 Ⅴ.5를 그대로 인용하지 않아요.
- 소속사 서면 동의를 허용하는 기존 B-6을 협찬 자격으로 원용하지 않아요. 협찬에는 성인·소속 에이전시 없음·본인 참여를 다시 명시해요.
- 협찬 연결만으로 우회 거래 제한을 확대하지 않아요. 반송을 일반적 선택지로 새로 만들지 않고, 토글을 끄기 전 유효 요청은 진행하며 하자·미배송·권리 침해는 별도 구제 대상으로 둬요.
