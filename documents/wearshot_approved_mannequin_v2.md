# 승인 마네킹 기반 착용컷 v2

`approved_mannequin_v2`는 생성·수정·검수가 같은 이미지 근거를 보도록 연결한 선택적 경로다. 기존 `generic_v1`, 해시 고정 `confirmed_gpt_v1` 템플릿과 기본 모델을 대체하지 않는다. 이 문서는 코드 계약 설명이며, 배포 완료나 생성 품질 100% 보증을 뜻하지 않는다.

## 무엇을 기준으로 보는가

| 입력 | 권한 | 가져오면 안 되는 것 |
| --- | --- | --- |
| 선택한 색감 조정 마네킹 | 해당 의류의 색·착용 핏·상대 기장·여유·실루엣·밑단 낙하 | 셀러 근거에 없는 새 봉제 구조 |
| 해당 의류 셀러 이미지 | 영구 구조·소재 조직·봉제선·부자재·필수 디테일 | 검증되지 않은 정확한 착용 기장 |
| 선택 얼굴·신체 시트 | 모델 외형·신체 비율 | 시트 안 옷의 색·기장·밑단 |
| 생성예시 | 카메라 거리·큰 구도·크롭·동작 의미·장소와 빛 | 예시 안 의류의 핏·기장·밑단 쌓임 |
| 촬영 질감 참조 | 카메라의 미세 선명도·샤프닝 표현 | 상품색이나 원단 구조 변경 |

상의와 매칭 하의에 각각 적용한다. 매칭 의류도 별도 선택 마네킹이 필요하다. 기존 합성 마네킹을 공유하는 경우는 원본 생성 메타데이터의 정확한 `matchItemId` 연결이 있을 때만 허용한다. 임의 업로드 이미지나 단순 상품 분류가 마네킹 승인 증거가 되지는 않는다.

상품 디테일은 분석 단계의 `hardFacts`와 정확한 `evidenceOrdinals`를 유지한다. 모든 상품에 중앙선이나 특정 밑단 모양을 강제하는 공통 규칙은 없다. 매칭 상품에 별도 분석 디테일 계약이 없으면 이를 발명하지 않으며, 셀러 이미지 기반 구조·소재 검사는 여전히 수행한다.

## 생성과 수정

1. API에서 선택한 마네킹·매칭·모델·예시와 근거를 고정한다. 작업이 실행되기 전에 선택이나 근거가 바뀌면 다시 확인하도록 보류한다. 작업 대기 중 새 색감 조정본이 생겨도 기존 요청의 마네킹을 몰래 교체하지 않는다.
2. 동일한 불변 계약과 원본 이미지들로 1차 생성한다. 이 경로에 셀러 색만 기준으로 하는 별도 best-of를 끼워 넣지 않는다.
3. 전체 v2 QC와, 얼굴이 보이는 경우 선택 얼굴·원본 인물·결과만 보는 추가 얼굴 검수를 수행한다. 헤어가 닮았다는 이유만으로 얼굴이 바뀌었다고 통과시키지 않는다.
4. 실패한 항목이 있다면 검증된 1차 기준본과 원본 근거를 함께 넣어 최대 한 번 수정한다. 정상이라고 검증한 항목만 보호하며, 얼굴이 마음에 든다는 이유로 잘못된 바지 밑단까지 고정하지 않는다.
5. 수정 후 근거 일치와 보호 항목 보존을 모두 확인한다. 디테일·기장·색·최소 변주·얼굴 등이 실패하면 실패한 1차본을 최종 이미지로 저장하지 않는다.

최종본은 생성예시와 비교해 작은 자연스러운 포즈 또는 배경 변주가 있어야 한다. 둘 다 그대로인 결과는 통과시키지 않는다. 카메라 거리·큰 구도·크롭은 유지한다. 이미 변주된 기준본의 질감 수정에서 추가 변주를 반복할 필요는 없다.

목 위로 잘린 컷에서 얼굴을 만들게 하거나, 화면 밖 바지 밑단을 검사하기 위해 전신으로 넓히지 않는다. 검증된 예시 범위에서 보이지 않는 항목은 `NOT_APPLICABLE`이며, 이는 그 항목이 정확하다고 확인했다는 뜻이 아니다. 근거 이미지 누락은 별개의 오류다.

## 클린 스냅 / 소프트 스냅

- `clean` / 클린 스냅: 자연스러운 휴대폰 선명도와 절제된 샤프닝. 스튜디오·HDR처럼 과장된 보정은 목표가 아니다.
- `soft` / 소프트 스냅: 구형 휴대폰처럼 미세 대비와 샤프닝을 약하게 표현하되, 실제 초점과 얼굴·헤어·원단 구조를 유지한다. 전체 블러나 색 필터가 아니다.

질감만 수정할 때는 상품색을 바꿀 권한이 없다. 상품색 자체가 틀린 경우에는 해당 마네킹을 기준으로 색을 바로잡는다. 조명이 틀린 경우 인물과 장소를 함께 자연스럽게 맞출 수 있지만, 이 과정에서도 상품색 검사는 생략하지 않는다.

v2 기본 캔버스는 긴 변 2048픽셀이다. API의 16픽셀 단위 때문에 원본 비율과 최대 0.5% 상대 오차를 허용한다. 큰 비율 왜곡은 보류하며, 반환된 실제 크기는 요청 크기와 정확히 일치해야 한다. 사후 크롭·리사이즈로 맞추지 않는다.

## API 사용과 적용 범위

기존 요청처럼 본문을 보내지 않으면 기존 경로가 유지된다. 새로운 요청 예시는 아래와 같다. 식별자와 UUID는 실제 선택값으로 바꿔야 한다.

```json
{
  "contractVersion": "approved_mannequin_v2",
  "matchingMannequinAssets": {
    "selected-matching-id": "00000000-0000-0000-0000-000000000001"
  },
  "variationAxis": "background",
  "captureProfile": "soft"
}
```

기존 `POST /v1/projects/{project_id}/detail-page:generate`를 사용한다. 추가 임의 프롬프트 필드는 허용하지 않는다. 예전 결과가 이미 있거나 다른 조건으로 실행 중인 작업이면 기존 결과를 새 방식으로 처리한 것처럼 반환하지 않고 409로 충돌을 알린다. 기존 파일을 지우지는 않는다.

초기 서버 적용 범위는 가상 모델·정면 styling·전체 예시 참조·기준색이다. 다음 다섯 예시에 해시 고정된 노출 범위를 추가했다.

- `ex_styling_women_top_full_snapshot_03`
- `ex_styling_women_top_medium_snapshot_01`
- `ex_styling_women_outer_medium_cafe_01`
- `ex_styling_women_dress_full_home_01`
- `ex_styling_women_dress_full_city_03`

다른 예시·실존 모델·horizon/mirror 유형·추가 색상 등을 지원한다고 가장하지 않고 사전 보류한다. 의류별 규칙이 이 다섯 사진에 하드코딩된 것은 아니다. 공통 계약은 범용이며, 서버에서는 검증된 예시 범위부터 선택적으로 사용한다. 프런트엔드 선택 UI 추가와 전면 배포는 별도 단계다.

생산 환경의 생성 모델 라우팅은 기존처럼 실행 시점 서버 Settings를 사용한다. 불변 근거 계약이 서버 운영 설정 전체를 고정한다는 의미는 아니다. 이번 변경은 전역 모델을 바꾸지 않는다. `WEARSHOT_QC_MODEL`은 v2 검수 모델, `WEARSHOT_REPAIR_MODEL`은 선택적 2차 수정 모델 설정이다. 비교 실험은 이와 별도로 양쪽의 모델·코드·입력·수정 지시를 고정한다.

v2 검수는 `WEARSHOT_QC_TIMEOUT_SECONDS`로 별도 제한 시간을 사용하며 기본 180초다. 기존 `ANALYSIS_TIMEOUT_SECONDS`의 30초 기본값은 바꾸지 않는다. 실제 기준본 검수에서 본 검수 39초·추가 얼굴 검수 12초가 걸려 기존 30초 제한에 걸리는 사례를 확인했다. 제한 시간 초과와 공급자 오류는 시각적 불합격과 구분해 기록한다. 로컬 비교 manifest의 `qcTimeoutSeconds`도 입력·모델과 함께 고정한다.

## Sunburst 비교 도구

`server/app/experiments/wearshot_repair_ab.py`는 실제 `cut_generator.repair`와 공통 검수를 호출한다. 두 모델은 `gpt-image-2`, `gpt-image-2.5-sunburst-2026-09-08`로 제한하며, 기본 동작은 호출·쓰기 없는 드라이런이다.

기준본 QC → 단일 모델 수정 → 수정본 QC가 분리된다. 같은 원본·마네킹·모델·근거 순서·수정/보호 항목·프롬프트·해상도·medium 품질을 사용하고 모델만 달라진다. 완료·실패·응답 불명확 실행 기록은 덮어쓰거나 자동 재전송하지 않는다. 실제 접근 거부를 다른 모델로 대체하지 않는다.

로컬 실험의 명시적 사용자 피드백은 자동 QC와 구분해 기록할 수 있다. 자동 QC가 놓친 실패를 추가할 수 있지만, 자동 검수에서 실패한 항목을 기계 PASS로 바꾸거나 그 근거 없이 보호할 수는 없다. 실제 비교 결과와 시각적 품질은 실행 후 별도로 보고해야 한다.
