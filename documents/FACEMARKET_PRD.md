## 1. FaceMarket 이 뭔가

셀러가 AI 컷을 만들 때 쓰는 **모델 얼굴의 공급·권리 계층**이다.

기존 스튜디오는 가상 모델(정적 3명)로 컷을 만들었다. FaceMarket 은 **실존 인물이 자기 얼굴을
등록하고, 사용 조건을 담은 라이선스를 발급받고, 셀러가 그 얼굴로 컷을 만들면 정산되는** 구조를
얹는다. 얼굴은 생체정보라 일반 이미지와 같은 규칙으로 다룰 수 없고, 그 제약이 이 제품의 화면과
플로우 대부분을 결정한다.

권리 증명은 **W3C VC**(Verifiable Credential)로 발급하고 **OmniOne Chain** 에 앵커한다.
QR 하나로 누구나 무인증 검증할 수 있다.

### 도메인이 둘로 나뉜다

| 도메인 | 역할 | 근거 |
|---|---|---|
| `facemarket.wearless.kr` | **모델 등록 전용.** 얼굴을 제공하는 사람이 오는 곳 | `src/lib/host.js` `IS_FACEMARKET` |
| `ai.wearless.kr` | 셀러 스튜디오. 모델 등록 메뉴는 **숨긴다** | `src/features/shell/shell.jsx:190` |

같은 코드베이스·같은 API 를 쓰고 호스트로만 갈린다. 로컬에서는 `?facemarket=1` 로 강제한다.

## 2. 사용자 3종

| 사용자 | 어디서 | 무엇을 한다 |
|---|---|---|

## 3. 핵심 개념 4개

```
등록(enrollment)  얼굴을 올리고 본인임을 증명하는 1회성 절차. 통과하면 모델이 생긴다.
모델(model)       셀러 카탈로그에 노출되는 사람. 등록 하나에 결속된다.
라이선스(license) 그 얼굴을 어떤 조건으로 쓸 수 있는지. 등록당 1건.
VC                라이선스를 담은 검증 가능한 자격증명. 체인에 앵커된다.
```

**등록 → 모델 → 라이선스 → VC** 가 한 줄로 이어진다. 재등록하면 이 줄이 통째로 새로 생기고,
이전 것은 갈아탄 것으로 정리된다(§7.4).

## 5. 등록 위저드 — 7단계

`src/features/model/ModelRegister.jsx`. 화면 상단에 진행 레일(`동의 · 신분증 · 사진 · 체형 ·
대표 · 라이브 · 완료`)이 늘 보인다. 순차 KYC 라 번호 마커가 의미를 갖는다.

### STEP 1/7 — 생체정보 처리 동의
- 필수 2건(수집·이용, 국외 이전) + 선택 1건(AI 학습)
- 동의 문서 버전을 저장한다(`BIOMETRIC_CONSENT_VERSION = "2026-08-v2"`). 직전 버전도
  수락한다 — 프런트(Vercel)·백엔드(CI) 배포 시점이 어긋나는 동안 등록이 막히지 않게
- 만 14세 미만 차단 고지
- 법정 고지 링크: 보관 기간 · 제3자 제공 · 국외 이전

### STEP 2/7 — 모바일 신분증 본인 확인
- RaonSecure **OACX** 표준인증창(ENT_MID)을 `#oacxDiv` 에 띄운다
- 성공하면 토큰 + **신분증 초상**(`data.dlphotoimage`, HEX JPEG)을 받는다
- 초상은 **메모리(ref)에만** 둔다. localStorage·sessionStorage·로그 금지
- 서버는 CI 를 HMAC-SHA256(pepper) 해서 저장한다. 원문 CI 는 저장하지 않는다
- ⚠️ 현재 prod 는 us-east-1 이고 OACX 는 한국 IP 전용이라 해외 IP 에서 실패한다(§12)

### STEP 3/7 — 얼굴 사진 3장
`src/features/model/ModelFaceUpload.jsx`. 순서 고정: **정면 → 45도(반측면) → 측면(옆모습)**

- 각 슬롯에 **촬영 예시 사진**이 붙는다(`/models/pose/{front,angle45,side}.webp`).
  파일이 없으면 라인 일러스트로 자동 폴백. 예시엔 "예시" 뱃지를 단다 —
  바로 위에 사용자가 올린 사진이 뜨기 때문에 구분이 필요하다
- 업로드하면 **그 사진을 되보여준다**. 서버가 격리 사진 바이트를 내주지 않으므로
  브라우저 로컬 objectURL 로 만든다. 새로고침하면 사라지고 "업로드 완료" 표시로 돌아간다
- 아이폰 HEIC 는 브라우저에서 JPEG 로 변환한 뒤 올린다(서버·QC 가 HEIC 를 못 읽는다)
- 업로드는 **직렬화**한다. 백엔드 photo-fence 가 등록 스코프라 동시 요청을 막는다
- QC 실패 사진도 화면에 남긴다 — 무엇을 다시 찍을지 알아야 한다

### STEP 4/7 — 체형·키 (선택, 건너뛰기 가능)
- **키**: 성별별 6구간. 값 접두사(`m_`/`f_`)가 성별을 스스로 인코딩해서 성별 없이도 저장된다
- **체형**:
  - 여성 — **볼륨 × 실루엣 매트릭스**. 행=여리여리/마름/보통/통통, 열=기본/상체 볼륨/골반 볼륨/상하 볼륨.
    행마다 가로 스크롤 사진 카드. 15장(통통·상하 볼륨은 시각적으로 안 갈려서 뺐다)
  - 남성 — 5종 사진 칩(마름·보통·잔잔한 근육·벌크업·통통)
  - 성별 미상 — 텍스트 칩 7종
- 값은 서버 enum 과 문자 그대로 일치해야 한다. 프롬프트에 자유문자열을 절대 방출하지 않는다
- **'이전' 링크**로 사진 단계로 돌아갈 수 있다

### STEP 5/7 — 대표 이미지 (선택, 건너뛰기 가능)
- 셀러 카탈로그 카드에 쓸 이미지
- 고르면 **4:5 프리뷰**로 먼저 보여주고 "이 사진으로 할게요"를 눌러야 올라간다.
  "다시 고르기"로 취소 가능. 카탈로그 카드와 같은 비율이라 잘릴 모습이 미리 보인다

### STEP 6/7 — 라이브 얼굴 확인
- AWS Rekognition **Face Liveness**(us-east-1 고정). 브라우저가 임시 자격증명으로 직접 호출
- nonce 재사용을 차단한다(등록 간 전역 유일)
- 서버 설정으로 끌 수 있다(`fm_liveness_enabled`). 끄면 신분증 초상이 매칭 앵커가 된다

### 처리 중 — 매칭·자산 생성
- 신분증 초상 ↔ 라이브 프레임(신원 앵커) → 임계 `0.25`
- 업로드 사진 ↔ 앵커 → 임계 `0.15`, **측면만 `0.10`**(§9)
- 통과하면 모델 자산(face_front, grid_sedcard)을 만든다. 이 화면은 닫았다 열어도 이어진다

### STEP 7/7 — 완료
- `모델 정보 등록 완료` + CTA **`VC 발급 하러 가기`** → `/model/license`
- 카드가 뷰포트 세로 중앙에 선다

## 6. 상태 머신

### 등록(enrollment)
```
identity_pending → photos_pending → liveness_pending → processing
                 → asset_building → license_pending → vc_pending → passed
실패 경로: failed(사유 기록) · cancelled(사용자 취소) · expired(24h TTL)
```
- TTL 24시간. 만료 스윕은 **앞 4단계만** 정리한다. `license_pending` 이후는 만료시키지 않는다
- 사용자당 진행 중 등록은 1건(부분 유니크 인덱스)

### 모델(model)
```
pending → verified → (재등록 시작) reverification_required → verified
```

### 라이선스(license)
```
pending → active → revoked | expired | reverification_required
```

**전이 규칙 3개가 화면에 직접 드러난다:**
1. 새 등록을 시작하면 기존 `active` 라이선스가 `reverification_required` 로 강등된다
2. 새 라이선스가 활성화되면 같은 모델의 옛 `reverification_required` 라이선스는 `revoked` 가 되고
   그 VC 는 폐기 큐에 들어간다
3. 목록에는 `revoked` 를 보여주지 않는다 — 행은 이력으로 남는다

## 7. 라이선스

### 7.1 조건 항목
| 항목 | 형태 |
|---|---|
| 허용 브랜드 유형 | 다중 선택 |
| 금지 브랜드 유형 | 다중 선택 |
| 단가 | 셀러가 1회 사용할 때마다 지불하는 금액 |
| 유효기간 | 일 단위(기본 365) |

### 7.2 발급
1. 라이선스 행을 `pending` 으로 생성(등록당 1건 유니크)
2. 등록을 `vc_pending` 으로 전이
3. **fm-holder** 에 순서대로: 지갑 생성(`409` 허용=이미 있음) → DID 등록 → VC 발급
   - 멱등키 `fm-license:{license_id}` 를 함께 보낸다
4. 성공하면 같은 트랜잭션에서 라이선스 `active` + 모델 `verified` + 등록 `passed`
5. 실패는 `vc_issue_delayed` 로 돌려주고 클라이언트가 **8초 간격 최대 4분** 자동 재시도한다

### 7.3 대기 UX가 인프라 때문에 존재한다
holder 는 평소 **0대**(scale-to-zero)고 콜드부트가 **~2분**(JVM 4개)이다. 그래서:
- 첫 사진 업로드 시점에 holder 를 미리 깨운다(사진 3장에 3분 이상 걸리므로 부팅이 가려진다)
- 그래도 늦으면 발급 버튼이 "발급 준비 중… 최대 3분 걸릴 수 있어요"로 바뀐다
- 유휴 30분이면 다시 0대로 내려간다

### 7.4 VC 카드와 공개 검증
- 앞면: 얼굴 + 마스킹된 신원 + VC ID + 용도 + 단가 + 유효기간 / 뒷면: QR
- QR → `{origin}/verify/{licenseId}`
- **공개 검증 페이지는 얼굴을 렌더하지 않는다.** 서버 응답 화이트리스트에 얼굴·digest·CI·
  생년월일·user_id·model_id 가 애초에 없다

### 7.5 폐기
- 사용자가 폐기하거나, 갈아타서 죽거나, 재검증 배치가 무효화하면 **폐기 큐**에 잡이 쌓인다
- 워커가 holder 에 verify → revoke → verify 순으로 확인하고 종결한다
- 실패는 지수 백오프(최대 5분)로 재시도, **50회를 넘기면 `dead` 로 빼고 경고 로그**를 남긴다

## 9. QC·매칭 정책

### 사진 품질(업로드 시 즉시, 차단)
| 코드 | 의미 |
|---|---|
| `occlusion` | 얼굴이 가려짐 |
| `low_resolution` | 흐리거나 작음 |
| `multiple_faces` | 여러 명 |
| `angle_mismatch` | 선택한 칸과 얼굴 방향 불일치 |

Gemini → GPT 폴백. 판정 불가면 **503 으로 막는다**(검증 안 된 얼굴을 저장하지 않는다).
45도·측면 슬롯에는 "고개를 돌려 한쪽 눈이 안 보이는 건 정상"이라는 지시를 프롬프트에 덧붙인다 —
안 그러면 자연스러운 self-occlusion 을 가림으로 오탐한다.

### 얼굴 매칭 임계
| 대상 | 임계 | env |
|---|---|---|
| 신분증 초상 ↔ 라이브 프레임 | `0.25` | `FM_ID_LIVE_THRESHOLD` |
| 업로드 사진 ↔ 앵커 (정면·45도) | `0.15` | `FM_RETOUCHED_LIVE_THRESHOLD` |
| 업로드 사진 ↔ 앵커 (**측면**) | `0.10` | `FM_SIDE_LIVE_THRESHOLD` |

측면을 따로 두는 이유: 정면 인식기(YuNet+SFace)는 측면에서 유사도가 구조적으로 낮다.
실측 — 같은 사람인데 정면 0.1806 / 45도 0.2605 / **측면 0.14825**. 공통 임계 0.15 를
쓰면 측면만 0.0017 차이로 떨어져 **등록 전체가 실패**했다(2026-09-01, 3회 반복).

검출된 사진은 **전부** 임계를 넘어야 하고, 최소 1장은 매칭돼야 한다(스왑 방지).

## 10. 프라이버시 하드룰

이 규칙들이 화면 설계를 직접 제약한다. 디자인 리뉴얼에서도 깨면 안 된다.

1. **얼굴은 공개 URL 을 갖지 않는다.** 항상 Bearer fetch + objectURL
2. **공개 검증 페이지에 생체정보 0픽셀.** 무인증이라 렌더한 건 전부 공개된다
3. 업로드 사진은 **격리(quarantine)** 상태로 저장되고, 통과 후에만 승인 상태가 된다
4. 신분증 초상은 메모리에만. 저장·로그 금지
5. CI 는 HMAC 해시로만 저장
6. QC 로그에 이미지·파일명·랜드마크 금지 — 판정·사유코드·provider 만
7. 동의문 용어(`생체정보 처리 동의`)는 버전 계약이라 임의로 못 바꾼다

  `/settlements/{payment_id}/confirm` · `/jobs/{job_id}/settlement`
- 서명 인텐트를 먼저 기록하고 체인 결과를 미러링한다. 재조정 루틴이 미완료 인텐트를 회수한다

## 12. 현재 상태

### 살아 있는 것
- 등록 7단계 전체(동의·OACX·사진 3장·체형·대표이미지·라이브니스·완료)

- 폐기 파이프라인(워커·백오프·dead 종결)
- opendid 온디맨드(scale-to-zero + 프리워밍)

### 알려진 제약
| 항목 | 내용 |
|---|---|
| **OACX 지역 차단** | prod 가 us-east-1 이라 한국 IP 전용인 OACX 가 막힌다. 해외 IP 허용 요청이 미해결 |
| **발급 속도** | holder 콜드부트 ~2분. 프리워밍으로 가리지만 근본 해결은 아니다. `fm_vc_issue elapsed_s` 계측 로그로 판단 중 |
| **발급 동시성** | holder 호출이 DB 락 밖이라 같은 라이선스에 동시 요청이 오면 issue-vc 가 두 번 나갈 수 있다. holder 멱등키에 의존하는데 **실측된 적 없다** |
| **체형 사진 구분력** | 전신 컷이라 카드 크기(106px)에서 볼륨 차이가 약하다. 무릎 위 크롭 + 붙는 옷으로 재생성하면 개선 |
| **남성 매트릭스** | 여성만 매트릭스. 남성은 5종 칩 |

## 13. 디자인 리뉴얼 시 유의점

1. **7단계 진행 레일은 장식이 아니다.** 실제 순차 KYC 라 현재 위치가 늘 보여야 한다
2. **대기 화면이 제품의 일부다.** 콜드부트 2분·자산 생성 수 분이 정상 경로에 있다.
   "기다리면 된다"를 알려주는 상태 표현이 필요하다
3. **얼굴을 보여주는 모든 지점이 게이트를 거친다.** 썸네일 하나도 공개 URL 로 못 바꾼다
4. **선택 단계(체형·대표이미지)는 건너뛰기와 되돌아가기가 있어야 한다.** 이탈에 민감하다
5. **예시 사진과 내 사진이 한 화면에 같이 있다.** 구분 장치가 사라지면 안 된다
6. 법정 고지·동의문 문구는 계약이다. 표기(띄어쓰기) 외에는 건드리지 않는다
