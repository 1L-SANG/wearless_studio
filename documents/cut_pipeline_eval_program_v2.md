## 2. 1차 실행에서 고정한 파이프라인 — P2

이 절은 48장을 만들 때 실제로 사용한 역사적 계약이다. 실행 후 발견된 오류와 다음
입력 계약은 §11~§15가 대체한다.

### 2.1 1단계: 중립 착장 기준컷

상품별로 하나의 검증된 중립 착장 기준컷을 만든다. 이 컷은 선택 모델이 정확한 상품과 매칭 의류를 입은 상태만 확정하며, 최종 장소·포즈·카메라는 맡지 않는다.

같은 상품의 Gemini와 ImageGen 최종 비교에는 **완전히 같은 중립 착장 바이트**를 넣는다. 그래야 최종 결과 차이를 2단계 모델 차이로 해석할 수 있다. 전체 P2를 공급자별로 각각 돌리는 end-to-end 비교는 1차 오너 검토 뒤 어려운 2상품에서 별도 수행한다.

### 2.2 2단계: 연출 적용

두 공급자 모두 아래 다섯 장을 같은 순서로 받는다.

1. `WORN OUTFIT ANCHOR` — 선택 모델·체형·전체 착장 정본
2. `PRODUCT EVIDENCE GRID` — 앞·뒤·디테일을 합친 상품 사실 정본
3. `MODEL FACE` — 얼굴 정체성만
4. `MODEL FULL BODY` — 키 인상·어깨·몸통·골반·팔다리 비율만
5. `EXAMPLE REFERENCE` — 포즈·카메라·프레이밍·장소·광원·일상 촬영 톤만

매칭 의류는 1단계 중립 착장에 이미 고정한다. 2단계에서 새 매칭 의류를 추론하거나 예시 착장을 복사하지 않는다.

## 3. 동일 적용 계약

Gemini와 Codex ImageGen은 같은 프롬프트 본문, 같은 역할 라벨, 같은 입력 순서, 같은 상품·모델·매칭·사용자 설정을 받는다. 공급자 때문에 한쪽 프롬프트만 더 자세히 만들지 않는다.

- 상품 정본: 색, 소재, 무늬·로고·상품 글자, 실루엣, 길이, 포켓, 봉제, 여밈, 부자재
- 모델 정본: 시안 작업용 `mE/w2` 얼굴·전신, 수혁 `mD/m3` 얼굴·전신
- 사용자 우선: 색상, 방향, 샷, 얼굴 노출, 아우터 개방 상태
- 예시 권한 없음: 예시 인물·체형·옷·신발·액세서리의 전이 금지
- 얼굴이 가려진 예시는 동일하게 가린다.
- 예시의 헤드룸, 카메라-인물 거리, 화면 속 인물 크기, 크롭과 근/원근 관계를 보존한다.
- 카메라 높이·비스듬함·원근 규칙은 유지하되 렌즈·조리개·인물사진 모드를 추론하지 않는다.
- 예시에 읽히는 배경이면 비슷한 정도로 읽히게 유지하며, 합성 보케·인물모드 마스킹·가장자리 후광을 새로 만들지 않는다.
- 인물과 배경은 하나의 광원·노출·화이트밸런스를 공유한다. 피부·옷의 면마다 방향성 음영, 접촉 그림자, 반사광, 원단 자체 그림자를 적용한다.
- 좌우 대칭 마네킹 포즈로 펴지 않는다. 예시의 무게 중심, 어깨·골반 반대각, 팔·손 높이, 다리 간격, 머리카락 흐름을 샷과 호환되는 범위에서 유지한다.
- 일상 휴대폰 스냅은 일상 스냅으로 남기며 광고 화보로 승격하지 않는다.

## 4. 배경·문자 정책

`배경만`은 이번 `all` 참고 실험의 어떤 팔에도 포함하지 않는다. 이는 빈 플레이트 편집용
과거 저장값·조건부 API 호환 방식까지 제품 전체에서 삭제한다는 뜻은 아니다(ADR-0011).

스타일링 `전부 참고`는 **같은 시각적 가족과 분위기·톤을 가진 다른 구체 장소**를 쓴다.
장소 유형·시간대·큰 색감·광원 논리·공간의 핵심 인상은 유지하되, 구체 위치·공간 구조와
평범한 소품 배치는 자연스럽게 달라야 한다. 원본 장소를 거의 복제하거나 전혀 무관한 장소로
바꾸는 양극단을 모두 허용하지 않는다.

배경에 원래 존재하는 간판·글자는 자동 삭제하지 않는다. 다만 없던 브랜드·글자·워터마크를 새로 만들거나, 알아볼 수 없는 가짜 문자를 전경에 크게 추가하면 실패다. 휴대 소품의 브랜드 처리에는 `reference/genexamples/ANCHOR_REGEN_PLAN.md` §8을 적용한다.

## 5. 핵심 2×2 실험

상품 4개에서 풀샷·미디움샷을 각각 만든다.

1. 여성 하의 — 스카이블루 프릴 장식 스커트
2. 여성 아우터 — 크로셰 반팔 가디건
3. 남성 하의 — 배색 스티치 바지
4. 여성 원피스 — 브라운 드롭웨이스트 원피스

각 상황의 예시는 반드시 `성별 × 정확한 의류 카테고리 × 샷`이 맞고, 쇼핑몰 원본과 서비스 생성예시가 같은 계보로 연결된 쌍이어야 한다.

| 조건 | 공급자 | 마지막 참고 이미지 | 연출 프로필 |
|---|---|---|---|
| A | Gemini Pro | 서비스 생성예시 | off |
| B | Gemini Pro | 연결 쇼핑몰 원본 | off |
| C | Codex built-in ImageGen | 서비스 생성예시 | off |
| D | Codex built-in ImageGen | 연결 쇼핑몰 원본 | off |

`4상품 × 2샷 × 4조건 = 32장`이다. 한 호출에는 원본과 서비스 예시를 동시에 넣지 않으며, 마지막 이미지 한 장만 교체한다.

## 6. 연출 프로필 보정군

복잡한 포즈·카메라·광원을 가진 4상황만 고른다. 핵심 2×2의 profile-off 결과를 재사용하고, 같은 네 셀에 profile-on 결과를 하나씩 추가한다.

- 추가 생성: `4상황 × 4셀 = 16장`
- 전체 1차 최종 결과: 48장

프로필은 아래 세 묶음만 담는다.

1. `poseAndFace`: 몸 방향, 무게 중심, 자연스러운 비대칭, 얼굴 가림·고개·시선
2. `cameraAndCapture`: 카메라 높이·방향·거리, 헤드룸, 화면 속 인물 크기, 크롭, 휴대폰 스냅 톤

## 7. 공급자 해석 경계

광범위 비교의 ImageGen 팔은 API 비용을 줄이기 위해 Codex built-in ImageGen을 사용한다. built-in 경로의 정확한 모델 버전은 공개되지 않으므로 API `gpt-image-2`와 동일하다고 주장하지 않는다.

오너 검토 뒤 ImageGen 계열이 우세하면 대표 4상황만 `gpt-image-2` API로 재확인한다. 실제 서버 공급자 채택은 그 소표본까지 통과한 뒤 결정한다.

## 8. 오너 선검토와 QC 순서

48장 첫 결과를 모두 만든 뒤 자동 QC 없이 오너 비교 HTML을 먼저 제공한다. HTML에는 상품 업로드, 마네킹, 중립 착장, 모델 얼굴·전신, 원본/서비스 예시, 프로필 본문과 익명 결과를 함께 표시한다. 오너는 좋은 점·나쁜 점을 자유롭게 적고 JSON으로 저장한다.

오너 검토 파일과 이미지 SHA-256이 고정된 뒤에만 독립 QC를 `shadow`로 실행한다. 첫 검토 전에 자동 선별·재생성·제외를 하지 않는다.

QC가 우선 보는 것은 상품·로고/글자·모델·컷 계약, 심각한 인체/원단 물리 오류, 인물-공간 광원 불통합, 명백한 예시 인물/의상 전이다. 작은 자연 주름 차이, 평범한 소품 이동, 미세한 색감 차이는 자동 차단하지 않는다.

## 11. 발견된 입력 계약 오류

1차 실행은 프롬프트와 실제 첨부의 1~5번 순서 자체는 정확히 일치했다. 그러나 의도했던
최종 서비스 입력과 비교하면 다음 두 항목이 잘못됐다.

1. 방향별 모델 얼굴·전신 시트 대신 정면 얼굴 한 장과 정면 전신 한 장만 넣었다.
2. 사용자가 선택한 매칭 의류 원본을 2단계에 직접 넣지 않고 중립 착장 기준컷에만 압축했다.
3. 이미 만들어진 선택 마네킹컷을 최종 호출에 직접 넣지 않고, 다시 생성한 중립 착장
   기준컷으로 대신했다. 마네킹컷은 기준 색상의 상품 핏·길이·실루엣 근거이고 중립 착장과
   같은 것이 아니다.

이 때문에 48장은 공급자·참고 이미지·장면 통합의 예비 경향에는 쓸 수 있지만, 방향별 모델
동일성과 실제 매칭 의류 보존을 포함한 최종 파이프라인의 승인 근거로 쓰지 않는다.

같아야 했다. 다음 실험도 이 배열과 라벨 상품 evidence grid를 기준선으로 유지한다.

## 13. 중립 착장 기준컷 결정은 보류한다 — 단계 A 이전 가설

> 이 절은 단계 A를 실행하기 전 계획의 기록이다. 단계 A 오너 검토 뒤의 최신 결정은
> §16.1이며, 현재 styling 기본값은 `OFF`다.

현재 48장은 모든 결과에 같은 중립 착장을 넣었으므로 중립 착장이 도움이 됐는지 검증하지
못했다. 중립 착장은 상품·모델·매칭 의류의 착용 관계와 레이어 순서를 먼저 고정할 수 있지만,
생성된 중간 이미지의 색·핏·얼굴 오류를 최종 결과에 전파하고 입력을 중복시킬 위험도 있다.
따라서 이번 증거만으로 항상 사용하거나 바로 제거하지 않는다. 다만 선택 마네킹컷·방향별
모델 시트·상품 evidence·직접 매칭 evidence가 이미 들어가면 중립 착장은 같은 정보를 한 번
생성해 압축한 손실성 파생 이미지에 가깝다. 현재 기본 가설은 **off**이며, 옷끼리의 레이어
순서·겹침·턱인·오픈 상태·밑단 관계가 복잡할 때만 추가 이득이 있는지 확인한다.

다음 실험은 먼저 방향별 모델 시트와 직접 매칭 의류 입력을 공통으로 고정한 뒤, 대표 세
상황에서 `anchor off/on × Gemini/ImageGen × 2회 반복`만 비교한다. 참고 이미지는 한 종류로
고정해 anchor 효과와 섞지 않는다.

- 레이어링이 중요한 아우터+매칭 의류 풀샷 1개
- 방향 시트와의 충돌을 볼 수 있는 하의+매칭 의류 사선/사이드 또는 미디움샷 1개
- 별도 매칭 의류가 없어 anchor가 중복일 가능성이 큰 원피스 풀샷 1개

anchor-on에서는 이 이미지를 전체 착장 정본으로 부르지 않고 `OUTFIT INTERACTION GUIDE`로
권한을 좁힌다. 모델 얼굴·체형, 상품·매칭 의류의 디자인·색·소재, 포즈·카메라·배경을 맡기지
않고 레이어 순서·겹침·턱인·개방 상태·밑단 관계만 참고한다.

중립 착장이 복잡한 레이어링에서만 이득이면 조건부 단계로 남기고, 단순 착장까지 일관되게
이득이면 공통 단계로 검토한다. 상품·매칭·모델 오류나 제외 결과를 늘리면 기본 경로에서
제거한다. 이 결정을 마친 뒤에만 선택된 anchor 정책을 고정하고
`provider × reference source` 비교를 다시 수행한다.

## 14. 단계 A 실행 계획과 기록 — 후속 계획은 §20으로 대체

다음 실험은 여러 변인을 한 번에 다시 섞지 않고 아래 순서로 진행한다.

### 단계 A — 입력 계약 교정과 중립 착장 off/on (24장)

공통 고정:

- 방향별 모델 얼굴 시트와 방향별 전신 시트
- 현재 선택 색상과 일치하고 상품 동일성 사전검사를 통과한 선택 마네킹컷
- 판매 상품 evidence grid
- 사용자가 고른 매칭 의류 evidence. 선택하지 않은 상품만 생략
- 서비스 생성예시 한 종류. 이 단계에서는 실제 UX의 기본 후보를 고정하기 위한 시험 재료일
  뿐, 서비스 예시를 최종 채택했다는 뜻이 아니다.
- profile off
- 같은 샷·방향·얼굴 노출·색상·아우터 개방 상태

비교 변수는 `중립 착장 off/on × Gemini/ImageGen`이다. 대표 세 상황을 각 조건에서 두 번씩
생성해 총 24장으로 모델의 우연한 한 번을 분리한다. 오너가 먼저 보고, 기존 이미지의
`부분 수정 수준` 평가는 재생성 명령으로 사용하지 않는다. anchor-on 입력은 전체 착장
정본이 아니라 `OUTFIT INTERACTION GUIDE`의 제한된 권한만 가진다.

실행 전 입력 QC에서 상품과 충돌하는 마네킹컷은 그대로 넣지 않는다. 2026-08-11 육안
사전검사에서 기존 크로셰 가디건 마네킹컷은 셀러 원본의 붉은 끈·장식 여밈을 둥근 단추로
바꾼 것이 확인됐다. 두 번의 교정 후보도 검정 이너, 가는 격자 조직, 포켓 모티프와
길이 문제로 탈락시켰다. 최종 선택 후보는 검정 이너 없이 짧고 넓은 실루엣, 굵은 크로셰,
서로 다른 좌우 포켓 장식과 두 개의 매듭 여밈을 복원해 독립 사전검사를 통과했다. 원피스도
기존 마네킹의 매끈한 상체가 판매 증거의 곡선 요크 아래 셔링과 느슨한 몸판을 지운 것을
발견해, 셔링·세로 드레이프·드롭웨이스트 밴드와 플라운스를 복원한 후보로 교체했다.
이것은 오너가 `부분 수정 수준`으로 평가한 최종 결과를 수정한다는 뜻이 아니라, 다음
실험의 잘못된 입력을 차단하는 준비 검사다.

단계 A의 `OUTFIT INTERACTION GUIDE`는 이상적으로 완벽한 기준사진의 효능 시험이 아니다.
실제 생성된 손실성 중간 이미지가 레이어 순서·겹침·턱인·개방·밑단 관계를 전달하는 이득과,

## 17. 앞면·뒷면을 구분하는 상품 증거 계약

사용자가 처음 입력 페이지에서 올리는 `앞면`, `뒷면`, `앞면 디테일`, `뒷면 디테일`은
단순 파일 순서가 아니라 면별 권한으로 보존한다. 하나의 무라벨 그리드에 합친 뒤 모델이
스스로 추측하게 하지 않는다.

1. 분석 단계에서 상품 사실을 `sharedFeatures`, `frontOnlyFeatures`, `backOnlyFeatures`로
   나눈다. 앞·뒤 모두에서 보이는 색·소재·전체 길이는 shared이고, 특정 요크·포켓·절개·
   로고·여밈 위치는 해당 면에만 둔다.
2. 생성 방향이 `front`이면 `앞면+앞면 디테일`을 `DOMINANT SURFACE — FRONT`로 둔다.
   이는 앞면만 평면처럼 보이라는 뜻이 아니다. 몸통이 비틀어지면 옆선과 뒷면 일부가
   자연스럽게 보일 수 있으며, 그 가시 영역에는 뒷면 증거를 사용한다.
3. `back`이면 위 권한을 반대로 적용한다. `side`에서는 앞·옆·뒤 중 실제 카메라에서 보이는
   면의 비중을 따라가고, 가능하면 실제 사이드 근거를 우선한다.
4. 한 장의 비용 효율적인 증거 팩을 유지하되 각 패널 바깥 여백에 역할 라벨을 넣고,
   프롬프트의 이미지 역할표에도 같은 패널 지도를 자동 생성한다. 업로드 완료 순서가 아니라
   저장된 슬롯 종류로 결정한다.
5. 프롬프트는 `VISIBLE SURFACE PLAN`을 만든다. 예를 들어 front 3/4이면 앞면이 주권을 갖고,
   옆선과 카메라에 실제로 드러나는 뒷면 조각만 보조 증거를 사용한다. back-only 포켓·요크·
   절개가 보이지 않는 앞면 중앙으로 감겨 들어오는 것은 금지한다.
6. 생성 후 QC는 목표 면 고유 특징과 반대 면 고유 특징을 따로 비교한다. 반대 면 전용 구조가
   보이는 면으로 전이되면 상품 동일성 실패다.

이 방식은 이미지 입력 수를 늘리지 않으면서도 사용자가 나눠 올린 앞·뒤 정보를 실제 생성
권한으로 사용한다. `integrated-v4`의 공통 개선사항으로 이미 적용했으며 별도 A/B로 되돌리지
않는다. 이후 앞뒤 전이가 반복될 때만 해당 실패 사례에서 다시 연다.

### 17.1 `front / side / back`과 3/4의 의미

서비스의 사용자 선택값은 기존처럼 `front / side / back` 세 가지로 유지한다. `정면 3/4`를
새 UI 카테고리나 새 생성예시 버킷으로 만들지 않는다. 여기서 3/4는 카메라에 여러 면이 함께
보이는 자연스러운 상태를 설명하기 위한 내부 용어일 뿐이다.

시스템이 먼저 셀러 업로드를 `정면 / 정면 3/4 / 사이드`로 다시 분류하는 것도 아니다.
셀러가 올린 앞면·뒷면 슬롯은 그대로 증거 역할을 맡고, **사용자가 고른 출력 방향과 선택한
생성예시의 실제 몸 비틀림을 함께 보고 최종 이미지에서 어느 면이 얼마나 보일지를 정한다.**
이를 몇 개의 딱딱한 각도 클래스로 자르지 않고 `front-dominant / back-dominant / side-visible`
같은 가시면 계획으로만 사용한다. 사용자 방향이 생성예시와 충돌하면 사용자 방향이 우선하며,
생성예시에서는 호환되는 포즈·카메라·프레이밍만 가져온다.

## 18. 배경에 따른 선택적 포인트 광원

남성 하의 후보 H는 Codex·guide OFF 결과였으며, 오너는 배경에서 자연스럽게 들어온 빛을
장점으로 평가했다. 이는 중립 착장 가이드의 효과가 아니다. 다만 같은 결과에서 상품 하의가
조금 밝아지고 매칭 상의가 틀렸으므로 빛의 미적 장점과 상품 충실도를 분리해야 한다.

공통 실험 프롬프트에는 강제 효과가 아니라 아래의 조건부 규칙을 넣는다.

> 장면의 창문·햇빛 틈·실내 조명처럼 물리적으로 가능한 광원이 있을 때만, 한 번의 절제된
> 포인트 빛을 허용한다. 빛은 배경·피부·판매 상품·매칭 의류에 같은 방향과 색온도로 작용해야
> 하며, 상품의 중간톤 영역에는 원래 색을 판별할 수 있는 부분을 남긴다. 근거 없는 스튜디오
> 스포트라이트, 상품 색 바램, 과노출, 얼굴만 빛을 받지 않는 합성은 금지한다.

이 규칙은 사용자 옵션으로 추가하지 않고 styling의 촬영 완성도 규칙 후보로 둔다.
`integrated-v4`에서는 양 공급자·양 참고 출처에 똑같이 적용했으므로 포인트광 자체의 A/B는
아니었다. **현재 프로덕션 프롬프트에는 아직 배선하지 않았다.** 라운드 2에서도 모든 팔에
공통 적용해 변수를 섞지 않고, 근거 없는 조명이 반복될 때만 해당 실패 사례에서 끈다.

프롬프트 SHA와 ordered-input SHA가 같고, 실제 입력은 `선택 마네킹 → 얼굴 방향 시트 → 전신
방향 시트 → 판매자 상품 증거 → 직접 매칭 의류(있는 경우) → 일반 all/pose 예시(마지막)`다.
정확 배경판 편집은 bg plate가 첫 입력인 기존 예외다. 중립 착장
가이드와 연출 프로필은 모두 끈 상태다.

최종 첫 결과는 Gemini Pro 2K 8장과 OpenAI API `gpt-image-2` medium 1024×1536 8장으로,
오류·누락·재시도 없이 16/16 생성됐다. 검토용 파생본만 동일한 848×1272 PNG 캔버스로
정규화했고, 원본 결과 바이트는 그대로 보존했다. 후보의 공급자와 참고 출처는 별도 blind key에만
있으며 검토 HTML에는 노출하지 않는다. 오너 검토판은
`server/ab_out/cut_pipeline_integrated_ab_v4_20260812/OWNER_REVIEW.html`이다. 이 시점에는
최종 결과의 품질 QC·자동 제외·수정·재생성을 하지 않았다. 독립 정적 감사에서는 16개 결과의
감사 해시, 공급자 쌍의 동일 입력, source/service 간 마지막 예시만의 차이, 후보 블라인드,
동일 검토 캔버스, 자동 저장·JSON 내보내기를 모두 확인해 실제 차단 문제 없이 PASS했다.

### 20.3 라운드 2: 실패 셀만 복구하고 QC를 보정

오너가 라운드 1을 모두 본 뒤 반복되는 원인을 분류한다. 전면 구조·길이·색·모델·직접 매칭처럼
상품/정체성 자체가 틀리면 전체 재생성 후보, 배경의 작은 광원·표정·국소 여밈처럼 나머지가 이미
좋으면 국소 수정 후보로 둔다. 같은 실패를 두 공급자에서 반복할 때 프롬프트/입력 계약을 고치고,
한 공급자에서만 반복할 때 공급자 차이로 본다. 자동 QC는 이 라운드까지도 shadow다.

연출 프로필은 라운드 1 결과에서 헤드룸·인물 크기·가림·비대칭 같은 동일 사실 누락이 반복될
때만 대표 실패 사례의 off/on 소표본으로 연다. 상품에 없는 주머니나 특정 행동을 새로 넣지 않으며,
반복 개선이 보이고 hard fail을 하나도 늘리지 않을 때만 조건부 보조정보로 남긴다. 정확한
채택 수치는 라운드 2 결과를 보기 전에 임의로 고정하지 않는다.

### 20.3.1 통합 1라운드 오너 판정과 공급자 경향

오너 판정 원본은
`/Users/daily/Downloads/integrated-v4-blind-review.json`이며, 이 파일의 의미는 다음과 같다.

- `good`: 현재 그대로 사용해도 되는 수준
- `repair`: 일부를 고치면 쓸 수 있는 수준이며, 이 라벨 자체가 즉시 이미지 수정을 지시하지는 않는다.
- `exclude`: 이 방식의 결과를 그대로 내보내면 안 되는 수준

16장 집계는 `good 3 / repair 9 / exclude 4`다. 블라인드 키를 해제하면 OpenAI API는
`good 1 / repair 6 / exclude 1`, Gemini Pro는 `good 2 / repair 3 / exclude 3`으로 총점만으로는
공급자 하나를 고를 수 없다. 대신 상품별 상호작용이 뚜렷하다.

| 상품 | 관찰된 경향 | 현재 해석 |
|---|---|---|
| 남성 청바지 | OpenAI 두 결과는 모두 하의 구현이 좋았고, Gemini 두 결과는 모두 하의 구현 아쉬움으로 제외 | 매장 옷걸이·혼합광·낮은 해상도의 불완전한 denim 증거를 OpenAI가 더 잘 견딘 신호. 단 한 상품이라 라우팅 규칙으로 확정 금지 |
| 흰 원피스 | 네 결과 모두 부분 수정 수준 | Gemini raw는 얼굴·의류가 좋았지만 포즈/바닥 프레임이 아쉬웠고, OpenAI는 자연스러운 포즈 대신 화보화 또는 인물-공간 합성감이 나타남. 공급자 승자 없음 |
| 빨간 가디건 뒷면 | Gemini raw만 그대로 사용 가능 | Gemini는 상품 구현과 자연광 표현이 상대적으로 좋았고, OpenAI는 얼굴·광원 통합 또는 의류/포즈가 아쉬움. 다만 Gemini service도 얼굴/헤어 실패 |
| 여성 줄무늬 상의 | Gemini raw만 그대로 사용 가능, service 팔은 두 공급자 모두 제외 | raw 결과에서 자연스러운 포즈가 살아났고 service 결과는 셔츠 하단·거리·피부/표정 문제가 발생. OpenAI raw는 상의와 포즈는 좋았지만 모델·직접 매칭 실패 |

참고 이미지 출처는 `raw: good 2 / repair 5 / exclude 1`, `service: good 1 / repair 4 /
exclude 3`으로 raw가 약간 앞서지만 표본이 작고 상품·공급자와 강하게 얽혀 있다. 쇼핑몰 원본을
서비스 갤러리에 직접 공개할 근거로 사용하지 않는다. 원본은 내부 연출 원천, 서비스 생성예시는
사용자 노출 자산이라는 제품 경계는 유지한다.

판매자 입력 품질도 판정에 같이 기록한다. 남성 청바지는 매장 옷걸이, 혼합광, 클립으로 당겨진
허리, 열린 지퍼, 가격표와 배경 의류 때문에 실제 허리 곡률·착용 핏·정확한 워싱 분포가 불확실하다.
흰 원피스는 흰 바탕과 접힌 밑단 때문에 정확한 길이·비침·밑단 파형이 불확실하고, 줄무늬 셔츠는
구김과 다운샘플링 때문에 줄 간격·밑단 핏이 불확실하다. 이런 항목은 공급자 hard fail로 단정하지
않고 `input_uncertain`로 분리한다. 두 판매자 사진에서 반복되거나 가리지 않은 디테일 한 장이
명확히 증명한 사실만 hard product gate로 쓴다.

청바지의 판정 메모는 서로 다른 장점을 함께 보존해 읽는다. OpenAI는 전체 실루엣과 착용 가능한
바지 형태를 더 안정적으로 만들었지만 한 결과에서 고정 매칭 흰 티를 검정으로 바꿨고, 워싱을
검정 단색에 가깝게 평탄화했다. Gemini는 두 결과 모두 오너에게 제외됐지만 판매자 사진의 진한
raw-indigo 워싱과 오렌지 스티치는 상대적으로 더 살렸다. 따라서 `OpenAI=상품 사실 전체 우세`가
아니라 `OpenAI=착용 형태 안정성`, `Gemini=일부 표면 신호 보존`이라는 가설로만 남긴다.

### 20.3.2 아이폰 일상 스냅 캡처 A/B

통합 1라운드의 **별도 실험 프롬프트**에는 iPhone, DSLR, 특정 렌즈 수치, 조리개, ISO, 셔터,
Portrait mode 지정이 없었다. 그러나 카메라 지시 자체가 없었던 것은 아니다. 예시의 카메라
높이·비스듬함·거리·프레이밍·헤드룸·인물 크기·원근·단축을 보존하고 `casual capture class`와
화보화 금지를 따르도록 했다. 따라서 공급자가 채운 빈 부분은 구도 전체가 아니라 **정확한 촬영
기기와 기본 사진 처리 방식**이다.

실서비스 `server/prompts/cut_generate_v1.txt`에는 더 많은 카메라 문구가 있다. `85mm at a
moderate aperture`는 호리존 전용이고, `phone camera`·자연 그레인·손촬영 불완전성은 거울컷
전용이라 일반 스타일링에는 적용되지 않는다. 반면 스타일링 `all`에는 예시의 compatible camera
geometry, lens behavior, modest sharpness, 노출·화이트밸런스·대비·채도, 인공 portrait blur
금지와 헤드룸·인물 크기·크롭 보존이 실제 UI 생성 경로에서 적용된다. 그러므로 다음 A/B는
기존 카메라 계약을 삭제하는 시험이 아니라 그 위에 `iPhone default Photo mode`를 명시했을 때
스냅 질감이 더 안정되는지 보는 시험이다.

다음 소표본의 주효과는 **촬영 질감**이다. 다만 포즈와 배경은 셀러가 생성예시를 고르는 핵심
이유이므로 평가에서 빼지 않는다. 별도 변인으로 흔들지는 않되, 예시의 포즈 의미와 전체 배경
분위기를 보존하면서 같은 분위기의 다른 구체 장소가 되었는지를 비열화 게이트로 함께 본다.

| 고정 항목 | 내용 |
|---|---|
| 상품 | 흰 원피스 풀샷 + 여성 줄무늬 상의 미디움샷 |
| 참고 이미지 | 사용자 노출 계약에 맞춰 service example만 사용 |
| 공급자 | Gemini Pro + OpenAI API `gpt-image-2` |
| 입력 | 선택 마네킹, 방향별 얼굴/전신 시트, 판매자 증거, 직접 매칭, 예시의 바이트·순서 모두 동일 |
| A | 현행 capture 문구 |
| B | 명시적인 `recent iPhone default Photo mode` 일상 스냅 계약 |
| 반복 | 오너 지시에 따라 사전 계획된 전 셀 2회: `2상품 × 2공급자 × 2문구 × 2회 = 16장` 완료. 반복 2는 재시도·best-of가 아님 |
| 해상도 | `integrated-v4`와 동일한 Gemini 2K 세로 2:3 + OpenAI `gpt-image-2` medium·1024×1536 |

iPhone 팔은 기본 Photo mode, 넓고 읽을 수 있는 초점, 보통의 자동노출·화이트밸런스, 절제된
연산 HDR/샤프닝, 자연스러운 피부 미세질감과 약한 손촬영 불완전성을 요구한다. Portrait/Cinematic
mode, 인공 보케, 가짜 필름 그레인, 어안 왜곡, 망원 압축, 뷰티 보정, 스튜디오 광택과 영화식
색보정은 금지한다. 예시가 소유한 카메라 거리·헤드룸·인물 크기·구도는 그대로 유지하며,
휴대폰 느낌을 내려고 더 넓게 잡거나 다시 크롭하지 않는다.

오너는 스냅/화보 인상, 피부 보정, 배경 가독성과 가짜 보케, 인물 거리·헤드룸, 공간과 인물의
노출·화이트밸런스·광원 일체감, 의류 디테일 저하를 본다. 동시에 예시의 행동·몸 방향·체중·
지지점·접촉·시선·대략적 프레이밍은 알아볼 수 있게 유지하면서 관절 각도·손 위치·고개·머리카락·
원단에는 작은 자유가 있는지, 같은 분위기·톤·장소 유형을 유지하되 정확한 공간 구조·소품 배치는
다른 구체 장소인지 기록한다. 포인트광은 예시의 창·햇빛 틈·실내 조명에 물리적 근거가 있을 때만
허용하며, 배경·피부·상품·매칭 의류에 같은 방향과 색온도로 작용해야 한다.

### 20.3.3 누적 공급자 근거의 해석 경계

통합 1라운드의 `OpenAI=안전형, Gemini=고점형`은 **이번 16장 안에서만 보인 경향**이다.
이전 근거와 합칠 때는 다음 세 종류를 섞지 않는다.

1. Codex 내장 ImageGen은 정확한 모델 버전이 공개되지 않으므로 OpenAI API `gpt-image-2`의
   대리 표본으로 사용하지 않는다. 비용 없는 탐색 자료로만 보존하고 서비스 공급자 결정 집계에서는
   제외한다.
2. 쇼핑몰 원본에서 서비스 생성예시 자산을 만드는 실험은 실제 셀러 상품을 입히는 런타임보다
   입력 권한 충돌이 훨씬 적다. 그 실험에서 ImageGen이 강했던 사실을 실제 의류컷 공급자 우위로
   그대로 옮기지 않는다.
3. 실제 상품을 넣은 이전 Nano/Gemini 대 내장 ImageGen 비교는 모델 얼굴·포즈·장소 변주에 관한
   방향성 증거지만, OpenAI API를 직접 호출한 비교가 아니므로 이번 OpenAI API 8장과 숫자를
   합산하지 않는다.

따라서 현재 API 공급자에 대해 확정 가능한 누적 결론은 아직 제한적이다. Gemini Pro는 여러
실험에서 자연광·스냅 동작·니트/openwork 표현의 고점을 보였지만 상품 구조가 무너지거나 장소를
복제하는 편차가 반복됐다. OpenAI API는 이번 16장에서 착용 형태의 폐기율이 낮았지만 직접 매칭,
워싱 평탄화, 화보화와 인물-공간 광원 분리 문제가 있었다. 두 API를 같은 최신 입력 계약으로 직접
비교한 표본은 이번 8쌍뿐이므로 아이폰 캡처 A/B 뒤에도 단일 공급자로 바로 통일하지 않는다.

|---|---|---|---|
| 1. 핵심 파이프라인 선택 | 앞뒤 증거·모델·매칭·예시 역할을 고정하고 Gemini/OpenAI API와 raw/service의 결과 범위를 확인 | `integrated-v4` 16장 생성·오너 판정까지 완료. `good 3 / repair 9 / exclude 4`; 전역 공급자 승자는 미확정 | 다시 생성하지 않는다. raw/service 경향은 보존하되 service는 사용자 선택 자산, raw는 내부 연출 원천으로 역할을 고정한다 |
| 2. 실패 교정·QC 방식 선택 | 1차의 `repair 9 + exclude 4`를 이용해 촬영 질감, 공급자 차이, 포즈·배경 해석, 프로필·복구·QC를 **같은 실패 사례**에서 결정 | 첫 16장 생성 완료·오너 판정 대기 | 오너가 표본 부족을 피하기 위해 전 셀 2회 독립 반복을 지시했다. 양 API를 같은 입력으로 비교하며, 오너 판정 뒤 같은 결과에 QC shadow를 적용한다 |
| 3. 실제 서비스 통합 검증 | 확정된 입력·촬영·공급자·복구·QC 계약을 실제 상세페이지 흐름에서 확인 | 미착수 | 남녀·4카테고리·full/medium·front/back/twist·matching 유/무를 작은 coverage matrix로 덮고, 통과 결과만 출고한다 |

#### 라운드 2에서 한꺼번에 확인할 것

첫 소실험은 1차 실패 풀에서 카메라·화보화 문제가 실제로 있었던 흰 원피스 풀샷과 줄무늬 상의
미디움샷을 고른다. `현행 capture / recent iPhone default Photo mode`만 주효과로 바꾸고,
Gemini Pro와 OpenAI API `gpt-image-2`를 계속 짝지어 본다. 원래 비용 절감안은
`2상품 × 2공급자 × 2문구 = 8장`을 먼저 보고 애매한 셀만 추가하는 방식이었다. 오너가
2026-08-13에 8장은 너무 적다고 판단해 전 셀 2회 독립 반복을 지시했고, 실행 계약을
`2상품 × 2공급자 × 2문구 × 2회 = 16장`으로 바꿨다. 두 반복은 재시도나 best-of 후보가 아니라
프롬프트·입력·공급자 요청 바이트가 같은 사전 계획 독립 첫 결과다.

아래 항목은 실험 변수가 아니라 공통 기준선이다.

1. `integrated-v4`의 선택 마네킹 → 얼굴 방향 시트 → 전신 방향 시트 → 면 라벨이 픽셀에
   표시된 상품 evidence grid → 직접 매칭 → service example 마지막 순서를 유지한다.
2. 중립 착장 가이드와 사실형 연출 프로필은 기본 OFF다. 조건부 포인트광과 인물-공간 공통 광원
   규칙은 양 팔에 똑같이 적용한다.
3. 셀러는 생성예시에서 **포즈와 전체 배경 분위기**를 보고 선택한다. 행동, 몸 방향, 체중과
   지지점, 중요한 접촉, 시선, 대략적 프레이밍은 알아볼 수 있게 유지하되 관절 각도, 손 위치,
   고개, 머리카락과 원단에는 작은 자연스러운 자유를 허용한다. 정밀 관절 복제나 전혀 다른
   행동으로의 변경은 모두 실패다.
4. 장소 유형, 전체 분위기·톤, 시간대와 광원 논리는 유지하되 **다른 구체 장소**여야 한다.
   같은 방·문·벽·화분·자전거 배치를 거의 복제하는 것도, 전혀 다른 장소로 뛰는 것도 실패다.
   이전의 `SAME-PLACE` 표현은 폐기하고 `SAME-MOOD, DIFFERENT-PLACE`로 명확히 쓴다.
5. 품질 판정은 Gemini 2K와 OpenAI medium·1024×1536으로 한다. 1K는 품질 표본이나 비용절감
   팔이 아니라 배선 확인용 기술 스모크에만 쓴다.

오너 판정표에는 상품 구조·앞뒤 면, 소재·무늬, 모델 정체성, 직접 매칭, 포즈 의미와 작은 자유,
배경 분위기와 장소 변주, 자연광·iPhone 스냅감, 인물-공간 광원 통합을 따로 기록한다. 공급자
총점 하나만 보지 않고 각 축을 누적하며, 두 번째 결과를 만든 셀에서만 반복 안정성을 기록한다.
같은 강점이 독립 상품에서도 반복되기
전에는 `하의=OpenAI`처럼 카테고리 라우팅을 확정하지 않는다. Codex 내장 ImageGen 결과는
OpenAI API 근거에 합산하지 않는다.

#### 같은 실패 사례에서 복구와 QC를 결정하는 방법

추가 생성 없이 먼저 라운드 1과 라운드 2 결과에 독립 QC를 shadow로 돌린다. 다른 모델,
직접 매칭 불일치, 앞뒤 구조 전이, 심한 색·길이·실루엣 변화, 명백한 인물-공간 광원 분리는
`HARD FAIL` 후보로 두고, 작은 여밈·주름·헤드룸·취향 차이는 경고로 분리한다. 자동 차단 기준은
미리 임의 숫자로 확정하지 않고 라운드 2에서 오너 라벨과의 회수·과잉 차단을 다시 계산한 뒤
오너가 승인한다.

오너가 `repair` 또는 `exclude`로 본 대표 사례만 다음처럼 복구한다.

- 상품·모델·매칭·면·전체 색/실루엣 오류: 전체 재생성 또는 다른 공급자 결과와 비교
- 나머지가 이미 좋은 국소 여밈·표정·작은 광원 오류: 국소 편집과 전체 재생성 비교
- 헤드룸·인물 크기·가림·비대칭처럼 동일한 사실 누락이 반복된 사례: 그때만 짧은 사실형
  연출 프로필 OFF/ON 확인
- 양 공급자가 같은 방식으로 실패: 입력·프롬프트 문제로 분류
- 한 공급자만 반복 실패: 공급자 특성으로 기록하고 대체 공급자 복구 후보로 분류

복구 결과는 원래 오류만 고쳤는지가 아니라 기존에 맞았던 상품·모델·매칭·포즈·배경이 새로
망가지지 않았는지 재QC한다. 이 라운드의 목적은 모든 이미지를 억지로 고치는 것이 아니라,
오류 유형별로 `국소 편집 / 전체 재생성 / 대체 공급자 / HOLD` 중 무엇이 안전한지 확정하는 것이다.
판매자 사진 품질 A/B는 같은 상품의 새 정면·뒷면 재촬영본이 생겼을 때만 연다. 현재 사진을 AI로
정리한 이미지를 깨끗한 정본으로 간주하지 않는다.

비용은 해상도를 낮춰 줄이지 않는다. 이번 첫 배치는 오너 지시에 따라 전 셀 2회로 만들었지만,
이후 추가 생성은 오너 판정에서 필요한 실패 사례만 복구한다. 같은 Gemini Pro 품질의 비실시간 호출은 Batch 실행기가 준비된
뒤 Batch로 보낸다. Flash 같은 저가 모델 비교는 3라운드 완료 뒤의 선택적 운영비 A/B이며
파이프라인 확정 단계에는 포함하지 않는다.

### 20.3.5 QC보다 먼저 닫을 생성 파이프라인 보강

독립 QC의 출고 차단을 먼저 열지 않는다. 판정 기준이 되는 생성 계약이 계속 바뀌면 같은 오류를
QC 모델의 오탐과 생성기의 회귀로 구분할 수 없기 때문이다. 이번 라운드 2의 16장을 만들기 전에
아래 항목을 새 실험 패킷의 정적 검사와 봉인 manifest에 실제로 넣었다. 완료된
`integrated-v4` 파일은 역사 증거이므로 수정하지 않는다.

1. **입력 배열은 유지한다.** 선택 마네킹 → 얼굴 방향 시트 → 전신 방향 시트 → 면 라벨이
   픽셀에 표시된 셀러 evidence grid 한 장 → 직접 매칭 → service example 마지막 순서를
   양 공급자와 양 capture 팔에서 동일하게 쓴다. 뒷면·얼굴 비노출 컷도 얼굴/머리 정체성
   시트를 생략하지 않는다. 셀러 사진을 다시 여러 장의 무라벨 입력으로 흩어 넣지 않는다.
2. **포즈 과잠금을 없앤다.** 생성예시에서 행동, 몸 방향, 체중과 지지점, 중요한 접촉, 시선,
   대략적 프레이밍만 보존한다. 관절각, 손 위치, 고개, 머리카락과 원단에는 작은 자연스러운
   자유를 준다. 정밀 복제와 완전히 다른 행동은 모두 실패다.
3. **장소 복제를 금지하되 차이를 위한 소품을 강제하지 않는다.** 생성예시는 평면도나 편집
   캔버스가 아니라 연출 참고다. 장소 유형, 전체 분위기·톤, 시간대, 광원 논리, 공간 밀도와
   카메라 관계를 유지하면서 그 종류의 장소에서 자연스럽게 있을 법한 다른 구체 장소를 만든다.
   원본의 특징적인 벽·문·길·가구·화분·간판 관계를 같은 장소로 읽힐 만큼 복제하지 않되,
   다르게 보이기 위해 가구·식물·간판·설비·소품을 억지로 추가·이동·복제하지 않는다. 배경
   요소는 실제 그 장소에 있을 법한 종류·크기·받침과 자연스러운 위치일 때만 둔다.
   `cut_generate_v1.txt`에 남아 있던 `공간 구조 1개 + 배치 2개` 문장도 제거했으며, 이 폐기된
   옛 규칙은 회귀 검사로 라운드 2나 이후 운영 프롬프트에 다시 들어오지 못하게 한다.
4. **셀러 증거의 판정 가능성을 봉인한다.** grid의 각 패널을 `usable|uncertain|missing`으로
   기록하고 흐림, 가림, 옷걸이 왜곡, 혼합광, 접힘, 낮은 대비 같은 이유를 남긴다. 상품 사실도
   `hard|uncertain`으로 구분한다. 불확실한 사실은 결과 QC에서 실패가 아니라
   `UNJUDGEABLE` 또는 오너 검토 대상이다.
5. **마네킹은 추정을 정본으로 세탁하지 않는다.** 마네킹은 착용 기하와 대략적 핏을 돕는
   보조 근거다. 셀러 픽셀에서 불확실한 길이·밑단·비침·워싱·볼륨을 새로운 hard truth로
   승격하지 않는다. 명확한 셀러 사실과 충돌하면 셀러 evidence가 우선한다.
6. **grid 가독성을 생성 전에 검사한다.** 방향·구조·미세 무늬를 판단해야 하는 dominant cell의
   유효 픽셀이 부족하면 낱장 입력으로 회귀하지 않고 같은 grid 안에서 해당 셀을 확대하거나
   `uncertain`으로 봉인한다.
7. **첫 결과에는 자동 선별을 끈다.** QC, best-of, 하네스 재시도, 국소 편집, 공급자 fallback을
   모두 끈다. 이번에는 오너 지시에 따라 각 셀의 사전 계획 독립 첫 결과를 2장씩 모두 블라인드로
   보여 준다. 두 결과 중 하나를 먼저 고르지 않아 capture와 공급자 차이를 선별 효과와 섞지 않는다.

이 보강 뒤 생성한 16장은 오너가 먼저 판정한다. 같은 16장에 독립 QC shadow를 나중에 병행하되,
새 이미지 생성 호출은 추가하지 않는다. Round 3 서비스 배선 전에는 선택 VIRTUAL 모델 자산이
불완전하거나 로드되지 않을 때 모델 참조 없이 계속 생성하는 경로도 제거하고 해당 컷을
fail-closed/HOLD로 보내야 한다.

### 20.3.6 독립 전문 QC 설계 — 지금 설계하고, 첫 16장 뒤 shadow 실행

현재 `cut_output_qc`의 한 호출이 16개 gate를 함께 판정하는 방식은 오프라인 참고 구현으로만
둔다. 운영 후보는 **서로의 verdict를 보지 않고 자기 영역만 검사하는 독립 판정 호출**로
나눈다. 생성 프롬프트, 생성 모델의 자기평가, 다른 QC의 결과는 어느 판정자에게도 주지 않는다.
필요한 역할 이미지와 결과 이미지, 봉인된 사실 계약만 제공한다.

| 담당 | 보는 것 | 보지 않는 것 |
|---|---|---|
| Q0 입력·계약 preflight | 파일 decode, SHA/MIME/순서, 필수 역할, applicable gate, 이미 봉인된 evidence judgeability 라벨·픽셀 크기 검증 | 이미지 미학·취향, judgeability 의미의 신규 추론 |
| Q1 상품 구조·면·색 | 목표 앞/뒤 면, 실루엣, 길이, 봉제·패널·여밈 구조, 목표 바탕색 | 모델 얼굴·배경 취향 |
| Q2 상품 표면·식별요소 | 소재, 무늬, 부자재, 텍스트·로고, 근거 없는 세부 발명 | 포즈·장소 |
| Q3 매칭·레이어링 | 직접 매칭 의류 동일성, 색·형태, tuck/가림/레이어 관계 | 주상품의 취향성 주름 |
| Q4 모델 머리·정체성 | 보이는 얼굴, 두상, 헤어 실루엣, 부분 프로필·귀·목. 뒷면도 헤어/두상은 검사 | 체형·상품 |
| Q5 모델 체형·인체 | 키·어깨·몸통·허리·골반·팔다리 비율, 인체 자체의 손·관절 이상 | 얼굴의 미세 닮음 |
| Q6 포즈·카메라 | 행동·몸 방향·체중·지지·접촉·시선·프레이밍 보존과 허용된 작은 자유 | 상품 미세 무늬 |
| Q7 공간·촬영 질감 | 같은 분위기·톤·장소 유형이면서 다른 구체 장소인지, iPhone capture·노출·WB·심도 | 상품 구조의 불확실한 사실 |
| Q8 물리 통합 | 인물·의류·매칭·배경의 공통 광원, 그림자, 접지, 반사, 주름·장력, 합성 경계 | 장소가 예쁜지 여부 |

담당 중복으로 같은 오탐을 두 번 증폭하지 않도록 모든 atomic code는 아래 한 담당만 소유한다.
이 표는 라운드 2의 `styling/direct + all example` 범위다. mirror, horizon, product, space-set과
페이지 continuity의 code registry는 라운드 3 배선 전에 별도로 확장한다.

| 담당 | 단독 소유 atomic code 범위 |
|---|---|
| Q0 | `fileValidity`, `roleCompleteness`, `inputIntegrity`, `factApplicability`, `sealedJudgeability` |

Q1의 `garmentBaseColor`는 바탕색만, Q2의 `patternScalePlacementColor`는 줄무늬·프린트 안의 색만
본다. Q1의 여밈 구조는 단추·지퍼·플래킷의 상품 사실이고, Q6의 `outerClosure`는 사용자가
요청한 open/partial/closed 상태다. Q6은 카메라 위치·원근·프레이밍 계약을, Q5는 결과 인체
자체의 비율·손·관절만 본다.
Q7은 사진 전체의 목표 노출·화이트밸런스·심도 등급을, Q8은 그 빛과 반사가 인물·상품·매칭·
배경에 일관되게 작용하는지만 본다.

Q0는 로컬 결정 코드로 실행한다. Q1~Q8의 첫 shadow 후보 모델은 모두 고정된
`gemini-3.5-flash`의 별도 호출로 두고 낮은 thinking을 사용한다. 같은 모델을 쓰더라도 호출,
시스템 지시, 입력 역할, JSON schema와 감사 원장이 분리되므로 담당 간 verdict가 섞이지 않는다.
실행마다 evaluator가 바뀌는 provider fallback은 금지하고 provider-pinned 호출 경로를 쓴다.
`FAIL`이 치명적이거나
`UNJUDGEABLE`이 실제 출고 결정을 막는 경우에만 고정된 2차 판정자 `gpt-5.4-mini`를 호출하는
방식으로 calibration한다. OpenAI 판정용 secret과 배포 배선은 아직 열지 않으며, 첫 shadow에서
오너 라벨과 비교하기 전 이 모델 선택을 enforce 근거로 쓰지 않는다. enforce 전에는 오너가
정상으로 본 PASS 표본도 층화 추출해 2차 판정자에게 보내 두 모델이 같은 false PASS를 만드는지
별도로 측정한다.

모든 전문 판정자는 자기 코드마다 정확히 한 번씩 다음 구조만 반환한다.

```json
{
  "checks": [
    {
      "code": "위 단일 소유표의 exact atomic code",
      "status": "PASS|FAIL|NA|UNJUDGEABLE",
      "magnitude": "none|minor|material|catastrophic",
      "confidence": "low|medium|high",
      "evidence": "이미지에서 확인한 짧은 사실"
    }
  ]
}
```

적용 대상과 `NA` 가능 여부는 모델이 아니라 Q0의 결정 코드가 정한다. 각 담당은 적용되는 exact
code를 누락·중복 없이 한 번씩 반환해야 하며, 알 수 없는 code, 누락·중복, schema 불일치,
timeout은 이미지 verdict와 분리된 `JUDGE_ERROR`다. `PASS`는 `magnitude=none`, `NA`와
`UNJUDGEABLE`은 `magnitude=none`만 허용하고 다른 조합은 schema 오류로 거부한다.

`input_uncertain`은 상품 전체가 아니라 fact별 atomic code에만 매핑한다. 예를 들어 밑단 곡선이
불확실해도 같은 이미지의 명확한 neckline 구조 오류는 Q1이 FAIL로 판정할 수 있다. 봉인한
불확실 사실은 source-side `UNJUDGEABLE` 사유 중 하나다. hard fact라도 후보나 reference의
필요 영역이 잘림·가림·너무 작은 크기·모호함 때문에 물리적으로 비교 불가능하면 해당 code는
`UNJUDGEABLE`일 수 있다. 반대로 CutPlan상 보여야 하는 영역을 결과가 명백히 잘라내거나 가린
경우는 판정 불가가 아니라 계약 위반 `FAIL`이다. 전문
판정자의 자유문장을 생성 프롬프트에 붙이지 않고, 나중에 승인된 `code + magnitude`만 고정된
교정 템플릿의 `국소 편집|전체 재생성|대체 공급자|HOLD`로 매핑한다.

최종 집계는 또 다른 LLM이 아니라 결정적 코드가 한다. 한 담당의 PASS가 다른 담당의 FAIL을
상쇄할 수 없다. shadow에서 `JUDGE_ERROR`는 판정기 장애로 따로 기록하고 이미지와 사용자 노출을
바꾸지 않는다. `FAIL`은 자동 PASS가 아니며 오너가 승인한 `code + magnitude` 표에 따라
`WARNING|REPAIR|HARD_FAIL`로 결정적으로 매핑한다. 그 표는 오너 라벨을 본 뒤 별도 승인한다.
향후 enforce에서 applicable `UNJUDGEABLE`, `JUDGE_ERROR`, 1·2차 판정 불일치는 자동 통과하지
않고 사람 검토 또는 HOLD 후보가 된다. `REPAIR|HARD_FAIL`이 승인된 복구 최대 2회 뒤에도
남을 때만 해당 컷의 최종 상태를 HOLD로 확정한다. repair 뒤에는 실패 담당만 보지 않고 모든 applicable 담당을 다시 실행해 새
회귀를 잡는다. 이번 16장에서는 이 구조를 오너 판정 뒤 **shadow**로만 실행하고, 자동 편집·차단·
사용자 노출 변경은 하지 않는다. 각 담당의 누락과 과잉 차단이 오너 라벨에 맞는지 따로 보정한
뒤에만 담당별로 enforce 승격을 제안하고 오너 승인을 받는다.

이를 보정할 오너 검토판도 총평과 자유서술만 받지 않는다. Q1~Q8과 같은 영역마다
`정상|경미|수정 필요|제외 수준|판정 불가`를 먼저 저장하고 QC 결과는 오너 제출이 끝날 때까지
숨긴다. 언급되지 않은 영역을 임의로 PASS로 해석하지 않으며, 이 영역별 오너 라벨과 각 전문
판정자의 결과를 대조해 담당별 누락·과잉 차단을 계산한다.

### 20.3.7 사용자 피드백 회귀 감사 — 2026-08-13

대화 시각·봉인 산출물·PRD·ADR·실서비스 렌더러를 다시 대조했다. 사용자 직접 결정과 그 결정에
대응하기 위해 만든 보조 안전장치를 같은 등급으로 기록하지 않는다.

**사용자 결정으로 고정한 항목**

- 셀러 사진은 무라벨 낱장으로 흩뿌리지 않고 앞·뒤·상세와 `DOMINANT|CONTEXT`가 픽셀에 적힌
  한 장의 evidence grid로 넣는다.
- 선택 마네킹 → 얼굴 방향 시트 → 전신 방향 시트 → seller grid → 직접 매칭 → service example
  마지막 순서를 유지한다. 뒷면·얼굴 비노출이어도 모델 identity/body 방향 시트를 빼지 않고,
  방향 시트와 중복되는 정면 얼굴 한 장도 추가하지 않는다.
- 포즈는 행동·몸 방향·체중과 지지측·중요 접촉·큰 팔다리 역할·시선·비대칭을 유지하면서
  관절각·손·고개·머리카락·원단에 작은 자연 자유를 준다. 예시의 헤드룸·카메라 거리·화면 속
  인물 크기와 원근도 capture 팔과 무관한 공통 계약이다.
- 일반 `all`은 같은 분위기·톤과 장소 유형의 다른 구체 장소다. `구조 1개 + 소품 배치 2개`
  할당량, 같은 장소 복제, 차이를 위한 화분·가구·간판 추가는 폐기한다. 자연스러운 배경 글자는
  무조건 지우지 않되 고유 브랜드·간판을 그대로 복제하거나 가짜 상호·두드러진 깨진 글자를
  새로 만들지 않는다. 공간 세트는 예시와 다른 새 장소를 한 번 배정한 뒤 세트 내부에서 공유한다.
- raw 쇼핑몰 원본은 내부 연출 원천이며 사용자가 고르는 런타임 자산은 service example이다.
  Gemini Pro와 OpenAI API를 계속 같은 입력으로 비교하고 Codex 내장 결과는 API 수치에 합산하지
  않는다. 품질 게이트는 Gemini 2K/OpenAI medium이며 1K는 기술 스모크 전용이다.
- 첫 결과에서는 중립 가이드·프로필·QC·best-of·재시도·repair·fallback을 끄고 오너가 먼저 본다.
  이후 같은 바이트에 독립 전문 QC를 shadow로 적용한다.

**피드백 대응을 위해 만든 보호장치이며 아직 품질 검증 전인 항목**

- 패널 `usable|uncertain|missing`, 사실 `hard|uncertain`, 라벨 28px·셀 short edge 640px·grid long
  edge 4096px 기준은 입력 불확실성을 세탁하지 않기 위한 실험 안전장치다. 사용자 취지에는
  부합하지만 이 숫자 자체가 오너가 확정한 운영 임계값은 아니다.
- Q0~Q8의 exact 분업, 첫 판정 모델과 2차 판정 모델, 향후 enforce 임계값은 shadow 결과와
  영역별 오너 라벨을 보기 전에는 운영 정본이 아니다.

감사에서 발견한 실제 회귀도 정리했다. 폐기한 장소 수량 규칙이 PRD·공통 계약·ADR 역사 문구뿐
아니라 실제 `cut_plan`, `cut_generate_v1`과 비활성 단일 QC에도 남아 있었고, 라이브 `all` 포즈는

생성·QC를 자연 변주와 bounded pose 계약으로 맞췄다. `bg` 플레이트·공간 세트·horizon·product
예외는 건드리지 않았다.

### 20.4 라운드 3: 운영 활성화와 실프로젝트 스모크

기준선의 입력·촬영·공급자·복구 정책이 확정되면 실제 서비스 프롬프트와 실행기를 소수 스모크에

뒤 오너가 enforce를 별도로 승인한다. 승인 전에는 자동 복구·차단·숨김을 실행하지 않는다.
실험 결과와 문서 갱신만으로 운영 환경을 바꾸지 않으며, 별도 승인을 받은 뒤 소수 스모크를 진행한다.
콘티보드에서 사용자가 고른 색·방향·매칭 의류·예시가 자동값보다 우선해야 하고, 같은 프로젝트의
모든 컷·재생성에서 상품 색·무늬·로고/글자·모델 체형·매칭 의류가 이어지는지 확인한다. 남녀,
상의·하의·아우터·원피스, 풀·미디움, 앞·뒤·비틀어진 방향, 매칭 유·무를 전수 곱하지 않고 작은
coverage matrix로 분산한다. 정확한 수량은 복원된 과거 결정이 아니므로 실행 전에 별도 표로
봉인한다.

양 API 비교는 라운드 2에서 끝내지 않는다. 라운드 3의 대표 고난도 sentinel은 같은 입력으로
Gemini/OpenAI를 계속 짝지어 공급자 강점표와 QC 후 복구율을 갱신하고, 나머지 셀만 잠정 기본
공급자를 쓴다.

실서비스 출력은 한 번 생성하고 바로 사용자에게 내보내지 않는다.

`1차 생성 → 독립 QC → 오류 유형에 맞는 국소 편집·전체 재생성·대체 공급자 → 재QC → 통과분만 출고`

각 복구 시도 뒤 독립 QC를 다시 돌리고, ADR-0010에 따라 재시도는 최대 2회까지만 허용한다.
그 뒤에도 hard fail이 남으면 결과를 숨기고 `HOLD`로 보낸다. 품질 판정은 Gemini 2K/OpenAI
medium을 유지하고, 1K는 점수에 넣지 않는 기술 스모크에만 쓴다. 4K는 최종 통과 후보 일부를
같은 봉인 입력·프롬프트로 재생성해 2K 대비 패턴·원단·얼굴·글자 개선을 비교하는 데만 쓴다.

### 20.5 독립 QC shadow 보정

Stage A부터 오너 판정과 독립 블라인드 QC를 대조한다. 자동 차단은 아직 열지 않는다.
상품 면 혼동, 다른 모델, 직접 매칭 불일치, 심각한 광원 분리처럼 오너가 `제외`한 오류를
안정적으로 잡는 항목만 후보로 남긴다. 작은 소품·미세 주름·취향 차이는 차단하지 않는다.
라운드 2에서는 같은 결과를 오너가 먼저 보고, 그 뒤 QC shadow와 대조한다. QC가 실제 복구를
요청하는 시점은 오너 라벨에 대한 누락과 과잉 차단이 충분히 낮아졌고 오너가 enforce를 승인한
뒤다. 그 전에는 QC 결과로 이미지를 자동 재생성하거나 사용자에게서 숨기지 않는다.

## 21. 단계 A 독립 QC shadow 대조 — 2026-08-12

생성에 관여하지 않은 독립 이미지 판정자는 오너 판정·공급자·guide·반복 번호를 보지 않고
24장을 다시 검사했다. 결과는 `PASS 5 / HOLD 19`였다.

- 오너 `제외` 8장은 독립 QC도 8/8 HOLD했다. 명백한 실패를 놓치지는 않았다.
- 그러나 오너 `좋음` 7장 중 4장도 HOLD했다. 이 상태를 자동 차단기로 쓰면 쓸 수 있는 컷의
  절반 이상을 과하게 막는다.
- 독립 PASS 5장은 오너 기준 `좋음 3 / 수정 수준 2`였다. 즉 작은 차이를 허용하는 기준도
  오너의 출고 판단과 완전히 같지는 않다.

과잉 차단의 주원인은 작은 여밈 모양·미세한 포즈 차이까지 모두 출고 차단으로 취급한 것이다.
그 관찰 자체는 확대 검토용 경고로 가치가 있지만 자동 실패 조건으로 쓰지는 않는다.

**QC 정책 후보:** 다음 shadow에서는 아래처럼 두 층으로 나눈다.

1. `HARD FAIL` — 명백히 다른 모델, 사용자가 고른 매칭 의류 불일치, 앞·뒤 고유 구조 전이,
   심한 길이·실루엣·색상 변화, 인물과 배경의 광원·접지가 명백히 분리된 합성.
2. `WARNING` — 작은 여밈·주름 차이, 포즈가 조금 정적임, 경미한 헤드룸·배경 변주·노출 차이.

자동 재생성이나 차단은 여전히 열지 않는다. 다음 오너 검토 결과에서 이 축소된 `HARD FAIL`만 shadow로
적용해 오너의 제외를 잡으면서 좋음의 과잉 차단을 줄이는지 다시 본다.

자동 차단으로 승격할 표본 수·제외 회수율·좋음 과잉 차단 수치는 19:24 기준에 확정된 결정이
아니다. 라운드 2에서 축소한 `HARD FAIL` 규칙의 실제 누락·과잉 차단을 오너 라벨과 대조한 뒤
수치를 제안하고 별도 승인받는다. 그 전에는 경고와 원인 기록만 남긴다. QC와 오너가 함께 실패로
본 대표 사례에서 `국소 편집 / 전체 재생성 / 대체 공급자`를 비교해 오류 종류별 복구 방식을
정한 뒤에만 프로덕션 파이프라인 배선을 검토한다.

## 22. 예전 생성예시 제작에서는 Codex built-in이 좋았는데 이번에는 약했던 이유

같은 공급자 이름만 보고 두 작업을 같은 난도로 보면 안 된다. 기록을 대조하면 다음 차이가
있다.

| 축 | 쇼핑몰 원본→서비스 생성예시 제작 | 실제 셀러 의류컷 단계 A |
|---|---|---|
| 중심 입력 | 쇼핑몰 연출 앵커 1장 | 마네킹·얼굴 방향 시트·전신 방향 시트·상품·매칭·예시 6장 안팎 |
| 의류 목표 | 같은 카테고리의 새 무채색 의류면 됨 | 셀러의 실제 판매 상품과 매칭 의류를 정확히 보존 |
| 장면 목표 | 원본 한 장의 포즈·카메라·장소를 통제 변주 | 여러 이미지의 서로 다른 권한을 동시에 합성 |
| 프롬프트 | 앵커마다 손·발·고개·카메라·장소·광원을 구체적으로 기술 | 여러 상품에 쓰는 공통 역할·물리 계약 중심 |
| 판정 | 후보 생산 뒤 사람 선별과 필요 시 국소 교정 | 24장 첫 결과를 보정 없이 모두 블라인드 노출 |

예전 예시 프롬프트는 `viewer-left shoe`, 컵을 든 손, 계단에서의 발 위치, 인물 높이 비율,
광원 방향처럼 한 이미지의 실패 가능 지점을 구체적으로 풀어 썼다. 잘못 나왔을 때도 캔버스·
신발처럼 틀린 부분만 고치는 교정 프롬프트를 붙였다. 보관된 v2-staging 영수증 602건 중
93건은 attempt 2 이상이고, 208건은 사람 검토 필요로 기록돼 있다. 우리가 기억하는 좋은
결과는 이 생산·선별 과정을 통과한 결과다.

반면 단계 A는 한 장 안에서 `실제 가디건의 끈`, `다른 파일의 검정 바지`, `방향 시트의 얼굴·
체형`, `생성예시의 포즈·배경`을 동시에 지켜야 했다. Codex built-in은 이 다중 권한 결합에서
예시 옷이나 임의 코디로 돌아가는 경향을 보였다. 이는 예전의 한 연출 앵커 기반 변환 능력과
모순되지 않는다.

또한 예전 영수증의 내장 모델은 `unreported`여서 현재 내장 모델과 같은 버전이라고 증명할 수
없다. 모델 버전 변화 가능성은 부차적 가설로만 남기고, 확인 가능한 주원인은 작업 난도·입력
수와 권한 충돌·맞춤 프롬프트·선별 과정의 차이로 본다. 이 때문에 OpenAI API `gpt-image-2`는
내장 결과와 분리해 같은 `integrated-v4` 기준선에서 다시 확인한다.
