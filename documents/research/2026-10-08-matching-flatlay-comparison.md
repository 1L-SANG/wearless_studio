# 내 옷 정리의 SAM과 Gemini 비교

작업 모델은 gpt-6.1-sol, effort는 xhigh다. 여러 비동기 작업과 과금 경계를 함께 확인하는 작업이므로 xhigh를 사용했다. 이 문서는 2026-10-08의 로컬 실험 근거이며 제품의 모델 선택을 확정한 문서는 아니다.

## 결과와 추천

이번 원본 네 장에서는 **원본을 직접 넣고 보존 지시를 강화한 Nano Banana 2.1**이 가장 잘 보존했다. 이 조건을 매칭 의류 정리의 우선 검토안으로 추천한다. 강화 지시를 적용한 Pro는 이번 새 실험에 포함하지 않았으므로, 모델 자체의 품질 순위를 확정한 결과는 아니다.

후속 [정돈 수준 비교](2026-10-08-matching-garment-tidying.md)에서는 강화 Pro와 두 정돈 강도도 확인했다. 라벨까지 같은 기준으로 다시 확인하자 재사용한 2.1 데님도 완전 보존을 확인하지 못해 종합 판정을 보류했다. 아래의 네 장 통과는 당시 색·구조 중심 검토 기록이며, 후속 종합 세 장 통과와 한 장 보류를 구분한다. 색·워싱·핏의 데님 검사는 여전히 통과다.

| 조건 | 입력과 모델 | 지시 | 통과 | 실패 | 판정 보류 | 평균 Gemini 응답 | 장당 사용량 추정액 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| A | SAM 누끼와 Nano Banana Pro | 기존 | 1 | 2 | 1 | 21.0초 | $0.140 |
| B | 같은 SAM 누끼와 Nano Banana 2.1 | 기존 | 1 | 1 | 2 | 19.3초 | $0.044 |
| C | 원본과 Nano Banana 2.1 | 기존 | 0 | 2 | 2 | 16.7초 | $0.043 |
| D | 원본과 Nano Banana 2.1 | 강화 | 4 | 0 | 0 | 14.2초 | $0.041 |

통과와 실패는 원본 사진의 색, 소재, 구조, 실루엣을 직접 비교한 독립 검토 결과다. 실물 색이나 픽셀 동일성을 판정한 검사는 아니다. 표본은 네 장이고 조건별 한 번만 생성했다. 네 장 통과를 전체 의류의 성공률로 해석하지 않는다. 시간도 네 응답의 관찰값이며 운영 서버 대기나 기동 시간은 포함하지 않는다.

[Google 공식 모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3-pro-image)에 따르면 기존 Gemini 3 Pro Image의 제품명이 Nano Banana Pro이고 모델 코드는 `gemini-3-pro-image`다. 새 모델 코드는 [공식 Nano Banana 2.1 문서](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)에 명시된 `gemini-nano-banana-2.1`이다. 실제 응답의 modelVersion도 각각 이 코드와 일치했다.

## 원본별 보존 결과

| 원본 | A | B | C | D |
| --- | --- | --- | --- | --- |
| 코바늘 가디건 | 판정 보류 | 판정 보류 | 판정 보류 | 통과 |
| 줄무늬 셔츠 | 실패 | 통과 | 판정 보류 | 통과 |
| 워싱 데님 | 통과 | 판정 보류 | 실패 | 통과 |
| 빨간 가디건 | 실패 | 실패 | 실패 | 통과 |

코바늘 가디건은 네 조건 모두 단추 네 개, 주머니 두 개, 반소매와 빨간 배색을 유지했다. D 외에는 목 라벨 글자가 변형돼 완전 보존 판정을 유보했다. 라벨은 색과 실루엣 외의 추가 보존 항목이다.

셔츠는 SAM 중간 단계에서 커프스 일부가 잘렸다. A는 원본의 가로줄 커프스를 없애고 세로줄 소매 끝으로 다시 만들었다. B와 D는 가로줄 커프스와 앞 단추 여섯 개를 유지했다. C는 파란 줄이 매우 옅어져 색 보존 판정을 유보했다.

데님은 A와 D가 불규칙한 워싱과 주름, 긴 기장과 넓은 밑단을 비교적 잘 유지했다. B는 바지 통이 좁아 보이지만 원근 교정과 구분하기 어려웠다. C는 워싱을 매끈한 세로 패치로 다시 그렸고 오른쪽 패치의 황갈색이 강해졌다.

빨간 가디건은 모두 단추 다섯 개와 V넥, 긴소매를 유지했다. D 외에는 원본 사진의 밝은 주황빛 빨강이 어둡고 갈색 기 있는 빨강으로 변했다. SAM을 앞에 넣어도 이 색 변화가 해결되지 않았다.

SAM 중간 결과에는 코바늘 가디건의 옷걸이 조각, 셔츠의 커프스 손실, 데님 가장자리의 작은 배경 조각이 있었다. SAM은 보존한 부분의 RGB를 다시 그리지는 않지만, 잘못 잘라낸 부분은 후속 모델이 원본 근거 없이 복원해야 한다.

## 비교 조건과 기존 서비스의 차이

A와 B는 같은 SAM PNG를 입력했다. C와 D는 같은 원본 PNG를 입력했다. A, B, C의 사용자 지시는 동일한 기존 `matching_flatlay.build_prompt`다. 모든 출력은 1K 정사각형이고 각 요청에 입력 사진 한 장만 넣었다. 온도는 기본값이다. Pro는 기존 호출처럼 thinking을 지정하지 않았고, 2.1은 공식 기본값 medium을 명시했다. 모델별 thinking 지원과 기본값이 달라 모든 생성 설정이 동일하다고 주장하지 않는다.

줄무늬 셔츠의 SAM 결과는 기존 `cutout_color_agrees`에서 delta 10으로 탈락했다. 실제 서비스에서는 후속 Gemini를 호출하지 않고 원본을 유지한다. 모델 비교를 위해 이번 실험에서만 A와 B의 후속 생성을 진행했고, 비교 HTML과 plan에 그 차이를 표시했다. 제품의 검사 규칙은 바꾸지 않았다. 표의 A와 B 시간과 비용은 이 비교용 호출을 포함한다.

기존 로컬 SAM 캐시는 네 원본 모두 없었다. 제품의 `sam_service.segmentation.Sam2Segmenter`와 `matching_cutout.flatten_on_bg`를 직접 사용했다. 모델은 `facebook/sam2.1-hiera-tiny`, 공개 가중치 revision은 `de431c4043854a71d8101e17995dfe596bf101a5`, 알고리즘은 `sam2-grid8-v3`, grid는 8, 추론 축소는 0이다. 로컬 MPS에서 torch 2.14.0과 transformers 4.57.6으로 실행했다. 운영 바이너리와 실행 환경이 동일하다고 확인한 것은 아니다.

최초 모델 로딩은 8.026초였다. 코바늘 가디건, 셔츠, 데님, 빨간 가디건의 로컬 추론은 각각 6.195초, 2.554초, 3.069초, 2.392초였다. 두 Gemini 모델에는 이 누끼 결과를 재사용했다. 이 수치를 운영 SAM의 CPU 추론, 콜드 스타트, 대기 시간으로 해석하지 않는다.

## 강화 시스템 지시의 근거

[Google 프롬프트 설계 문서](https://ai.google.dev/gemini-api/docs/prompting-strategies)의 명확한 구조와 중요 제약 우선 배치, [시스템 지시 문서](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/learn/prompts/system-instructions)의 공통 행동 규칙 분리, [이미지 편집 문서](https://ai.google.dev/gemini-api/docs/image-generation)의 변경 영역 한정과 구체적 세부 보존을 적용했다.

상품 색과 구조, 비율 보존을 배경 정리와 보기 좋은 자세보다 우선했다. 원본에 찍힌 색을 유지하고, 조명 보정으로 실제 색을 추측하지 않도록 했다. 단추와 주머니, 커프스, 워싱과 밑단 폭을 구체적으로 적었다. 이미 사용 가능한 자세는 유지하고, 숨은 구조를 지어내야 할 정도로 펼치지 않도록 했다. 공통 규칙은 실제 API의 `systemInstruction`으로, 사진별 관찰은 사용자 요청으로 전달했다. [API 규격](https://ai.google.dev/api/generate-content)에 맞는 별도 시스템 필드를 썼다.

정확한 강화 지시는 같은 폴더의 `matching-flatlay-preservation-system-20261008.txt`에 보관한다. 프롬프트는 보존을 보장하지 않는다. D는 시스템 필드와 사용자 지시를 함께 바꿨으므로 시스템 필드 하나만의 효과를 분리한 실험은 아니다.

## 승인과 사용량

사용자가 최대 16회 비교를 승인했다. 실제 유료 HTTP 요청은 정확히 16회이며 Pro 네 회, 2.1 열두 회다. 모두 HTTP 200과 최종 이미지 한 장을 반환했다. 재시도, 모델 자동 전환, 추가 재생성은 없었다. 요청마다 60초 제한을 적용했다. 모델 응답 성공 16건을 보존 검사 성공 16건으로 보고하지 않는다.

[공식 Standard 가격표](https://ai.google.dev/gemini-api/docs/pricing)에 따르면 이미지 출력 예상액은 약 $0.94였다. 입력과 텍스트, thinking까지 응답 사용량으로 계산한 추정액은 **$1.0704525**다. 청구서를 확인한 금액은 아니다. A의 합계는 $0.560442, B는 $0.1747575, C는 $0.17157, D는 $0.163683이다.

가격 계산은 출력 이미지 토큰과 나머지 텍스트 토큰을 구분하고 thinking을 별도로 합산했다. 응답은 출력 세부 항목에 이미지 토큰만 기록하면서 총 출력에는 텍스트도 포함했다. TEXT와 IMAGE만 요청했으므로 이미지 상세와 총 출력의 차이를 텍스트로 집계했다. Pro의 입력 이미지 한 장은 공식 고정값 560 토큰으로 계산했다. 원시 ledger는 보존하고 집계는 별도 summary 파일에 남겼다.

운영 DB와 R2, AWS, 배포에는 접근하지 않았다. SAM은 공개 가중치를 로컬로 다운로드해 계산했다. 실제 운영비 감소는 확인하지 않았다. 제품 전처리와 마네킹 색감 마스크에는 SAM이 여전히 쓰이므로, 매칭 의류에서 SAM을 생략해도 서버 비용이 같은 비율로 줄지는 않는다.

## 검증과 로컬 산출물

실험 비용 경계, 모델별 상한, 첫 실패 중단, 재실행 방지, 입력 해시 공유, SAM 검사 미통과 표시, 실응답 사용량 계산을 확인하는 오프라인 pytest 19개가 통과했다. 이 추가 작업은 실험과 문서이며 제품 코드의 기본 모델과 프롬프트는 바꾸지 않았다.

제품 코드의 직전 전체 검증은 서버 pytest 7,698개 통과와 104개 건너뜀, 프론트 테스트 2,806개 통과, 빌드 통과다. 이번 문서 작업에서 전체 제품 테스트를 다시 실행한 결과는 아니다. 104개는 별도 테스트 DB 설정, 선택 모델 가중치, 샘플과 라이브러리 등 환경 조건에 따른 건너뜀이다.

로컬 증거는 요청한 워크트리의 `.scratch/bg-removal-3min/nano-banana-2.1/`에 있다. `comparison.html`은 원본, SAM 중간 결과와 새 16장을 보여 준다. `plan.json`과 조건별 prompt JSON은 입력과 지시, `ledger.json`은 원시 사용량, `results-summary.json`은 시간과 추정 비용, `quality-review.json`은 독립 보존 판정이다. `prepare-local-sam.py`와 `experiment.py`, `test_experiment.py`도 같은 폴더에 있다. 수집 원본과 생성 이미지는 커밋하지 않는다.

비교 HTML의 폰 다섯 폭과 WebKit 스크린샷, 자동 줄바꿈 검사는 못 했다. Chrome 연결이 시간 초과됐고 내장 브라우저는 로컬 파일 URL을 보안 정책으로 차단했다. 이미지는 파일 도구로 직접 확인했다. 제품의 실제 대기 안내는 새 셀러 흐름의 도달 경로 확인이 남아 있어 기존 PR을 초안으로 유지한다.

## 쉬운 설명

같은 옷 네 장을 네 방식으로 정리했다. 이번에는 원본을 2.1에 직접 넣고 옷을 바꾸지 말라는 지시를 구체화한 방식이 더 잘 보존했고 응답 시간과 호출 비용도 낮았다. SAM이 먼저 옷 일부를 잘라낼 수 있다는 점도 확인했다. 이 방식을 우선 검토하되, 네 장만으로 전체 품질을 보장하지 않고 Pro 강화 지시와 더 다양한 의류는 미검증으로 남긴다.
