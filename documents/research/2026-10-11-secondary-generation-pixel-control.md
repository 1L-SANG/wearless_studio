# 2차 생성에서 바꾸지 않을 부분을 서버가 고정하는 방법

실사용 작업 모델은 gpt-6.1-sol, effort xhigh다. 사용자가 단추 모양이 바뀌는 원인은 생성 AI의 문제이며 2차 생성에서 제어할 방법을 찾아야 한다고 지적했다. 맞는 구분이다. QC는 잘못 만든 결과를 발견하고 채택을 막으며, 생성기의 보존 능력을 직접 보장하지 않는다.

## 권장하는 제어

같은 사진의 제한된 부분 보정에서는 AI가 전체 프레임을 최종 결과로 다시 그리게 하지 않는다. 수정 부위의 후보만 만들고, 서버가 허용 마스크 안의 픽셀만 되붙인다. 나머지는 보정 전 사진의 실제 RGB 픽셀을 그대로 쓴다. 수정하지 않을 단추와 로고 등은 크롭 내부에 있어도 마스크의 보호 영역으로 뺀다. 경계 부드럽게 처리는 허용 영역 안에서만 한다.

서버의 L 마스크는 0이면 보존, 양수이면 반영한다. OpenAI 입력 마스크는 투명한 alpha 0이 수정 부위이므로 같은 파일을 그대로 재사용할 수 없으며 의미를 맞춰 변환해야 한다.

| 단계 | 이전 시험 | 권장하는 같은 프레임 보정 |
| --- | --- | --- |
| 생성 | 현재 전신과 원본을 넣어 전신 편집 응답을 받음 | 같은 부위 크롭과 원본 Detail로 수정 후보를 받음 |
| 전체 사진 반영 | 전체 응답 또는 지역 그림을 보조로 한 새 전신 응답 | 서버가 허용한 픽셀만 교체하고 나머지는 Before로 고정 |
| 작은 장식 | 좋은 지역 그림도 전신 재생성에서 다른 장식으로 바뀔 수 있음 | 지역 그림을 또 전신 AI에 보내 그리게 하지 않음 |
| 검사 | 보정 목표와 다른 부위의 보존을 모델이 판단 | 밖 픽셀은 코드로 비교하고, 수정 부위의 원본 일치와 경계 품질은 검사 |

이 방식이 확실하게 막는 것은 허용 영역 밖의 변화다. 마스크 안에서 AI가 정확한 원본 단추를 그리는 것까지 수학적으로 보장하는 방법은 아니다. 원래 틀렸던 단추를 그대로 보호하면 오류도 보존된다. 이미 맞는 부분을 보존하는 것과 틀린 부분을 정확히 복원하는 것을 분리해야 한다.

[OpenAI 공식 이미지 문서](https://developers.openai.com/api/docs/guides/image-generation)의 GPT Image 마스크는 모델의 지시 자료이며 정확한 경계 준수를 보장하지 않는다. 이전 마스크 시험의 후보를 그대로 채택해서는 코드의 픽셀 불변 계약이 생기지 않는다. API 마스크는 생성 보조로 쓰고, 실제 출력 반영 범위를 서버에서 별도로 고정하는 것이 필요하다.

저장소의 `server/app/agents/face_mask_lock.py:198`부터 있는 `put_back`은 얼굴 후보를 크롭 영역의 알파로 되붙이는 기존 예다. `face_identity`의 합성 테스트도 마스크 밖 픽셀 불변을 검사한다. 얼굴 전용 마스크와 경험 상수를 의류에 가져오지 않고, 이번에는 별도 작은 연구 함수로 같은 원리를 확인했다.

## 실제 로컬 검증

이전 [마네킹 생성 연구](2026-10-11-sol-mannequin-generation-repair-results.md)의 시험 불량 세 단추 Before와 이미 만든 지역 그림을 재사용했다. 새 이미지 생성 요청은 0회다. 지역 그림은 원본 사진의 권위를 갖지 않으며, 최종 검수에는 실제 원본 Front, Back, Detail을 유지했다.

처음 단추판 전체를 허용했을 때는 마스크 밖 픽셀을 보존해도 마스크 안의 끝점이 바뀔 수 있었다. 다음 좁은 마스크의 검수도 하단 이동을 잡았다. 확대 확인 결과 실제 하단 약 y752부터 y775가 당시 허용 y596부터 y772 안에 있었다. 처음 무료 검사에서 하단으로 잡은 y780부터 y823은 실제 끝점 좌표가 아니었다. 이것은 범위 선택 오류이며 코드의 마스크 밖 보존 실패와 다르다.

마지막 v4는 원본 좌표 `(693,596,726,752)`의 내부만 허용하고, 실제 하단을 포함한 외곽과 목둘레, 가슴 절개를 제외했다. 수정 전후 native 1536×2304 PNG를 비교해 허용된 4960픽셀 밖 **3,533,984픽셀의 변경 0개**를 확인했다. 하단 y752부터 y775도 동일하다. PNG를 저장한 뒤 다시 읽어 확인했으며 파일 bytes 자체가 동일하다는 뜻은 아니다.

최종 Sol의 원래 응답은 `protected_regions_unchanged=true`, 회귀 이유 없음이다. 다섯 단추와 끝점, 나머지 옷의 보존을 확인했다. 하지만 실제 전신 사진의 작은 단추에서 정확한 표면과 구멍은 판독이 어려워 fasteners를 UNJUDGEABLE로 남기고 `target_resolved=false`를 반환했다. 기존 연구 가드는 필수 부위 미확인을 전후 인증에도 반영해 보정본을 채택하지 않았다. 이 보류를 새로운 단추판 회귀 FAIL이라고 보고하지 않는다.

QC 로그를 보지 않은 독립 native 검토도 다섯 단추와 고른 간격, 기존 하단의 동일 픽셀을 확인했다. 눈에 띄는 사각 색띠와 이중 끝점은 발견하지 못했다. 정확한 구멍과 입체 표면은 미확인이며 기존 어깨 능선은 그대로 남는다.

별도 무료 제어 대조에서는 어깨 부위만 허용해 기존 전체 생성 후보에서 그 부위 픽셀만 반영했다. 기존 단추 영역의 픽셀은 변경 0개다. 이는 어깨 보정의 자연스러움이나 원본 장식 품질 검증이 아니라, 생성 후보에 다른 단추가 있어도 서버가 보호 영역에 반영하지 않는다는 검증이다.

## 검사와 비용

전체 응답을 그대로 받는 단순 재현에서 무료 테스트 8 실패와 1 통과를 확인한 뒤, 픽셀 고정 함수에서 9 통과를 확인했다. 보호 영역과 크롭 안의 구멍, 경계 번짐, 잘못된 마스크, 빈 범위, 투명 후보와 비율 변경 거절을 검사했다. 기존 얼굴 합성의 마스크 밖 불변 테스트 2개도 통과했다. 마지막 합계는 **11 통과, 실패 0**이다.

이 추가 시험의 유료 호출은 Sol high 전후 검사 두 번과 Gemini 베이스 검사 두 번, 총 텍스트 4회이며 생성 0회다. 추정 추가 $0.157478, 새 $5 승인 연구의 누적은 **$2.468074**다. 누적 POST 46회는 이미지 10회와 텍스트 36회다. 미확인과 예약은 0이고 과거 $8 원장은 변경하지 않았다. 모든 이번 응답의 정상 종료와 요청 모델, usage를 확인했다.

v3 준비 중 이전 단계의 검사 비용이 빠진 비용 기준을 발견해 v3 유료 호출은 하지 않았다. v4는 완료된 v2의 $2.393792와 44 POST를 정확히 이월했다. 최초 준비 결과와 실패 기록, 각 계획과 해시는 보존했다. 코드와 실제 자료는 `.scratch/bg-removal-3min/generation-control-20261011`에 있다. 최종 후보는 `endpoint-locked-v4/locked.png`이고 이미지와 비공개 응답은 커밋하지 않는다.

제품 코드와 운영 설정, 화면은 바꾸지 않았다. 전체 서버와 프론트 테스트, 빌드는 이미 확인한 제품 코드에서 재실행하지 않았다. 이번에는 DB 연결 테스트가 필요하지 않아 접속 실패로 건너뛴 검사도 없다. 연구 함수는 UI 비도달이며 운영에서 이미 픽셀을 고정한다는 보고가 아니다.

## 일반 적용에 필요한 경계

수동으로 확인한 이 한 샘플의 좌표를 다른 의류에 그대로 쓸 수 없다. 수정할 부위, 보호할 단추와 절개, 실제 끝점을 같은 현재 이미지 좌표에서 검증해야 한다. 좌표가 모호하거나 보호 영역과 충돌하면 보정을 진행하지 않는 경계가 필요하다. 마스크 안의 원단도 바뀔 수 있다.

이전 지역 생성은 입력과 출력 비율이 달랐다. 이번에는 늘이지 않고 생성 그림 중앙을 잘라 크롭 비율에 맞췄으며 변환을 기록했다. 중앙 크롭과 축소가 원본 장식의 정합과 기하를 보장하지는 않는다. 실제 제품 경로는 생성 전부터 크롭, 패딩과 되붙일 좌표 변환을 고정해야 한다. 나중의 전체 리사이즈와 JPEG 저장 등은 여기의 native PNG 픽셀 불변 주장 밖이다.

같은 프레임의 소매선이나 밑단 보정에는 이 경계를 적용할 수 있다. 마네킹에서 새로운 사람 착장으로 바꾸거나 포즈와 핏을 크게 바꾸는 생성은 같은 좌표가 아니므로 그대로 붙일 수 없다. 그 경로의 단추와 로고는 실제 원본 디테일을 직접 공급하고 위치와 원근을 별도로 맞춰야 한다. 원본에서 디테일을 추출해 정합하는 후보 방식도 고려할 수 있지만 이번에 검증하지 않았다.

## 쉬운 설명

AI가 소매를 고치다가 멀쩡한 단추까지 바꾸는 문제는 서버가 단추 픽셀을 그대로 보존하면 막을 수 있다. 이번에는 실제 사진에서 그 고정이 작동했다. 다만 수정 범위를 잘못 잡으면 단추판 끝점도 바뀔 수 있어 범위 확인이 필수다. 원래 틀린 단추를 원본처럼 만드는 문제는 여전히 별도로 확인해야 한다. 전체 그림을 계속 다시 그리는 보정보다 이 제한 반영 방식을 추천한다.
