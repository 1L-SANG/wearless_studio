## 3. 핵심 발견

### 3.1 정보 섹션은 전 플랫폼 공통 + 전부 정형 데이터
이미지 컷을 뺀 나머지 — 사이즈표, 케어/세탁, 법정 고시표, 배송·교환 공지 — 는 성별·플랫폼 불문 반복 등장하며, 구조가 표/폼으로 완전히 정형화되어 있다. 그런데 현업은 이를 매번 포토샵에서 이미지로 다시 그린다. wearless의 현 자동 블록(size=단일 실측 4칸 타일, care=고정 1문장 — `server/app/agents/page_assembler.py:148-215`)은 실물 대비 크게 빈약해 업그레이드 여지가 크다.

### 3.2 성별(플랫폼)별 차이는 "정보의 결"
- **남성향(무신사 성향)** — 데이터·검증 지향: 핏 도식 비교 가이드, 키×몸무게 추천 사이즈 매트릭스(남/녀 표), 기능성 테스트리포트, 모델 스펙 캡션
- **여성향(에이블리 성향)** — 감성·연출 지향: 국+영 타이포 헤더, 특징 3종 아이콘 카드, MODEL INFO 다인 스펙 카드, 거울샷 실착, 컬러명 라벨, "구매 전 확인" 공지
- 코어(사이즈·케어·고시·공지)는 동일하므로, 기능은 전원 제공하고 성별은 추천·기본값에만 반영하는 설계가 맞다 (확정 방향).

### 3.3 색상별 반복은 남녀 공통 최대 노동 (후속 기회)
디미트리 7색×모델컷, 프랑제이 5색×3컷타입 — 같은 구도의 색만 다른 반복 제작이 소호·중소브랜드의 최대 공수. wearless는 wardrobe가 이미 colorId로 그룹화되어 있어(`server/app/routes.py:1117-1139`) "색상 변형 섹션 복제"의 데이터 기반이 존재한다. 단, 컷 영역이므로 이번 범위에서 제외하고 후속 백로그로 남긴다.

## 4. 기능 도출 (2026-07-29 확정 범위)

원칙: **제품 컷 파이프라인(콘티→AI 컷 생성→page_assembler 자동 조립)은 그대로**. 에디터는 그 결과물을 최종 수정하는 곳이고, 여기에 정보 블록 시스템을 추가한다. brand/soho **UI 분기 없음** — 전 기능 노출, `analysis.targetGenders`는 추천 배지·프리필·템플릿 기본값에만 사용.

- 정보 코어 4종: 사이즈표(사이즈 행×실측 열 + 실측도 슬롯), 법정 고시표, 케어 가이드(소재별 문구 라이브러리), 배송/교환 공지
- 성별 차이 5종: 핏 가이드, 추천 사이즈 매트릭스, 타이포 헤더, 특징 아이콘 카드, 모델 스펙 카드
- 정보 템플릿: 작은 스타일 토글(브랜드형/소호형) + 정보 블록 세트 일괄 삽입 (컷 블록 불변)

### 후속 백로그
- 색상 변형 섹션 복제 (wardrobe colorId 스왑)
- 풀페이지 템플릿 / page_assembler 아키타입 테마 / 컷 프롬프트 톤("Musinsa/Ably" 하드코딩, `server/prompts/cut_generate_v1.txt:35`) 파라미터화
- PRD §10.14 "값 없으면 `정보 입력 필요` 자동 배치"
