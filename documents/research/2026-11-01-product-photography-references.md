Threads는 검색 도구로 열리지 않았으나 숨김 브라우저에서 공개 게시물을 확인했다. [Instagram](https://www.instagram.com/framestudio_kr/)은 공개 프로필과 썸네일만 확인했고 개별 캡션과 전체 캐러셀은 로그인 제한으로 읽지 못했다. 썸네일에 보이는 지지체를 최종 납품 결함이라고 단정하지 않는다. 이미지 원본을 복제하거나 서비스 카탈로그에 넣지 않았다.

## 구현에 적용한 해석

이 절은 스튜디오가 공개한 생성 기술이 아니라, 관찰을 바탕으로 한 구현 결정이다.

- 세 방식 모두 판매 상품의 색, 실제 글자, 패턴, 버튼과 포켓, 봉제, 실루엣을 원본에서 보존한다.
- 고스트는 제품을 부풀리는 효과가 아니라 자연스러운 입체 지지와 빈 목, 소매 공간을 표현한다. 원본에서 알 수 없는 라벨과 안감은 추측하지 않는다.
- 평면은 정면의 정돈된 단독 상품사진이다. 지지체는 보이지 않고, 몸통이 차 있는 듯한 부피와 강제 바닥 시점은 배제한다.
- 자연광은 밝은 실제 배경과 부드러운 조명, 일관된 그림자를 사용한다. 야외 장소와 노란 색조를 강제하지 않는다.
- 상품 원본의 앞뒷면과 색은 예시보다 우선한다. 같은 상품의 촬영 방식을 바꿔도 디자인은 바뀌면 안 된다.

## 모델과 프롬프트

| 모델 | 정확한 ID | 비교 가설, 아직 제품컷 실측 전 |
|---|---|---|
| Nano Banana 2.1 | `gemini-nano-banana-2.1` | 효율적인 반복 제작 후보. 원단과 로고 보존을 먼저 확인한다. |
| Nano Banana Pro | `gemini-3-pro-image` | 복잡한 구조와 다중 원본 활용 후보. 비용 대비 승인 가능한 결과의 비율을 확인한다. |
| GPT Image 2.5 Flare | `gpt-image-2.5-flare` | 빠른 일반 상품컷 후보. 같은 조건에서 Sunburst와 차이를 측정한다. |
| GPT Image 2.5 Sunburst | `gpt-image-2.5-sunburst` | 까다로운 질감과 구조의 품질 기준 후보. 검증 전 자동 기본 모델로 바꾸지 않는다. |

Google은 [Nano Banana 2.1](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)을 효율 중심의 이미지 생성·편집 모델로 설명한다. [공식 이미지 생성 문서](https://ai.google.dev/gemini-api/docs/image-generation)는 Nano Banana Pro와 구분한다. 저장소의 과거 실험에서도 두 ID는 서로 다르다. 사용자 표현의 숫자 구분은 확인 질문을 남겼으며, 네 모델 목록은 현재 비교 후보로 기록한다.

OpenAI의 [공식 프롬프트 가이드](https://developers.openai.com/api/docs/guides/image-prompting)는 Flare의 속도와 Sunburst의 품질 지향을 구분하고, 같은 원본·프롬프트·크기·품질로 먼저 비교하도록 권한다. 그래서 첫 시험의 프롬프트는 공통으로 고정한다. 이후 실패 유형이 확인되면 모델별 지시를 하나씩 바꿔 별도 실험한다. 모델 이름만 보고 서로 다른 긴 프롬프트를 쓰면 모델 효과와 문구 효과를 구분할 수 없다.

앱의 이미지 편집 API는 텍스트 `prompt`와 이미지 입력을 받는다. 여기서 말하는 시스템 프롬프트는 앱이 조립하는 고정 촬영 지침이며, 별도의 API `system` 역할이 전달된다고 주장하지 않는다. 이미지 입력별 역할과 변경할 것, 보존할 것을 분리한다.

## 평가 방법

세 방식의 준수, 상품 구조, 색, 소재, 글자, 윤곽을 각각 확인한다. 점수를 평균내어 단추나 로고 오류를 숨기지 않는다. 상품 식별에 영향을 주는 오류는 별도 실패로 표시한다. 속도와 비용은 전체 호출이 아니라 사용 가능한 결과 한 장당으로도 계산한다.

사용자가 15달러 한도의 실험을 승인해 네 카테고리로 범위를 확정했다. 줄무늬 셔츠, 배색 스티치 바지, 크로셰 카디건, 초록색 원피스를 사용한다. 각 촬영 방식에 Gemini 두 모델은 한 번씩, GPT 두 모델은 공통 지시와 모델별 지시를 한 번씩 적용한다. 총 72회이며 GPT 48회, Gemini 24회다. 원본, 출력, 프롬프트, 모델, 요청 설정과 실제 크기, 시간, 사용량을 함께 남긴다. 임의의 백분율 유사도나 스튜디오 대비 99% 달성 수치는 만들지 않는다.

실행 전 비용은 현재 [Google 가격](https://ai.google.dev/gemini-api/docs/pricing)과 저장소의 가격표, 과거 실험 사용량을 근거로 보수적으로 잡는다. 요청당 예약액은 API 사업자가 보장하는 청구 상한이 아니다. 실행 횟수와 사용량은 비교 폴더의 결과 기록을 정본으로 삼는다.
