# 기존 QC와 부위 근거를 연결한 수정안의 비교 결과

실사용 작업 모델은 gpt-6.1-sol, effort는 xhigh다. 오너가 같은 원본의 Before/After 비교 최대 52회와 Google 및 OpenAI API로의 사진 전송을 승인했다. 실제 요청은 30회였으며 모두 HTTP 200과 usage를 받았다. 운영 코드와 저장 계약을 바꾸거나 배포하지 않았다.

## 무엇을 유지하고 무엇을 고쳤나

기존 QC 모델, 판정 스키마와 임계, 베이스 검사와 보정 체계는 유지했다. 수정 조건에만 앞뒤 밑단과 팔 연결 등 부위 관찰, 원본 부위와 결과 상체 확대를 기존 검사 요청에 함께 전달했다. 생성에도 같은 부위 자료를 사용했다. 검사 AI를 따로 추가하거나 전체 체계를 교체한 실험은 아니다.

| 단계 | Before | After 제안 |
| --- | --- | --- |
| 구조 분석 | 옷 전체 밑단 한 값과 소매 형태 이름 같은 요약을 사용한다. | 앞 밑단과 뒷자락, 양팔 경계와 실제 솔기를 부위별로 구분한다. |
| 생성 | 기존 원본 구조 요약을 전달한다. | 부위 자료와 원본에서 확인한 위치 관계를 보존한다. |
| QC | 기존 원본과 생성본을 비교한다. | 같은 검사에 부위 근거와 확대 입력을 연결하고 원본 픽셀을 우선한다. |
| 보정 | 기존 검사에서 지적한 부분을 수정한다. | 같은 부위와 위치 근거로 수정하고 기존 체계에서 재검사한다. |

미래 제품안에서는 기존 AG-01 호출에 부위 질문을 통합하는 것을 우선한다. 이번 실험은 저장된 분석을 바꾸지 않기 위해 원본에서 별도 실험용 부위 자료를 두 번 추출했다. 같은 사진에 두 QC를 적용하는 교차 검사도 실험 측정으로만 수행했다. 제품에 두 분석과 두 QC를 상시 붙이는 구현은 아니다. 입력 이미지와 자료가 늘면 토큰과 시간은 증가할 수 있다.

## 통제한 조건

흰 셔츠와 핑크 헨리넥의 원본 다섯 장을 사용했다. 원본과 기존 비구조 분석, 분류와 성별, 자동 핏, 베이스와 매칭, Sunburst native 1K와 medium, Pro 검사 설정을 고정했다. 정돈은 사용하지 않았다. Before도 같은 조건에서 새로 생성했으며 앞선 실험의 사진을 새 결과로 재사용하지 않았다.

새 부위 관찰은 흰 셔츠 앞 직선·뒤 곡선, 긴 소매 부착을 분리했다. 핑크는 양팔을 continuous_panel_bound_edge로 기록하고 실제 가슴 곡선 절개를 관찰했다. 오너의 정답을 새 AI 관찰에 수동 주입하지 않았다. 기존 분석 JSON과 사진 해시, 서명을 다시 작성하지 않았다.

## 첫 비교와 발견된 회귀

첫 수정안은 흰 셔츠 앞 밑단을 기존보다 직선에 가깝게 만들었다. 그러나 실제 드롭숄더 연결선이 어깨 위로 올라가고 품과 기장이 작아 보였다. 독립 시각 검수에서도 이 회귀를 확인했다. 전체 상품 보존 성공으로 세지 않았다.

실험용 변환기가 구조 관련 옛 요약을 넓게 제거하면서 원본에서 이미 확인된 drop_shoulder_seam의 위치 관계까지 삭제한 것을 확인했다. 같은 부착 소매라는 관찰만 남기면 소매 연결의 위치를 잃을 수 있었다. 무료 재현 검사에서 그 위치 사실이 누락되는 실패를 확인하고, 분류명만의 cap sleeve 단정과 전체 혼합 밑단 요약을 제거하되 유효한 위치 관계는 유지하도록 수정했다. 생성과 QC에 같은 관계를 전달했다.

첫 어댑터 코드는 region-v1.py에 원래 snapshot 해시와 일치하는 상태로 보존했다. 첫 결과와 요청, 원장은 덮어쓰지 않았다. 같은 승인 총량 안에서 흰 셔츠의 수정 조건만 한 번 더 확인했고 새 부위 분석은 다시 호출하지 않았다. 원본과 기존 분석, 최초 부위 관찰, 모델과 다른 조건은 같았다. 이는 첫 수정안과 같은 단일 조건의 반복이 아니라 어댑터 결함을 수정한 추가 확인이다.

## 사진의 실제 Before와 After

| 품목 | Before | After와 한계 |
| --- | --- | --- |
| 흰 셔츠 | 드롭숄더는 보이지만 앞 밑단을 둥글게 표현했다. | 첫 수정안의 어깨 회귀를 고친 재확인에서는 드롭숄더가 유지됐다. 최초 사진에 긴 뒷자락이 빠졌고 QC가 이를 지적해 수정 한 번을 실행했다. 최종 사진은 우측 뒤의 긴 뒷자락 일부가 보이며 앞뒤 길이 차이가 회복됐다. 정확한 전체 기장과 핏은 보류다. |
| 핑크 헨리넥 | 우측 어깨에 몸판과 짧은 소매를 나누는 듯한 선이 있었다. 실제 가슴 절개와 다섯 단추는 이미 보였다. | 이 선이 약해져 넓은 연장 어깨에 가까워졌다. 가슴 절개와 단추는 유지됐다. 다만 밑단이 더 짧고 직선에 가까워져 기장 보존과 단추 세부는 보류다. |

흰 셔츠 최종 앞 가장자리에는 자연스러운 약한 굴곡이 남는다. 픽셀상 완전한 수평 직선이라고 표현하지 않는다. 앞 직선·뒤 곡선인 재단 구조와 착용 사진에서 보이는 입체 드레이프를 구분한다. 전면 3/4 사진으로 뒤 전체 곡선을 검증한 것은 아니다.

직접 검수와 독립 검수를 모두 수행했다. 네 첫 조건의 final은 직접 본 첫 생성과 픽셀이 같았고 재확인 final은 보정 02와 픽셀이 같았다. 선택한 최종 사진만 제시하지 않고 첫 수정안과 재확인 보정 전후를 보고서에 함께 남겼다.

## QC 자체가 나아졌는가

같은 첫 사진을 반대 방식의 QC로도 검사했다. 이 측정은 다른 생성 사진의 변동을 제외하고 검사 판정 차이를 보는 참고다.

핑크 수정 사진에서 기존 QC는 실제 보이는 가슴 절개를 없다고 지적했다. 부위 근거를 받은 QC는 보이는 절개와 연속 어깨를 인정했다. 이런 오판 감소 신호는 있었다. 다만 각 검사 한 번이며 같은 모델의 판정 변동도 포함한다.

반면 흰 셔츠 기존 사진의 잘못된 앞 밑단을 부위 근거가 있는 QC도 통과시켰다. 첫 수정안의 올라간 어깨와 줄어든 여유도 놓쳤다. 유효한 위치 관계를 유지한 재확인에서는 긴 뒷자락 누락을 major로 지적하고 보정을 실행했지만, 이것만으로 검사 일관성 전체를 입증하지 못한다.

재확인 보정 후 의류 QC 이벤트는 pass였으나 저장된 결과 상태는 needs_review다. 원래 흰 셔츠 첫 조건 둘은 auto_pass, 핑크 첫 조건 둘은 needs_review였다. 자동 판정의 pass와 실제 상품 충실도, 저장 상태를 구분했다. 모든 문제를 잡는 QC로 개선됐다고 주장하지 않는다.

## 비용과 요청

실제 POST 30회는 Flash 부위 관찰 2회, Sunburst 이미지 6회, Pro 검사 22회다. 이미지 여섯 장에는 네 최초 조건과 흰 셔츠 재확인 최초 및 보정이 포함된다. 사용량 추정 총액은 $1.0156685이며 실제 청구서를 확인하지 않았다. 실패 응답과 시간 초과, 사용량 미확인은 없었다.

첫 비교는 22회였고 재확인은 8회였다. 두 원장을 합산해 최초 이미지 12회와 텍스트 40회, 전체 52회 상한을 유지했다. 흰 셔츠 after의 이미지 요청도 첫 수정안 한 장과 재확인 두 장으로 셀별 세 번을 넘지 않았다. 같은 원본의 부위 관찰을 재생성하거나 처음 실패한 사진을 숨기지 않았다.

부위 확대와 교차 검사는 실험의 입력과 비용에 포함된다. 결과 이미지의 목표 부위 변화와 기존 또는 보강 QC의 오판을 따로 보았으며, 제품 운영의 큐와 사용자 체감 시간 또는 전체 서버비 절감 측정은 아니다.

## 권장 판단

기존 QC를 유지하고 분석 표현과 검사 근거를 보강하는 방향은 유효한 개선 신호가 있다. 특히 앞뒤 구분과 연장 어깨를 범주명으로 단정하지 않는 관찰은 나아졌다. 유효한 기존 기하 정보를 버리지 않는 것이 함께 필요하다.

다만 현재 프로토타입을 그대로 운영에 넣을 단계는 아니다. QC가 일부 실제 문제를 여전히 통과시키고 기장·핏 보존과 반복 안정성도 확인되지 않았다. 다음 제품 구현은 앞뒤와 부위별 계약, 두 사실 투영 소비자와 구 버전 호환, 위치 관계의 보존, 초기부터 모든 보정 후 검사까지를 함께 다뤄야 한다. 실제 소매가 있는 옷, 연장 어깨, 앞뒤 밑단이 다른 옷과 잘린 사진을 반례로 반복 검사해야 한다. 항상 재생성하거나 운영 specialist를 바로 켜는 방식으로 대신하지 않는다.

## 검증과 못 한 것

무료 재현 검사 14개가 통과했다. 부위 구분과 원본 바인딩, 미확인 단정 거절, 실제 부착선 보존, 생성 확대의 역할과 실제 전체 이미지 해시, 부모 입력 레지스트리와 원본 파일 동결을 확인했다. 드롭숄더 위치 관계 삭제의 실패를 재현한 뒤 수정했고 재확인도 처음 승인한 전체·셀별 요청 한도에 합산되는 것을 확인했다. 비교 HTML 이미지 참조 14개는 파일 존재를 확인했다.

제품 코드를 바꾸지 않아 전체 서버 pytest와 프론트 검사, 빌드는 이번에 다시 실행하지 않았다. 이 비교는 실험용 어댑터가 적용된 로컬 후보 생성·검수 경로이며 운영 저장·화면·정산·알림, 다른 생성 소비자의 버전 호환까지 구현한 것이 아니다. DB 테스트도 이번에 새로 실행하지 않았다.

모바일 다섯 폭과 WebKit의 스크린샷 및 줄바꿈·가로 넘침 검사는 브라우저 로컬 파일 제한으로 수행하지 못했다. 기존 비교 보고서의 keep-all과 balance 스타일을 유지하고 실제 사진을 직접 확인했다. 새 스타일로 제품 화면을 바꾸지 않았다.

원본과 생성 사진, 입력 crop, API 인증값과 원시 응답은 커밋하지 않는다. 로컬 폴더 `.scratch/bg-removal-3min/view-region-ab-20261009`에 before-after-overview.png, comparison.html, 처음 결과와 revision-geometry를 보존했다.

## 쉬운 설명

검사 AI를 갈아엎지 않고 옷의 부위 정보를 연결해 실제로 비교했다. 앞뒤 밑단과 팔 쪽 선은 나아졌지만 다른 구조 정보도 지켜야 했고, 검사가 놓치는 문제는 남았다. 개선 방향은 확인했으나 전체 품질과 안정성을 보장하는 제품 수정은 아직 아니다.
