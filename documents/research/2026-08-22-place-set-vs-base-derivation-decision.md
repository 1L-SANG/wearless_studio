## 2. Claude 독립 분석

### 2.1 프레이밍: "어느 쪽"이 아니라 "어느 층"의 문제

A와 B는 같은 층에서 경쟁하는 대안이 아니다. 세 층으로 갈라진다.

1. **소비 계약(런타임이 무엇을 읽는가)** — 공간 세트 manifest(SeriesPlan). 이미 확정·발행·배선된 계약이고, A든 B든 결과물을 담는 그릇으로 계속 유효하다.
2. **제작 공장(세트 멤버를 어떻게 만드는가)** — 여기가 진짜 갈림길. (A) 수집 실사 멀티뷰를 원천으로 멤버를 독립 생성 vs (B-오프라인) 베이스 1장에서 warp/파생으로 멤버를 제작.
3. **런타임 기능(사용자에게 파생을 직접 노출하는가)** — "이 컷과 같은 장소로 더" 버튼. B의 최종 형태이지만 별도 게이트가 필요한 미래 기능.

방식 B를 "베이스 1장만 남기고 세트를 없앤다"로 읽으면 층 2와 층 3을 한 번에 바꾸는 것인데, 층 3의 기술이 아직 ±15°+LaMa 수준이라 지금은 성립하지 않는다.

### 2.2 각도별 평가

**① 품질·공간 일관성**
- A의 멤버는 각자 독립 생성되고 `sameSpace` 게이트는 지각 기준("이어 찍은 것으로 보임")이다. 실제 기하(창·가구 위치)는 멤버 간 드리프트할 수 있다 — 상세페이지에서 인접 배치되면 어긋남이 보일 수 있는 구조적 한계.
- B의 warp 파생은 ±15° 안에서는 **기하학적으로 진짜 같은 공간**이다(같은 픽셀의 재투영). 일관성만 보면 봉투 안에서는 A보다 강하다.
- 그러나 상세페이지가 요구하는 컷 다양성(풀↔미디움, 정면↔사이드↔백, 문가↔창가)은 ±15°를 훨씬 넘는다. 단일 이미지 NVS는 안 보이던 기하를 복원할 수 없고, 역앵글·공간 반대편은 원리적으로 불가능하다. 디퓨전 인페인트로 봉투를 넓히면 이번엔 발명된 기하가 늘어나 "베이스와 같은 공간"이라는 근거 자체가 약해진다.
- 결론: **B는 '위치 변주'(±15°, 리프레이밍, 시차)를 주고, A는 '컷 커버리지'(다양한 샷·방향)를 준다. 오늘 기준 서로 대체재가 아니다.**

**② 저작권·법률·평판**
- 발행 자산은 생성물이고 수집 원본은 내부에만 있지만, 제작 파이프라인이 권리 미확인 수집물에 의존한다는 사실이 문서에 명문화돼 있다(eval v2 §15). 쇼핑몰은 잠재 고객군이라 분쟁 시 평판 타격이 이중이다.
- B는 이 의존을 끊는다. 베이스는 텍스트/자체 레퍼런스에서 생성 가능 — **권리 관점에서 B 방향이 명확히 우월**.

**③ 라이브러리 확장성·콘텐츠 운영**
- A의 병목은 "같은 공간을 여러 각도로 찍은 실사 시리즈"의 희소성이다. 대부분의 몰 상세페이지는 체계적 멀티뷰를 찍지 않는다. 세트 1개 추가 = 수집·선별 노동 + 권리 노출 증가.
- B-오프라인은 베이스 1장(이미지 콜 1회)에서 시작하므로 장소 무한 확장. 노동이 '수집'에서 'QC'로 이동하는데 QC는 이미 체계가 있다(공간 세트 5게이트, HOLD 정책).
- **확장성은 B 압승. 단, 오프라인 제작+사람 검수로 쓸 때 이야기다.**

**④ 런타임 비용·지연**
- A는 런타임에 GPU 단계를 추가하지 않는다(레퍼런스 첨부만).
- B-런타임은 요청마다 depth+warp+inpaint+재적용이 붙는다. 마네킹 지연을 102초→단축하려고 싸운 직후이고, AWS 비용 절감 트랙에서 GPU 상시 서버를 0대로 만든 방향과 정면 충돌한다. sam2식 온디맨드 기동을 재활용해도 콜드스타트 지연이 붙는다.
- **런타임 관점에서는 A(사전 제작 소비)가 명확히 우월. B는 오프라인에서 돌리면 이 비용이 소멸.**

**⑤ 기술 리스크·일정**
- A: 지금 작동한다. 릴리스 도구·UI·서버 레지스트리 전부 있음.
- B: 스파이크 수준. 남은 난제 = ±15° 초과(디퓨전 인페인터), 피사체 인식 크롭, 인물 재배치·의류 재적용 fidelity(Qwen 경로는 로고를 깨먹은 전례), QC 자동화. 특히 **전문 QC 파일럿이 hard 오류를 놓친 현재, 사람 검수 없는 런타임 파생은 출고 사고로 직결**된다.
- 다행히 두 문서가 이미 부품을 갖고 있다: warp된 장면 플레이트(B) + SCENE_SCAFFOLD/GARMENT_APPLY(2단계 파이프라인) 조합이 "장면 고정 멤버 생성"이 된다. 순수 연구가 아니라 조립 문제에 가깝다.

**⑥ 셀러 UX**
- "같은 장소로 여러 컷" UX는 B가 없어도 성립한다 — 첫 컷(시그니처 컷)을 세트의 plate/멤버에 앵커하면 이후 컷은 형제 멤버로 뽑으면 된다(A로 구현 가능).
- B만이 주는 UX는 "라이브러리에 **없는** 장소"(사용자가 좋아한 임의 컷, 자체 업로드 배경)의 확장이다. 진짜 차별점이지만 오늘의 핵심 경로는 아니다.
- 수요 실측(자체 hook_composition 40건): 같은 촬영 연속 프레임을 쓴 후킹이 32.5%(13/40), "같은 공간 연속극"이 명명된 장치로 반복 등장. **같은 공간 멀티컷은 실재하는 상세페이지 문법이지만 지배적 문법은 아니다** — 공급 능력은 갖추되(세트 유지), 모든 것을 엄격 기하 일관성에 걸 필요는 없다는 방증.
- ±15° 한계 상태로 "다른 위치컷"을 팔면 기대(백뷰·반대편)와 실제(약간 옆) 간 격차로 실망을 산다. 노출한다면 "리프레이밍/줌/미세 앵글 변주"로 정직하게 스코프해야 한다.

**⑦ 차별화·해자**
- 수집 기반 A는 해자가 없다(누구나 수집 가능 + 권리 부채).
- 장면 고정 파생 파이프라인(B)은 눈에 보이는 품질 해자이고 특허 각도(핏 폐루프 다음 후보)로도 유효하다. 파생 과정에서 쌓이는 "같은 장면 멀티뷰 페어" 데이터는 장차 자체 모델 학습 자산이 된다.

**⑧ 대표 실패 모드**
- A 계속: 몰 권리 분쟁 1건으로 라이브러리 제작이 동결되는 시나리오. 세트 간 기하 드리프트로 인접 컷 어긋남 지적.
- B 몰빵: 파생 엔진이 ±15°를 못 넘는 채 라이브러리 성장이 멈추고, 런타임 왜곡 이미지(휘어진 문틀, 녹은 가구)가 구매자에게 출고되는 시나리오.

### 2.3 결론 (단호하게)

**B를 방향으로, A를 다리로.** 구체적으로:

1. **소비 계약(공간 세트)은 유지한다.** 런타임은 계속 사전 제작·검수된 세트를 소비한다. "베이스 1장만 두고 런타임 파생"은 지금 채택하지 않는다.
2. **세트 제작 공장을 갈아끼운다**: 신규 세트는 수집 실사 시리즈 대신 **베이스 1장 → warp/scaffold 파생 → 멤버 생성 → 사람 QC → 기존 계약으로 발행**(B-오프라인)으로 만든다. 권리 의존을 끊고 장소 확장을 연다. 지금 만들고 있는 ComfyUI 실험 인프라가 정확히 이 공장의 발판이다.
3. **수집 기반 신규 세트 제작은 권리 확인 전까지 동결**한다(기존 56세트는 유지, 소스 사용 이력만 봉인).
4. **런타임 '같은 장소 다른 위치컷' 버튼은 게이트 통과 전 노출 금지.** 그 전까지 B의 사용자 가치는 "시그니처 컷을 세트에 앵커 → 형제 멤버로 확장"으로 A가 대신 전달한다.

### 2.5 이 추천이 뒤집히는 조건

- 디퓨전 인페인터 실험이 ±45°+에서 구조 보존과 의류 fidelity를 빠르게 입증하면 → 층 3(런타임 파생)을 앞당기고 라이브러리를 베이스 중심으로 축소하는 순수 B 노선이 열린다.
- 반대로 파생 멤버의 오너 좋음률이 수집형 대비 크게 낮으면(G1 실패) → 공장 전환을 보류하고, 권리 확인을 서둘러 수집형을 유지하는 A 노선이 남는다.
- G4에서 "같은 공간 연속 컷"이 실제 상세페이지에서 드물다고 나오면 → 문제 자체의 우선순위가 내려가고, 세트도 파생도 아닌 "같은 무드 다른 장소"로 충분할 수 있다.

## 3. Codex 독립 분석 (요약)

원문 세션: Codex `01a025d4-3fbf-7840-85f1-92e91328ff11` (10분 18초, effort 최대). 아래는 충실 요약이며, 코드 인용은 이 세션에서 재검증한 것만 남겼다.

**최종 추천 (Codex)**: "혼합안 — 런타임은 A의 사전 제작·검수 공간 세트 계약을 유지하되, 신규 세트의 제작 원천을 권리 깨끗한 베이스 장면 → 오프라인 파생 → 사람 QC → 공간 세트 발행(B-오프라인)으로 단계 전환. 권리 미확인 쇼핑몰 실사를 이용한 신규 제작은 중단. 순수 B 런타임(베이스 1장 보관 + 요청마다 NVS)은 채택하지 않음. B의 첫 운영 형태는 런타임 기능이 아니라 오프라인 공간세트 제작 도구."

Codex 고유 논거·발견:

1. **현행 계약이 워프 복제를 명시적으로 금지** — 공간 세트 생성 프롬프트는 "never a warped, stretched or re-cropped copy of another cut"(`server/prompts/cut_generate_v1.txt` SPACE CONTINUITY 절), 페이지 QC도 "warped or re-cropped duplicates ... fail"(`server/prompts/page_output_qc_v1.txt` space_continuity). **B의 워프 산출물을 멤버로 그대로 출고하는 것은 현행 계약 위반** — B는 내부 scaffold/plate 제작용이거나 계약 개정이 선행돼야 함.
2. **같은 장소 블록은 시장 필수 코어** — `documents/cut_composition_research.md`: 같은 장소 2~4컷 블록이 **31/35 상품**(run 최빈 3컷), 필수 코어로 분류. 회전 트리오(정면→3/4→뒷면)는 시퀀스 1위지만 ×10 전량 쿠어 + 인사일런스 2상품이라 "쿠어 정형"(브랜드 귀속)임.
3. **스파이크 "로고·얼굴 100% 보존" 주장 반박** — `warp_nvs.py`는 보존율을 **인페인트 마스크 비율**(`preserved = 1-(mask>0).mean()`)로만 계산하고 동일도 측정이 없으며, 결과를 `quality=92` JPEG로 재인코딩 + LaMa 후 리사이즈함. 확대 시 어깨·팔·건축물 경계 찢어짐·번짐 관찰. 즉 "원본 픽셀 보존"은 미측정 주장.
4. **런타임 B는 인프라 방향과 충돌** — warp+LaMa 반복 구간 7.4~17.8초(로딩 제외), sam2 온디맨드 설계의 콜드스타트 101초+, 두 단계 파일럿 97~114초 vs 원샷 63초. 추가로 **에디터 vary 경로는 현재 QC가 없음**(`editor_image_job.py`: "vary 경로는 QC·메타 모두 무변경").
5. **에디터에 이미 '같은 장소 이미지 생성' 진입점 존재 + 라벨이 서버 동작과 정반대** — 도달 경로: 에디터 → 이미지 선택 → AI 탭 → 현재 이미지 수정. `EditorPanels.jsx` 주석·코드상 변경 미선택 → 버튼 "같은 장소 이미지 생성" → `changes=[]` 전송 → 서버(`cut_variator.py`)는 빈 배열을 "비슷한 컷 만들기"로 해석. 반대로 변경 선택 → 버튼 "비슷한 컷 만들기" → 같은 장소 유지 프롬프트. **라벨 2개가 맞바뀐 상태**(이 세션에서 코드로 확인).
6. **보안**: `mockups/nvs_angle_spike/stage2/run_chain.sh` 3행에 **HF 토큰 평문 노출** — 즉시 폐기·회전 권고(이 세션에서 확인. mockups/는 gitignore라 커밋은 안 되나, 8/22 윈도우 미러 이전 39파일에 포함됐는지 확인 필요).
7. **법률**: 한국 저작권법상 복제권·2차적저작물작성권, 공정이용은 종합 판단 — "내부 참고"나 "결과가 조금 다름"만으로 자동 면책 아님(국가법령정보센터·한국저작권위원회 안내서 인용). 기존 65세트도 출처·이용근거·식별가능성 감사 권고.
8. **manifest v2 제안** — 현행 v1은 세트당 plate 1장. B 파생을 정식화하려면 멤버별 `memberPlate` + 카메라·깊이·마스크·원천 해시 영수증을 담는 v2를 별도 스테이징으로(기존 v1 소비자 무회귀).
9. **결정 게이트 G0~G8**: 권리 원장(G0) → 스파이크 재현성·수치 정합(G1) → 오프라인 B 품질 블라인드(G2: hard fail 0·sameSpace ≥95%·선호 ≥60%) → 제작 경제성(G3: 총비용/승인 세트) → 계약·릴리스(G4) → 자동 QC(G5: hard fail 회수율 ≥95%, 현재 미통과라 런타임 자동 출고 금지) → 런타임 성능(G6: p95 +≤30초·원가 ≤1.25배) → 셀러 UX(G7: 요청형 사용률 15% 미만이면 후순위) → 특허(G8: 결합 청구만, 선행조사 선행).

## 4. 두 분석 비교·종합

### 4.1 수렴 (독립 분석이 같은 결론에 도달)

| 항목 | Claude | Codex |
|---|---|---|
| 최종 노선 | "B를 방향으로, A를 다리로" — 세트 계약 유지 + 제작 공장을 파생형으로 전환 | 동일 구조의 혼합안 |
| 순수 B 런타임 | 게이트 전 노출 금지 | 채택 불가, 마지막 단계 |
| 수집 원천 신규 제작 | 권리 확인 전 동결 | 동일 (더 강하게: 기존 세트 감사까지) |
| ±15° 한계 해석 | "위치 변주"는 되지만 "컷 커버리지"는 불가 | 동일 + 종이 인형 효과·경계 왜곡 실측 |
| QC 자동화 미성숙 | 전문 QC hard miss → 런타임 파생 위험 | 동일 (G5 미통과 명시) |
| 과도기 UX | 시그니처 컷을 세트에 앵커 → 형제 멤버 확장 | 사전 제작 형제 컷 추천 |
| 정직한 명칭 | "리프레이밍/줌/미세 앵글 변주"로 스코프 | 동일 |

서로 결론을 모른 채 두 모델이 같은 구조(소비 계약 유지 / 제작 원천 교체 / 런타임 유예)에 도달한 것 자체가 이 노선의 신뢰 근거다.

### 4.2 Codex가 잡고 Claude가 놓친 것 (전부 코드 재검증 완료)

- 워프 복제 금지가 이미 프롬프트·QC 계약에 있다는 사실(§3-1) → "B-오프라인도 워프 결과를 그대로 멤버로 쓸 수 없고, **워프는 후보/plate 생성까지만, 최종 멤버는 재렌더링**"이라는 구현 제약이 확정됨.
- 같은 장소 블록 31/35 실측(§3-2) → Claude의 후킹 32.5%만으로는 수요를 과소평가할 뻔함. 종합하면: **본문에서는 거의 보편(31/35), 후킹에서는 1/3** — 같은 장소 멀티컷 공급 능력은 필수, 단 회전 트리오 같은 큰 시점 변화는 카메라 이동(NVS)이 아니라 **모델이 도는 것**이라 장면 고정 재렌더링(현행 A 방식)으로 달성 가능.
- 스파이크 "100% 보존" 주장의 측정 공백(§3-3) → 스파이크 재현성 게이트(G1)에 무손실 PNG·동일도 실측 추가 필요.
- 세트 수 65·212(Claude는 56으로 구버전 인용), 평문 HF 토큰, 에디터 라벨 스왑, vary 무QC.

### 4.3 Claude가 잡고 Codex가 안 다룬 것

- 후킹 첫 화면에서의 같은 촬영 사용률 32.5% 실측(hook_composition.jsonl) — 첫 화면 문법에서는 지배적이지 않음.
- 인물 재배치 다리(pose_gen)의 GPU abort 실패 기록(chain.log) — Codex는 "산출물 부재"로 추정했고 Claude는 실패 로그로 확정.
- 파생 과정에서 쌓이는 "같은 장면 멀티뷰 페어" 데이터의 학습 자산 가치.

### 4.4 남는 이견

실질 이견은 없음. 강조점 차이만 있다: Codex는 기존 65세트의 소급 권리 감사까지 요구(더 보수적), Claude는 기존 세트 유지 + 소스 이력 봉인 수준. 절충: **신규 동결은 즉시, 소급 감사는 변호사 상담 결과에 따라**.
