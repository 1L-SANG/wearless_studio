# 남성 베이스 운영 반영과 체크셔츠 반복 비교 결과

실사용 작업 모델은 gpt-6.1-sol, effort는 xhigh다. 오너가 남성 베이스 운영 반영의 좁은 예외와 앞면 통제 비교 최대 여섯 번을 승인했다.

## 남성 베이스의 실제 운영 반영

선택한 내장 Codex 원본을 새 객체 `seed/mannequin/base-men-native-20261009-fd984e5e2b79.png`로 등록했다. 버킷은 현재 API가 쓰는 wearless이며 seed/public asset id는 `2da88ae4-aa72-45d9-bb1a-7f5853224b3f`다. RGB PNG 1024×1536, 1533135바이트, SHA256 `fd984e5e2b798831098a07feb1d1feae47968ba8793d04ed51f41b2267f691f2`를 실제 R2 반환 바이트와 DB 행에서 확인했다. 기존 객체와 기존 seed 행은 그대로 보존했다.

승인된 운영 조회에서 API의 기존 task definition은 `wearless-use1-api:195`였고 남성 id도 작업 브랜치의 기존 값과 일치했다. 현재 운영 모델은 Sunburst 1K여서 이번 반복 비교의 모델과 출력 설정도 일치했다.

새 task definition `wearless-use1-api:196`은 남성 환경변수 `MANNEQUIN_BASE_MEN_ASSET_ID` 하나만 새 번호로 바꾼다. 등록 요청을 역으로 복원했을 때 기존 요청과 동일함을 확인했다. 여성 값, 비밀 참조와 다른 설정, 이미지 URI는 유지했다. 실행 이미지의 ECR 태그 digest도 실제 기존 태스크와 같음을 확인했다.

반영 전 실행 중인 잡이 0개인 것을 집계로 확인하고 API 서비스만 롤링 교체했다. 새 revision의 정상 태스크 1개, pending 0개, 단일 배포 COMPLETED, 기존 태스크 STOPPED를 확인했다. 새 API 이미지 digest는 교체 전과 같은 `sha256:86ad187b098fc1ddc6a273662309377ded2f0ac16ba7069aacd073bb136b1e6b`다. 서버 코드를 재빌드하거나 다른 서비스를 배포하지 않았다.

원복 자료는 로컬 `men-base-replacement-20261009` 폴더의 이전 service와 task definition, 실행 태스크 및 기존 seed 메타데이터다. 이전 revision 195와 에셋 `736ff2ab-0f15-4f9a-b2ee-c40cd0ed7ee0`를 보존했다. 기존 생성컷과 정상 저장 마스크는 다시 만들지 않았다. 다만 과거 컷의 캐시 없는 마스크 준비와 베이스 관측은 실행 당시 global 베이스를 참조하는 현재 동작이 있으므로 이 반영은 그 기준도 바꾼다. 실제 마스크 품질 저하를 재현한 결과는 없으며 후속 작업의 영향은 앞선 준비 문서에 기록했다.

같은 항목을 manifest에도 바꿨다. 남성 설정 한 줄만 담은 별도 브랜치 `codex/men-native-base-20261009`, 커밋 `4d867bfd986167227025725ffb3e648c67a8439a`로 최신 origin/main 기준의 설정 PR을 준비했다. 이 PR을 main에 반영하기 전에는 main의 이전 manifest로 하는 후속 Copilot 배포가 이전 id를 다시 가져올 수 있다. main 머지는 하지 않았다.

## 체크셔츠의 변인통제 실행

원본 앞면과 앞서 만든 가벼운 정돈 앞면을 각각 세 번 생성했다. 순서는 원본, 가벼움, 가벼움, 원본, 원본, 가벼움이다. 여섯 번 모두 같은 새 남성 베이스와 같은 지시문, Back와 Detail, 매칭 바지, 모델과 quality, 출력 크기를 썼다. PNG 해시와 역할 순서를 확인했다.

모든 입력은 실제 sRGB PNG로 준비했고 앞면은 같은 2048×2048 캔버스로 맞췄다. Display P3 원본은 ICC 변환했고 태그 없는 RGB는 sRGB로 해석하는 가정을 기록했다. 원본 비율을 유지하며 부족한 부분은 여백으로 채웠다. 정돈본이 바꾼 옷 배치와 점유율, 완성한 밑단과 상품 세부 차이는 남는다. 따라서 주름 하나만의 인과 효과가 아니라 Front 대체의 효과를 통제해 비교했다.

HTTP POST는 승인한 여섯 번만 실행했다. 모두 HTTP 200과 1024×1536 이미지 한 장씩 반환됐다. 사용량 추정 합계는 $0.406656이며 개별 요청은 모두 $0.067776이다. 캐시 입력 할인을 적용하지 않았고 청구서 금액은 확인하지 않았다. 새 Gemini 정돈 호출과 실패 재시도, 다른 모델 전환은 없었다.

## 직접 검수와 독립 검수

정돈 Front가 상품 재현을 꾸준히 개선했다는 근거는 이번에도 부족하다. 원본군도 정돈 없이 자연스러운 착장이 나왔다. 여섯 결과 모두 네이비 바탕과 여러 가는 선이 묶인 체크 계열은 유지했고 굵은 몇 줄로 완전히 바뀐 실패는 보이지 않았다. 정확한 미세 선 순서와 간격, 반복 수는 보류다.

| 결과 | 관찰 |
| --- | --- |
| 원본 1회 | 앞을 열고 흰 이너를 노출했다. 자연스러운 여유가 있으며 단추 세부는 보류다. |
| 원본 2회 | 앞을 닫은 안정적이고 깔끔한 착장이다. 미세 체크 정확성은 보류다. |
| 원본 3회 | 앞을 닫았지만 가슴 단추가 작은 고리처럼 깨지고 아래 일부 단추도 조각처럼 보인다. 바지 노란 워싱은 약하다. |
| 가벼운 정돈 1회 | 앞을 열었다. 일부 단추 형태가 흐리다. 반대편 밝은 고리는 단추구멍일 수 있어 추가 단추로 단정하지 않는다. |
| 가벼운 정돈 2회 | 앞을 닫은 깔끔한 착장이다. 원본 2회보다 명확히 좋다고 보기 어렵고 바지 워싱은 비교적 잘 보인다. |
| 가벼운 정돈 3회 | 앞을 열었다. 단추는 비교적 구분되지만 정확한 수는 보류다. 셔츠가 짧아 보이고 바지 워싱은 약하다. |

정돈군 세 장은 원본군보다 모두 조금 짧아 보였다. 머리와 발 프레임이 같아 반복되는 차이로 관찰할 수 있으나, 원본 Front 밑단이 프레임에 닿고 입력 점유율도 달라 어느 기장이 정확한지는 확정하지 못한다. 두 조건 모두 자연스러운 여유가 있는 착장이며 주요 칼라와 커프스, 긴소매와 손발, 전신 프레임은 유지됐다.

원본은 열림 1장과 닫힘 2장, 정돈은 열림 2장과 닫힘 1장이다. 현재 지시문이 열림을 금지하지 않으므로 실패율이 아니라 스타일 변동으로 기록한다. 자연스러운 착용 주름도 실패로 세지 않았다. 바지 여유와 밑단 접힘, 노란 워싱도 조건 내에서 흔들려 정돈군이 더 일관적이라고 볼 수 없다.

## 왜 제품컷의 보기 좋은 정도와 착장이 다른가

작은 제품컷에서는 배경과 옷 배치가 정리된 이득이 먼저 보인다. 그러나 정돈 사진의 미세 패턴과 단추 구조, 옷의 비율이 달라지면 다음 생성이 받는 상품 근거도 달라진다. 원본 Back와 Detail을 그대로 넣었으므로 정돈 Front와 일부 근거가 서로 다를 가능성도 있다. 실제로 정돈 Front의 라벨과 단추 구멍이 바뀐 점은 앞선 검수에서 확인했다.

여기에 생성 변동이 섞인다. 이번처럼 외부 조건을 맞추고 반복해도 두 군 모두 일부 단추와 워싱이 흔들렸다. 어느 내부 원인이 먼저 작용했는지는 확인하지 못했으며, 색공간 통일로 문제를 해결했다고 단정하지 않는다. 한 번의 원본 성공과 정돈 실패를 전처리의 일반적인 성패로 확대하지 않는다.

현재 권장안은 이 체크셔츠의 주상품 마네킹에는 원본을 기본 입력으로 유지하는 것이다. 보기 좋은 가벼운 정돈 제품컷을 카드에 쓰는 판단과 마네킹 전처리의 이득을 분리한다. 이 결과로 기본 상품 전처리나 자동 QC 기준을 바꾸지 않았다.

## 검증과 한계

무료 통제 검사 네 개와 운영 설정의 남성 값 단독 변경 검사 두 개가 통과했다. 실제 R2 바이트와 DB seed 메타데이터, 요청 설정과 실행 이미지 동일성, API 롤링 완료와 이전 태스크 종료를 확인했다. 실제 여섯 이미지도 직접 보고 독립 검수를 반영했다.

연구와 설정 한 값 변경이며 서버 코드와 화면은 바꾸지 않았다. 앞선 작업 브랜치 제품 코드의 전체 검사 결과는 서버 7698 통과와 104 조건부 건너뜀, 프론트 2806 통과, 빌드 통과다. 이번 단계에서 로컬 전체 검사를 다시 실행하지 않았다.

별도 설정 PR [497](https://github.com/1L-SANG/wearless_studio/pull/497)의 최신 main 기준 CI는 일반 서버 7737 통과와 97 건너뜀, 분리 DB 검사 227 통과와 1 건너뜀으로 성공했다. 실행 번호는 37826163023이며 두 검사 범위는 CI에서 분리돼 있다. 합계는 7964 통과와 98 건너뜀이다. Vercel 검사도 성공했다. 이 CI는 별도 설정 브랜치에 대한 결과이며 기존 연구 브랜치의 로컬 검사와 섞어 설명하지 않는다. CI 요약에는 건너뜀의 개별 이유가 나오지 않았다.

새 비교 HTML의 모바일 다섯 폭과 WebKit 검사는 브라우저 연결 및 로컬 파일 제한으로 수행하지 못했다.

이번 생성은 AG-01 계약과 Front crop, 유료 QC 및 자동 보정 없는 첫 생성 분기다. 전 운영 흐름을 실행한 검사와 구분한다. 각 세 번도 소표본이며 다른 의류의 품질과 모든 세부 재현을 보장하지 않는다.

로컬 운영 자료는 `.scratch/bg-removal-3min/men-base-replacement-20261009`, 비교 자료는 `.scratch/bg-removal-3min/check-shirt-front-control-20261009`에 저장했다. 후자에 요청 계획과 입력 해시, ICC 기록, 여섯 결과, usage와 원시 응답, 비교 HTML 및 `six-result-comparison.png`가 있다. 사진과 비밀값은 커밋하지 않는다. AWS CLI 세션 인증값과 API가 사용하는 DB 및 R2 인증값은 메모리에서만 사용하고 출력하거나 파일에 보관하지 않았다.

## 쉬운 설명

남성 기본 몸 사진은 선택한 우측 후보로 운영에 반영했다. 프로그램은 같은 이미지를 유지하고 몸 사진 번호만 바꿨다. 체크셔츠는 같은 조건에서 앞면만 바꿔 세 번씩 봤지만 정돈본이 더 정확하다는 이득은 확인하지 못했다. 제품컷을 깔끔하게 보이게 하는 것과 실제 상품을 더 정확하게 입히는 것은 별개다.
