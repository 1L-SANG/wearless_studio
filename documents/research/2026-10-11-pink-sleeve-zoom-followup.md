## 비교 조건

기존 실제 마네킹 워커에서 저장한 핑크 C0 입력을 사용했다. 기존 입력에도 원본 Front, Back, Detail과 Front의 상·중·하 crop, 베이스와 매칭 의류가 포함된다.

A는 이 기존 입력이고 B만 소매 앞뒤의 원래 픽셀 crop 두 장을 더한다. 두 조건의 지시문은 완전히 같으며 추가 사진이 있으면 같은 상품의 부위 근거로만 쓰도록 설명했다. 기존 프롬프트에 이 공통 설명을 추가했으므로 과거 운영 요청과 완전히 같은 대조라고 부르지 않는다. 실제 HTTP 요청의 기존 8장 bytes와 지시문, 모델, 크기와 품질이 같은지 확인했다.

Front crop은 원본 768×1024의 `(520,150,768,650)`, Back crop은 `(540,230,768,620)`이다. 각각 248×500과 228×390이며 원래 RGB와 ICC를 유지했다. 확대 재샘플링과 AI 복원은 없다. 새로 가까이서 촬영한 사진도 아니다. 두 crop을 추가한 묶음의 효과를 시험하며 각각의 효과를 분리하지 않았다.

두 조건은 각각 두 번, A1, B1, A2, B2 순서로 생성했다. 요청 모델은 gpt-image-2.5-sunburst, medium, 1536×2304다. 생성 seed는 통제하지 않았으며 한 개발 의류의 네 결과를 일반 정확도로 확대하지 않는다.

네 장 모두 실제 외곽 바인딩, 가슴 곡선 절개와 다섯 단추는 보인다. 내부 선이 실제 추가 봉제인지, 단추의 미세 장식과 반투명도가 정확한지는 미확인이다. 가장 약한 소매 선을 만든 079도 전체 상품 보존의 성공이나 채택 대상으로 인증하지 않았다. 독립 검토자는 조건 배정, 생성 지시문과 QC 답안을 보지 않았다.

이 표본에서는 소매 crop을 더한 조건의 일관된 우세가 보이지 않는다. 그렇다고 모든 crop이나 새 근접 사진이 무효라는 뜻도 아니다. 원본 픽셀을 잘라 보여 주는 것은 모델의 주목을 돕지만 원래 없는 촬영 정보를 더하지 않는다.

생성 요청의 원본 분석에는 `cap sleeve cut`이라는 분류도 남아 있다. 이 말이 일반적인 별도 소매 구조로 해석될 수 있다는 것은 추가 검증할 가설이다. 이번 실험은 해당 문구만 바꾸는 대조가 아니므로 발생 원인으로 확정하지 않는다. 별도 부착선의 존재와 소매 길이 분류를 구분하는 구조 관찰, 생성 시 해당 관찰의 반영, 생성 결과의 부위 검수가 다음 검증 방향이다.

## 검증과 비용

무료 실험 검증 8개가 통과했다. 기존 이미지 한도는 이전 단계에 유지하고 이번 비교에만 네 장을 추가했다. 총 $15 제한, $14부터 새 호출 중단, 비용 미확인 중단과 자동 재시도 금지를 유지했다. 요청 전에는 입력 해시와 crop 원픽셀·ICC를 확인했고, 생성 뒤 실제 HTTP의 공통 사진 bytes와 프롬프트 및 설정 동일성을 확인했다. 비교 그림의 네 crop도 저장된 결과의 RGB와 정확히 같다.

추가 이미지 POST는 4회, 추정 비용은 $0.352244다. 별도 $15 승인 원장 누적은 80 POST, 이미지 28회와 텍스트 52회, 추정 $12.681341다. 예약 중인 금액, 미확인 비용과 실행 중 요청은 0이다. 이전 $8과 $5 원장은 유지했다.

제품 코드 변경이 없어 성공한 전체 서버 8,702 통과와 108 건너뜀, 프론트 3,276 통과와 build 결과를 반복 실행하지 않았다. 머지 커밋의 기존 자동 테스트와 배포가 별도로 성공했다. 새 근접 촬영, 새로운 독립 의류, 정상 착용 정답 및 미세 장식 전체는 검증하지 않았다. 이번에 화면을 바꾸지 않아 모바일 스크린샷 검사는 실행하지 않았다.

## 촬영과 고도화에 대한 판단

가까운 사진이 꼭 필요한 것은 아니다. 기존 전체 사진에서 구조가 충분히 보이면 우선 그 근거를 사용해야 한다. 봉제와 주름이 구분되지 않거나 라벨과 장식이 너무 작을 때는 전체 앞뒤 사진을 유지하면서 해당 부위 앞뒤의 선명한 근접 사진을 추가하는 편이 낫다. 단순 디지털 확대와 실제 근접 촬영을 혼동하지 않는다.

[OpenAI의 이미지 평가 예제](https://developers.openai.com/cookbook/examples/multimodal/image_evals)는 의류 동일성과 봉제 같은 세부 검수에 crop을 보조 수단으로 설명한다. [Vision 안내](https://developers.openai.com/api/docs/guides/images-vision)는 판독과 개수 오류가 가능하고 입력 이미지가 처리 중 조정될 수 있음을 설명한다. 확대 입력만으로 생성 정확성을 보장한다는 근거는 아니다.

## 쉬운 설명

검수 보강은 실제 서버에 반영됐다. 핑크 소매를 따로 크게 보여 줘도 거슬리는 선이 남았으므로 촬영 탓만으로 보기 어렵다. 원본을 다시 찍는 것을 필수로 만들기보다 소매가 실제로 어떻게 연결돼 있는지 판단해 생성과 부위 검사에 함께 전달하는 방향을 추천한다.
