# 의류 검수와 재생성 제어 실험

작성일은 2026년 10월 11일이다. 주 작업과 코드 검증 모델은 gpt-6.1-sol, effort xhigh다. 외부 설계 검토는 Claude Fable 5.1의 max, GPT-6 Astra의 xhigh로 수행했다. 모델 합의와 검사 코드의 통과를 사진 정확도의 증명으로 취급하지 않았다.

## 문제와 이번 제품 변경

옷 사진을 새로 만들면서 단추가 늘거나 작은 장식이 단순해질 수 있다. 검수가 이를 놓칠 수도 있고, 잘 보이지 않는 뒤쪽이나 주름을 오류라고 단정할 수도 있다. 수정 지시만 전달한 전체 재생성은 이미 잘 나온 부위도 다시 그린다.

이번 제품 수정은 기존 QC에 다음 경계를 보강한다.

1. 고정 검수 정책을 OpenAI의 developer 메시지와 Gemini의 systemInstruction으로 전달한다. 상품 사진, 셀러 자유 문구와 원본 관찰은 데이터 영역에 둔다.
2. 검수 호출부가 서버에서 검증한 소유권 열거값, 실제 사진 순서, 부위 종류와 원본 순번만 별도 정책에 넣는다. crop 좌표, 상품 이름, 셀러 문구와 모델 관찰을 높은 권한으로 올리지 않는다. 잘못되거나 빠진 항목은 추가 권한을 주지 않는다.
3. 원본 동일성, 변경 전후 보존, 수정 목표 달성과 허용 영역 밖 보존을 다른 판단으로 구분한다. 보이지 않는 특징을 없음이나 일치로 메우지 않는다. 앞뒤 밑단은 독립적으로 비교한다.
4. cut QC와 unscored, scene, pick QC도 단일 후보와 정상 완료 상태를 요구한다. 토큰 한도, 차단, 완료 상태 누락, 여러 후보 또는 잘못된 응답 구조에 성공 JSON이 섞여 있어도 정상 판정으로 사용하지 않는다. 기존 provider fallback은 유지한다.
5. QC enforce 또는 shadow가 이미 켜져 있고 같은 상품 종류와 성별, 매칭 아이템에서 두 번 이상 편집해 fresh 생성으로 돌아간 사용자 조정은 이전 사진을 QC의 BEFORE로 비교한다. 요청한 조정 목표와 비수정 영역 보존을 기존 paired 검사로 확인하며, 그 비교 사진을 읽지 못하면 이미지를 생성하기 전에 기존 품질 실패 경로로 종료한다. 비호환 부모나 일반 첫 생성까지 새 저장 규칙을 넓히지는 않는다.

고정 QC 정책은 시각 정답을 만드는 장치가 아니다. 모델이 사진을 틀리게 읽거나 같은 사진에 다른 답을 할 수 있다. 코드의 역할은 권한과 응답 완료 상태를 확인하는 것이다. 일반 분석 호출은 정책을 명시하지 않으면 기존 요청 형식과 기본값을 사용한다.

생성 모델, 모델 순서와 timeout, QC 스키마와 점수 기준, 보정 횟수와 저장 경로는 기존 값을 유지한다. HOLD나 검사 예외 뒤 기존 사진을 보존하고 저장하는 정책을 출고 차단으로 바꾸지 않았다. 반복 사용자 조정에서 비교 입력이 빠지는 한 경로는 기존의 보존 검사 계약을 적용하도록 수정한다. QC enforce 또는 shadow이며 부모의 category, gender와 매칭 아이템이 같고 정수 editDepth가 2 이상인 경우에 한정하며, 일반 최초 생성이나 비호환 부모의 저장 정책을 전면 변경하지 않는다. 생성에는 이전 사진을 쓰지 않더라도 같은 QC 호출에는 BEFORE를 추가한다. 현재 enforce 배포 선언에서는 기존 QC 1콜에 BEFORE 한 장을 추가하므로 추가 QC 호출은 만들지 않지만 사진 입력 실비는 늘 수 있다. QC off는 새 fallback 보호 대상이 아니며 기존 fresh와 추가 BEFORE 읽기 없는 0콜을 유지한다. 깊이 두 번 미만의 기존 edit이 off에서 shadow로 검사되는 동작은 그대로다. DB와 저장소, 배포 설정의 변경은 없다.

## 사진 실험 조건

자료는 알려진 개발 의류 6종, 원본 17장과 원래 픽셀의 부위 crop 22개다. 빨간 가디건은 제외했다. 원본 관찰, 오너 확인, 표현 정책과 미확인을 구분했고 실제 정상 착용 정답 사진과 실측 치수는 없다. 새 의류의 독립 검증 표본이라고 부르지 않는다.

최초 생성은 의류마다 두 조건, 총 12장이다. 두 조건은 원본과 베이스, 매칭 사진과 2K 생성 조건을 고정한다. C1은 원본 부위 근거와 crop을 함께 추가한다. 공통으로 매칭 사진의 상대적 마지막 순번 지시를 명시 순번으로 정리했다. C1 효과는 프롬프트 한 줄의 인과 효과로 분리되지 않는다. 정돈본을 원본 정답으로 승격하지 않았다.

검수 비교는 같은 흰 셔츠와 줄무늬 셔츠 결과 4장에 세 정책 조건을 적용했고 각 2번, 총 24회다.

| 조건 | 전달 방식 |
| --- | --- |
| P0 | 기존 템플릿에 공통 원본 자료와 부위 확인 지시를 추가 |
| P1 | P0에 고정 정책과 컨텍스트를 user 본문으로 추가 |
| P2 | 같은 고정 정책과 컨텍스트를 실제 developer 메시지로 전달 |

세 조건의 사진과 QC 스키마, Sol 모델과 high 설정은 같다. P1과 P2는 정책의 위치를 비교한다. P0는 공통 자료를 추가했으므로 수정 전 운영 요청과 바이트가 같은 대조가 아니다. 다른 네 의류의 최초 결과 8장에는 P2를 한 번씩 적용했다.

각 요청의 실제 본문과 이미지, 정책과 전체 컨텍스트의 해시, 종료 상태와 usage를 로컬 원장에 남겼다. 원본 사진과 원시 API 응답은 Git에 넣지 않는다. 기존 제품의 promptHash가 전체 privileged 요청까지 인증한다고 주장하지 않는다.

## 확인된 결과와 불확실한 결과

줄무늬 원본은 전체 여밈과 밑단이 보이고 칼라 포함 단추 6개다. C0 결과는 서로 분리된 단추가 최소 7개다. 이 확인 가능한 추가 단추를 P0는 2번 모두 놓쳤고, P1과 P2는 2번 모두 수정 대상으로 잡았다. 한 벌의 특정 오류에서 얻은 결과이므로 전체 정확도나 P2의 우세 비율이 아니다.

흰 셔츠는 원본 앞층과 뒤층을 분리해 보아야 한다. 오너 확인은 짧은 직선 앞단과 긴 곡선 뒷단이다. 착용 사진의 완만한 곡률만으로 직선 cut의 훼손을 확정하지 않는다. C1에서 긴 뒤층의 일부가 더 잘 보였으나 전체 cut과 실측 핏을 통과했다고 선언하지 않았다. 작은 단춧구멍을 추가 단추로 세는 위험도 남았다.

네이비 체크는 원본에서 7개, 결과에서 최소 8개가 보인다. 원본 하단이 잘렸으므로 보이는 개수와 상품 전체 개수는 다르다. 원본 아래에 다른 여밈이 없다는 근거 없이 단추 추가의 확정 오류로 세지 않는다. 밑단 전체도 미확인이다.

핑크의 다섯 여밈, 실제 가슴 절개와 외곽 바인딩은 보인다. 내부 어깨 능선이 주름인지 봉제선인지, 미세 단추 장식이 원본과 같은지는 미확인이 남는다. 반복되는 선이라는 이유만으로 새 봉제선이라고 단정하거나, 주름이라는 이유로 자동 통과시키지 않는다.

청바지의 두 허리 여밈과 면바지의 금속 원판, 앞 주머니와 리벳 같은 큰 특징은 읽힌다. 뒤 주머니와 요크, 미세 금속 표면과 실측 핏은 이번 정면 결과에서 인증하지 않는다. 검수의 누락 지적을 원본 비교 없이 확정 결함으로 채택하지 않는다.

Fable과 Astra는 다른 모델의 판정과 이전 QC를 받기 전에 원본과 후보 사진을 독립 검토했다. 해석이 엇갈려 teacher 결과도 정답집이나 다수결로 쓰지 않았다. 비싼 모델로 전부 교체하는 권고는 이 자료에서 도출하지 않는다.

## 생성 모델 대안과 수정 제어

흰 셔츠와 핑크는 같은 정규화 입력 bytes와 C1 지시문으로 Nano Banana 2.1도 한 장씩 생성했다. Sunburst medium은 1536×2304, NB2.1의 provider 2K 기본 출력은 1696×2528이었다. 출력 설정 차이가 있어 순수 모델 효과로 단정하지 않는다. 핑크의 내부 선 표현은 달라졌지만 작은 장식은 여전히 미확인이다. 흰 셔츠는 열린 앞과 큰 접힘으로 앞 cut 확인이 쉬워지지 않았다. 이너 색은 실제 기존 생성 지시의 허용 정책과 상품 정답을 구분했다.

같은 프레임 국소 수정의 첫 두 실험은 수동으로 정한 좁은 어깨 영역 밖을 서버가 기존 RGB로 복사했다. 모델 raw 결과에서 약 333만 또는 350만 픽셀이 달라졌지만, 서버 합성 뒤 영역 밖 3,533,728픽셀의 변경은 0이었다. 이는 다른 부위가 다시 그려지는 것을 막았다는 증거다. 영역 안의 상품 보존과 목표 달성의 증거는 아니다. 해당 능선은 충분히 없어지지 않았으므로 수정 성공이나 자동 채택으로 세지 않았다.

## 적용 범위와 추천

완료된 응답만 사용하는 코드 경계와 검증된 메타데이터 분리는 제품 리뷰 대상으로 삼는다. 전체 사진의 지시만 강화해서 미세 장식과 모든 구조 오류가 해결됐다고 주장하지 않는다.

일반 QC는 비용이 낮은 모델을 유지하는 방향이 합리적이다. 관측 가능한 의심 부위에 원본과 현재 결과의 crop을 연결해 별도 확인하고, 원본이 잘리거나 불명확하면 해당 특징을 미확인으로 남기는 방안을 추가 검증한다. 수정은 근거가 있는 목표로 좁히고 같은 프레임일 때 영역 밖의 기존 픽셀을 고정한다. 마스크 내부와 새로운 포즈에서는 별도 보존 검사가 필요하다.

이 실험은 운영 반영과 모델 교체를 하지 않았다. 셀러의 전체 흐름과 발행 정책을 변경할 때는 관측 가능한 정답 표본, 지연과 추가 비용, 미확인 결과 처리의 검증이 더 필요하다. 원본 부족을 모델 추론으로 확정하지 않는 것이 우선이다.

## 공식 문서 근거

[OpenAI 이미지 지시 작성 안내](https://developers.openai.com/api/docs/guides/image-prompting)는 바꿀 부위와 유지할 요소를 구분하고 입력 사진의 역할을 명시하는 방법을 설명한다. [이미지 편집 API](https://developers.openai.com/api/reference/python/resources/images/methods/edit)는 mask가 첫 이미지에 적용되며 같은 크기의 PNG와 투명 영역을 요구한다고 설명한다. 모델에 변경 범위를 요청하는 것과 서버가 영역 밖을 실제 복사해 보존하는 것은 다르다.

## 쉬운 설명

검수가 잘린 답을 정상으로 쓰지 않게 하고, 사진 근거와 수정 권한을 분리했다. 검사가 켜진 반복 조정에서 새로 그리는 방식으로 돌아가도 이전 사진과 비교하도록 연결했다. 줄무늬 셔츠의 추가 단추는 강화한 검사에서 잡았지만, 모든 옷이 해결됐다는 결론은 아니다. 모르는 부위는 모른다고 남기고, 수정할 때 다른 부위를 다시 그리지 못하게 하는 방향을 추천한다.

## 부위 검사와 실제 마스크의 추가 결과

부위 검사 준비 20조건 중 최대 예약액이 남은 한도에 들어가는 8조건을 응답 확인 전에 선택했다. 줄무늬 C0에는 D0와 D1을 각각 두 번, 원본 아래가 잘린 네이비와 명료한 3단추 통제에는 D1을 두 번씩 적용했다. 흰 셔츠와 자연 핑크 후보의 이 부위 검사는 실행하지 않았다. 이 선택을 20조건 전부의 성공으로 보고하지 않는다.

D0와 D1의 원본, 정책과 custom 진단 스키마는 같고 D1만 CURRENT의 원래 픽셀 crop을 더한다. crop은 같은 물체의 다른 표시이며 독립 근거가 아니다. 전신 CURRENT는 마지막에 둔다. 인벤토리는 전신 좌표의 같은 단추를 한 번씩 기록하고 원본의 전체 개수와 후보의 최소 가시 개수를 구분한다.

| 대상 | 실제 2회 또는 4회 관찰 |
| --- | --- |
| 줄무늬의 추가 단추 | 네 번 모두 FAIL. D0는 정확한 8개라고 주장했고 D1은 최소 7개와 정확한 총수 미확인을 구분했다. 독립 native 확인은 최소 7개다. D0의 정확한 8개까지 정답으로 인증하지 않는다. |
| 하단이 잘린 네이비 원본 | 두 번 모두 원본 전체 개수 null, 부분 관측, UNJ. 후보의 8개가 보여도 원본 전체 7개라는 단정으로 오류를 만들지 않았다. |
| 의도적 핑크 3단추 통제 | 두 번 모두 원본 5개와 후보 3개, FAIL. 자연 의류의 성공률 분모에서 제외한다. |

Source와 candidate의 잘못된 읽기를 코드가 해결한 것은 아니다. custom 스키마 검사는 모델이 제출한 가시성, 개수와 판단 사이의 모순을 거절한다. crop 효과, 정책 효과와 스키마 효과를 한 원인으로 합치지 않는다. 원본이 불명인데 확정 FAIL을 만들지 않는 조건은 두 네이비 표본에서 관찰됐다.

실제 OpenAI 편집 API의 mask를 넣은 조건과 넣지 않은 조건은 같은 첫 CURRENT와 원본들, 지시문, medium 2K 설정으로 각 두 번 생성했다. API mask는 서버 허용 영역만 완전 투명하게 만든 같은 크기 PNG다. 네 raw 결과 모두 영역 밖의 RGB도 변했다. 여기에 서버 합성을 적용하니 네 번 모두 영역 밖 변경은 0이었다. API mask가 픽셀 불변을 보증한다고 해석하지 않는다.

별도 명료한 3단추 통제의 actual-mask 복구 두 번에서는 다섯 단추가 보이고, 영역 밖 3,533,984픽셀과 보호한 placket 하단은 기존 값이다. 이는 이 통제의 개수 복구와 밖 보존의 결과다. 단추의 미세 장식, 마스크 내부의 모든 비대상 보존, 자연 의류 전체 성공률의 증거가 아니다.

실제 최초 줄무늬 오류에도 두 번 복구를 생성했다. collar를 보호하고 body placket 영역만 서버 합성에 사용했다. 두 합성 모두 영역 밖 3,519,795픽셀 변경은 0이다. 독립 native 검토에서는 두 raw부터 칼라 1개와 몸판 6개가 읽히며 locked도 같았다. 원본의 칼라 포함 총 6개 목표에 미달했고 자동 채택하지 않았다. raw의 몸판 5개가 합성 때문에 6개로 늘었다는 근거는 없다. 능선의 U0와 U1 각 두 반복, 총 네 locked에는 기존 arc가 남아 충분한 완화를 확인하지 못했다. 현재 실험은 수정 영역을 좁히는 것만으로 모든 개수와 형태 목표가 해결된다고 보여주지 않는다.

복구 후 진단은 정상 줄무늬 두 결과와 의도적 3단추 통제의 두 복구 결과, 총 4회다. 정상 N1과 N2는 원본 6개와 CURRENT 7개로 두 번 모두 count FAIL이다. 통제 C1과 C2는 원본 5개와 CURRENT 5개로 count PASS지만, face와 sleeve, rear 특징은 UNJ다. 이는 통제 두 장의 가시 개수 복구 관찰이며 전체 원본 동일성 인증이나 자연 의류 성공률의 증거가 아니다. 이 네 진단은 source와 CURRENT의 부위 확인이며 BEFORE와 AFTER의 paired preservation audit으로 수행하지 않았다.

## 최초 배경 정리 요청과의 구분

이 QC 브랜치는 기존 PR 482의 배경 정리 3회 재시도와 60초 카드 안내를 포함하지 않는다. 기존 PR 작업 폴더에는 그 코드와 테스트가 있지만, 일반 새 상품 흐름에서는 분석 화면의 내 옷을 로컬 원본 카드로 먼저 만들고 콘티 이동 후 서버 정리를 시작한다. 해당 분석 화면 문구가 실제 정상 경로에서 노출된다고 아직 증명하지 못했다. 따라서 최초 요청 전체도 완료됐다고 보고하지 않는다.

165초는 SAM 재시도 대기 합계이며 전체 실행의 엄격한 180초 마감이 아니다. 현재 QC 기본 브랜치의 SAM 4회 정책, 30분 복구 창과 유휴 설정은 바꾸지 않았다. 초기 요청의 실제 알림 연결과 현재 QC 경계 보강은 다른 변경이다.
