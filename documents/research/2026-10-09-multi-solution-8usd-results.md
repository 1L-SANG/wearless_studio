# 밑단과 소매선 여러 해법 실험 결과

실사용 작업 모델은 gpt-6.1-sol, effort xhigh다. Claude의 실제 토론 모델은 claude-sonnet-5-5, effort high다. 이 단계에서 제품 코드는 바꾸지 않았으며 최신 2K 정돈과 부위 QC를 제품이나 운영에 적용하지 않았다.

## 먼저 답할 사항

PR482의 커스텀 매칭 경로에는 원본에서 Pro 1K가 직접 제품컷을 만드는 코드가 있다. 최신 가벼운 정돈 NB 2.1 2K와 새 부위 QC는 실험 실행기에만 있다. `server/app/services/matching_flatlay.py`의 IMAGE_SIZE는 1K이며 입력은 첫 원본 한 장, 기존 Identity Lock 지시, 기본 image_high다. `server/app/workers/matching_cutout_job.py`는 그 결과를 카드와 full 생성 입력에 쓴다. 최신 개선이 커스텀에도 이미 적용됐다고 답하면 틀린다.

흰 셔츠는 Front 사진에 앞판과 뒷판이 함께 보인다. 기존 전체 밑단 한 값과 FRONT가 하나라도 포함되면 앞 사실로 넘기는 코드는 앞뒤 차이를 잃었다. 흰색 때문에만 발생한 오류가 아니다. 새 실험에서는 앞 짧고 직선, 뒤 길고 곡선이라는 오너 확인을 별도 근거로 사용했다. 미확인 앞단은 직선 생성 정책을 적용하지만 원본 관찰은 unknown으로 남긴다.

핑크의 문제 선은 실제 외곽 바인딩, 가슴 절개, 어깨 안쪽의 추가 연결선 같은 표현을 구분해야 한다. 원본의 넓은 어깨를 cap sleeve라고 부르는 것이 별도 소매 봉제 경계를 입증하지 않는다. 잘못된 확정 분류가 생성 입력에 전달되는 경로는 확인했지만 생성 모델 내부 인과는 가설이다.

같은 비교의 조건과 결과를 전부 로컬 HTML에 보존했다. 첫 생성과 편집은 Python으로 의미를 바꾸거나 결과를 합성하지 않았다. 확대와 비교판은 저장된 같은 픽셀을 잘라 배치한 자료다. 정돈 제품컷이 원본 Front를 대신한 주상품 마네킹의 효과를 이번에 다시 측정한 것은 아니다.

## QC에서 확인한 실패

첫 검사 8건은 0..1 지시와 다른 좌표를 반환했고 재검사 2건은 잘못된 원본 이미지 번호를 반환했다. 모두 무효로 기록했으며 통과로 정규화하지 않았다. 문자열 이미지 ID와 명시한 0..1000 단위로 바꾼 뒤 별도 검사를 진행했다. 정수 enum을 Gemini 스키마가 거절한 400 응답 한 건도 원래 요청과 함께 보존했다.

뒤 검사의 형식이 유효하다고 판단이 정확한 것은 아니다. 원본에서 확인한 곡선을 직선 기대값으로 읽거나 미확인 앞단의 정책상 직선을 구조 오류로 판단한 반례가 있다. 마지막 핑크 범주형 검사도 front_cut 질문에 밑단 대신 scoop neck을 답했다. 이런 의미 오류를 자동 수정 근거로 쓰면 안 된다. 범주형 결과는 진단이며 전체 통과나 수정 허가를 출력하지 않는다. 최종 반례의 범주형 재검사는 비용 중단으로 실행하지 못했다.

마스크 밖에서 값이 달라진 픽셀은 약 91.3%부터 93.0%다. 8비트 RGB 채널 평균 차이는 약 1.46부터 1.68이라 아주 작은 값 변화도 비율에 포함된다. 이 비율을 전부 눈에 띄는 재디자인으로 해석하면 안 된다. 다만 모든 비대상 픽셀이 고정된 것은 아니라는 증거다. [OpenAI 이미지 편집 공식 안내](https://developers.openai.com/api/docs/guides/image-generation)도 GPT 이미지 모델의 마스크를 편집 안내로 설명하며 정확한 경계 준수를 보장하지 않는다.

## 공식 안내와 지시의 실제 전달 방식

[Google 이미지 생성 공식 안내](https://ai.google.dev/gemini-api/docs/image-generation)의 구체적인 유지·편집 지시에 맞춰 앞판과 뒷자락 및 실제 마감을 따로 적었다. API가 같은 상품과 모든 디테일을 보장한다는 뜻은 아니다. [Google 시스템 지시 공식 안내](https://ai.google.dev/gemini-api/docs/text-generation#system-instructions)의 system_instruction 설정은 일반 user 내용과 별도다. 이번 직접 생성 실행기는 강화 내용을 user contents에 합쳤으며 별도 systemInstruction 필드를 사용하지 않았다. 따라서 시스템 역할 자체의 효과를 통제해 입증한 실험이라고 부르지 않는다.

## Claude 토론과 독립 검수

Claude는 텍스트 두 번, 실제 사진 한 번을 보았다. 사진 검수에서는 흰 원본의 짧은 앞판과 긴 곡선 뒷자락을 구분했고 생성 여덟 장의 혼동과 핏 변화 가능성을 지적했다. 부위별 질문, owner_confirmed와 source_observed 및 default_straight 분리, 가려진 부분의 unknown 유지, 국소 수정의 비대상 보존 검증을 제안했다.

마스크를 보지 않았고 이후 새 결과도 보지 않았다는 한계는 원문에 남겼다. 캡슬리브라는 명칭과 세로 절개 확정 표현은 별도 봉제 구조의 정답으로 채택하지 않았다. 원본 픽셀과 독립 검수를 우선했다. 독립 검수는 QC 답변을 읽기 전에 출력 28장 전체와 원본을 직접 비교했고, 흰 NB 반복의 약한 앞 곡선과 부분 수정의 큰 기장 단축, 핑크 주름과 디테일 변화도 기록했다. 원문 세 개는 로컬 claude-round1-verbatim.txt, claude-round2-text-verbatim.txt, claude-round3-verbatim.txt에 보존했다. 사진과 API 응답, 인증값은 커밋하지 않는다.

## 추천하는 Before와 After

기존 방식은 원본 분석의 전체 밑단 한 값과 소매 이름을 최초 생성에 넘기고 일반 QC가 결과를 비교한다. 새 추천은 기존 분석과 QC의 역할을 유지하며 면별 구조와 확인 상태를 연결하는 방식이다. 생성에서 앞판과 뒷자락, 실제 바인딩과 별도 소매 연결을 구분하고 원본의 잠김 상태를 유지한다. 원본에서 입증된 곡선은 보존하고 미확인 앞단에만 오너의 직선 기본값을 적용한다.

기존 QC에 앞 중앙 밑단, 뒤 자락, 실제 팔 마감과 내부 추가 선, 장식 단추를 각각 묻는 항목을 보강하는 것이 우선이다. 모른다는 답변과 원본 해석 충돌을 통과로 취급하지 않는다. 다른 디테일이 변한 부분 수정은 채택하지 않는다. 기존 전역 검사에서 색, 패턴, 로고와 상품 정체성 확인을 지우지 않는다. 부위 검사만으로 전체 QC를 대체하지 않는다.

흰 셔츠의 NB 2.1 2K 최초 생성은 면별 분리의 개선 후보다. 두 결과 모두 앞 중앙의 약한 곡선이 남아 직선 해결 완료로 세지 않는다. 독립 검수는 전체 균형에서는 Sunburst의 짧은 지시 두 후보를 더 무난하게 평가했다. 모델 전체 승자는 확정하지 않는다. 핑크의 반복 검증이 끝나지 않았고 단추와 핏 문제도 있다. 정돈을 항상 넣거나 마스크 수정만 반복하는 흐름은 추천하지 않는다. 제품 구현은 앞뒤 값을 나누는 호환 계약과 다른 사실 소비자, 최초 및 후속 편집 검사까지 함께 검증해야 한다. 이번 연구에서는 그 제품 코드를 구현하거나 배포하지 않았다.

## 비용과 중단

새 원장은 63건이다. 직접 HTTP POST는 60회이며 이미지 요청 29회와 검사 요청 31회다. Claude 실행은 3회이며 CLI 내부 전송 수를 직접 POST 수에 섞지 않았다. 이미지 28장을 얻었고 29번째는 이미지가 없다. 직접 POST는 200 응답 59건, 스키마 거절 400 응답 1건이다. HTTP 200은 사진 성공이나 QC 통과와 같지 않다.

## 검증과 제품 상태

이번 무료 pytest는 실험 예산과 unknown 정책, 좌표 검사와 기존 부위 근거 재현을 합쳐 28 통과, 실패 0이다. 마지막 상한 조정 재현은 수정 전 1 실패와 13 통과, 수정 후 14 통과를 확인했다. 원본과 분석 및 참고 베이스의 보호 해시는 바뀐 것이 없다. 과거 실행 코드 해시가 현재 코드와 다른 것은 과거 plan을 덮어써 숨기지 않았으며 별도 변경 해시를 남겼다.

로컬 HTML의 이미지 참조 86개와 출력 28장 존재를 확인하고 사진을 직접 검수했다. 폰 폭 320, 360, 375, 390, 414px와 WebKit 화면 검사는 브라우저 로컬 파일 제한으로 못 했다. 제한을 우회하지 않았다.

제품 코드의 앞선 전체 검사 기록은 서버 7698 통과, 104 조건부 건너뜀, 실패 0이며 프론트 2806 통과, 실패 0과 빌드 통과다. 로컬 DB 접속 실패는 없고 알려진 날짜 의존 alias 검사도 당시 통과했다. 이번 문서 단계에서 제품 코드가 바뀌지 않아 전체 pytest, pnpm test:frontend와 pnpm build를 재실행하지 않았다. 앞선 결과를 최신 main의 머지 검사나 새 이미지 품질 통과로 주장하지 않는다.

셀러 경로는 상품 입력의 커스텀 내 옷 업로드, 다음 단계, 콘티 등록 후 서버 매칭 작업 시작, 콘티의 해당 매칭 카드다. 분석 화면에 구현한 지연과 실패 문구는 그 새 제작 경로에서 UI 비도달이며 콘티 카드에 아직 연결되지 않았다. 이 원래 PR의 체크리스트도 끝난 상태가 아니다. PR482는 초안을 유지한다. 별도 PR497의 남성 베이스 한 값 변경과 이번 연구는 구분하며 어떤 PR도 머지하지 않았다.

## 쉬운 설명

뒤 자락을 앞 밑단으로 착각하는 문제는 앞뒤를 따로 설명하니 개선됐다. 핑크의 가짜 소매선은 줄일 수 있었지만 단추나 기장까지 바뀌는 경우가 있어 그대로 적용하면 다른 옷이 될 위험이 있다. 첫 생성에서 실제 구조를 지키고 기존 검사에 부위 질문을 보강하는 방향을 추천한다. 모든 옷에 통하는 해결 완료는 아니며 제품 적용과 실제 셀러 대기 안내 연결은 남아 있다.
