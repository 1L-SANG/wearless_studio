# 저렴한 QC 후보와 실제 보정 사진 비교

실험은 2026년 10월 10일 시작해 11일 새벽에 마무리했다. 실사용 작업 모델은 gpt-6.1-sol, effort xhigh다. 이번 사진 검수는 실제 gpt-6.1-sol, claude-sonnet-5-5, claude-opus-5-5 API를 각각 high로 호출했다. Astra와 Fable을 새로 호출하지 않았다. 생성은 기존 작업 코드의 gpt-image-2.5-sunburst, 2K와 medium 설정이다. 제품 QC 모델이나 운영 설정을 바꾼 단계가 아니다.

## 결론과 추천

Astra 대신 Sol 6.1을 중요한 부위의 저렴한 독립 검수 후보로 시험하는 방향을 추천한다. 전면 교체를 확정하지는 않는다. 모델 교체만으로 문제가 해결되지는 않았다. 작은 장식은 전신 사진에서 판독 보류가 됐고, 흰 앞단의 원본 해석도 모델별로 달랐다.

실제 생성 사진에서는 구체적인 고정 지시로 변화가 있었다. 흰 앞단의 곡률은 줄었고, 핑크 단추는 일반 단추에서 장식형에 가까워졌다. 이것은 정확한 원본 재현이나 자동 QC 개선 완료를 뜻하지 않는다. 소매선과 장식 세부, 정상 착용컷의 오탐률이 남아 있다.

앞선 [Astra와 Fable 토론 기록](2026-10-10-qc-model-debate-and-pilot.md)의 Astra 우선 재검수 후보는 이번 비용 요구와 실측으로 재검토했다. 이번 결과만으로 Sol이나 Claude의 일반 정확도가 Astra와 같다고 말하지 않는다.

## 같은 자료와 다른 모델

기존 최종컷 두 장과 원본, 마네킹, 매칭 사진을 고정했다. 핑크는 원본 Front, Back, Detail이며 흰 셔츠는 Front와 Back이다. 모든 사진 검수는 같은 논리적 지시와 필수 항목, high와 출력 한도 8192다. OpenAI는 Chat Completions의 reasoning_effort와 image detail high, Claude는 Messages의 adaptive thinking과 output_config.effort를 실제 요청에 넣었다. 공급자별 토큰화와 추론 수준을 같은 계산량이라고 가정하지 않는다.

17개 기존 검사에 단추 하위 비교 5개와 앞단, 뒤단, 어깨 구조의 독립 관찰을 추가했다. 개수로 장식을 통과시키지 않는다. 원본 관찰, 후보 관찰, 관계를 따로 적는다. 핑크 전신에서 필수 부자재는 개수와 바탕 윤곽, 원본에서 확인된 장식이다. 작은 구멍과 조명에 따른 투명 인상은 기록하지만 필수 통과 조건으로 만들지 않았다. 흰 앞면 후보의 보이지 않는 뒤단은 미확인으로 기록하며 앞단 실패로 자동 전환하지 않는다.

필수 비교의 누락과 중복을 거부하고, 필수 FAIL과 미확인을 상위 PASS가 덮지 못하게 했다. 순서가 바뀐 응답에서 optional 구멍 FAIL을 장식 FAIL로 착각할 수 있는 연구 코드 오류를 리뷰에서 찾아 고쳤다. 배열 위치 대신 part 이름을 조회한다. 이 가드는 모델의 원본 오독까지 고치지는 않는다.

Sonnet의 흰 전체 FAIL은 밑단이 아니라 얼굴 가림과 매칭 청바지였다. 따라서 셔츠 밑단을 제대로 잡았다고 세면 틀린다. 오너가 확인한 앞 직선과 뒤 곡선을 같은 특징으로 뭉뚱그리는 원본 해석 문제도 남았다. Sol은 추가 흰 후보에서 원본 앞단이 대체로 직선이라고 관찰했지만 착용 사진의 약한 곡선을 재단 변화라고 단정하지 않았다.

모든 판단은 저장된 10월 9일 작업 프로필과 이 브랜치의 generic horizon 코드다. 서비스 예시와 선택 모델이 없고, 얼굴을 가린 앞면 전신이다. 흰 셔츠는 실제 분석 유형 outer와 닫음 선택을 생성 및 검수에 일치시켰다. 기존 명시 팔 내림 포즈를 썼다. 이 실험의 모든 구도와 매칭 판정이 최신 배포 코드의 동작이라는 뜻은 아니다.

## 실제 생성에서 바꾼 것

기존 최종컷을 복사해 편집하지 않고 원래 원본, 마네킹, 매칭 입력으로 기존 cut_generator.generate를 다시 실행했다. 원본만 상품의 재단과 부자재를 결정하고 마네킹은 거친 착용 형태의 참고라는 generic 권한을 유지했다.

흰 셔츠 한 장은 오너가 확인한 앞 직선과 뒤 곡선을 고정 지시에 분리했다. 이 지시는 원본 Front의 짧은 앞단, Back의 긴 곡선 뒤단, 자연스러운 착용 드레이프와 옆 연결, 기장과 닫음을 보존하도록 한다. 모델이 명확한 앞단 FAIL을 찾았다고 가장하지 않은 정책 실험이다.

핑크 두 장은 같은 원본과 설정에서 지시만 달리했다. 첫 조건은 기존 patternHardware의 원본 무늬와 정확한 부자재 개수, 종류, 위치 복원 문구다. 둘째 조건은 고정 문구로 PRODUCT Detail의 입체 장식, 원형 단추 다섯 개, 평범한 4구 셔츠 단추로 대체하지 않기, 실제 골지와 가슴 절개, 소매 바인딩 보존을 명시했다. 자유로운 QC 근거 문장을 프롬프트에 넣지 않았다.

최초 모델 판단은 핑크 HOLD였다. 따라서 새 핑크 사진은 직접 원본과 후보를 비교해 확인한 장식 변화의 연구용 보정 조건이다. 현재 운영 워크플로우가 그 판단으로 자동 보정했다는 뜻이 아니다. 기존 자동 흐름은 필수 미확인을 발견하면 새 생성을 하지 않는다.

모든 조건은 단회 생성이다. 원본, 지시 이외 설정, 모델과 구도를 통제했지만 공유 난수 시드가 없으며 새 생성에서 인물, 포즈, 매칭 바지와 신발도 달라졌다. 지시만으로 결과 차이 전부가 생겼다고 인과 확정하거나 정확한 원본 재현 성공률을 제시하지 않는다.

## 직접 확인한 이미지 변화

흰 앞단은 중앙이 내려오는 곡률이 줄어 더 평평해졌다. 독립 Sol 리뷰도 같은 부분 개선을 확인했다. 양옆의 완만한 굴곡은 남고, 재단과 착용 드레이프를 완전히 구분하거나 뒤 전체 곡선을 확인할 수는 없다. 긴 뒤꼬리와 드롭숄더, 소매, 커프스, 카라 등 주요 형태는 보존됐다. 눈에 띄는 몸판 단축은 없지만 정확한 기장과 작은 부자재까지 검증됐다는 뜻은 아니다. 매칭 청바지와 신발, 인물 표현은 바뀌었다.

핑크의 넓은 보정은 평범한 단추를 다시 만들었다. 장식을 명시한 조건은 장식형 단추를 만들며 직접 볼 수 있는 차이가 있다. 다섯 개와 바탕 윤곽이 같다고 원본 장식 모양, 색과 광학적 인상까지 정확한 것은 아니다. 독립 리뷰는 두 새 조건 모두 우측 어깨 안쪽에 가짜 소매 접합선처럼 선명한 곡선 능선이 되살아났다고 확인했다. 기존 약해졌던 문제가 재발한 것이다. 실제 외곽 바인딩과 가슴 절개는 남지만 이 두 조건을 전체 상품 충실도 승자로 채택할 수 없다.

비교 이미지와 원본, 요청 해시, usage, 모델의 raw 판정은 ignored 로컬 .scratch/bg-removal-3min/qc-affordable-repair-20261010에 보존했다. qa/white-before-after.png와 qa/pink-before-after.png는 실제 사진을 잘라 나란히 보여 주는 검토 자료이며 새로 그린 상품 이미지가 아니다. 사진과 키, 원시 API 응답은 커밋하지 않는다.

## 새 사진 세 장의 교차 검수

| 같은 새 사진 | Sol 6.1 high | Sonnet 5.5 high | Opus 5.5 high |
| --- | --- | --- | --- |
| 흰 앞뒤 밑단 고정 지시 | 앞단의 직선 원본을 읽었으나 후보 재단과 드레이프 구분 보류 | 앞단을 곡선으로 읽고 PASS. 매칭 바지 FAIL | 앞단 PASS, 전체 KEEP_STAGE1 |

| 핑크 장식을 명시한 보정 | 어깨 구조 FAIL, 장식 판독 보류 | 어깨 PASS, 장식 판독 보류 | 어깨 PASS, 장식 판독 보류 |

Sol의 어깨 FAIL은 직접 관찰과 독립 시각 리뷰의 재발 판단에 맞았다. 이번 두 결과에서 조용한 구조 PASS를 피했고, 원본 앞뒤 분리도 상대적으로 신중했다. 이 좁은 실측이 저렴한 독립 검수 후보로 추천하는 근거다. 모든 모델의 단추 개수는 다섯 개로 맞았다. 그러나 장식 후보의 미세 차이는 여전히 읽지 못했다. 세 모델 모두 핑크 전체는 HOLD_STAGE1이므로 이 판단으로 자동 보정 사진이 만들어졌다고 표현하지 않는다.

이번은 이미 알려진 두 의류의 개발 실험이다. 정상 착용 사진의 합격 정답군, 새 상품의 미사용 검증, 반복 생성 및 판단 안정성은 없고 정확도 비율을 계산하지 않는다. 표의 앞단과 어깨 같은 부분 판정과 전체 워크플로우 경로를 구분한다.

## 마지막 원본 우선 탐색

앞의 두 새 핑크 사진 모두 어깨 능선이 재발해 마지막 조건을 하나 더 준비했다. 원본 Front, Back, Detail과 같은 매칭 사진만 쓰고 생성된 마네킹 참고를 뺐다. 고정 단추 문구는 유지하며 원본의 연속된 어깨와 캡소매, 별도 안쪽 소매 접합선과 새 패널을 만들지 않기, 실제 바인딩과 가슴 절개 및 자연스러운 부드러운 주름 보존을 고정 지시로 추가했다.

이것은 마네킹 제거와 구조 고정 두 변인이 함께 바뀐 단회 탐색이다. 마네킹만의 원인이나 고정 지시만의 효과라고 분리해서 주장하지 않는다. 새 QC도 실제 생성과 같은 마네킹 없는 원본 참조 및 사진 번호로 구성했다. 상품 원본의 권한을 높이는 실험이며 제품의 마네킹 사용 흐름을 변경한 것은 아니다.

직접 검토와 독립 리뷰 모두 마지막 사진의 어깨 안쪽 선이 크게 줄어 연속된 원단에 더 가까워졌다고 봤다. 외곽 바인딩과 가슴 절개는 남았다. 그러나 단추는 다섯 개를 유지하면서 일반 흰 4구 형태로 되돌아갔고, 장식 보정 조건보다 기장이 짧아 보였다. 정확한 기장과 가슴 절개 곡률의 원본 보존은 미확인이다. 두 문제를 함께 해결한 사진으로 채택할 수 없다.

마지막 Sol 검수는 어깨 PASS, 단추 장식과 매칭 청바지의 워싱 변화 FAIL을 반환해 재생성을 제안했다. Sonnet과 Opus는 어깨 PASS이지만 단추 장식을 판독 보류로 남겼다. Opus는 매칭 바지도 FAIL했다. 새 사진이 더 좋아 보이는 일부 부위가 있다고 전체를 자동 통과시키면 안 된다. 검수에서 생긴 재생성 제안을 성공할 때까지 반복하지 않았다.

같은 모델, 1536x2304, medium, 한 장 출력의 앞선 세 비용은 약 $0.062~$0.068였다. 원본 참조 수가 줄어든 이 단회는 별도 계획에서 $0.50을 보수적으로 예약했다. 기존 $0.90 예약과 미확인 $1.05 기록을 고치지 않았고 총 $8, 새 미확인 중단과 중복 방어를 그대로 적용했다. 이 예약은 정확한 청구액을 보장한다는 뜻이 아니다. 실제 생성 비용은 $0.050559였다.

## 남은 검증과 경계

전신 사진의 부자재가 작으면 모델 교체만으로는 추가 생성을 결정할 수 없다. 원본 픽셀을 자른 부위 자료를 전체 사진과 함께 보내는 지역 검수 계획을 준비했고, 새 합성이나 보간 없이 원본 픽셀이 보존되는 테스트도 했다. 하지만 자동 승인 검토가 파생 crop의 외부 전송은 기존 승인의 범위가 아니라고 거절했다. OpenAI와 Anthropic으로 해당 자료를 보내도 되는지 따로 물었으며 아직 전송하지 않았다. 다른 형태로 crop을 보내거나 같은 전송을 우회하지 않았다.

허용되면 같은 결과의 부위 검수를 비교하고, 보정 전후 장식과 소매, 밑단을 전체와 부위로 함께 확인해야 한다. 현재 제품 QC 제공자는 GPT와 Gemini이고 Anthropic을 제품에 연결하지 않았다. 모델 설정만 바꾸면 모든 생성과 검수가 자동으로 개선된다고 주장하지 않는다.

보류와 사진 사용 가능 상태도 다른 문제다. 현재 워커는 HOLD_STAGE1 뒤에도 사진을 보존하고 QC 메타데이터를 저장한다. 다운로드, 비용 차감과 환급, 실제 사용 차단을 이 연구에서 변경하지 않았다. 도달 경로는 상품 등록, 콘티보드 호리존 선택과 마네킹 선택, 상세페이지 생성 뒤 에디터의 컷이다. 내 옷 커스텀 대기 알림의 실제 화면 연결은 기존 PR482의 별도 미완료 항목이다.

## 공식 문서

[Sol 6.1 모델 안내](https://developers.openai.com/api/docs/models/gpt-6.1-sol)는 이미지 입력과 구조화 출력을 지원하며 Chat Completions는 도구 호출 없이 쓸 수 있다고 명시한다. [OpenAI 표준 가격](https://developers.openai.com/api/docs/pricing)에서 짧은 컨텍스트의 Sol 입력과 출력 요율은 각각 $2와 $10이며 Astra의 $10와 $50 대비 5분의 1이다. 실제 요청 전체 비용이 항상 5분의 1이라는 뜻은 아니다.

[Claude Sonnet 5.5](https://platform.claude.com/docs/en/models/sonnet-5-5/overview)와 [Opus 5.5](https://platform.claude.com/docs/en/models/opus-5-5/overview), [가격 안내](https://platform.claude.com/docs/en/about-claude/pricing)를 확인했다. 이번 요청은 입력 $2와 출력 $10의 Sonnet, 입력 $4와 출력 $20의 Opus로 usage를 계산했다. [Claude 구조화 출력](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)의 output_config.format과 [추론·비용 안내](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost)의 adaptive thinking, effort, 출력 한도를 따랐다. 공급자별 스키마 제한은 전송 스키마에서 처리하고 코드에서 원래 필수 비교를 다시 검증한다.

## 비용과 테스트

실제 유료 POST는 22회로 사진 검수 18회와 새 생성 4회다. Sol, Sonnet, Opus를 각 6회 검수에 사용했고 모두 200, 요청한 반환 모델, 완결된 응답과 파싱, usage를 확인했다. 이미지 응답은 model 필드가 없으며 감사 훅으로 요청의 Sunburst, 사이즈, quality와 n을 확인하고 usage를 기록했다. 새 미확인 비용과 자동 재시도는 없다. 무료 모델 GET으로 세 모델 접근을 확인했으며 이를 유료 생성 수에 섞지 않는다.

실측한 호출당 비용은 Sol 약 $0.060~$0.078, Sonnet 약 $0.049~$0.070, Opus 약 $0.133~$0.177이다. Sol은 중요한 어깨 재발을 잡았지만 1분 이상 걸려 전면 적용 시 지연 부담이 있다. 좁은 핵심 부위 검수에서 같은 정확도와 더 짧은 시간으로 쓸 수 있는지 별도 검증해야 한다. 가격과 일부 사례만으로 전체 모델을 교체하지 않는다.

 기존 $8을 새 예산으로 초기화하지 않았고, 앞선 확인 추정 $4.74637675와 미확인 예약 $1.05를 그대로 포함했다. 매 요청 전에 text 또는 이미지 예약을 하고, 새 비용 미확인과 초과, 중복 stage, $8 한도를 막는다. 미확인 과거 비용을 풀지 않았으며 확인 추정 $6.80부터 다음 호출을 중단한다.

연구용 무료 pytest는 13 통과, 실패 0이다. 필수 비교와 optional 부위, 뒤면 미노출, 미확인 비용, 전체 예산 합산, 고정 지시, native crop 픽셀 보존과 순서가 바뀐 배열을 확인했다. 실제 순서 오류를 1 실패와 11 통과로 재현한 뒤 수정해 12 통과를 확인했고 마지막 source-only 참조 보존 테스트를 더해 13 통과를 확인했다.

제품 코드와 앱 화면을 바꾸지 않아 서버 전체 pytest, pnpm test:frontend와 pnpm build는 이번 연구에서 다시 실행하지 않았다. 직전 제품 변경 때의 서버 7698 통과와 104 조건부 건너뜀, 프론트 2806 통과와 빌드 통과는 이전 기록이다. 이번 연구의 모델 품질 통과나 최신 main 검증으로 쓰지 않는다. 이번 실행에서 로컬 DB가 필요한 테스트는 없었고 DB 접속 실패로 빠진 테스트도 없다. 모바일 다섯 폭과 WebKit 검사는 앱 화면 변경이 없어서 새로 하지 않았다. 사진은 네이티브 이미지 도구로 직접 검토했다. 정상 착용컷 오탐 평가와 부위 crop API 비교, 다른 상품 및 실제 운영 저장과 다운로드 검증은 하지 못했다. 부위 전송의 별도 허용 질문은 아직 답변 대기다.

## 쉬운 설명

저렴한 Sol도 신중한 검수 후보가 될 수 있지만 모델 이름만 바꿔서는 사진이 고쳐지지 않았다. 앞뒤 밑단과 단추 장식을 구체적으로 나눠 지시하니 실제 사진이 달라졌다. 아직 원본 그대로 해결됐다고 확정할 단계는 아니며, 작은 부위를 잘 볼 수 있게 하는 검사와 소매선 보존을 함께 확인해야 한다.
