# 추가 색상 의류 재현, 기획과 검증 기록

## 확정 방향

추가 색상은 사진이 적으므로 대표 색상의 충분한 사진으로 옷을 재현하는 과정을 먼저 거친다. 그 결과에 추가 색상의 실사진을 적용한다. 사용자는 새 프로듀싱 콘티의 인스펙터에서 최종 색상 하나만 고른다. 제품 단독컷은 그 색의 원본에서 직접 만든다.

설계 정본은 `docs/adr/0025-base-garment-color-application.md`, 실행 명세는 `docs/superpowers/specs/2026-11-06-garment-color-flow.md`다. 기존 프로듀싱 작업 공간의 미커밋 변경을 복사해 `codex/garment-color-flow`에서 작업했다. 검증 후 원본 프로듀싱 작업 공간의 해당 파일들이 시작 시점 그대로임을 해시로 확인하고, 이번 기능의 36개 파일 변경만 반영했다. 통합한 파일은 검증 사본과 바이트 단위로 일치한다. 운영 서버는 수정하지 않았으며, 이 작업만의 변경분을 패치로 함께 보관한다.

## 독립 기획과 논쟁

- Codex는 초기 독립안을 먼저 파일에 기록했다. Opus 5.5는 별도 Claude Code 세션에서 코드와 문서를 읽고 독립안을 제시했다. 실행 옵션은 `--model claude-opus-5-5 --effort xhigh`, 실제 모델은 세션 기록에서 확인했다.
- 초기 두 안은 한 칸 한 색과 생성 계약 분리에 동의했지만, 색상별 직접 생성에 무게를 뒀다. 사용자가 대표색의 풍부한 사진을 먼저 활용해야 한다고 정정한 뒤 그 안을 폐기했다.
- 수정안은 대표색 결과에 마지막 색 적용을 붙이는 방식이다. Opus는 기존 확정 GPT 템플릿을 바꾸지 않고 이를 연결할 수 있다는 데 동의했다.
- 논쟁에서 반영한 사항은 실패한 색 적용의 기준색 대체 금지, 내부 원본 보관, 목표색 배경과 내부 실행색의 분리, 과금에서 중간 결과 제외, 별도 색상 검수, 비슷한 컷의 새 자세에 맞는 내부 원본이다.
- ‘검증된 원본’이라는 표현도 정정했다. 기존 생성과 QC에서 채택한 대표색 결과이지, 모든 원본이 완벽히 검증됐다는 뜻은 아니다.

## 실제 이미지 시험

사용자의 GPT API 비용 승인 상한은 5달러다. 기존 앱의 `garment_edit.generate` 경로를 호출했으며, 새로운 별도 SDK 생성기를 만들거나 운영 DB와 R2에 결과를 쓰지 않았다. 모델은 `gpt-image-2.5-flare`, 중간 화질, 호출별 자동 재시도 없음이다.

| 시험 | 결과 | 응답 usage 기준 비용 |
| --- | --- | ---: |
| 밝은 지퍼 재킷을 실제 짙은 원단 사진으로 변경 | 대체적인 형태, 포즈와 장면 유지. 주름과 지퍼 세부는 다시 그려짐 | $0.021625 |
| 브라운 털 재킷을 아이보리 원본으로 변경 | 사람과 장면 유지, 털결과 옷깃 일부 변화 관찰 | $0.023486 |
| 같은 털 재킷, 구조 보존 지시를 추가해 비교 | 옷깃과 볼륨 일부 개선으로 보이나 질감 보존은 여전히 불완전 | $0.024181 |
| 합계, 3회 | 추가 유료 이미지 시험 없음 | **$0.069292** |

비용은 응답의 실제 토큰 사용량과 [OpenAI 공식 Standard 요금표](https://developers.openai.com/api/docs/pricing)로 환산했다. 해당 이미지 모델의 텍스트 입력, 이미지 입력과 이미지 출력 단가는 프로젝트의 실비 계산기와 일치했다. 실제 청구서의 세금이나 별도 계정 할인은 반영하지 않았다.

원본과 출력, 원본 SHA256, 프롬프트와 usage 기록은 `.scratch/colorway-flow-20261106/qa/ledger.json`에 있다. 두 종류의 기존 사진을 이용해 마지막 색 적용 단계를 확인한 소량 시험이다. 전체 생성 파이프라인을 운영 계정에서 유료로 실행한 검증은 아니다. 낮은 해상도 원본과 같은 상품 여부의 불확실성이 있어 실물색 정확도나 모든 원단에서의 정확한 형태 보존을 입증하지 않는다.

독립 검토자도 털결과 옷깃의 재생성을 확인했다. 따라서 표본 하나의 보존 문구를 기존 프롬프트에 그대로 도입하지 않았다. 대신 대표색 생성 검수와 분리된 목표색 검수를 연결했다. 자동 검수는 구조, 질감, 인물과 장면, 목표색, 명백한 디자인 불일치를 비교하며, 확인하지 못한 결과를 통과로 기록하지 않는다.

## 코드 검증

- 작업 전 프론트: 389개 파일 통과.
- 작업 전 서버: 11,065개 통과, 140개 건너뜀.
- UI 변경 뒤 전체 프론트: 390개 파일 통과, 실패 0.
- 최초 서버 전체 검증에서는 50개 실패를 발견했다. 40개는 새 소유권 조회와 대표색 렌더를 반영해야 하는 호리존 fixture, 2개는 변경된 착용컷 근거 정책, 2개는 옛 색상 미지정 기록의 불필요한 메타데이터, 6개는 체크포인트 복원 기록 손실이었다. 실패를 숨기지 않고 해당 원인을 수정한 뒤 재실행했다.
- 독립 최종 검토에서 내부 업로드 취소의 스레드 경합과 비슷한 컷의 색 적용 우회를 추가로 찾았다. 실제 스레드와 이벤트로 경합을 재현해 수정했고, 콘티 후속 컷과 에디터 후속 컷 모두 새 자세의 대표색 원본을 보관하도록 보완했다.
- 관련 서버 묶음 889개 통과 뒤 전체 서버가 11,125개 통과, 140개 건너뜀, 실패 0으로 끝났다. 그 전체 실행 이후 두 줄의 옛 원본 색상 기록을 보정했고, 관련 176개 테스트와 독립 재현 검토가 통과했다. 전체를 다시 실행하지 않은 범위는 이 두 줄의 기록 보정뿐이다.
- 빌드가 통과했다. 기존 큰 번들 경고는 남아 있다.

## 화면 검증

내장 브라우저의 숨김 탭에서 로컬 목 데이터로 진행했다. 실제 운영 데이터나 크레딧을 쓰지 않았다.

- 새 콘티에서 아이보리를 고르면 실제 선택과 원본 사진 설명이 바뀐다. 판을 닫고 다시 열어도 선택이 유지된다.
- 콘티 저장, 마네킹 단계와 목 생성, 에디터 진입까지 연결됐다. 에디터 새 이미지 색상에서도 아이보리를 선택하고 원본을 확인했다.
- 데스크톱 1280, 1440, 1920px에서 콘티 가로 넘침 없음.
- 입력 화면 320, 360, 375, 390, 414px에서 변경한 안내의 글자별 위치를 측정했다. 어절 중간 줄바꿈과 안내 영역 넘침 없음.
- 입력 안내의 실제 글자색은 `rgb(110,110,110)`, 12px였다. 기존 상품 입력 배경과 orb를 유지했다. 문서 전체의 1px 가로 초과는 기존 장식 영역에서 관찰되어 새 안내의 넘침과 구분했다.
- 목 생성 후 기존 FaceMarket 정산 조회에서 `API no-session` 로그가 관찰됐다. 새 색상 필드의 렌더 오류는 없었다. 인증 없는 목 환경의 정산 조회는 실제 운영 정산 검증을 대신하지 않는다.
- WebKit 별도 실행은 하지 않았다. 화면 캡처와 측정 기록은 `.scratch/colorway-flow-20261106/qa/`에 보관했다.

## 운영 적용 전 상태

프로듀싱 작업 공간 `/Users/daily/.codex/worktrees/templates-mvp/wearless_studio`에 통합했다. 커밋, 푸시와 운영 배포는 실행하지 않았다. DB 마이그레이션이 필요하지 않다. 추가색 착용컷은 내부 이미지 편집 호출이 늘어나므로 운영 시간과 원가를 계속 관찰해야 한다. 자동 검수를 끈 환경은 색상 검수도 `not_run`이며, 켠 환경에서만 별도 시각 비교가 수행된다.
