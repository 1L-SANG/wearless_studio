# 의류 QC 고도화 토론과 같은 사진의 모델 대조

실사용 작업 모델은 gpt-6.1-sol, effort xhigh다. 여러 모델의 판독 오류와 비용, 검사 결과 소비 경계를 함께 다뤄 xhigh를 사용했다. Codex 내부 설계 토론은 실제 gpt-6-astra, xhigh 세 번이며 세션 기록으로 확인했다. Claude 텍스트 토론 두 번은 실제 claude-fable-5-1, high다. 유료 사진 검수의 Astra는 gpt-6-astra, high이며 내부 토론의 xhigh와 구분한다.

이번에 제품 QC와 운영 설정을 변경하지 않았다. 추천 후보와 로컬 검사 가드를 시험한 연구 단계다. Fable은 사진 없이 설명과 실제 측정 결과를 받아 토론했고, Fable의 비전 검수 성능을 측정했다고 말하지 않는다.

## 추천 결론

현재 모델을 한꺼번에 교체하기보다 원본의 사진 역할, 필수 비교와 판독 가능 상태를 먼저 보강하는 것이 필요하다. 저렴한 1차 후보는 Gemini Pro의 강화 검사와 high 추론이다. Astra는 장식 단추, 중요한 글자와 무늬 등 상품 식별에 중요한 부위의 독립 재검수 후보로 둔다. 이번에 Astra가 단추 변경과 동일 원본 대조를 올바르게 구분한 신호는 있으나 다른 상품과 정상 착용 사진의 정확도는 미측정이다.

재검사를 1차 FAIL에만 걸면 원래 문제인 과잉 PASS를 놓친다. 원본에서 확인한 중요한 특징과 비교 누락을 기준으로 대상을 정해야 하며, 첫 판정이 PASS여도 중요한 특징은 재검사할 수 있어야 한다. 두 모델의 동의만으로 사실을 확정하거나, 반복 생성과 검사를 성공할 때까지 이어가는 방식은 추천하지 않는다.

## 무엇을 확인했나

보존한 핑크 최종컷의 기존 QC는 장식 단추 대신 일반 단추를 만든 결과를 다섯 개라는 이유로 PASS했다. 현재 스키마는 17개 항목마다 판정과 한 문장의 근거를 요구한다. 개수와 종류, 장식, 구멍처럼 서로 다른 비교 조건이 한 항목에 묶여 일부만 확인해도 PASS되는 빈틈이 있다. 참조 변환에서도 PRODUCT Front, Back, Detail이 PRODUCT 1, 2, 3으로 축약된다.

첫 비교 계획은 실행 전에 고정했다. 같은 저장 사진과 계약으로 기존 P0, 단추 5개 하위 비교를 필수로 한 P1, 원본과 후보의 분리 관찰, 실제 Astra P1, 동일 원본 대조와 사전 예정된 P1 반복을 총 8회 실행했다. 후보 이름에 이전 판정이나 정답을 넣지 않았고 각각 새 독립 API 요청이다. 모델에 이전 검사 결과를 주지 않았다.

P0는 기존 검사 지시와 사진 바이트를 재현했다. 비용 보호를 위해 4096 출력 한도를 적용했으므로 운영 요청의 모든 설정이 바이트 그대로라는 뜻은 아니다. P1은 기존 17개 항목을 유지하며 단추의 개수, 바탕 윤곽, 표면 입체 장식, 보이는 광학적 인상, 읽을 수 있는 구멍 배치를 나눴다. 원본과 후보 관찰을 각각 적고 관계를 판정하도록 했다. source와 candidate를 같은 호출에서 관찰하는 것이 독립성을 보장한다는 뜻은 아니다.

Gemini는 gemini-3.1-pro-preview, low이며 Astra는 gpt-6-astra, high와 image detail high다. P1의 사진 바이트와 지시, 스키마는 같지만 공급자의 이미지 처리와 계산 설정이 같다고 추정하지 않는다. 순수 모델 구조의 우열보다 실제 대체 검사 구성의 비교다. 모든 API 응답은 반환 모델과 정상 종료, 사용량을 기록했다.

## Gemini 추론 수준의 별도 4회 대조

비싼 모델 교체 외의 대안으로 P1, 같은 사진과 스키마, 출력 한도 8192를 고정하고 low와 high만 달리했다. 잘못된 후보와 같은 원본 대조 각각 한 번이다. 원래 8회와 출력 한도가 다르므로 별도 계획과 결과로 기록했다.

| 후보 | low | high |
| --- | --- | --- |
| 장식이 단순화된 최종컷 | 입체 장식 FAIL, 구멍 UNJUDGEABLE | 입체 장식 FAIL. 다만 작은 구멍이 안 보이는 것을 없다고 FAIL한 과잉 단정도 있음 |
| 동일 원본 Detail | 장식은 PASS, 구멍은 UNJUDGEABLE인데 원래 hardware는 PASS | 하위 항목 모두 PASS |

high는 이 두 진단에서 변형과 동일 원본을 구분했다. 그러나 읽을 수 없는 구멍을 없다고 판단한 문제는 남는다. 더 오래 생각하거나 더 높은 가격의 모델이라고 항상 올바른 판정을 내리는 것은 아니다.

측정한 P1 호출은 Pro low 약 $0.03와 17~20초, Pro high 약 $0.062~0.067와 약 37초, Astra high 약 $0.244~0.265와 48~55초다. 모두 같은 작은 진단의 usage와 공개 단가 추정이며 운영 전체 지연이나 일반 품질을 보장하지 않는다. source-only와 candidate-only의 더 작은 요청은 이 전신 검사 시간 비교에 섞지 않았다.

## 실제 논쟁과 받아들이지 않은 의견

Astra는 관찰 누락이 드러나는 비교와 정상 대조를 먼저 만들고 모델 교체를 실측하자고 제안했다. Fable은 같은 호출에서 원본과 후보를 함께 보면 원본 해석이 후보에 끌려갈 수 있다며 두 호출로 분리하고 코드로 값을 비교하자고 반박했다.

분리 관찰의 후보 개수 오류를 보여준 뒤 Fable은 이를 자동 판정 장치로 쓰자는 제안을 철회했다. 원본 관찰 캐시도 검증 없이 정본이 될 수 없으며, 원본과 후보의 값 차이가 상품 차이라는 뜻은 아니다. 코드가 값을 일관되게 비교하는 것과 입력 관찰이 정확한 것은 다르다.

Fable의 이산값만 FAIL하고 연속 속성은 항상 보류하자는 규칙도 수정됐다. 명확한 입체 장식 누락은 FAIL 근거가 될 수 있고, 반대로 단추 개수 자체가 오판일 수도 있다. 조명이나 크기, 가림으로 못 읽은 부분은 판독 불가이며 결함이라고 단정하지 않는다.

Fable이 제안한 10% 무작위 감사는 근거 없는 운영 수치라 채택하지 않았다. Fable의 최종안은 Pro FAIL 또는 UNJUDGEABLE에만 Astra를 붙이고 두 모델이 같으면 확정하자는 것이었으나, 그 방식은 Pro의 조용한 과잉 PASS를 놓치고 두 모델의 동일 원본 오독도 막지 못한다. 따라서 중요한 상품 특징에 대한 PASS 재검사와 원본 근거 확인을 포함하는 쪽을 추천한다. 한 번의 자기 일치 실패로 모든 다른 사진의 판정을 거짓으로 확정하는 것도 피한다.

Fable의 첫 설명 중 QC1은 큰 차이, QC2는 미세 차이였다는 주장은 사진 없이 한 추정이라 취소됐다. Fable의 텍스트 논쟁과 Astra의 사전 설명이 있는 설계 토론은 블라인드 모델 성능 시험으로 세지 않는다.

## 판정과 실제 사진 사용의 경계

작업 코드와 2026-10-10 최신 origin/main b05ef7a9를 대조했다. cut_output_qc의 UNJUDGEABLE은 passed=false이며 HOLD_STAGE1으로 처리한다. 하지만 워커는 그 뒤 save_final과 _store_cut으로 사진을 보존하고 cutQc 메타데이터를 기록한다. HOLD라는 이름만으로 실제 출고나 다운로드 차단이 된다고 설명하면 틀린다. Astra도 앞선 출고 차단처럼 설명한 부분을 정정했다.

사진 보존, 검수 보류 표시, 사용과 다운로드 가능 상태, 재생성과 차감은 다른 결정이다. 검사 모델이 더 정확해져도 소비자가 여전히 실패 사진을 정상 사진처럼 받는다면 실제 개선은 보장되지 않는다. 품질 상태를 소비하는 경계가 함께 설계돼야 한다. 이 연구에서 저장, 다운로드와 과금 정책을 변경하지 않았다.

도달 경로는 상품 등록, 콘티보드의 호리존 선택, 마네킹 선택, 상세페이지 생성 뒤 에디터의 해당 컷이다. 실제 운영 작업과 저장을 실행한 것은 아니며 코드의 이 경계를 읽기 전용으로 확인했다. 기존 PR482의 내 옷 대기 안내 연결도 별도로 남아 있다.

## 최소 구현 방안

1. 원본 Front, Back, Detail과 생성 마네킹, 후보를 역할과 해시가 있는 자료로 유지한다. 과거 자료에 없는 뷰를 추측해서 채우지 않는다. 앞 직선·뒤 곡선의 오너 확인, 원본 관찰, 미확인 앞단의 직선 생성 정책은 서로 구분한다.
2. 개수만 맞으면 종류까지 PASS하는 모순을 막는다. 원본 관찰, 후보 관찰, 관계와 판독 가능 상태를 나눈다. 필요한 하위 비교가 누락되거나 미확인인데 상위 항목만 PASS할 수 없도록 검증한다. 단, 전신 컷에 모든 미세 구멍까지 무조건 요구하면 불필요한 보류가 늘므로 원본과 목표 컷에서 확인할 특징을 선별한다.
3. 원본 관찰을 재사용할 때 원본 픽셀과 한 번 대조한다. 바이트와 슬롯, 관찰 계약, 모델과 정책 버전으로 캐시를 구분한다. 잘못된 관찰을 서명하거나 해시를 붙인다고 올바른 사실이 되지 않는다.
4. 공유 분석 모델을 통째로 바꾸지 않고 QC 전용 추론 수준과 모델 경로를 둔다. 현재 vision_llm은 gpt와 gemini 제공자만 지원한다. Astra는 기존 GPT 통신 경로를 사용할 수 있지만, 단순 fallback 설정만 바꾸면 정상 형식의 오판 PASS에서 호출되지 않는다. 독립 검사 경로가 필요하다. Fable을 제품 QC로 쓰려면 Anthropic 제공자 연결과 인증, 응답 검증이 추가로 필요하며 이번에 구현하지 않았다.
5. Pro high를 저렴한 1차 후보로 검증하고, 중요한 장식과 글자, 무늬 및 비교 누락·원본 해석 충돌은 Astra의 제한된 독립 재검수 후보로 둔다. 첫 판정을 주지 않고 먼저 관찰하게 하며, 두 표결만으로 자동 확정하지 않는다. Fable 비전은 같은 조건의 후속 후보이며 이번에 우수하다고 선택하지 않는다.
6. 확인된 결함에만 기존 고정 보정 지시를 사용한다. 자유로운 모델 근거 문장을 생성 지시로 그대로 넣지 않는다. 판독 불가는 자동으로 단추나 밑단을 새로 그리는 근거가 아니다. 보정 뒤에는 지적 부위와 실제 바인딩·절개·개수 같은 보존 항목도 다시 본다.
7. 출고와 보류 상태의 소비 정책은 별도로 확정한다. 이미지 초안을 보존하는 것과 검수 완료 표시를 분리한다. 다운로드 차단이나 차감·환급은 모델의 판단만으로 이번에 바꾸지 않는다.

로컬 prototype에는 실제 반복 결과의 raw hardware PASS와 하위 UNJUDGEABLE 모순을 처리하는 가드를 만들었다. 판독 불가 항목을 억지로 PASS하지 않고, 다른 패턴·부자재 실패를 단추 PASS가 지우지 않게 한다. 이 가드는 비교 누락과 모순을 막으며 모델의 잘못된 원본 판독과 개수 오류까지 해결하지는 않는다. 제품 코드에 적용한 상태가 아니다.

## 공식 문서와 실사용 증빙

[OpenAI Astra 공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)와 [Anthropic 모델 목록](https://platform.claude.com/docs/en/models/overview)에서 요청한 모델과 이미지 입력 지원을 확인했다. 계정의 실제 Astra 접근은 유료 호출 전 모델 GET과 실제 반환 모델로 확인했다. Fable은 CLI modelUsage의 canonicalModel과 첫 번째 및 두 번째 토론 응답으로 증빙했다.

[OpenAI 평가 안내](https://developers.openai.com/api/docs/guides/evaluation-best-practices)는 실제 사례와 대표·경계 사례를 기준으로 평가하는 방향의 근거다. [Claude 비전 안내](https://platform.claude.com/docs/en/build-with-claude/vision)는 이미지 크기와 시각 토큰의 차이를 설명한다. 따라서 이미지 바이트가 같아도 공급자별 처리와 계산량이 같다고 가정하지 않는다. [Gemini thinking 안내](https://ai.google.dev/gemini-api/docs/thinking)는 Pro 3.1의 low, medium, high 지원과 출력 한도가 thinking도 포함함을 설명한다. 이 안내가 특정 상품의 정확도를 보증하는 것은 아니다.

공식 가격과 기록한 사용량을 사용했으며, Astra API 입력은 캐시 할인 없이 보수적으로 추정했다. Fable 비용은 CLI가 보고한 목록가격 추정이다. Codex 내부 토론의 계정 사용량은 외부 API 실험 요청 수와 비용표에 섞지 않았다. 실제 청구서는 확인하지 않았다.

## 비용과 검증

새 사진 검수 POST는 12회이며 Gemini 10회, Astra 2회다. 모두 200과 정상 종료, 파싱 완료다. Fable 텍스트 CLI 실행은 2회이며 CLI 내부 HTTP 수를 직접 POST 수에 섞지 않았다. 새 사진 생성과 운영 DB, R2, AWS 쓰기 및 조회, 배포는 없다.

같은 승인 총 $8 안에서 매 요청 전 예약했고 확인 추정 $6.80부터 새 요청을 막는다. 기존 미확인 $1.05와 이전 중단 기록을 풀지 않았다. 이번 새 미확인 비용과 중복 stage는 없다. 원래 계획과 실행 코드, 이후 가드 변경과 추론 수준 대조의 별도 계획 해시를 보존했다. 과거 계획이 현재 변경 코드까지 검증한다고 주장하지 않는다.

이번 무료 pytest는 7 통과, 실패 0이다. 실제 저장된 반복 응답의 상위 PASS와 하위 판독 불가를 재현했고 새 가드로 보완했다. 제품 코드와 화면이 바뀌지 않아 전체 서버 pytest, pnpm test:frontend와 pnpm build는 재실행하지 않았다. 이전 제품 검사는 서버 7698 통과와 104 조건부 건너뜀, 프론트 2806 통과와 빌드 통과였으며 로컬 DB 접속 실패는 없었다. 이 기록을 최신 main 검사나 새 QC의 운영 품질 통과로 쓰지 않는다.

Fable의 사진 판독, 흰 앞 밑단과 소매선에 대한 새 모델 비교, 다른 의류, 실제 정상 착용컷의 오탐률, 반복 안정성과 실제 운영 저장·다운로드·정산은 못 했다. 자기 일치 대조만으로 운영 모델 채택을 확정하지 않는다. 이번 화면 변경은 없어 모바일 다섯 폭과 WebKit 검사는 새로 하지 않았다.

## 쉬운 설명

기존 AI는 같은 단추를 다르게 읽기도 했고 다섯 개를 세고도 장식이 달라진 것을 놓쳤다. Astra는 이번 비교를 더 잘 처리했고 Gemini도 더 생각하게 하니 개선 신호가 있었다. 추천은 저렴한 검사를 먼저 보강하고 중요한 디테일만 독립적으로 다시 보는 것이다. 검사 보류가 실제 사용자 화면과 사진 사용에 어떻게 반영되는지도 함께 다뤄야 하며, 제품 QC가 이미 교체되거나 해결된 상태는 아니다.
