# 쇼핑몰 상세페이지 FAQ·말풍선 블록 리서치 (2026-08-12)

> 후속 기술 설계: [에디터 오브젝트 라이브러리·FAQ 통합 기술 설계](../editor_object_library_design.md)

## 조사 범위

사용자가 첨부한 두 레퍼런스처럼, 셀러가 wearless 에디터에서 추가해 **최종 1000px 폭의 정적 상세페이지 이미지**로 내보내는 FAQ/Q&A 콘텐츠 블록을 조사했다.

이 문서는 다음을 다룬다.

- 말풍선형 FAQ가 실제로 하는 역할
- 정적 상세페이지에 맞는 시각 패턴
- 패션 상품에서 먼저 답해야 할 질문
- 질문·답변 카피 작성 규칙
- wearless 기존 `내용 추가` 구조에 맞춘 권장 사양

에디터 자체의 도움말, 챗봇, 툴팁, 웹 상품 페이지의 인터랙티브 아코디언은 이번 범위가 아니다. 아코디언 사례는 정적 이미지에서는 왜 답변을 펼쳐 보여줘야 하는지 판단하는 비교 근거로만 사용한다.

---

## 1. 결론

FAQ는 넣는 편이 좋다. 다만 **범용 정책을 길게 반복하는 블록**이 아니라, 상품 설명과 사진만으로 남은 구매 망설임을 3~5개의 실제 질문으로 해소하는 블록이어야 한다.

wearless에는 아래 두 레이아웃을 먼저 제공하는 것이 적절하다.

1. **카드형 FAQ — 기본값**
   - 첨부 1과 같은 독립 배경 + Q/A 카드 스택
   - 사진 없이도 안정적이고, 어떤 상품에도 적용 가능
   - 3~5개 질문을 한 열로 모두 펼쳐 보여줌

2. **포토 대화형 — 강조 옵션**
   - 첨부 2와 같은 상품 사진 + 좌우 교대 말풍선
   - 핵심 반론 2~3개만 다룸
   - 배경 사진이 답의 증거가 될 때 사용

세 번째 별도 레이아웃을 늘리기보다, 포토 대화형에서 사진을 비우면 단색 배경 대화형으로 동작하게 만들면 충분하다.

FAQ 블록의 제품 역할은 `특징 포인트`와 다르다.

- `특징 포인트`: 브랜드가 먼저 말하는 장점
- `FAQ`: 고객이 망설이는 조건·예외·한계를 먼저 인정하고 답하는 영역

Baymard의 상품 페이지 테스트에서도 FAQ/Q&A는 상품 설명을 대체하는 것이 아니라, 설명을 짧고 읽기 쉽게 유지하면서 미처 답하지 못한 사용자의 질문을 보완하는 영역으로 관찰됐다. [Baymard — Product Page FAQ & Q&A](https://baymard.com/blog/product-page-faq-and-qa)

## 2. 첨부 레퍼런스 해석

### A. 포인트 컬러 카드형

첨부 1은 엄밀히 말해 채팅 UI보다 **에디토리얼 FAQ 카드**에 가깝다.

- 큰 `FAQ` 제목
- 검은 Q/A 본문 카드
- 카드 뒤의 오렌지 절각 도형으로 브랜드 포인트
- 질문 4개를 같은 규칙으로 반복

장점:

- 사진 유무와 관계없이 쓸 수 있다.
- 질문과 답변의 계층이 명확하다.
- 긴 상세페이지에서도 섹션 경계가 분명하다.
- 현재 wearless의 흰색·연회색·잉크 블록과 결합하기 쉽다.

주의점:

- 모든 답변이 비슷한 길이여야 카드 리듬이 안정적이다.
- 장식 도형이 본문보다 강하면 읽기보다 분위기 연출이 앞선다.
- 배송·교환 안내를 그대로 옮기면 기존 `배송·교환 안내` 블록과 중복된다.

### B. 포토 대화형

첨부 2는 **고객의 반론 → 브랜드의 즉답**을 채팅처럼 연출한 구성이다.

- 질문은 짧은 흰색 말풍선
- 답변은 큰 브랜드 컬러 말풍선
- Q/A 방향을 좌우로 교대
- 상품 착용 사진이 배경이자 증거

장점:

- “젖지 않나요?”, “사이즈 괜찮나요?”처럼 실제 구매자가 속으로 하는 질문을 바로 드러낸다.
- 제품 사진과 답이 한 화면에 있어 기능·핏 설명의 설득력이 높다.
- FAQ라는 딱딱한 정보 블록보다 콘텐츠성이 강하다.

주의점:

- 배경이 복잡하면 글자가 급격히 안 읽힌다. 말풍선은 불투명하게 두고 사진 위에 직접 글자를 얹지 않는다.
- 4개 이상 넣으면 사진을 가리고 대화 흐름도 산만해진다.
- 고객 후기처럼 보이게 이름·프로필·별점을 붙이면 실제 사용자 발화로 오인될 수 있다. `자주 묻는 질문` 또는 `Q/A`임을 명확히 한다.

### 핵심 해석

말풍선은 독립된 FAQ 기능이 아니라 **질문을 더 인간적으로 보이게 하는 시각 문법**이다. 좋은 질문과 근거 있는 답이 없으면 말풍선만 추가해도 전환 장벽은 줄지 않는다.

## 3. 어떤 질문을 넣어야 하는가

### 우선순위

| 순위 | 질문 범주 | 패션 상품 질문 예시 | wearless에서 쓸 수 있는 근거 |
|---|---|---|---|
| 1 | 사이즈·핏 | 정사이즈인가요? 여유 있게 입으려면요? 기장은 어디까지 오나요? | `fit`, 실측, 모델 정보, 착용 사이즈 |
| 2 | 소재감 | 두께감은 어떤가요? 비침이 있나요? 신축성이 있나요? 까슬거리나요? | 소재 + 셀러 입력. 현재 두께·비침·신축 필드는 부족 |
| 3 | 기능·사용 조건 | 생활 발수인가요? 보온성은요? 수납은 충분한가요? | 검증된 selling point 또는 셀러 입력만 사용 |
| 4 | 컬러·실물 차이 | 화면과 실제 색이 같은가요? 밝은 색은 비치나요? | 컬러 옵션 + 표준 촬영/화면 차이 고지 |
| 5 | 세탁·관리 | 세탁기에 돌려도 되나요? 줄어들 수 있나요? | 소재별 care 규칙 + 케어라벨 확인 |
| 6 | 계절·스타일링 | 어느 계절에 입기 좋나요? 이너와 함께 입을 수 있나요? | 두께/핏 근거가 있을 때만 |
| 보조 | 배송·교환 | 언제 출고되나요? 교환 가능한가요? | 판매자 정책. 기존 정책 블록과 중복 최소화 |

국내 실제 의류 FAQ와 상품 Q&A에서도 사이즈 선택, 구성 차이, 소재, 재입고 등이 반복된다. 페르테는 상세페이지의 실측·스타일별 차이·가슴둘레 우선 확인을 안내하고, LF몰 공개 상품 Q&A에도 소재·구성·사이즈 관련 질문이 그대로 나타난다. [페르테 FAQ](https://perte.co.kr/board/faq/list.html?board_no=3), [LF몰 공개 상품 Q&A 예시](https://www.lfmall.co.kr/app/product/F575XX02232)

Baymard도 의류 사이즈 정보는 범용 문구가 아니라 상품 종류와 브랜드에 맞아야 하며, 실측 방법을 함께 보여줘야 한다고 권고한다. [Baymard — Apparel Sizing](https://baymard.com/blog/apparel-size-information)

### 상품 유형별 기본 질문 후보

**상의·아우터**

- 평소 사이즈대로 고르면 될까요?
- 이너를 입어도 여유가 있나요?
- 두께감과 비침은 어느 정도인가요?
- 지퍼·스트링·포켓은 어떻게 쓰나요?
- 세탁은 어떻게 해야 하나요?

**팬츠**

- 허리와 힙은 정사이즈인가요?
- 허리 밴딩이나 신축성이 있나요?
- 키별 기장감은 어떤가요?
- 밝은 컬러는 비침이 있나요?
- 세탁 후 수축이나 이염에 주의해야 하나요?

**스커트·원피스**

- 안감과 비침은 어떤가요?
- 허리·가슴 기준으로 어떤 사이즈를 고르나요?
- 키별 총장감은 어떤가요?
- 신축성이 있나요?
- 세탁과 다림질은 어떻게 하나요?

### 질문을 고르는 실제 데이터 순서

1. 반복 CS 문의
2. 상품 Q&A
3. 반품 사유
4. 리뷰의 기대 차이 표현
5. 경쟁 상품 페이지
6. 위 데이터가 없을 때만 카테고리 기본 질문

NN/g는 실제 질문과 사용자의 어휘를 쓰고, 많이 필요한 질문부터 배열하라고 권고한다. [NN/g — Strategic Design for FAQs, pp. 62–68](https://media.nngroup.com/media/reports/free/Strategic_Design_for_Frequently_Asked_Questions.pdf) Shopify의 최신 가이드도 지원 문의·고객 여정·경쟁사·포럼에서 질문을 수집하고, 상품 정보와 사이즈를 핵심 범주로 제시한다. [Shopify — FAQ Guide](https://www.shopify.com/blog/120928069-how-to-create-faq-page)

## 4. 질문·답변 카피 규칙

### 질문

- 고객이 실제로 말하는 문장으로 쓴다.
- 한 질문에는 한 가지 걱정만 둔다.
- 정보 단어를 앞에 둔다: `사이즈는…`, `비침은…`, `세탁은…`.
- 1000px 캔버스 기준 한 줄, 최대 두 줄을 넘기지 않는다.
- `FAQ 01`보다 질문 자체가 먼저 보이게 한다.

좋음:

- `밝은 컬러는 비치지 않나요?`
- `평소 사이즈대로 고르면 될까요?`

나쁨:

- `고객님들이 가장 궁금해하시는 사이즈 관련 내용을 알려드립니다.`
- `이 상품은 정말 완벽한가요?`

### 답변

답변은 **결론 → 조건/예외 → 다음 확인점** 순서가 좋다.

예:

> 밝은 컬러는 강한 조명에서 약간 비칠 수 있어요. 스킨톤 이너 착용을 권장하며, 정확한 두께감은 원단 접사도 함께 확인해 주세요.

규칙:

- 예/아니오 질문은 첫 단어부터 `네`, `아니요`, `경우에 따라 달라요`처럼 답한다.
- 1~3문장으로 끝낸다.
- 장점만 반복하지 말고 조건과 한계를 쓴다.
- `완벽`, `누구나`, `100%`, `절대` 같은 보장 표현은 피한다.
- 방수·냉감·항균·UV 차단처럼 검증이 필요한 기능은 입력된 시험/상품 근거가 있을 때만 쓴다.
- 모르는 답을 AI가 채우지 않는다. 셀러 입력 전에는 `정보 입력 필요` 또는 질문 추천만 보여준다.

NN/g는 평이한 언어, 짧은 답, 명확한 시각 계층을 높게 평가하며, 닫힌 질문에는 Yes/No/It depends 같은 직접 답부터 시작하라고 권고한다. 또한 FAQ는 다단보다 한 열을 권장하고, 모양을 맞추기 위해 답을 잘라내지 말라고 한다. [NN/g FAQ 보고서](https://media.nngroup.com/media/reports/free/Strategic_Design_for_Frequently_Asked_Questions.pdf)

## 5. 정적 상세페이지용 시각 원칙

### 공통

- 질문 수: 기본 4개, 허용 2~6개
- 레이아웃: 모바일 축소를 고려한 단일 열
- 질문은 답변보다 굵고 크게
- 카드/말풍선 좌우 여백과 꼬리 방향을 일관되게 유지
- 포인트 컬러는 질문/답변 구분 또는 장식 중 하나에만 집중
- 이모지는 기본값에서 제외하고 셀러가 선택할 때만 허용
- `Q.`와 `A.`만 반복 강조하지 말고 실제 질문 키워드를 강조

### 카드형 권장값 — 1000px 캔버스

- 콘텐츠 폭: 기존 블록과 같은 880px
- 바깥 여백: 좌우 60px
- 질문: 약 28~34px, 600~700 weight
- 답변: 약 19~23px, 행간 1.5~1.65
- 카드 안쪽 여백: 32~40px
- 카드 간격: 20~28px
- 답변 최대 폭: 카드 전체 폭보다 짧게 유지해 행 길이를 줄임

### 포토 대화형 권장값

- 질문 수: 2~3개
- 배경: 착용컷 또는 기능을 보여주는 컷 1장
- 말풍선: 완전 불투명, 충분한 대비
- 질문 폭: 45~65%
- 답변 폭: 65~85%
- 질문은 왼쪽, 답변은 오른쪽을 기본으로 교대
- 얼굴·상품 핵심 디테일·손을 말풍선이 가리지 않도록 사진 선택 단계에서 안전 영역 확인

웹 FAQ라면 아코디언이 스크롤을 줄일 수 있지만 답이 숨겨진다는 단점이 있다. wearless 산출물은 클릭할 수 없는 정적 이미지이므로 모든 답을 펼친 상태가 맞다. [W3C Accordion Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/), [NN/g FAQ 보고서](https://media.nngroup.com/media/reports/free/Strategic_Design_for_Frequently_Asked_Questions.pdf)

## 6. 상세페이지 안의 배치

기본 순서:

`핵심 장점 → 핏·코디 → 제품 확인 → FAQ → 사이즈/케어/고시/배송·교환`

권장 이유:

- FAQ는 제품을 충분히 본 뒤 생기는 망설임에 답한다.
- 법정 고시와 정책 표보다 앞에 두면 감성 콘텐츠에서 정보 콘텐츠로 넘어가는 완충 역할을 한다.
- 사이즈가 가장 큰 장벽인 상품은 FAQ를 핏·모델 정보 바로 뒤로 당길 수 있다.
- 포토 대화형은 관련 기능을 보여주는 컷 다음에 배치할 수 있다.

예외:

- 반품 정책은 FAQ에만 숨기지 않는다. Baymard 연구에서 많은 사용자가 상품 페이지에서 반품 정보를 찾았으므로, 기존 `배송·교환 안내` 블록은 유지하고 FAQ에는 상품별 예외만 짧게 답한다. [Baymard — Return Policy on PDP](https://baymard.com/blog/current-state-ecommerce-product-page-ux)
- 사이즈 FAQ는 사이즈표를 대체하지 않는다. 답에서 실측표와 모델 정보를 연결한다.

## 7. wearless에 맞는 제품 제안

현재 PRD §10.14는 FAQ를 `필요할 때 추가` 콘텐츠로 이미 정의했지만 구현 카탈로그에는 아직 없다. 현재 `ContentPanel`은 `INFO_PRESET_TYPES`를 중요도별로 노출하고, `InfoBlockModal`의 폼 상태를 `block.info` 정본으로 저장한 뒤 `infoPresets.js` 빌더가 1000px 캔버스 요소를 만든다.

따라서 새 독립 시스템보다 기존 흐름에 `faq` 정보 블록을 추가하는 것이 맞다.

### 권장 카탈로그 위치

- 그룹: `필요할 때 추가`
- 이름: `자주 묻는 질문`
- 설명: `사이즈·소재·사용법처럼 구매 전 망설이는 질문 2~6개`
- 반복 추가: 허용. 상품 FAQ와 정책 FAQ를 분리할 가능성 때문

### 권장 폼

- 레이아웃: `카드형` / `대화형`
- 제목: 기본 `FAQ` 또는 `자주 묻는 질문`
- 질문·답변 2~6쌍
- 순서 이동, 추가, 삭제
- 대화형일 때 배경 사진 선택/해제
- 답변 글자 수 가이드와 넘침 경고
- 사실 근거가 없는 답변은 자동 생성하지 않음

권장 정본 shape:

```js
{
  layout: 'cards' | 'chat',
  title: 'FAQ',
  backgroundSrc: null,
  items: [
    { question: '', answer: '' }
  ]
}
```

별도 색상 값을 정보 정본에 많이 넣기보다 기존 블록 배경과 디자인 토큰을 우선 사용한다.

### 자동 프리필 범위

현재 데이터로 안전하게 제안 가능한 것:

- `fit` → 사이즈/핏 질문 후보
- `measurements` → 실측 확인 답변 보조
- `materials` → 소재/케어 질문 후보
- `sellingPoints` → 기능 질문 후보. 단, 표현을 사실로 검증할 수 있을 때만
- `selectedModel` → 모델 착용 정보 질문 후보
- 기존 care 규칙 → 세탁 답변 초안

현재 자동 답변이 위험한 것:

- 비침
- 두께
- 신축성
- 촉감
- 생활 방수/발수
- 보온성
- 계절감
- 세탁 후 수축

이 값들은 현재 분석 정본에 명확한 필드가 없으므로 질문만 추천하고 답변은 셀러가 확인해 입력하게 해야 한다. FAQ가 허위 상품 설명을 만드는 통로가 되어서는 안 된다.

## 8. MVP와 후속 범위

### MVP

1. `자주 묻는 질문` 프리셋 1개
2. 카드형 + 포토 대화형 2개 레이아웃
3. 질문·답변 2~6개 편집
4. 안전한 데이터만 프리필
5. 기본 배치: 구매 정보의 첫머리
6. 모바일 축소 미리보기에서 가독성 확인

### 후속

- 실제 셀러 문의 로그에서 질문 추천
- 상품 유형별 질문 세트
- 질문별 근거 출처 표시 또는 검수 상태
- 브랜드 컬러 프리셋
- 포토 대화형 안전 영역 미리보기

### 이번에 하지 않을 것

- 가짜 구매자 이름·프로필·별점 생성
- 자유 입력 챗봇
- 정적 이미지 안의 가짜 아코디언/버튼
- 배송·교환 정책 블록 삭제 또는 대체
- 근거 없는 성능·소재 특성 자동 작성

## 9. 출시 후 확인할 지표

FAQ 블록의 효과는 레이아웃 취향만으로 판단하지 않는다.

- FAQ 블록 추가율
- 추천 질문 중 실제로 유지·수정·삭제된 비율
- 가장 많이 쓰인 질문 범주
- 글자 넘침/수동 수정 빈도
- 카드형과 포토 대화형 선택률
- 셀러가 FAQ를 넣은 상품의 반복 CS 질문 변화
- 가능하면 쇼핑몰 측 전환·반품 사유 변화

질문 데이터가 쌓이면 인기 질문을 위로 올리고 오래되거나 중복된 질문을 정리한다. 이는 실제 질문과 사용 빈도를 바탕으로 FAQ를 운영하라는 NN/g·Shopify의 권고와도 맞는다.

---

## 10. 최종 판단

wearless에는 FAQ를 추가할 근거와 자리가 모두 있다. PRD에 이미 `필요할 때 추가`로 정의돼 있고, 현재 정보 블록 구조에도 자연스럽게 들어간다.

제품 방향은 다음 한 문장으로 정리된다.

> **기본은 읽기 쉬운 카드형 FAQ, 강조가 필요한 상품에는 사진 위 대화형 FAQ. 실제 구매자의 말투로 묻고, 확인된 사실과 조건으로 짧게 답한다.**
