# 마네킹 후보를 넣은 실제 최종컷 검증

실사용 작업 모델은 gpt-6.1-sol, effort xhigh다. 이 문서는 앞선 마네킹에서 보인 소매선과 앞 밑단 문제가 실제 상세페이지 의류컷에도 이어지는지 확인한 로컬 실행 기록이다. 제품 코드를 바꾸거나 배포하지 않았다.

## 현재 규칙과 검증 범위

2026-10-09 git fetch origin 뒤 origin/main 1eef1335와 작업 브랜치의 실제 코드를 확인했다. 일반 생성 템플릿 `cut_generate_v1.txt`는 PRODUCT 원본을 상품 정체성과 구조의 정본으로 지정하고 MANNEQUIN은 원본에서 뒷받침되는 착용 형태의 참고로만 쓴다. 원본에서 불확실한 색, 소재, 구조, 핏과 길이를 마네킹으로 확정하지 않는다. 일반 QC도 같은 원본 우선 정책을 쓴다. 상품 단독 product 컷에는 `detail_page_job.py`가 마네킹을 붙이지 않는다.

확정 스타일링의 별도 `cut_generate_confirmed_gpt_v1.txt`는 상품 구조와 봉제선은 원본을 우선하지만 마네킹의 착용색과 핏, 기장, 실루엣, 볼륨과 드레이프에는 더 강한 권한을 준다. 모든 경로에 같은 약한 마네킹 권한이 있다고 답하면 틀린다. 이번에 그 별도 경로를 바꾸거나 생성 검증하지 않았다. 원래도 마네킹의 사람, 몸, 자세, 배경과 카메라를 복사하는 지시는 아니다.

실행 코드는 PR482 작업 브랜치이며 최신 main과 원본 우선·확정 경로의 권한 문구를 대조했다. 실제 선택한 시험은 기존 generic 호리존이다. 서비스 예시와 선택 모델이 없는 지원 경로이며 익명 인물, 정면, 전신, 얼굴 숨김을 사용했다. 특정 가상모델과 FaceMarket, 예시 적용, 확정 스타일링, 전체 운영 워커를 검사했다고 주장하지 않는다. 현행 생성 코드와 저장된 승인 프로필의 설정을 사용했다. `MODEL_ROUTING_HORIZON_CUT=gpt-image-2.5-sunburst`, `DETAIL_CUT_IMAGE_SIZE=2K`로 실제 요청은 1536×2304, medium, PNG다. 저장된 `GARMENT_QC_MODE=off`와 `CUT_OUTPUT_QC_MODE=repair`도 구분했다.

원본 Front와 Back 및 핑크 Detail, 앞선 NB 2.1 controlled-1 마네킹, 같은 청바지를 역할별로 전달했다. 새 정돈본으로 원본을 대체하지 않았다. 강화한 새 밑단 지시를 붙이지 않고 기존 생성 요청을 사용했다. 기존 cut_output_qc가 판정하고 고정 보정 지시와 원본에서 한 번 재생성한 뒤 기존 compare_repair로 채택 여부를 결정했다.

핑크 최초 결과의 추가 선은 실제 최종컷에서도 나타났다. 재생성 뒤 약해진 개선 신호는 있지만 QC가 그 선을 잡아 직접 고친 실험은 아니다. QC는 단추만 지적했고 전체를 다시 그리는 과정에서 어깨 표현도 달라졌다. 이 변화의 인과나 반복 성공률을 확정하지 않는다.

독립 사진 검수는 QC 답변을 읽기 전에 원본과 마네킹 및 최종 후보를 대조했다. 핑크 두 최종 결과 모두 장식 단추가 원본의 반투명·불규칙 장식판보다 규칙적인 흰 4구 단추에 가까워졌다. 단추 수 PASS와 장식 정체성 PASS는 다르며 두 번째 QC의 전체 PASS를 그대로 품질 통과로 쓰지 않는다. 가슴 절개와 외곽 바인딩까지 지우는 해결안도 아니다.

흰 Front 사진 아래의 둥근 층은 긴 Rear 자락이다. 전체 윤곽을 앞단으로 읽지 않는다. 마지막 팔 내림은 손가림을 줄인 단회 진단이며 앞선 자동 자세와 다른 조건이다. 마네킹과 실제 착용의 체형, 자세와 물리적인 원근이 달라 같은 픽셀 곡선을 그대로 복제했다거나 컷의 실제 재단을 사진만으로 입증했다고 말하지 않는다.

## 실험 연결 오류와 정정

흰 저장 분석은 outer이고 생성은 기본 open 상태로 정상 요청됐다. 처음 실험 실행기의 QC 계획만 top으로 하드코딩해 실제 생성의 상품 종류와 여밈 선택이 어긋났다. 이것은 제품 코드의 오류가 아니라 이번 테스트를 꾸린 제 오류다. 초기 흰 QC 두 건과 그 판정으로 만든 보정 후보는 무효로 기록하고 원시 응답과 생성본을 그대로 보존했다. 해당 두 후보를 기존 워크플로우의 유효한 성공이나 실패로 세지 않는다.

생성 요청과 검사 계획의 종류 및 여밈이 같은지 재현했다. 수정 전 top과 outer 차이로 1 실패, 수정 후 무료 검사 5개가 통과했다. 이후 기존 닫아서 입기 옵션으로 다시 생성해 검사했다. 아우터 분류를 몰래 상의로 바꾸거나 과거 응답을 수정하지 않았다. 추가 팔 내림은 작업 브랜치의 명시 자세 입력만 바꾼 마지막 진단이며 성공할 때까지 무제한 반복한 것이 아니다. named 자세 지원의 최신 main과 차이도 있으므로 이 마지막 포즈 진단까지 운영 화면과 동일하다고 주장하지 않는다.

## 비용과 안전 경계

앞선 총 $8 승인에 포함했다. 이전 확인 추정 $2.9177475와 미확인 예약 $1.05를 그대로 이월했다. 이전 ledger와 stopped 및 response를 수정하지 않았다. 이전 MAX_TOKENS 요청은 공식 단가와 사용량에 따라 출력 모달리티를 가장 비싸게 계산하고 2K 이미지 금액도 중복 더한 보수 추정 상한 $0.115944를 확인했지만 실제 비용으로 정산하지 않고 $0.90 예약을 유지했다. 400 요청의 $0.15도 유지했다. [Google 공식 가격](https://ai.google.dev/gemini-api/docs/pricing)을 근거로 상한만 검토했으며 청구서는 확인하지 않았다.

새 별도 원장은 기존 모든 추정액과 보류액을 합산해 각 이미지 $0.90, 검사 $0.15를 보내기 전에 예약한다. 합산 $8 초과나 확인 추정 $6.80부터 멈추며 새로운 미확인 비용은 즉시 차단한다. 같은 단계의 자동 재시도도 차단했다. 최초 상한은 이미지 4와 검사 8이었다. 흰 검사 계획 오류의 정정과 손가림 진단에 필요한 추가 이미지 두 장만 허용해 이미지 상한을 6으로 기록했고 검사 상한 8과 돈 한도는 유지했다.

이번 실제 POST는 이미지 6회와 QC 6회, 총 12회로 모두 HTTP 200이고 이미지 6장이 해독됐다. 새 추정 비용은 $0.548088이다. $8 승인에 대한 누적 확인 추정은 $3.4658355, 보류 $1.05, 합산 $4.5158355다. 새 비용 미확인 응답은 없다. 이전 승인들을 합쳐 한도를 늘리지 않았다. 운영 DB, R2, AWS와 배포에는 접근하지 않았다.

## 산출물과 검증

모든 원본과 마네킹, 실제 최종컷, 첫 흰 열린 후보와 무효 검사, 닫음 손가림과 마지막 팔 내림까지 로컬 비교 HTML에 보존했다. 이미지 참조 24개의 파일 존재를 확인했고 같은 픽셀 부위 확대를 직접 봤다. 코드와 입력 역할 및 예산 검사 5 통과, 실패 0이다. 사진과 API 응답, 인증값은 커밋하지 않는다. 모바일 다섯 폭과 WebKit 화면 검사는 기존 브라우저 로컬 파일 제한으로 못 했다.

제품 코드가 바뀌지 않아 이번 전체 pytest와 pnpm test:frontend, pnpm build는 재실행하지 않았다. 앞선 제품 검사 기록은 서버 7698 통과, 104 조건부 건너뜀, 프론트 2806 통과와 빌드 통과다. 이전 로컬 DB 접속 실패는 없고 알려진 날짜 의존 alias 검사도 당시 통과했다. 이번 사진 결과와 최신 main의 머지 확인에 그 기록을 대신 사용하지 않는다.

셀러 도달 경로는 상품 등록, 콘티보드의 스튜디오 호리존 설정, 마네킹 선택, 상세페이지 생성 뒤 에디터의 해당 컷이다. 최종컷을 검사한 것이 원래 PR482의 콘티 카드 대기 안내를 연결한 것은 아니다. 그 체크리스트는 남고 PR은 초안이다. 실제 운영 등록과 저장, 차감, 다운로드까지 실행하지 않았다.

## 쉬운 설명

마네킹이 조금 틀렸어도 최종 사진이 무조건 똑같이 틀리는 것은 아니다. 원본을 다시 보는 흐름은 있지만 핑크의 선이 첫 실제컷에도 생겼고, 다시 만들면서 약해져도 장식 단추는 달라졌다. 흰 밑단은 원본 우선 문구가 있어도 정확한 앞뒤 보존을 확정하기 어렵고 QC가 지나쳤다. 마네킹만 보고 결론내릴 수 없으며 최종 단계에서도 부위별 원본 검사가 필요하다.
