# 매칭 의류를 알아보기 쉽게 정돈하는 실험

실사용 모델은 gpt-6.1-sol, effort는 xhigh다. 실제 세션 기록에서 확인했다. 2026-10-08 사용자의 주름 정돈과 여러 방면 비교 지시에 따라 진행한 로컬 연구이며 제품 설정을 확정한 문서는 아니다.

## 추천과 관찰

이번 표본에서는 **Nano Banana 2.1 보존 중심을 기본 후보로 두고, 구김이 큰 셔츠에만 가벼운 정돈을 선택적으로 검토**하는 쪽을 추천한다. 배경과 지지물 제거, 옷을 알아보기 쉬운 배치가 개선의 대부분이었다. 이번 줄무늬 셔츠는 Pro의 가벼운 정돈에서 몸판과 소매의 큰 구김이 더 분명하게 줄었다. 원본부터 깨끗한 빨간 가디건은 추가 생성의 이득이 작았다.

Pro 상품컷 조건은 코바늘 가디건의 단추를 네 개에서 여섯 개로 늘렸다. 더 가지런한 사진이 같은 옷을 더 잘 보존한 사진을 뜻하지는 않는다. 강한 정돈을 모든 의류의 기본값으로 채택할 근거는 얻지 못했다.

## 정돈 수준과 동일 조건

보존 중심은 원본의 구김과 그림자까지 유지하며 배경과 지지물, 최소 배치를 정리한다. 가벼운 다림질은 보관 중 생긴 큰 접힘과 뭉친 소매를 풀되 디자인 주름과 원단의 자연스러운 처짐을 유지한다. 상품컷 정돈은 보이는 구조를 더 가지런히 펼치고 촬영 구김을 더 줄인다.

두 새 정돈 수준은 색과 소재, 단추와 주머니, 넥라인과 커프스, 몸판과 소매 비율을 우선한다. 데님 워싱과 구김 그림자를 구분할 수 없는 영역은 유지한다. 니트는 조직과 작은 굴곡, 부드러운 처짐을 유지한다. 비율은 사진의 전체 경계 상자가 아니라 보이는 옷의 구성 부분을 뜻한다. 보이지 않는 구조를 지어내야 할 정도로 펼치지 않도록 했다.

같은 수준의 Pro와 2.1에는 같은 원본 PNG 바이트와 사용자 지시, 시스템 지시를 전달했다. 입력 해시와 이전 결과의 재사용 바이트를 독립 검토했다. 출력은 모두 1K 정사각형이고 요청마다 입력 한 장이다. 온도는 기본값, Pro는 기본 thinking, 2.1은 medium이다. 시스템 지시는 별도 API 필드로 전달했다.

원칙은 [Google 이미지 편집 가이드](https://ai.google.dev/gemini-api/docs/image-generation)의 변경 범위 한정과 중요한 세부 보존, [프롬프트 설계 가이드](https://ai.google.dev/gemini-api/docs/prompting-strategies)의 구조화와 중요 제약 우선 배치에 기반했다. 정확한 새 지시는 같은 폴더의 `matching-garment-gentle-system-20261008.txt`, `matching-garment-catalog-system-20261008.txt`에 남겼다.

## 의류별 결과

코바늘 가디건은 배경과 옷걸이 제거, 소매 배치가 개선의 대부분이었다. 추가 다림질 이득은 작았다. Pro 상품컷은 앞섶을 더 닫고 단추를 여섯 개로 만들어 실패했다. Pro 보존과 2.1 가벼움은 라벨 글자 확인이 불명확해 판정을 유보했다.

줄무늬 셔츠는 Pro 가벼움에서 큰 구김이 줄고 단추 여섯 개, 가로줄 커프스, 파란 줄무늬가 유지됐다. 2.1 가벼움의 추가 이득은 더 작았다. Pro 상품컷도 정돈 효과는 있었지만 더 강한 지시가 항상 더 큰 개선을 만들지는 않았다. Pro 보존은 라벨 확인이 불명확하고, 2.1 상품컷은 밝고 옅어진 줄 색을 재조명과 구분하기 어려웠다.

데님은 여섯 조건 모두 색과 워싱, 주요 구조와 핏이 대체로 유지됐다. 큰 주름은 대부분 남아 추가 다림질 효과가 뚜렷하지 않았다. 작은 허리 라벨 문구 전체를 원본과 확실하게 대조할 수 없어 종합 판정은 모두 보류했다. 워싱을 평탄하게 만들어 더 매끈하게 보이는 것을 성공으로 평가하지 않았다.

빨간 가디건은 원본부터 충분히 정돈돼 있었다. Pro 보존과 상품컷은 더 주황색으로, Pro 가벼움과 2.1 상품컷은 더 탁한 빨강으로 보였다. Pro 상품컷은 소매를 안으로 접어 새 팔꿈치 접힘까지 만들었다. 소매 배치만으로 핏 변경을 판정하지는 않았지만 전체 색 변화는 실패 근거다.

### 판정 기준 정정

초기 집계에는 재사용한 2.1 데님의 이전 PASS가 남아 있어 새 다섯 조건과 기준이 불균등했다. 동일하게 라벨까지 확인하자 재사용 결과도 완전 보존을 확인하지 못했다. 이번 종합 판정은 여섯 조건 모두 UNCERTAIN이다. 재사용 이미지 자체는 바뀌지 않았고 색·워싱·핏 중심 검사는 여전히 통과다. 이전 연구의 네 장 통과는 당시 검토 범위의 기록이며 이번의 라벨 포함 종합 세 장 통과와 구분한다.

## 비용 없는 카드 표시 비교

사진 정돈 외에 표시 방식도 살폈다. `src/styles/features.css:523`의 model-card 사진 영역은 높이 130px, object-fit cover다. 기본 폭은 110px이며 custom 카드 폭은 그리드에 따라 달라진다. 실제 화면이 항상 110px라는 뜻은 아니다.

원본, 기존 SAM 결과와 2.1 보존 결과를 110×130 영역에 잘라 채우는 경우와 전체 표시하는 경우로 정적 재현했다. 잘라 채우기는 데님의 허리와 밑단, 펼친 코바늘 의류의 소매 끝을 가릴 수 있었다. 전체 표시는 이를 줄이지만 원본의 큰 배경 여백이나 SAM이 이미 잘라낸 커프스는 복구하지 못한다. 작은 사진에서는 무늬나 단추 보존까지 검증하기 어렵다.

이 자료는 브라우저의 실제 셀러 화면 캡처가 아니다. 배지와 삭제 버튼도 재현하지 않았다. 표시 방식의 기하와 생성 이미지 자체의 보존을 분리한 참고 자료다. 새 제품 CSS는 수정하지 않았다.

## 착장 참고 구성의 확인 범위

원본만, 정돈본만, 원본과 정돈본을 함께 넣는 grid 후보를 기존 `compose_garment_grid`로 만들었다. 이번 각 의류는 원본 한 장이라 두 사진을 한 grid로 조합할 수 있었다. 기존 2.1 보존 결과를 재사용했고 새 착장 사진 생성은 하지 않았다.

착장 마네킹은 `server/app/workers/mannequin_job.py:2661`, 상세페이지 착장 컷은 `server/app/workers/detail_page_job.py:1590`에서 매칭 의류의 image_asset_id를 찾고 grid를 읽는다. 카드 썸네일과는 별개다. 현재 full 모드는 `matching_cutout_job.py:166`에서 첫 원본을 정돈본으로 교체한다.

`garment_grid.py:17`은 최대 네 사진, `confirmed_gpt_runtime.py:194`는 매칭 첨부 최대 한 장을 허용한다. 원본 네 장을 모두 유지한 채 정돈본을 다섯 번째로 추가하거나 매칭 첨부를 두 장으로 늘리는 동작은 현재 계약에 없다. 그 계약과 저장 구조는 수정하지 않았다. 입력 사진의 보존을 평가한 결과를 실제 착장 생성의 보존 개선으로 확대해 해석하지 않는다.

## 승인, 사용량과 검증

사용자가 전체 권장 비교를 승인했다. 신규 요청은 정확히 20회이며 Pro 12회, 2.1 8회다. 모두 HTTP 200, 최종 이미지 한 장과 요청한 모델 코드에 일치하는 modelVersion을 반환했다. 기존 2.1 네 장을 재사용해 총 24개 조건을 비교했다. 재시도와 자동 재생성은 없었다.

[공식 Standard 가격표](https://ai.google.dev/gemini-api/docs/pricing) 기준 이미지 출력 예상액은 $1.8768이었다. 실제 응답 사용량으로 입력과 텍스트, thinking을 합산한 새 20회의 추정액은 **$2.0268775**다. 실제 청구서를 확인한 금액은 아니다. 재사용한 네 장의 이전 사용량은 새 합계에서 제외했다. 입력 한 장인 Pro는 공식 560 토큰 고정값을 반영했다. 이미지 상세만 있고 총 출력에 텍스트가 포함된 응답은 TEXT와 IMAGE만 요청한 조건에 맞춰 나머지를 텍스트로 집계했다.

실험 비용 경계와 모델별 상한, 동일 입력과 지시, 중복 호출 방지, 재실행 차단, 첫 실패 중단과 디코드 전 사용량 보존을 확인하는 오프라인 pytest 9개가 통과했다. 큰 원본과 결과는 독립적으로 검토했고 초기 기준 불일치를 정정했다.

새 제품 코드 변경은 없다. 제품 코드의 직전 전체 검증은 서버 7,698개 통과와 104개 환경 조건으로 건너뜀, 프론트 2,806개 통과, 빌드 통과다. 이번 문서 단계에서 전체 제품 테스트를 다시 실행한 결과는 아니다. 새 모델과 지시는 제품 기본값에 아직 적용하지 않았다.

운영 DB와 R2, AWS, 배포는 사용하지 않았다. 사진과 결과는 워크트리의 `.scratch/bg-removal-3min/garment-tidying/`에 보관하고 커밋하지 않는다. `comparison.html`, `plan.json`, 조건별 prompt JSON, `ledger.json`, `results-summary.json`, `quality-review.json`과 정적 미리보기가 근거다. 이전 실행 자료는 덮어쓰지 않았다.

실제 UI의 모바일 다섯 폭과 WebKit, 자동 줄바꿈 검사는 수행하지 못했다. 앞선 브라우저 연결 시간 초과와 로컬 파일 URL 정책 차단이 있었고, 이번에는 파일 도구로 이미지와 정적 재현을 확인했다. 실제 착장 생성 효과, 더 많은 의류의 반복 성공률, 운영 대기와 총 서버비 절감도 미검증이다. 실제 셀러 상태 안내 연결이 남아 있어 PR은 초안으로 유지한다.

## 쉬운 설명

배경과 옷걸이를 지우고 잘 보이게 놓는 것만으로 좋아지는 사진이 많았다. 셔츠는 가볍게 다려주는 효과가 있었지만 더 강하게 정돈하면 단추나 색까지 달라졌다. 기본은 보존 중심을 우선하고, 필요할 때만 약한 정돈을 선택하는 방향이 합리적이다. 이미 깔끔한 사진은 새로 만드는 가치가 작은지도 함께 봐야 한다.
