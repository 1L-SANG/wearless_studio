# Sol 상품 검수로 실제 마네킹 생성과 보정을 실행한 결과

실사용 작업 모델은 gpt-6.1-sol, effort xhigh다. 유료 상품 검수는 같은 모델의 high이며, 생성 모델의 품질 설정 high와 구분한다. 사용자가 10월 11일 API 종류와 관계없이 추가 총 $5를 승인했다. 이전 $8 실험과 별도 원장으로 관리했다. 운영 코드, 설정, 저장과 배포는 바꾸지 않았다.

후속으로 [2차 생성의 서버 픽셀 고정](2026-10-11-secondary-generation-pixel-control.md)을 시험했다. 기존 지역 그림을 재사용해 새 생성 없이 허용 부위 밖 변경을 0픽셀로 제한했다. 추가 검사 4회와 $0.157478을 합친 같은 $5 승인 누적은 $2.468074다. 아래 본문은 그 이전 생성 연구의 동결된 비용과 결과이며 운영 적용을 뜻하지 않는다.

## 실행 경로와 비교 조건

현재 작업 브랜치의 실제 `mannequin_job._run_candidate`를 로컬 I/O로 실행했다. 상품 분석은 이전에 저장한 원본 분석을 재사용하고 Front, Back, Detail과 기존 매칭 사진, 여성 베이스를 유지했다. 흰 셔츠의 분석 종류는 outer 그대로다. 상품 분석을 top으로 꾸미거나 기존 앞뒤 분석 결과를 덮어쓰지 않았다.

상품 동일성 QC만 Sol 전용 어댑터로 바꿨다. 같은 `image_qc.verdict` 계약의 점수, 위험, 매칭 판정과 전후 보존 필드를 유지한다. 별도 핏, 베이스와 밑단 넣음 검사는 저장된 Gemini 설정을 유지했다. 공유 vision 함수와 분석 모델 순서를 바꾸지 않았다.

Gemini 조건에서 처음 생성한 이미지를 Sol 조건에도 정확히 재사용했다. 두 조건의 최초 요청과 입력 해시를 비교하고, 같을 때만 이미지 응답을 재생했다. 이는 같은 이미지에 대한 검사 경로 비교이며 서로 다른 최초 생성 두 장의 품질 비교가 아니다. 로컬 저장 성공도 상품 세부 보존 합격을 뜻하지 않는다.

처음 핑크 1K medium으로 연결을 확인한 뒤 세 상품을 Sunburst native 2K high로 새로 생성했다. 새 생성에는 핑크의 원본 단추와 소매 구조, 흰 셔츠의 오너 확인 앞 직선과 긴 뒤 곡선을 추가했다. 해상도, 생성 지시, 검사 자료와 모델이 함께 바뀌었다. 따라서 새 이미지의 개선을 Sol 교체만의 효과로 주장하지 않는다. 정돈 전처리를 추가한 실험도 아니다.

## 기존 검사와 추가한 검사

| 구간 | 기존 방식 | 이번 로컬 시험 |
| --- | --- | --- |
| 생성 | 저장된 원본 분석과 사진을 넣어 생성 | 같은 원본을 유지하며 확인된 부위 사실을 생성 지시에 추가 |
| 상품 검사 | 기존 Gemini 점수와 주요 위험 검사 | 같은 계약에 Sol, 앞단과 뒤단, 소매, 단추, 기장을 각각 비교 |
| 작은 디테일 | 전체 생성 사진 중심 | 전체 사진과 같은 픽셀의 부위 crop, 사진 역할과 번호를 명시 |
| 판독이 어려운 부위 | 모델 전체 응답에 의존 | 미확인을 통과 근거로 쓰지 않고 검수 필요로 남김 |
| 확실한 오류 | 기존 원본 기반 보정 경로 | 같은 원본 기반 보정 함수와 전후 검사, 보호 부위도 함께 확인 |

모든 부위의 판독 근거와 상태를 필수로 받고, FAIL은 코드에서 기존 구조 위험에 연결했다. 기존 심각한 기술 오류를 지우거나 낮추지 않는다. 미확인은 자동 수정 권한을 주지 않는다. 전후 검사에서 필수 부위가 미확인이면 수정 완료와 보존 완료를 인증하지 않는다. 생성 후보와 원본 사진을 섞지 않으며, 뒤판을 앞단의 근거로 옮기지 않는다.

쌍대 검사에서 뒤에 Before 부위 사진을 붙였을 때 기존 LAST 지시가 잘못된 사진을 가리킬 수 있어 CURRENT 전체 사진 번호로 바꿨다. 실제 12장 요청의 사진 역할을 무료 캡처 테스트로 확인했다.

| 상품 | 기존 Gemini 결과 | Sol 결과 | 원본과 직접 대조한 범위 |
| --- | --- | --- | --- |
| 흰 셔츠 | 검수 필요 | 검수 필요 | 앞 중심이 거의 직선으로 구현됐다. 옆의 자연스러운 상승과 일부 뒤판은 남으며 뒤단 전체와 정확한 길이는 미검증이다. 흰 단추의 작은 구멍과 전체 개수는 미확인이다. |
| 핑크 헨리넥 | 자동 통과 | 검수 필요 | 다섯 원형 단추는 보이나 정확한 반투명 표면 장식은 미확인이다. 외곽 바인딩과 가슴 절개는 유지됐다. 어깨 안쪽 곡선 능선이 남아 완전히 해결됐다고 할 수 없다. |
| 검정 워싱 청바지 | 검수 필요 | 자동 통과 | 두 단추 허리, 앞 주머니, 동전 주머니, 워싱과 퍼지는 밑단이 보인다. 미세 각인과 뒷주머니, 정확한 착용 길이는 미검증이다. |

최초 세 상품에서는 확실한 새 오류에 따른 자동 보정이 실행되지 않았다. 연구 어댑터가 모호한 부위를 무조건 FAIL로 만들거나 불필요한 재생성을 시키지 않는 동작을 확인했다. 자동 통과는 검사기의 판정이며 사람의 완전한 상품 보존 인증이나 일반 정확도 수치가 아니다. 정상 착용 정답 사진과 반복 대조는 없다.

## 실제 오류 검출과 보정

아래 보정 대조는 전체 운영 잡의 자동 실행이 아니다. 연구 컨트롤러가 실제 `_observe_generation_qc`, `_source_backed_edit_request`와 보정 피드백 함수를 호출하고, 결과를 기존 점수와 전후 보존, 베이스 판정으로 평가했다. 최초 세 상품의 전체 워커 실행과 구분한다. 연구의 매칭 하의 판정은 운영 최종 보정의 경고 처리보다 보수적이지만, 이번 네 거절은 주상품의 단추와 보호 부위 때문이라 그 차이가 결론을 만든 것은 아니다. 화면 진입 경로는 없으며 로컬 연구 코드에서만 실행했다.

자연 생성에서 보정이 실행되지 않아, 핑크 최초 2K 사진의 단추 다섯 개를 API로 세 개로 바꾼 시험 불량을 만들었다. 상품 결과로 쓰지 않으며 정상 생성 성공률의 분모에도 넣지 않는다. 이 시험의 목적은 실제 오류를 잡고 수정, 재검사, 채택 판단까지 연결되는지 확인하는 것이다.

Sol은 원본 다섯 개와 시험 불량 세 개를 비교해 구조 FAIL을 냈다. 실제 워커의 원본 기반 편집 요청 함수와 최종 보정 피드백을 써 Sunburst 4K high로 수정했다. 다섯 개가 됐지만 가운데 두 단추가 붙고 평범한 4구 모양이 되어 재검사가 채택을 막았다.

다음에는 단추판만 투명한 입력 마스크와 전체 단추 배열을 다시 배치하는 지시를 사용했다. 개수와 간격은 나아졌지만 단추판 길이와 다른 부위도 바뀌었고 장식은 미확인이라 채택하지 않았다. 공식 [OpenAI 이미지 문서](https://developers.openai.com/api/docs/guides/image-generation)의 마스크는 모델의 지시 자료이며 정확한 경계 보존을 보장하지 않는다. 입력 첫 사진과 같은 크기의 알파 마스크를 주었으며 결과 픽셀을 직접 합성하지 않았다.

같은 불량 사진과 원본, 보정 목표로 Nano Banana Pro 4K도 실행했다. 다섯 개와 간격은 복원했지만 원본의 장식이 재현되지 않고 보호 부위가 다시 그려져 Sol이 채택을 막았다. Pro와 Sunburst는 캔버스와 마스크 방식도 달라 순수 모델 성능 비교는 아니다. [Google 공식 이미지 문서](https://ai.google.dev/gemini-api/docs/image-generation)의 모델 ID `gemini-3-pro-image`와 반환 모델을 확인했다.

전신 편집에서 작은 장식이 사라지는 가설을 시험하기 위해 같은 불량 사진에서 단추판 주변 native 픽셀만 먼저 1K high로 수정했다. 이 부위 그림에서는 원본과 가까운 다섯 개의 반투명 불규칙 표면과 중심 구멍 배열이 나타났다. 부위 그림은 원본의 권위를 갖지 않는다. 실제 전체 사진 보정의 진단 보조로만 제공하고 원본 세 장을 계속 정본으로 유지했다. 전체 결과도 이미지 API로 생성하며 수동 픽셀 합성은 없다.

지역 보조를 넣은 마지막 전체 4K에서는 다섯 개와 단추판 길이는 맞았지만 아래 단추가 다시 평범한 4구 모양이 됐다. 청바지 워싱도 달라져 Sol은 목표 미해결과 보호 부위 변경을 냈다. 채택 결과는 false다. 부위 생성이 성공적으로 보이는 것과 전체 착장에 같은 장식을 보존하는 것은 별개다. 네 가지 전체 보정 조건을 모두 검사했고 이번에는 채택 가능한 성공을 확보하지 못했다.

독립 시각 검토도 일반 보정의 가까운 두 단추, 마스크 보정의 개선된 간격, 정확한 장식의 미확인을 확인했다. 어깨 안쪽 곡선 능선은 불량 Before에도 있고 보정에도 남았다. 보정 때문에 새로 생겼다는 근거가 아니라 기존 잔존 문제로 기록한다. 검사기는 이 능선을 자연스러운 접힘으로 읽어 소매 PASS를 냈으므로, 어깨 문제까지 해결하거나 검사 정확도를 확정한 결과가 아니다.

일반 전신 재생성을 더 반복하지 않고 이 가설 시험을 마쳤다. 남은 $5를 모두 쓰는 것이 통과 기준은 아니다. 중요한 작은 장식의 복원과 실제 변경 부위 보존을 함께 보장하는 경계가 필요하다는 실패 근거를 확보했다. 아직 미확인 장식을 자동 통과시키거나 마스크 밖 보존 검사를 완화할 근거는 없다.

2K high 첫 장의 해당 구간은 약 $0.20~$0.24였다. 새 분석과 정돈, 매칭 의류 전처리, 큐와 서버, 저장 비용은 표 밖이다. Sol 최초 상품 검사는 약 66~71초, 쌍대 보정 검사는 약 83~116초였다. 생성 응답을 받은 뒤 상품 검사와 베이스 검사를 병렬로 실행하며 생성 시간을 포함한 전체 대기는 더 길다. 공유 vision 기본 30초와 다르므로 운영 전환에는 검수 전용 시간 예산이 필요하다.

일반 Sunburst 4K 보정과 재검사는 $0.276246, 마스크 보정은 $0.281898, Pro 보정은 $0.344504가 추가됐다. 수정한 결과의 채택 여부와 과금은 별개다. Pro 사용량은 이미지 출력과 나머지 출력을 분리했고 [Google 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 입력 $2, 이미지 출력 $120, 나머지 출력 $12의 백만 토큰 단가를 적용했다. 사용량 구분이 없으면 보수적인 상한으로 계산하도록 무료 검사를 붙였지만 이번 응답은 구분이 있었다. 실제 청구서와 운영 평균은 확인하지 않았다.

지역 수정 이미지 $0.063056과 보조를 쓴 전체 이미지 및 재검사 $0.268741이 추가됐다. 승인된 새 $5 연구 전체 추정은 $2.310596, 미확인과 대기 예약은 각각 0이다. 실제 POST 42회는 이미지 10회와 텍스트 검사 32회다. 일반 최초 생성은 4장으로 1K 연결 확인 한 장과 세 상품 2K 한 장씩이다. 나머지 생성은 시험 불량 한 장, 전체 보정 네 장, 지역 진단 한 장이다. 모든 응답은 200이며 텍스트 정상 종료, 요청 모델과 usage를 확인했다. OpenAI Images API가 model 필드를 반환하지 않은 응답은 실제 송신 모델을 기록했고 반환 모델 검증으로 과장하지 않았다.

이전 $8 연구의 확인 추정 $6.81875375와 과거 보류 $1.05는 변경하지 않았다. 새 $5의 남은 승인 예산은 $2.689404이며 운영 자동 평균 단가나 다음 요청의 확정 비용을 뜻하지 않는다.

## 검증과 남은 범위

예산은 이전 단계 비용과 대기 중인 예약을 모두 더한다. 비용을 알 수 없는 완료 요청, 통신과 파싱 오류는 후속 유료 호출을 중단한다. 별도 원장을 이어가며 과거 실패와 중단 기록을 보존했다. 처음 보정 검사의 로컬 타입 참조 오류는 API 요청 전에 발생해 비용과 POST가 0이었다. 수정한 재개 계획으로 기존 시험 불량을 재사용했다.

코드 검토에서 보정 연구 컨트롤러의 명시적 캔버스 검사가 빠진 점을 찾아, 기존 실행 기록을 덮어쓰지 않고 실제 `evaluate_canvas_alpha_qc`로 이미 받은 결과들을 다시 검사했다. 디코드 실패와 투명 캔버스를 거절하는 무료 재현 테스트를 추가했다. 마지막 지역 보조 전체 실험은 유료 QC 전에 이 검사를 한다. 출력 개수도 응답에서 확인했다. 이 검사 통과는 상품 정체성 통과를 뜻하지 않는다.

무료 pytest 28 통과, 실패 0이다. 비용 누적과 예약, 미확인 중단, 필수 부위, 기존 심각한 오류 보존, CURRENT 번호, 실제 요청 역할과 캔버스 거절을 확인했다. 별도 최종 원장 검사에서 요청 42개와 응답 42개, 합계 $2.310596, 같은 stage와 요청 해시 쌍의 중복 및 새 미확인 없음, 세 정상 후보의 두 조건 동일 바이트를 확인했다. 받았던 주요 출력 7개와 마지막 지역 및 전체 2개는 실제 캔버스 검사 9개 통과다. 처음 1K 연결 확인 출력은 실제 전체 워커에서 검사했으며 이 추가 9개 집계에 중복해 넣지 않았다.

계획과 실제 요청, 원본, 후보와 모델의 검사 근거는 `.scratch/bg-removal-3min/sol-mannequin-workflow-20261011`에 보존한다. `plan-v2.json`, `repair3-plan.json`, `refinement-plan.json`, `regional-plan.json`의 입력과 코드 해시, 각 단계 원장과 실행 결과를 덮어쓰지 않았다. 사진과 비공개 API 응답은 커밋하지 않는다. `normal-mannequin-comparison.png`는 정상 세 상품 표시용 축소 모음이며 `source-region-whole-native-comparison.png`는 원본, 지역, 마지막 전체의 같은 부위 native 비교다. 후자는 선명화와 보간을 하지 않았다.

제품 코드와 화면은 이번에 변경하지 않았다. 전체 서버 pytest, 프론트 전체 테스트와 빌드는 이전 제품 변경 뒤 통과했으며 이번 연구에서는 다시 실행하지 않는다. 이전 결과는 서버 7698 통과와 조건부 건너뜀 104, 프론트 2806 통과, 빌드 통과다. 이 숫자를 새 Sol 경로의 제품 통합 테스트로 쓰지 않는다. 이번 DB 접속 테스트는 없어서 로컬 DB 접속 실패로 빠진 테스트도 없다.

운영 전환, 최종 상세페이지 사람 착장, 실제 저장과 다운로드, 새로운 AG01 앞뒤 구조 분석, 정상 착용 사진 오탐률과 반복 안정성을 이번에 확인하지 않았다. 흰 앞단 개선은 오너가 확인한 사실을 직접 지시에 넣은 조건이라 자동 분석 개선의 증명이 아니다. 어깨 능선과 정확한 장식은 독립 시각 검토에서도 한계가 남는다. 원래 실제 셀러 경로의 대기 안내 연결도 PR의 미완료 항목이므로 초안을 유지한다.

추천은 전용 상품 검사에 Sol을 후보로 남기고, 모든 QC의 일괄 운영 교체는 보류하는 것이다. 최초 생성에 원본 부위 사실을 연결하는 개선, 필수 부위 미확인을 검수 필요로 남기는 경계는 의미가 있다. 다음 제품 단계에서는 원본 앞뒤 구조를 실제 분석 결과로 만드는 계약, 작은 장식의 최종 보존, 정상 착용 정답 대조, 검수 필요 상태를 셀러가 보는 방식과 전용 시간 예산을 검증해야 한다. 특히 어깨 접합선과 자연스러운 접힘의 구별에는 별도 정상과 오류 대조가 필요하다.

## 쉬운 설명

솔을 실제 마네킹 검사 자리에 넣어 사진을 만들고, 일부러 틀린 사진이 수정되는 과정도 확인했다. 틀린 단추 개수는 잡았지만 고친 사진이 다른 부분을 바꾸면 채택을 막았다. 앞뒤를 구분하는 생성 지시는 흰 셔츠에 도움이 됐다. 검수 모델만 교체하면 모든 의류가 정확해진다는 결론은 아니다. 원본을 자세히 보이는 자료와 수정 후 보존 검사까지 함께 다뤄야 한다.
