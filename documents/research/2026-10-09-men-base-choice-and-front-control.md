# 선택한 남성 베이스와 체크셔츠 앞면 통제 비교 준비

실사용 작업 모델은 gpt-6.1-sol, effort는 xhigh다. 오너는 2026-10-09에 우측으로 보여 준 내장 Codex 남성 베이스로 바꾸자고 선택했다. 이 선택은 PRD의 남성 베이스 요구사항에 반영했다. 실제 운영 적용은 아직 하지 않았다.

이 문서는 승인 전 준비 기록이다. 이후 오너가 두 실행 범위를 승인했고 실제 운영 반영과 여섯 번 비교를 수행했다. 적용한 에셋과 task definition, 검증 및 비교 결과는 [실행 결과](2026-10-09-men-base-rollout-and-front-control-results.md)에 기록했다.

## 승인 전 운영 교체의 준비 상태

선택 원본은 `.scratch/bg-removal-3min/men-base-20261009/codex-native.png`, RGB PNG 1024×1536이다. SHA256은 `fd984e5e2b798831098a07feb1d1feae47968ba8793d04ed51f41b2267f691f2`, 바이트 수는 1533135다.

검토용 신규 asset UUID는 `2da88ae4-aa72-45d9-bb1a-7f5853224b3f`다. 신규 R2 키는 `seed/mannequin/base-men-native-20261009-fd984e5e2b79.png`이며 기존 객체와 행을 보존한다. seed/public 등록 계약을 사용하고 기존 마이그레이션과 새 마이그레이션은 바꾸지 않는다. 이 번호는 아직 등록된 운영 에셋이 아니다.

현재 작업 브랜치의 남성 베이스 설정은 `MANNEQUIN_BASE_MEN_ASSET_ID=736ff2ab-0f15-4f9a-b2ee-c40cd0ed7ee0`다. 실제 운영 값은 아직 조회하지 않았다. 새 id를 쓰는 이유는 마네킹 초안 캐시의 지문이 baseAssetId를 포함하기 때문이다. 같은 id의 바이트를 덮어쓰면 새 몸과 기존 초안 캐시가 구분되지 않는다.

가장 작은 운영 반영은 새 객체와 seed asset 행을 등록하고, 현재 API task definition의 남성 환경변수 하나만 새 id로 교체한 revision으로 롤링 교체하는 것이다. 현재 실행 이미지와 다른 설정은 유지한다. 환경변수는 태스크 환경에서 읽으므로 재시작 없는 hot update 경로는 없다. 같은 항목을 manifest에도 기록해야 다음 Copilot 배포가 옛 id로 되돌리지 않는다. 일반 CI는 마이그레이션과 두 서비스 빌드를 포함해 범위가 넓으므로 이 교체에 사용하지 않는다.

초기 공통 규칙은 운영 쓰기와 운영 데이터 조회, manifest 변경과 배포를 금지한다. 따라서 운영 반영에 필요한 좁은 예외를 사용자에게 요청한 상태다. 승인 전에는 R2와 DB, AWS 조회·쓰기와 manifest 변경을 실행하지 않는다. 실제 설정 반영 전에는 현재 API 서비스와 task-definition, 실행 이미지 digest, 기존 남성 값과 다른 설정 유지 여부를 확인해야 한다. 작업 중인 잡을 방해하지 않을 시점을 확인하고 이전 task-definition으로 원복할 자료를 보존한다.

기존 생성컷은 바꾸지 않는다. 정상 저장된 톤 마스크도 env 변경만으로 다시 만들지 않는다. 다만 마스크가 없거나 업그레이드가 필요한 옛 남성 컷을 캐시 없이 분할할 때, 현재 global 베이스와의 Lab 차이가 SAM 후보 선택 점수에 쓰인다. 새 몸과 옛 컷의 차이가 선택에 영향을 줄 여지는 있지만 실제 품질 저하를 재현한 결과는 없다. 베이스 관측도 현재 global 기준을 읽으며 생성 당시 baseAssetId 기록은 컷 metadata에 없다. 이 동작과 원복 기준은 반영 기록에 남긴다. 운영 조회 없이 과거 컷을 일괄 변경하거나 새 저장 구조를 만들지 않는다.

## 이전 비교에서 실제로 통제된 것

네이비 체크셔츠의 원본 앞면 조건과 gentle 2K 조건은 지시문, 모델과 설정, 남성 베이스, 뒤·상세 사진과 매칭 바지가 같았다. 참조 순서도 같다. 요청 PNG 해시를 다시 비교한 결과 Front 한 장만 바뀌었다. 그러므로 두 번째 정돈 단계나 다른 모델로 몰래 바꾼 것은 아니다.

하지만 그 한 장 안에는 여러 변화가 들어 있었다. 원본은 768×1024의 Display P3 MPO 사진이고 정돈본은 2048×2048의 ICC 없는 JPEG다. 옷 배치와 구김, 배경, 목 안쪽 라벨과 단추 구멍도 달라졌다. 원본의 SPAO 라벨이 다른 글자 형태로 바뀌었고 두 구멍 단추를 네 구멍으로 그렸다. 겉보기에 깔끔한 제품컷과, 다음 모델이 참고할 상품 정보의 정확성은 다르다.

원래 Back와 Detail은 그대로여서 생성한 Front의 일부 구조와 서로 다른 근거를 줄 수 있다. 이것은 확인된 사진 차이에서 도출한 가능성이며 모델 내부 원인을 확인한 결과는 아니다. 생성 변동도 섞인다. 이 셔츠는 조건당 한 번이라 전처리 때문에 착장이 나빠졌다는 인과관계를 확정하지 못했다.

## 새 반복 비교의 통제

선택한 새 남성 베이스 하나를 모든 조건에 고정한다. 원본 Front와 앞선 실험의 가벼운 정돈 2K Front를 각 세 번 비교한다. 새로운 Gemini 정돈은 만들지 않으므로 그 생성 변동을 더 섞지 않는다. 순서는 원본, 가벼움, 가벼움, 원본, 원본, 가벼움으로 균형을 맞췄다.

모델과 quality, 출력 크기, 지시문, 역할 순서, Back와 Detail, 매칭 바지는 바꾸지 않는다. 모든 입력을 실제 sRGB PNG로 준비했다. Display P3는 ICC 변환으로 sRGB에 옮기고 ICC 없는 RGB는 sRGB로 해석하는 가정을 기록한다. [Pillow 공식 ImageCms 문서](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html)의 profileToProfile로 색 프로필을 변환했다.

두 Front는 같은 2048×2048 캔버스로 맞췄다. 원본 비율을 유지하고 부족한 부분만 회색 여백으로 채웠으며, 사진 내용을 새로 그리거나 옷 일부를 자르지 않았다. 원본 확대는 새 상품 세부를 복원하지 않는다. 정돈본의 소매 배치와 옷의 실제 사진 점유율, 완성한 밑단과 단추 등의 차이는 여전히 남는다. 따라서 이 비교도 주름 하나의 효과만을 분리하는 것은 아니며, 같은 외부 조건에서 어떤 Front가 나은지를 확인한다.

생성 결과는 체크의 선 순서와 간격, 단추 수와 배치, 칼라와 커프스, 색과 소재, 품과 기장, 매칭 바지를 원본과 비교한다. 셀러가 보기 좋은 인상과 상품 세부 보존을 따로 판정한다. 각 세 번도 소표본 탐색이며 전체 성공률로 설명하지 않는다.

Sunburst medium native 1024×1536 최초 생성만 고정한다. AG-01 계약과 crop, QC 및 자동 보정은 두 조건 모두 제외한 지원 분기다. 전체 운영 worker를 실행한 결과와 구분한다. 기존 분석 계약을 생성한 Front에 복사해 바인딩을 속이지 않는다.

## 비용과 검증 상태

계획은 최대 여섯 HTTP POST다. 입력 포함 예상액은 약 $0.50이며 실제 청구서 금액은 아니다. 재시도와 다른 모델 전환은 없고, 실패 또는 사용량 미확인 첫 건에서 멈춘다. 이전 승인 한도는 모두 사용해 추가 여섯 번 승인을 요청했다. 새 유료 호출은 아직 0회다.

로컬 준비와 무료 재현 검사 네 개가 통과했다. 여섯 요청과 세 번씩의 균형, Front만 달라지는 참조, 같은 캔버스와 실제 sRGB 프로필, 변경된 입력 및 예산 거절, 승인 전 키 접근 차단을 확인했다. 운영 교체의 객체·행·설정 검토 계획은 `.scratch/bg-removal-3min/men-base-replacement-20261009`, 비교 입력과 요청은 `.scratch/bg-removal-3min/check-shirt-front-control-20261009`에 보관했다. 사진은 커밋하지 않는다.

제품 코드와 화면은 이번 준비에서 바꾸지 않았다. 같은 제품 코드의 앞선 전체 검사는 서버 7698 통과와 104 조건부 건너뜀, 프론트 2806 통과, 빌드 통과이며 이번 준비 때문에 다시 실행하지 않았다. 실제 여섯 결과와 운영 등록 및 설정 반영은 아직 미완료다.
