# 새 의류의 원본과 정돈 보조 마네킹 비교 결과

실사용 작업 모델은 gpt-6.1-sol, effort는 xhigh다. 세 의류의 기존 방식과 가벼운 정돈 보조 방식을 원본 상품 분석과 활성 QC, 필요한 보정까지 실행했다. 운영 제품 흐름을 바꾸는 결정은 하지 않았다.

## 실행 조건과 결과

흰 셔츠, 핑크 골지 헨리넥, 검정 워싱 청바지의 원본 앞면과 뒷면, 제공된 상세 사진을 사용했다. 원본으로 상품 분석을 한 번씩 하고 두 조건에 같은 분석과 원본 사진, 성별 베이스, 매칭 사진과 핏, 모델 및 출력 크기를 적용했다. 분석 사실을 사람이 수정하지 않았다.

원본 방식은 원본 상품 사진을 사용한다. 정돈 보조 방식은 원본을 그대로 유지하면서 Nano Banana 2.1의 gentle 2K 사진 한 장을 처음 그릴 때의 참고로 추가했다. 정돈본으로 Front를 대체한 이전 실험과 다르다. 정돈본은 원본 대비 별도 검수에서 통과해야 사용하며, 마네킹의 초기 QC와 보정 및 후속 QC는 원본 사진을 기준으로 했다.

상품 분석은 Gemini 3.8 Flash, 정돈은 Nano Banana 2.1, 착장과 보정은 Sunburst native 1K, 검수는 저장된 운영 설정의 Gemini 3.1 Pro preview를 사용했다. 켜진 후보 생성·검수·보정 함수는 실제 코드로 실행하고 저장과 이벤트만 로컬로 바꿨다. 전문 구조 검사는 운영처럼 off를 유지했다.

정돈 제품컷 세 장은 별도 자동 검수에서 모두 pass를 받았다. 이는 모든 상품 세부가 보존됐다는 사람 검수의 확정 판정은 아니다. 여섯 착장 조건 중 다섯 장은 최종 저장됐으나 상태가 모두 needs_review다. 핑크 정돈 조건은 한 번 보정해도 최종 보존 검사에서 채택되지 않았다. 보정본이 존재한다는 이유로 최종 성공으로 세지 않았다.

## 직접 검수와 독립 검수

사진을 직접 비교했고 독립 리뷰도 사진을 먼저 본 뒤 자동 QC 기록을 대조했다.

| 의류 | 외관 관찰 | 상품과 QC 관찰 |
| --- | --- | --- |
| 흰 셔츠 | 정돈 보조 착장이 몸통 구김이 조금 덜해 약간 더 단정하다. | 오너가 앞 직선·뒤 곡선의 구조를 확인했다. 실제 분석은 두 면을 curved 하나로 합쳤고 두 착장의 앞면이 곡선으로 그려졌다. 이전의 올바른 밑단 보존 평가는 정정한다. 두 결과 모두 저장됐고 needs_review지만 상품 구조 재현 성공으로 보지 않는다. |
| 핑크 골지 헨리넥 | 원본과 정돈 조건의 첫 생성 및 보정본은 비슷하게 정갈하다. 추가 구김 개선이 작다. | 원본의 다섯 단추와 가슴 곡선 절개는 보인다. 원본 Detail의 반투명 장식 단추가 정돈 제품컷과 착장에서 평범한 원형처럼 단순화됐다. 원본 착장은 needs_review로 저장됐다. 정돈 보정본은 final_edit_preservation_rejected로 채택되지 않았다. |
| 검정 워싱 청바지 | 두 착장 모두 자연스럽다. 정돈 보조 쪽이 조금 더 매끈해 보일 수 있지만 차이는 작다. | 두 허리 단추와 밝은 워싱, 플레어 밑단 등 주요 특징은 보인다. 정돈 조건은 더 길고 밑단이 넓어 보이며, 정확한 워싱과 착용 핏은 보류다. 양쪽 모두 needs_review로 저장됐다. |

핑크의 자동 QC가 두 번 지적한 가슴 곡선 절개 누락은 실제 사진과 맞지 않는다. 첫 생성과 보정본에 절개선이 보인다. 장식 단추의 단순화에는 근거가 있지만, 원본을 정확한 꽃 외곽이라고 단정하는 표현도 조심해야 한다. 자동 QC의 문구를 그대로 원본 관찰의 확정 사실로 옮기지 않았다.

핑크와 검정 도형 검사에서 나온 missing_lower_body 역시 실제 전신 사진과 맞지 않는다. 다리와 발이 보이고 별도 베이스 QC도 통과했다. 이 도형 검사는 관측용이며 강제 출고 검사로 새로 켜지 않았다. QC가 있다는 것과 모든 오판이 제거됐다는 것은 별개다.

## 시간과 비용

실제 모델 HTTP POST는 34회다. 이미지 10회는 정돈 3회와 마네킹 7회다. 분석 및 검수 24회는 Flash 분석 3회와 Pro 검수 21회다. 응답 성공은 33회이며 한 번의 상품 QC가 읽기 시간 초과였다. 이미지 생성 요청은 모두 결과를 받았다.

응답 usage로 계산한 금액은 $1.138951이다. 시간 초과한 한 번의 QC는 usage가 없어 청구액을 확인하지 못했다. 이 금액은 전체 청구액의 확정값이 아니며 실제 청구서를 확인하지 않았다. 감시에 사용한 보수적 $2 예약은 실제 사용 금액으로 세지 않았다.

원본 방식의 후보 생성과 검수 구간은 흰 셔츠 49.2초, 헨리넥 42.8초, 청바지 44.7초였다. 흰 셔츠 정돈 조건의 같은 구간은 50.9초이고 정돈 생성과 사전 검수 37.7초가 추가됐다. 헨리넥은 정돈과 사전 검수 30.2초, 착장과 실패 보정 구간 68.1초였다. 청바지 정돈은 정돈과 사전 검수 33.2초가 추가됐으나 마지막 검수 중단과 재개가 있어 전체 시간을 같은 기준으로 비교하지 않는다. 공유한 상품 분석 시간과 큐, 사용자 입력 대기는 이 숫자에 포함하지 않았다.

## 마지막 QC의 시간 초과와 재개

청바지 정돈 최초 이미지는 정상 생성됐지만 32번 상품 QC가 ReadTimeout으로 중단됐다. 병렬로 실행한 33번 베이스 QC는 정상 완료됐다. 원래 실행 기록과 중단 표식, 요청 및 응답을 수정하지 않고 보존했다.

이미 승인된 81회 전체 요청 범위 안에서 누락된 검수부터 한 번 재개했다. 기존 원본과 분석, 보조본, 생성 설정과 실제 지시문, 모든 입력 해시가 첫 생성 요청과 같음을 확인했다. 처음 그린 이미지와 이미 완료된 베이스 QC는 그대로 재사용했다. 실제 새 요청은 같은 모델의 상품 QC 한 번뿐이며 추가 이미지 생성은 0회다. 최종 청바지 정돈 사진은 처음 생성한 사진과 바이트 및 SHA256이 동일하다.

기존 33회와 새 요청을 합산해 최초 전체 이미지 21회와 텍스트 60회 상한을 유지했다. 미확인 시간 초과 청구분에 감시용 $2를 예약하고 이후 응답 금액을 더해 다음 호출의 $4 중단 기준을 적용했다. 이 예약은 실제 청구액이나 보장된 최대 비용이 아니다. 재개 실행과 원래 중단은 각각 별도 원장에 남겼다. 모든 새 요청은 사용자가 허용한 Google Gemini API와 OpenAI 이미지 API로만 전송했고 운영 DB와 R2, AWS에는 접근하지 않았다.

## 권장 판단과 PR 482

이번 세 종류에서 정돈 보조를 주상품 마네킹의 기본 단계로 넣을 만큼 일관되고 큰 이득은 확인하지 못했다. 흰 셔츠에는 작은 외관 이득이 있다. 헨리넥은 외관 차이가 작고 최종 채택 실패가 있었으며 청바지의 정확한 핏은 보류다. 각 조건 한 번이므로 정돈이 실패율을 높였다고 일반화하지도 않는다. 정돈 제품컷의 보기 좋은 정도와 최종 착장의 상품 충실도는 분리해 판단한다.

현재 PR 482는 SAM 재시도 단축과 안내, 매칭 의류의 Gemini 직접 처리, 실험 기록과 남성 베이스 설정까지 포함한 draft다. 실험 기록 확정만으로 제품 동작까지 곧바로 채택할 수 없다. 현재 코드의 Pro 처리 방식과 이번 NB 2.1 정돈 보조 방식도 동일하지 않다. 실제 셀러 콘티 카드의 대기·실패 안내 연결과 Pro 상품 보존 문제는 앞선 PR 체크리스트에 남아 있다.

제품에서 채택할 방법을 정한 뒤 그 범위로 코드를 정리하고, 남은 셀러 경로를 검증하며 최신 main 기준 전체 검사를 확인한 다음 머지를 판단해야 한다. 남성 베이스 설정 한 값은 별도 PR 497로 분리돼 있다. 이번에는 main 머지나 운영 반영을 하지 않았다.

## 검증과 한계

무료 재현 검사 19개가 통과했다. 기존 16개에 검수 재개의 전체 호출 합산과 미확인 비용 예약, 기존 입력이 바뀌었을 때 이미지 재사용 거절 검사 세 개를 추가했다. 코드 및 입력 해시 검사가 통과했고 비교 HTML의 로컬 이미지 참조 36개도 파일 존재를 확인했다. 최종 사진과 채택하지 않은 보정본을 직접 보고 독립 검수를 받았다.

제품 코드와 화면을 바꾸지 않아 전체 서버 pytest와 프론트 테스트, 빌드는 이 연구 단계에서 다시 실행하지 않았다. 이전의 서버 7698 통과와 104 건너뜀, 프론트 2806 통과 및 빌드 통과는 앞서 검사한 제품 코드의 결과다. 새 이미지 품질이나 최신 main 기준 머지 검증의 결과로 사용하지 않는다. 로컬 DB 접속 테스트를 이번에 실행하지 않았다.

브라우저의 로컬 파일 정책 제한으로 비교 HTML의 320, 360, 375, 390, 414px 스크린샷과 단어 중간 줄바꿈·가로 넘침 자동 검사, WebKit 확인은 수행하지 못했다. 기본 keep-all과 balance를 유지하는 기존 비교 보고서 스타일을 사용했고 이미지와 파일 참조는 직접 확인했다. 다른 브라우저나 서버로 제한을 우회하지 않았다.

각 조건 한 번인 탐색이고 전체 운영 화면, 저장과 크레딧 정산, 알림, 선택적 SAM 자료 폴백을 검증한 것은 아니다. 자동 QC의 오판과 실제 상품 세부 변경이 함께 관찰됐으며 정확한 기장과 핏도 보류다. 사진과 API 인증값, 원시 응답은 커밋하지 않는다.

로컬 결과는 `.scratch/bg-removal-3min/full-workflow-tidy-20261009/comparison.html`과 세 종류의 비교 PNG, `results-summary.json`, 원래 원장과 `qc-resume-black-jeans`에 있다.

## 쉬운 설명

다른 옷 세 벌도 검사와 필요한 수정까지 비교했다. 정돈 사진을 참고하면 조금 더 깔끔해지는 옷은 있지만 모든 옷에서 더 좋은 최종 사진이 나오지는 않았다. 검사도 없는 문제를 지적할 수 있었다. 지금은 이 결과를 기록하고, 제품에 넣을 방법과 남은 사용자 안내를 정리한 뒤 482의 머지를 판단하는 것이 맞다.
