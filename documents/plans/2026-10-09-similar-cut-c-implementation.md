# 비슷한 컷 C 방식 구현 기록

상태: 로컬 구현 완료, 운영 배포·운영 DB 변경 없음.

## 동작

- 에디터 착용 사진의 생성 버튼을 `비슷한 컷 생성` 하나로 통합한다. 옵션 없이도 실행하며 기존 방향·포즈·표정 지정은 계획의 조건으로 반영한다. 제품 단독 사진은 기존 이미지 수정 흐름을 유지한다.
- `variationMode=similar` 요청은 같은 사용자·프로젝트의 살아 있는 원본을 검증한다. 후보를 다시 선택해도 서버가 보존한 최초 원본에서 생성한다. 클라이언트의 원본 계보·이력은 신뢰하지 않는다.
- 원본 사진·상품 구조·최근 12개 완료/예약 동작을 비전 모델에 보내 한 동작을 계획한다. 계획 오류나 반복 동작에는 한 번만 교정 계획을 요청하고, 실패 시 단순 생성으로 바꾸지 않는다.
- 계획을 jobs.metadata에 먼저 예약한다. 외부 AI 호출 동안 DB 연결을 잡지 않으며, 예약 시 원본 단위 잠금·이력 비교·작업 소유권을 확인한다. 동시 요청으로 이력이 바뀌면 최대 한 번 다시 계획한다. 회수된 작업은 저장된 계획을 재사용한다.
- 생성 결과 assets.metadata에 같은 계보와 계획을 보존한다. 기존 크레딧 예약·실패 반환·결과 저장·실존 모델 라이선스/얼굴 처리·디테일 전용 경로를 재사용한다. DB 마이그레이션은 없다.
- 생성 모델은 기존 에디터 설정을 사용한다. Gemini에는 원본 비율 추종을 요청하고 GPT에는 원본 크기와 요청 해상도에 맞춘 16픽셀 단위 캔버스를 전달한다. 정사각·가로·세로 및 1:3/3:1 경계를 검사했다.

계획은 이전 동작의 반복을 줄이지만 실제 이미지가 매번 다른 행동을 정확하게 구현한다는 보장은 아니다. 이 구현에 새 상품·장소 자동 QC 출고 차단이나 새 카메라 이동 기능을 추가한 것은 아니다.

## 검증

- 새 동작 계획·원본 소유·이력 예약·워커·기존 에디터·이미지 공급자·실존 모델 얼굴 회귀 검사: **173 passed**.
- 프론트 새 비슷한 컷·AI 패널·의류 목록 관련 검사: **26 passed**.
- `pnpm build`: 성공. 기존 대형 번들 경고가 남는다.
- 브라우저: mock 모드로 빌드한 로컬 앱에서 보관함 → 에디터 → 의류 AI 편집 → 옵션 없이 비슷한 컷 생성 → 같은 색상 그룹 5→6장 추가 → 생성 결과 다시 AI 편집 진입 확인. 기존 두 버튼 대신 한 버튼이 활성화됨을 확인했다.
- 독립 리뷰 2회: GPT 원본 비율/해상도 문제와 16px 내림의 비율 경계 문제를 발견해 회귀 테스트 후 수정했다. 명시 변경 조건과 기본 미세 변주 지시의 충돌도 해소했다.
- `git diff --check`: 통과.

전체 검사를 통과했다고 주장하지 않는다.

- 전체 서버 실행: 7503 passed, 123 skipped, 13 failed, 105 errors. 그 뒤 관련 173개는 최종 수정 상태에서 재검사해 통과했다.
- 개인화 DB 검사 오류는 로컬 Postgres `127.0.0.1:54322` 연결 거절로 재현했다. 환경 예시 검사 실패는 작업 시작 전부터 삭제돼 있던 `server/.env.example` 부재로 재현했다. 해당 사용자 삭제는 복구하지 않았다. 기타 패키징·셸 등 전체 검사 실패도 이번 범위에서 모두 해결했다고 주장하지 않는다.
- 전체 프론트 검사는 WSL 파일 접근 지연·Vite timeout, 이후 Windows 관리자 화면 검사 실패/종료 지연으로 끝까지 통과하지 못했다. 프로세스를 정리하고 관련 26개를 Windows에서 별도 실행해 통과했다.
- 기존 잠금 파일에 맞춰 누락된 패키지를 복구했고 최종 빌드/관련 화면 검사는 Windows 환경에서 수행했다. package.json·잠금 파일은 변경하지 않았다.
- 운영 DB·실제 이미지 공급자를 연결한 배포 E2E, 실제 PostgreSQL의 동시 예약 검증은 이번에 실행하지 않았다. 신규 서버 검사는 외부 AI·DB를 모의 처리한 단위/통합 경로 검사다.

로컬 증거: `.scratch/similar-cut-frontend-targeted.log`, `.scratch/similar-cut-build-windows.log`, `.scratch/similar-cut-ui.png`. 화면 확인용 mock 미리보기는 `http://127.0.0.1:5180/library`다.

다음 단계: 운영 반영 전에 전체 검사 환경/기존 실패를 정리하고, 실제 공급자·테스트 DB를 연결한 검증 및 배포를 진행한다. 별도 기능 C와 콘티 색상 반복 자동 변주의 실행 경로를 이번에 합치지는 않았다.
