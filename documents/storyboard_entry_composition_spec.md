## 0. 원칙 (기확정 상속)

- **구현 위치 = 진입 배정 단계.** 시드 빌더(defaultStoryboard/buildStoryboard)는 수정하지 않는다. 의류·성별·카탈로그를 아는 진입 시점에 세트 삽입과 총량 조정을 수행한다.
- **결정성**: 같은 프로젝트는 몇 번 들어와도 같은 결과(프로젝트 ID 시드). 재진입 재계산 0. 새 상세페이지(새 프로젝트)는 새 추첨 — "셀러 단위 고정"이 아니라 **프로젝트 단위 고정**이다.
- **세트 원자성 > 총량 정확성**: 컷수를 맞추려고 세트를 쪼개거나 늘리지 않는다. 총량 조정은 낱장 버퍼로만.
- **fail-closed**: 후보가 없으면 조용히 낱장으로 대체. 빈 카드·위장 문구 금지.
- **기존 프로젝트 보호**: 이 구성은 신규 프로젝트에만 적용. 기존 프로젝트는 재시드하지 않는다(낱장 자동 배정의 빈 슬롯 채움만 현행대로).

## 1. 기본형 구성 (타깃 "약 14컷" = 13~15)

> 2026-07-30 오너 재확정: 스타일링 세트는 카탈로그 멤버 **3컷 통째** 배치("3컷이 베이스" — 코어 2컷안 폐기). 카탈로그 실측: 스타일링 50세트 전부 3컷(최다 구성 풀1+미디움2). 이에 따라 종전 "약 12컷" 라벨을 "약 14컷"으로 조정.

| 순서 | 섹션 | 슬롯 | 컷수 |
|---|---|---|---|
| 1 | 핵심 장점 | 스타일링 **풀샷·정면** 낱장 (오프닝 — 무드 담당) | 1 |
| 2 | 핵심 장점 | **미디움샷** 낱장 (셀링포인트 — 현행 호리존 미디움 유지) | 1 |
| 3 | 핏·코디 | **스타일링 세트 A** — 카탈로그 멤버 3컷 통째 | 3 |
| 4 | 핏·코디 | **스타일링 세트 B** — 3컷, A와 장소 타입 상이 | 3 |
| 5 | 핏·코디 | **호리존 회전 세트** (horizon-rotation, 풀×3: 정면·사이드·뒷면) | 3 |
| 6 | 핏·코디 | **거울샷** 낱장 — 여성 상품만. **남성 상품은 낱장 컷(스타일링/호리존)으로 대체** (시장 근거: 남성 거울 0건) | 1 |
| 7 | 제품 확인 | 제품컷 ×2 (현행) | 2 |
| | | **합계** | **14** (폴백 시 13, 다색 시 +1/추가색 — §7) |

- 세트 배치 단위 = 카탈로그 멤버 전부(갤러리에서 셀러가 수동 추가할 때와 동일 단위 — 자동/수동 불일치 없음). 확장 멤버(order 4·5, §6)가 생겨도 기본형은 **order 1~3만** 사용한다.
- 페이지의 장소성 공간 = 3곳(오프닝·세트A·세트B) — 시장 표준 범위(2~4곳, 최빈 2~3) 내. 거울(방)·스튜디오는 별도 축.
- 마네킹 단계 표기: "12컷 고정" → **"약 14컷"**. 콘티보드 상단·크레딧은 실제 컷수 기준(현행 동적 로직).
- 컷 종류·샷·방향은 **역할 고정, 랜덤은 "어떤 예시·세트가 붙는가"에만** 적용된다.

## 2. 세트 선택 알고리즘

1. **후보 필터**: 발행된 세트 중 ① 성별 일치 ② 세트 종류 일치 — 스타일링 슬롯↔styling, **기본형 호리존 슬롯↔horizon-rotation**(성별당 1개뿐이어도 결정적 선택이라 문제없음), **horizon-sequence(4~5컷)는 확장형 전용**(§6) ③ 자산 완비(대표 플레이트·방향별 포즈) ④ 의류 일치 — 호리존은 세트 종류별로 다르다(2026-07-31 오너 정밀화):
   - **회전 세트(A2·A3) = 전 의류.** 원본이 하의 상품이라 메타가 하의로 박혀 있을 뿐, 회전 트리오는 공용 스튜디오 문법(포즈 자산+플레이트만 쓰므로 완성 사진 속 옷과 무관) → **스코프 분리 방식으로 실현**(§8, 카탈로그 세션 설계 2026-07-31): 세트 배치 스코프=전 의류 / 낱장 예시 스코프=기존 하의 유지(갤러리 오염·발행본 불변 계약 보호).
   - **시퀀스 세트(D1~D4, ZARA식) = 의류 구분 유지.** 옷의 거동(스카프형 아우터·유동감 팬츠·치노 등) 중심 기획이라 의류 특정이 본질 — 현행 메타(아우터/하의) 그대로. 상의·원피스용 시퀀스는 신규 생산 시 자동 편입.
   - **구현은 항상 카탈로그 메타를 따른다**(서버 저장 검증 `space_set_not_applicable`과 정합). 회전 전의류 선언 전까지는 하의 외 상품이 §5 낱장 트리오 폴백을 타고, 선언 즉시 자동으로 전 카테고리에 회전 세트가 배치된다. 확장형 시퀀스 승격은 의류가 맞는 카테고리(현재 하의·아우터)만, 그 외엔 회전 유지.
2. **선택**: 후보 **전체 풀에서 프로젝트 ID 시드 기반 결정적 선택**("고정 랜덤"). ~~카탈로그 상위 3 순환~~ 폐기(오너 결정 — 56세트 전부가 순환에 참여해야 하며, 품질 게이트는 순서가 아니라 발행 여부가 담당).
3. **페이지 내 분산**: 세트 A·B와 오프닝 낱장의 **장소 타입(placeType)이 서로 겹치지 않게** — 겹치면 다음 후보로 재추첨. 재추첨 불가(후보 고갈) 시 세트 1개 + 낱장 버퍼로 강등(같은 장소 세트 2개를 넣지 않는다).
4. **저장**: 선택된 세트는 `setSelectionOrigin='auto'`로 기록(아래 §4).

## 3. 낱장 배정 (기존 규칙 + 추가 2)

- 기존 낱장 자동 배정 규칙(#52) 그대로: 조건 필터 → 결정적 선택 → origin 기록 → 재진입 불변.
- (기확정) **세트 소속 예시는 낱장 자동 배정 풀에서 제외.** 셀러가 갤러리에서 직접 고르는 것은 허용.
- (신규) **배정된 세트와 같은 장소 타입의 낱장은 버퍼에서 후순위** — 페이지 내 장소 중복 방지.
- (신규) **하의 상품의 버퍼·대체 낱장은 뒷면 풀샷 우선** — 시장 근거: 하의 뒷면 비중이 상의의 3배. (진입 배정 단계는 의류 종류를 알므로 빌더 수정 없이 적용 가능)

## 4. 소유 구분(setSelectionOrigin)과 저장

- 세트에 `auto | user` 구분 저장 — 낱장의 `exampleSelectionOrigin`과 동일 패턴·동일 목적.
- **배정 결과는 origin과 무관하게 재진입 시 절대 변경되지 않는다.** auto 딱지는 배정을 바꾸기 위한 것이 아니라:
  ① 진입 자동 저장이 "수정된 콘티"로 오판되지 않게(기본 콘티 지문에서 auto 제외 — 낱장 체계에 편입)
  ② 셀러 선택분 절대 불가침의 경계선(추후 세트 회수·기본 구성 개선 배포 시 auto 배정분만 대체 가능)
- 셀러가 세트를 변경·해체·컷 추가한 순간 해당 세트는 `user`.

## 5. 폴백 사다리 (fail-closed)

| 상황 | 처리 |
|---|---|
| 스타일링 세트 후보 0 | 해당 슬롯을 낱장 2컷으로 대체(스타일링 풀+미디움) |
| 스타일링 세트 후보 1뿐 | 세트 1개만 + 낱장 버퍼 2컷 (같은 세트 중복 배정 금지) |
| 호리존 세트 미커버(성별·의류) | 호리존 낱장 **트리오 3컷**(정면·사이드·뒷면 풀 — 회전 문법 유지). 전의류 선언 전에는 하의 외 상품이 상시 이 폴백을 탄다 |
| 거울 예시 없음(여성) | 낱장 컷 대체 (남성 규칙과 동일 경로) |
| 낱장 예시도 없음 | 기존 미배정 안내(현행) — 위장 금지 |

## 6. 확장형 (2026-07-30 오너 확정)

시장의 "긴 상세페이지" 문법 3가지(① 같은 세션 안에서 컷 추가 — 드로우핏 풀세션 4~11컷 ② 제품 디테일 증량 — 마무리 코다 4~5컷 ③ 장소 1곳 추가 — 상한 4곳)를 조합. **같은 공간 컷 추가는 런타임 AI 생성으로 하지 않는다**(자산 완비 게이트·B안 파이프라인과 정합).

- 구성 = 기본형 14컷 + ① **스타일링 세트 C**(+3, 장소 4곳 = 시장 상한) + ② **호리존 슬롯을 horizon-sequence 세트로 승격**(4~5컷, 드로우핏 풀세션 문법 — rotation 대체, +1~2. 성별당 2개 보유, 미커버 시 rotation 유지) + ③ **제품 디테일 +2**(셀러 Detail 소스 있을 때 — 없으면 제품 정면/후면 추가로 대체) = **약 20컷(19~21)**. 다색 시 색상 블록 +4/추가색(§7). **기존 카탈로그 자산만으로 성립하며 추가 생산이 전제가 아니다.**
- **기존 세트 소급 확장 폐기**(2026-07-30 오너 결정): 원본 레퍼런스에 컷이 남았는지 세트별로 확인해 1~2장씩 추가 생산하는 안은 커버리지 들쭉날쭉·비효율로 폐기. 확장형의 깊이는 위 ①~③(장소 1곳 추가·시퀀스 승격·제품 증량)이 담당한다.
- **신규 생산분 전방 기준**: 앞으로 새로 만드는 스타일링 세트는 컷이 많은 원본 시퀀스를 골라 **처음부터 3~5컷**으로 생산(소급 없음). 배치 규칙은 이미 멤버 수 가변에 대응(기본형=order 1~3, 확장형=전체 멤버)이라 4·5컷 세트가 유입되면 확장형이 자동으로 더 깊어진다. 구성 우선순위(시장 근거): 하의 세트는 후면 컷(하의 후면 비중 상의의 3배), 그 외 미디움/클로즈업 포즈 변주.
- 다색 상품의 색상 반복 축은 §7에서 규정한다.

## 7. 다색 상품 (2026-07-30 오너 확정)

색상 축은 이미 코드에 존재한다(블록별 colorId, 확장형 시드의 색상 반복 관례 — src/lib/api/shapes.js defaultStoryboard). 이 절은 **기본값 시드 규칙**만 정한다. 셀러는 인스펙터 '대상 색상'으로 언제든 조정 가능(현행 유지).

- **원칙 — 착장 무드 축은 대표색 고정**: 오프닝·스타일링 세트·회전/시퀀스·거울은 대표색(base) 1회만. 시장 실측에서 색상 반복이 관찰된 유일한 문법은 **드로우핏 "스튜디오 고정 + 색상웨이별 풀세션"**(4~11컷/색)이며, **로케이션 세트를 색상별로 반복한 사례는 표본 0건**. 여성 소호는 색상 반복 없이 3~5컷 압축. 즉 색상 비교의 무대는 스튜디오(호리존)다.
- **기본형**: 추가색마다 **제품 정면 컷 +1** (오너 확정 — 최소 비용안. 착용 색감 확인은 확장형 또는 셀러 수동 몫). Detail 슬롯 색 선정 로직은 현행 유지. 현행 기본형은 추가색이 디테일컷 외 아예 안 보이던 구멍 — 이 규칙이 메꾼다.
- **확장형**: 추가색마다 **호리존 색상 블록 3컷**(정면 미디움 · 정면 풀 · 뒷면 풀 — 측면·후면은 색상블록당 1컷 구색이라는 실측 반영, 샷 크롭은 카테고리 문법 적용) **+ 제품 정면 1** = +4/추가색. 스타일링 세트는 색상 반복하지 않는다(현행 코드의 "색상마다 스타일링 페어 반복"은 이 규칙으로 교체).
- **상한**: 색상 반복은 최대 4색(현행 slice(0,4) 유지). 초과 색은 시드 미반영(셀러 수동).

## 8. 전제·전달 사항

- **placeType 정규화**(카탈로그 세션): 진행 중 확인(2026-07-31, codex/normalize-space-place-types 브랜치 — 13개 표준 어휘). 진입 배치의 정규화 매핑은 신구 어휘를 모두 흡수하도록 선반영됨(storyboardEntryPlacement.js).
- **회전 세트 전 의류화 = 스코프 분리 방식**(카탈로그 세션 설계 채택, 2026-07-31): applicableClothingTypes를 직접 바꾸지 않고(발행본 불변 계약·갤러리 오염·서버 [top,outer] 조합 제한 — server/app/agents/space_set_assets.py:276 실측) **"세트 배치 스코프" 필드를 분리 신설** — 세트로 통째 배치될 때는 성별 내 전 의류, 낱장 예시로 노출될 때는 기존 하의 유지. 시퀀스 D1~D4는 양쪽 모두 현행 의류 메타 유지. **수반 조건**: ① 서버 저장 검증(validate_storyboard_space_sets)도 세트-스코프 기준으로 통과하게 변경 ② 필드명·스키마 확정 시 진입 배치(storyboardEntryPlacement.js — 현재 applicableClothingTypes 필터)가 회전 세트에 한해 그 필드를 읽도록 후속 수정(그 전까지 하의 외 상품은 낱장 트리오 폴백 유지).
- **신규 세트 생산 표준**(생성 세션): §6 전방 기준 — 앞으로는 컷 많은 원본 시퀀스 위주로 골라 세트당 3~5컷 생산. 기존 세트 소급 없음.
- 핵심 장점 오프닝·거울 낱장도 §3 분산·풀 제외 규칙의 적용 대상이다.
