# 마네킹 후보 선택과 최종 재생성 기준

2026-09-10 사용자 결정. 적용 범위는 PR 252의 마네킹 생성과 조정이다.

## 판단 기준

검수는 주상품의 `logo_graphic`, `color`, `construction`, `pattern`, `material`, `fit`을 각각 판정하고 사진 근거를 남긴다. 값은 `none`, `minor`, `major`, `critical`, `uncertain`이다. 근거가 없거나 가려진 부분은 확인된 결함이나 정상으로 단정하지 않는다.

| 심각도 | 의미 | 예 |
|---|---|---|
| none | 상품을 올바르게 표현 | 자연스러운 주름, 정상적인 조명 반사 |
| minor | 구매 판단을 바꾸지 않는 작은 차이 | 약한 색조 편차, 작은 봉제 디테일 차이 |
| major | 구매 판단에 영향을 주는 명확한 차이 | 눈에 띄는 패턴 간격 또는 원단 인상의 변경 |
| critical | 다른 상품으로 오인하게 하는 핵심 손상 | 보이는 로고 누락·글자 변형, 색상군 변경, 주요 주머니·잠금 구조 누락 |
| uncertain | 사진 근거로 확인 불가 | 가려진 로고, 부족한 뒷면 자료, 판정 실패 |

로고라고 모든 차이가 critical인 것은 아니다. 읽히는 글자와 디자인이 맞고 아주 작은 렌더링 차이만 있으면 minor다. 색상도 명확한 상품색 변경과 정상 조명 차이를 구분한다. 사용자가 선언한 핏과 기장은 정당한 변경이며 결함으로 세지 않는다.

## 후보 선택

1. 가장 심한 결함의 수준이 낮은 후보가 우선한다. 결함 개수, 문장 개수, 가중 합계로 고르지 않는다.
2. 최고 심각도가 같으면 모든 항목이 같거나 좋아지고 적어도 하나가 좋아진 후보를 선택한다.
3. 같은 수준에서 서로 다른 항목이 좋아지고 나빠지면 우열이 불명확하다. 기존 후보를 유지하고 비교 사유를 기록한다.
4. 항목별 판정이 동등할 때만 기존 기술 품질 점수를 보조 기준으로 사용한다. 미판정은 정상 판정으로 취급하지 않는다. 일부 항목이 누락돼도 다른 항목에서 확인한 결함은 보존한다.
5. 자유문장 `critical_errors`는 하위 호환을 위한 보수적 차단 신호다. 문장의 개수나 표현 차이로 중요도를 추정하지 않는다.

## 보정 전후 선택

새 major 또는 critical이 생기거나 기존 문제가 더 심해지면 이전 사진과 그 판정으로 돌아간다. 이미 critical이 있어도 다른 항목의 새 critical을 허용하지 않는다. 구조화된 판정이 없어 전후 문제를 비교할 수 없는 치명 결함 사진은 선택적 보정으로 개선됐다고 인정하지 않는다. 새 판정이 실패하거나 불명확해져도 이전에 확인한 사진을 유지한다.

## 최종 한 장

기존 생성·보정 예산을 사용한 뒤에도 선택 후보에 중요한 상품 문제가 남으면, 서비스 부담으로 최종 이미지 생성 1회만 추가한다. 원본 상품 사진, 베이스 마네킹, 선언된 핏과 앞선 실패 근거를 사용한다. 이전 생성본의 잘못된 디자인을 정본으로 삼지 않는다.

최종 한 장에는 이미지 편집이나 재생성 루프를 다시 붙이지 않는다. 실제로 enforce 중인 의류, 매칭, 핏, 베이스 및 시리즈 검사를 통과해야 저장한다. 시리즈 참조가 없는 첫 생성은 비교를 생략하지만, 참조 조회나 검수 실패를 참조 없음으로 처리하지 않는다. 재검사 실패나 중요한 결함 잔존은 작업 실패로 끝내고 사용자 예약 크레딧을 해제한다. 성공해도 원래 예약한 크레딧만 차감하며 최종 한 장의 추가 비용은 서비스가 부담한다.

화면은 이 품질 종료를 자동 재시도하지 않는다. 최초 생성 요청과 분석 수정 버전별 종료 상태 및 멱등 키를 보존하므로 새로고침과 화면 재진입도 추가 생성을 만들지 않는다. 최초 생성이 다른 탭의 활성 작업에 합류하면 실제 작업 번호도 저장하고, 다음 진입은 새 생성 요청 없이 해당 작업을 조회한다. 작업 번호 응답을 받기 전 이탈하면 같은 키로 기존 서버 작업에 다시 연결한다. 사용자가 명시적으로 다시 시도하거나 상품 입력을 새로 수정하면 새 작업이 가능하다. 결과가 불명확한 네트워크 오류는 수동 재시도도 먼저 기존 작업을 확인한다. 편집에서 시작했더라도 최종 한 장은 원본 기반 신규 생성으로 이력을 기록한다.

합류 응답 자체가 유실되는 경우도 서버가 보호한다. 마네킹 요청은 `mannequin_job_requests`에 사용자, 프로젝트, 요청 키와 실제 작업 번호를 같은 트랜잭션으로 저장한다. 동시 요청은 프로젝트별로 직렬화하며 원래 작업의 키를 덮어쓰지 않는다. 작업이 실패한 뒤에도 같은 합류 키는 원래 작업을 반환하고 새 예약을 만들지 않는다. 다른 작업 종류와 키 없는 호출은 기존 동작을 유지한다.

배포 시 `20260910210906_mannequin_job_requests.sql`을 먼저 적용한 뒤 서버를 배포한다. 구버전 서버에서 이미 기록 없이 끝난 합류는 소급 복구되지 않으며, 구버전 서버가 남아 있는 배포 구간도 같은 보호를 보장하지 않는다.

off와 shadow는 새 정책에 의한 자동 차단 및 추가 생성의 근거가 되지 않는다. 주상품 shadow와 매칭 enforce는 독립적으로 적용한다. 일반 생성 요청의 결과가 네트워크에서 불명확해진 실패는 최종 생성이나 후속 편집 전에 즉시 종료한다. 검수 모델의 실제 탐지 정확도나 생성 성공을 보장한다는 의미는 아니며, 이번 검증은 결정·요청·저장 흐름을 고정한다.

## 검증 사례

- 로고 누락 한 건보다 작은 색감·디테일 차이 여러 건을 선택한다.
- 동일한 문제 설명이 중복돼도 선택 결과는 바뀌지 않는다.
- 같은 심각도에서 항목 간 교환이 있으면 기존 후보를 유지한다.
- 기존 로고 문제에 새 색상 문제가 생긴 보정본을 되돌린다.
- 두 시도가 실패하고 최종 세 번째가 통과하면 한 번만 저장한다.
- 최종 세 번째도 실패하면 저장과 사용자 과금이 없고 화면도 자동 재시도하지 않는다.
- 첫 시도 통과, off, shadow, 취소, 결과 불명 네트워크 실패에는 추가 생성이 없다.
