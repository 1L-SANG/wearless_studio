## 1. 보드 레이아웃

- **카드 = 현행 가로 전체 로우 유지** (썸네일 좌 + 정보 우). 카드 내부 구성(방향·샷·색상 칩·복제/삭제)은 변경 없음.
- **세트 = 로우들을 감싸는 띠(밴드) 래퍼**: 얇은 헤더("📍 공간 A · 카페 · N컷 같은 공간") + 옅은 배경/테두리 색. 컷이 늘면 세로로만 확장. 가로 분할 없음.
- 세트는 **접지 않는다** (토글 속 토글 금지 — 섹션 1층 토글만). 세트가 4컷+로 커지는 미래에 밴드 접기 추가 여지.
- 섹션(핵심 장점/핏·코디/제품 확인)은 **현행 유지** — 세트는 섹션 안의 선택적 묶음이며 섹션과 컷 종류를 1:1 결합하지 않는다(핵심 장점 ≠ 호리존).
- 시드 기본: 핏·코디 안에 공간 세트 1개(기존 spaceGroupId 쌍 = 풀샷+미디움샷), 나머지 현행. 공간 디폴트 총 1곳(+ 셀러 추가 자유).

## 2. 샷 네이밍·크롭

- 명칭 통일: **풀샷 / 미디움샷** (전신/상반신 표기 폐기 — 하의에서 상반신이 오라벨이므로). UIUX는 개편안 유지(갤러리 헤더 세그먼트·크롭 미리보기).
- **미디움샷 크롭 대역 = 카테고리별**: 상의=상단 크롭(머리~엉덩이), 하의=**허리~발**(2026-07-30 오너 결정 — 종전 "허리~무릎"안 폐기. 무릎에서 자르면 바지·치마 밑단이 사라져 상품 확인이 안 된다). 서버 규칙 크롭에 카테고리 파라미터. 크롭 미리보기 오버레이도 하의는 위쪽 딤.
- 세트 구성 기본: 스타일링 세트=풀샷+미디움샷, 호리존 세트=회전 풀×3(정면·사이드·뒷면 — ¾ 방향은 별도 결정 대기).
  - 하의 예외였던 "풀+풀 뒷면 대체"는 무릎 크롭 전제였으므로 **허리~발 채택과 함께 해제 후보**다(하의 미디움샷이 하반신 전체를 담으므로 풀+미디움이 성립). 확정 전까지는 현행 구현(카테고리 무관 풀+미디움)을 유지한다.
- **미구현 갭(2026-07-30 확인)**: 콘티 기본 구성 빌더는 의류 종류를 받지 않는다 — `src/lib/api/shapes.js:44 defaultStoryboard(colors, mode)`, mock `src/mock/db.js:356 buildStoryboard(mode, colors)` 둘 다 `clothingType` 인자가 없고 세트 쌍(`styling/front/full` + `styling/side/medium`)이 하드코딩이다. `createSpaceSetMembers`에도 카테고리 분기가 없다. 의류별로 갈리는 것은 예시 선별(`generationExamples.js` `applicableClothingTypes`)·프롬프트 프레이밍 문구(`_is_bottom`)·얼굴 노출 판정뿐이다.

## 3. 세트 추가/변경/해체

- **추가**: ① 섹션 하단 "＋ 블록 추가" → "같은 공간 세트" → **Ⓒ 세트 카드 갤러리**(폴라로이드 스택 + 컷 구성 라벨 "풀+미디움"/"회전 풀×3") → 선택 시 띠+컷들이 통째로 원자 추가. ② 카드 사이 호버 삽입(아래 §4).
- **공간 세트 변경** (네이밍 확정 — "공간 바꾸기" 아님): 버튼은 **띠 테두리 우측 상단에만** (동작 범위=버튼 위치 일치). 인스펙터의 공간 스트립은 정보 전용(버튼 없음).
- 변경 UI: **팝업/모달 금지** — 버튼을 누르면 **인스펙터(우측 창)에 세트 카드 갤러리가 인라인으로 뜬다** (우측 창 일관성 유지). 선택 시 세트 전체가 새 공간·구성으로 원자 교체.
- **"이 컷만 세트에서 빼기" 버튼 없음** (오너 결정). 세트에서 빼기 = **드래그로 띠 밖에 드롭**. 새 컷이 필요하면 블록 추가. "세트 전체 풀기"는 ⋯ 오버플로 메뉴 유지.

## 4. 드래그 & 사이사이 추가

- 호버 삽입 버튼: **띠 안 = "＋ 이 공간에 컷 추가"**(spaceGroupId 상속, 포즈 예시 선택 흐름) / **띠 밖 = "＋ 개별 컷 추가"**(현행). 라벨·색으로 구분.
- **드래그 드롭 미리보기 선 색 구분** (오너 제안): 드롭 위치가 세트 내부면 **세트 색(보라 계열) 선** = "이 공간에 편입됨", 세트 밖 일반 위치면 **기본색(회색/검정) 선** = "개별 컷으로 이동". 
  - 세트 밖 → 안 드래그: spaceGroupId 부여 + refScope=pose 강제 (기존 예시가 pose 비호환이면 재선택 유도 — fail-closed).
  - 세트 안 → 밖 드래그: spaceGroupId 해제 = 세트에서 빠짐. 세트에 1컷 남으면 세트 자동 해체.
  - 밴드 헤더 드래그 = 세트 통째 이동(멤버 인접성 보존 — 저장 계약의 연속 run 유지).

## 5. 인스펙터 (세트 멤버 카드)

- 클릭하면 현행과 동일한 설정 패널. 세트라서 달라지는 것 **3가지만**:
  ① 상단 공간 스트립(정보 전용: 공간 이름 + 형제 컷 미니 썸네일 + "공간 변경은 보드의 띠에서" 안내)
  ② 컷 종류 탭 잠금(세트 해제 시 풀림)
  ③ 예시 갤러리 = 포즈 예시(방향 호환 후보만), 레퍼런스 범위 = 포즈만 고정 표시(전부/배경만 비활성 + 사유 한 줄)
- 방향 변경 → 포즈 목록 재필터(방향 게이트, 자산 없으면 준비 중 fail-closed). 포즈 선택 → 그 컷만 변경(origin=user 보호).
- **⚠ 구현 시 현행 인스펙터 항목 전수 보존** (목업의 축약은 러프 표현일 뿐): 대상 색상(다색 선택), 매칭 의류 편집, 내 사진(refImages) 업로드, 아우터 열림 정도, 얼굴 노출, 레퍼런스 범위 칩+설명문, 예시 갤러리 새로고침/다른 예시 보기, 추가 옵션, 복제/삭제. 세트 멤버는 위 ①~③의 차이만 오버레이하고 나머지 전부 유지. 구현 전 현행 Inspector 필드 목록과 1:1 대조 체크리스트 필수.

## 6. 데이터·생성 (변경 최소)

- 저장: 블록 단위 현행 유지. 세트 = spaceGroupId 공유(연속 run). 서버 계약 변경 없음(§4 드래그 편입 시 refScope=pose 강제는 기존 canonicalize 규칙).
- 생성예시 세트 원본: 같은 상세페이지의 연속 컷을 세트로 읽되, 각 풀샷·미디움샷은 해당 원본 컷의 카메라 위치·구도·포즈를 따로 참고해 독립 생성한다. 미디움샷을 대표 풀샷의 확대·크롭으로 만들지 않는다.
- 생성예시 세트의 빈 배경: 대표 풀샷과 짝인 플레이트 **1장만** 세트 대표 배경으로 보관한다. 다른 풀샷·미디움샷은 같은 공간의 다른 위치·방향으로 독립 생성하며 별도 플레이트를 의무 생성하지 않는다.
- 실제 생성: 세트 대표 플레이트(공간, 프로젝트 시드 변주 풀) + 컷별 포즈 자산 + 컷별 방향 = 검증된 B안 파이프라인. scene QC는 대표 플레이트와 세트 공간 단서를 기준으로 한다.
- 각 컷은 ADR-0009 §1.3의 촬영 등급·얼굴 노출·포즈 비대칭/원근·인물 광원·연출 유사성 5개 하드 게이트를 모두 통과해야 한다. 세트 공간 연속성이 좋아도 이 중 하나가 실패하면 세트 전체를 승인하지 않는다.
- 세트 자산: 세트 단위 생산(플레이트 풀 + 완성 예시 쌍 + 방향별 포즈) — 생성 세션 전달 완료분 참조.

### 6.1 기존 개별 생성예시를 세트로 재사용하는 두 등급

- `displayReady`: 현재 이미지 세 장을 그대로 세트 미리보기에 놓아도 된다. 같은 공간뿐 아니라 같은 하우스 모델·동일 착장·필수 3컷 구성·대표 풀샷 플레이트가 모두 갖춰져야 한다.
- `referenceReady`: 공간·카메라 이동·광원·풀/미디움 흐름은 한 세트의 생성 레퍼런스로 쓸 수 있지만, 기존 이미지의 모델·착장 또는 대표 플레이트는 서로 다르거나 빠져 있다. 이 경우 기존 이미지를 버리지 않고 **세트 제작 레시피와 컷별 연출 앵커**로 묶어 사용하되, 사용자에게 보여줄 최종 세트 이미지는 동일 모델·동일 착장으로 다시 생성한다.

`displayReady`가 0개라는 이유로 `referenceReady` 후보까지 “묶을 수 없음”으로 처리하지 않는다. 반대로 `referenceReady`를 현재 서비스 미리보기용 완성 세트로 표시하지도 않는다.
