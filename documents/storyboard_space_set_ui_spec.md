# 콘티보드 공간 세트 UI — 확정 스펙 (오너 승인 결정 모음)

> 2026-07-23 확정. 목업 정본: mockups/storyboard_final_mockup.html (+ storyboard_row_band_mockup.html 레이아웃 원리, full_panel_ui.html Ⓒ 원안).
> 시장 근거: documents/cut_composition_research.md (회전 트리오·페어 문법), cut_sequence_market_research.md.
> 관련 계약: ADR-0004(spaceGroupId·spaceVariation), 자동 배정(documents/genexamples_autofill_design.md).

> **화면 절은 대체됨: 템플릿 콘티(ADR-0026), 2026-11-13.** §1 보드 레이아웃, §3 세트 추가·변경·해체, §4 드래그와 사이사이 추가, §5 인스펙터는 옛 콘티 화면 기준이며 지금 화면과 다르다. 지금 콘티는 왼쪽 페이지 구성, 가운데 무대, 옆 판으로 나뉘고, 장소 세트와 스튜디오 세트는 옆 판(`src/features/storyboard/StoryboardSpaceSetPanel.jsx`)에서 고른다. 세트 카드는 대표 사진, 선택 표시, 스튜디오 세트를 바꿀 때 늘어나는 컷 수("+N컷")만 보여 준다. 한 섹션은 사진 12장까지라 남은 자리보다 컷이 많은 세트는 추가할 수 없다. 처음 깔 때의 세트 고르기는 `documents/storyboard_entry_composition_spec.md` §2.0이 현행이다. §2 샷 이름·크롭과 §6 데이터·생성은 현행 규칙으로 남긴다. §6의 셀러가 바꿀 수 있는 것, 세트 안 참고 범위와 공간 변화 강도, 장소 종류 중복 방지 문장은 지금 코드에 맞췄고, 대표 plate와 scene QC 문장은 코드와 대조하지 않았다(확인 중).

용어: UI의 상위 이름은 **촬영 세트**다. 그중 스타일링 세트는 같은 장소 안에서
이어 찍은 **같은 공간 세트**이고, 호리존 회전·연속 세트는 별도 유형이다.

## 1. 보드 레이아웃

- **카드 = 현행 가로 전체 로우 유지** (썸네일 좌 + 정보 우). 카드 내부 구성(방향·샷·색상 칩·복제/삭제)은 변경 없음.
- **세트 = 로우들을 감싸는 띠(밴드) 래퍼**: 얇은 헤더("📍 공간 A · 카페 · N컷 같은 공간") + 옅은 배경/테두리 색. 컷이 늘면 세로로만 확장. 가로 분할 없음.
- 세트는 **접지 않는다** (토글 속 토글 금지 — 섹션 1층 토글만). 세트가 4컷+로 커지는 미래에 밴드 접기 추가 여지.
- 섹션(핵심 장점/핏·코디/제품 확인)은 **현행 유지** — 세트는 섹션 안의 선택적 묶음이며 섹션과 컷 종류를 1:1 결합하지 않는다(핵심 장점 ≠ 호리존).
- 시드 기본: 핏·코디 안에 현재 상품의 성별·의류 종류에 맞는 발행 스타일링
  촬영 세트 1개(현재 릴리스는 보통 3컷)를 넣고, 나머지는 현행대로 둔다.
  기본 공간은 총 1곳이며 셀러가 촬영 세트를 더 추가할 수 있다.
- 현재 조건에 맞는 발행 스타일링 세트가 없으면 임의 묶음을 만들거나 다른
  성별·카테고리 세트를 빌리지 않는다. 그 조건에서는 세트 없이 개별 컷만
  시드하고 촬영 세트 선택지는 준비 중으로 닫는다.

## 2. 샷 네이밍·크롭

- 화면 이름: 구도는 **전신**과 **상반신**이고, 하의는 상반신 대신 **하반신**으로 적는다. 저장값은 전신이 `full`, 상반신과 하반신이 `medium`이다(`src/lib/pageTemplates/storyboardPhotoChoices.js`의 `framingLabel`). 사진 판의 구도 고르기는 `모든 구도`, `전신`, `상반신`(하의는 `하반신`)이고, 사진이 하나인 섹션에는 `모든 구도`가 없다(`StoryboardChoiceControls.jsx`의 `PhotoFraming`).
- **세트의 상반신 사진은 전신 사진을 확대하거나 잘라 낸 파생 이미지가 아니다.** 같은 장소 안에서
  모델과 카메라가 이동하고 방향과 구도가 달라진 독립 촬영 예시를 사용한다. 개별 컷의 구도를
  바꾸는 기능이 있더라도 세트 자산 생산 규칙으로 사용하지 않는다.
- 세트 구성 기본: 스타일링 세트는 전신과 독립 상반신 사진, 호리존 회전
  세트는 전신 3장(정면, 옆, 뒷면), 호리존 연속 세트는 서로 다른 포즈와 방향의
  호리존 컷 묶음이다.

## 3. 세트 추가/변경/해체

- **추가**: ① 섹션 하단 "＋ 블록 추가" → "촬영 세트" → **Ⓒ 세트 카드 갤러리**(폴라로이드 스택 + 컷 구성 라벨 "풀+미디움"/"회전 풀×3") → 선택 시 띠+컷들이 통째로 원자 추가. ② 카드 사이 호버 삽입(아래 §4).
- **촬영 세트 변경**: 버튼은 **띠 테두리 우측 상단에만** (동작 범위=버튼 위치 일치). 인스펙터의 공간 스트립은 정보 전용(버튼 없음).
- 변경 UI: **팝업/모달 금지** — 버튼을 누르면 **인스펙터(우측 창)에 세트 카드 갤러리가 인라인으로 뜬다** (우측 창 일관성 유지). 선택 시 세트 전체가 새 공간·구성으로 원자 교체.
- **"이 컷만 세트에서 빼기" 버튼 없음** (오너 결정). 세트에서 빼기 = **드래그로 띠 밖에 드롭**. 새 컷이 필요하면 블록 추가. "세트 전체 풀기"는 ⋯ 오버플로 메뉴 유지.

## 4. 드래그 & 사이사이 추가

- 호버 삽입 버튼: **띠 안 = "＋ 이 공간에 컷 추가"**(spaceGroupId 상속, 포즈 예시 선택 흐름) / **띠 밖 = "＋ 개별 컷 추가"**(현행). 라벨·색으로 구분.
- **드래그 드롭 미리보기 선 색 구분** (오너 제안): 드롭 위치가 세트 내부면 **세트 색(보라 계열) 선** = "이 공간에 편입됨", 세트 밖 일반 위치면 **기본색(회색/검정) 선** = "개별 컷으로 이동". 
  - 세트 밖 → 안 드래그: spaceGroupId 부여 + refScope=pose 강제 (기존 예시가 pose 비호환이면 재선택 유도 — fail-closed).
  - 세트 안 → 밖 드래그: spaceGroupId 해제 = 세트에서 빠짐. 한 컷만 남아도
    세트는 자동 해체하지 않는다(오너 확정 2026-07-29).
  - 밴드 헤더 드래그 = 세트 통째 이동(멤버 인접성 보존 — 저장 계약의 연속 run 유지).

## 5. 인스펙터 (세트 멤버 카드)

- 클릭하면 현행과 동일한 설정 패널. 세트라서 달라지는 것 **3가지만**:
  ① 상단 공간 스트립(정보 전용: 공간 이름 + 형제 컷 미니 썸네일 + "공간 변경은 보드의 띠에서" 안내)
  ② 컷 종류 탭 잠금(세트 해제 시 풀림)
  ③ 예시 갤러리 = 세트에 호환되는 예시. 참고 범위 선택 UI는 제공하지 않으며 장소·자세 입력은 세트 내부에서 결정한다.
- 방향 변경 → 포즈 목록 재필터(방향 게이트, 자산 없으면 준비 중 fail-closed). 포즈 선택 → 그 컷만 변경(origin=user 보호).
- **⚠ 구현 시 현행 인스펙터 항목 전수 보존** (목업의 축약은 러프 표현일 뿐): 대상 색상(다색 선택), 매칭 의류 편집, 내 사진(refImages) 업로드, 아우터 열림 정도, 얼굴 노출, 예시 갤러리 새로고침/다른 예시 보기, 추가 옵션, 복제/삭제. 폐지된 참고 범위 칩은 복원하지 않는다. 세트 멤버는 위 ①~③의 차이만 오버레이하고 나머지 전부 유지. 구현 전 현행 Inspector 필드 목록과 1:1 대조 체크리스트 필수.

## 6. 데이터·생성

- 저장: 블록 단위 현행 유지. 정식 릴리스 세트의 `spaceGroupId`는
  `ssg1__<setId>__<instanceId>` 형식이며 같은 연속 run이 세트를 이룬다.
  과거 `sgset__` 또는 임의 그룹 값은 정식 릴리스 ID로 해석하거나 호환하지
  않는다. 현재 저장 데이터는 테스트 프로젝트뿐이므로 배포 전에 초기화한다.
- 세트 선택은 **공간 plate를 고르는 출발점**이지 멤버 구성을 영구 고정하는
  명령이 아니다. 선택 후 셀러는 세트 컷마다 사진 판의 "같은 장소의 다른 사진"에서
  다른 멤버를 고르거나 "이 컷만 다른 사진으로 바꾸기"로 다른 예시를 고를 수 있다
  (`StoryboardPhotoGallery.jsx`). 장소 세트는 무대의 옅은 칸으로 그 세트의 아직 안 쓴
  사진을 더할 수 있다.
  방향과 포즈를 따로 고르는 버튼은 없으며 방향은 고른 예시가 정한다(ADR-0015).
  서버는 발행 세트의 성별, 적용 의류, 공간 변화 강도, 세트 컷의 연속 배치, 배경
  옵션이 같은지를 검증하고, 각 블록이 고른 예시에 맞는 발행 pose를 사용한다
  (`server/app/agents/space_set_assets.py`).
- 세트 안 블록의 `refScope`는 서버가 컷에서 다시 계산한다. 스타일링 장소 세트는
  `pose`, 호리존 세트는 `all`이다(`server/app/agents/reference_mode.py`의
  `reference_scope`). 별도 `pose` 값은 저장하지 않고 저장할 때 지운다
  (`content_roles.py`의 `_canonicalize_v4_block`). `spaceVariation`은 발행 세트의 값과
  같아야 하며 다르면 `space_set_variation_mismatch`로 거절한다. 전체 보드를 기준으로
  연속성을 먼저 확인한 뒤 AI 생성 블록만 실행한다.
- 생성: 대표 plate + 컷별 독립 pose + 컷별 방향을 사용하며, 결과가 같은
  공간으로 보이는지 scene QC를 필수로 통과해야 한다. QC 판정 서비스가 실패해도
  공간 세트 결과를 그대로 발행하지 않는다.
- v1 릴리스는 승인된 **세트마다 대표 plate 1장**을 발행한다. 같은 세트를 고른
  프로젝트마다 서로 다른 plate를 배정하는 변주 풀은 아직 자산이 없으므로 이번
  릴리스 범위가 아니다. 향후 여러 plate를 실제로 확보한 뒤 프로젝트 시드 배정
  계약을 별도로 추가하며, 현재 서비스에서 지원한다고 표시하지 않는다.
- 자동 시드가 한 프로젝트에 스타일링 세트를 여러 개 배정할 때는 세트의
  `placeType`을 `normalizePlaceType`(`src/lib/storyboardEntryPlacement.js`)으로 묶은
  장소 종류(카페, 집, 실내, 도심, 해변, 자연, 리조트, 야간, 야외 등)가 아직 쓰이지
  않은 세트만 고른다. 비슷한 원래 값(예: 공원과 강변 산책로)은 같은 장소 종류로 본다. 쓸 수 있는 장소 종류가 떨어지면 반복하지 않고 남은
  자리를 개별 컷으로 채운다(`storyboard_entry_composition_spec.md` §2.0). 호리존은 중립 스튜디오가 비슷한 것이 정상이라 이 중복 방지
  대상에서 제외한다. 사용자가 갤러리에서 직접 같은 장소 종류를 고르는
  선택까지 막지는 않는다.

## 7. 미결(별도 결정 대기)

- ¾(45°) 방향 축 추가 여부 — 포즈 자산·방향 게이트 계약 변경 필요.
- 하의 한정 무릎 크롭 도입 여부.
- 공간 타입과 카테고리·성별 적용성은 공간 세트 릴리스 manifest가 정본이며,
  값이 없거나 잘못된 세트는 전체 적용으로 넓히지 않고 노출하지 않는다.
