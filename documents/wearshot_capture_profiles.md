# 착용컷 촬영 질감 이름과 검수 계약

2026-09-09 사용자 피드백과 후속 실행 기준. 촬영 질감 이름은 실험·리뷰 계약이며 서버 생성기의 배포된 프리셋이라고 주장하지 않는다. 후속 사용자 승인으로 실제 API10장·기본 QC30건·집중 검수3건과 아래 안전장치 코드를 구현했다. Goal 재활성화와 운영 배포·활성화는 하지 않았다.

## 두 가지 이름

| 부르는 이름 | 명세 ID | 느낌 기준 | 바꾸지 않는 것 |
| --- | --- | --- | --- |
| 클린 스냅 | `clean_snapshot_v1` | fr06-v2처럼 비교적 또렷한 피부·머리·원단 디테일과 깨끗한 일상 사진 표현. 스튜디오·화보를 뜻하지 않는다. | 선택 모델, 상품색·구조, 구도·거리·크롭 |
| 소프트 스냅 | `soft_snapshot_v1` | fr06-v3에서 사용자가 선호한 부드러운 미세 디테일과 구형 아이폰 스냅 인상. `구형 아이폰 스냅`, `올드 아이폰`도 이 계열을 뜻한다. | 위 항목에 더해 검수된 이전본의 의류 색상·채도·명도. 색보정·빈티지 색 필터를 포함하지 않는다. |

예: “소프트 스냅으로, 상품색은 승인본 유지, 2K로 보여줘.” / “같은 컷을 클린 스냅으로 비교해줘.”

이름은 특정 내장 모델, 해상도 또는 API `quality` 값과 동의어가 아니다. fr06-v2와 v3의 생성 원본은 모두 1083×1452이다. 2K 전달본은 별도 비생성 리샘플링으로 1527×2048을 만든 것이다. 일반화된 최종 소프트 스냅 레시피는 아직 검증 중이며, 이름을 정했다고 모든 장면에서 같은 품질을 보장하지 않는다.

## 색 보존과 질감의 분리

- 스타일 선호와 상품색 합격을 별도 기록한다. 현재 fr06은 **질감 기준 v3 / 의류 색 기준 v2**다. v3 전체를 완성본으로 승인한 것이 아니다.
- 색 기준은 해당 상품에 대해 사용자가 수용했거나 상품 증거로 검수한 프레임이다. 잘못된 기존색을 무조건 동결하지 않는다.
- 소프트 스냅 변환에서 화이트밸런스 변화, 전역 채도·대비·노출 변화, 암부 밀도 변화까지 한꺼번에 요청하지 않는다. 이것들은 색 표현에 영향을 줄 수 있으며 미세 질감 완화와 별도 실험이다.
- 생성기에 “색 유지”를 적은 것만으로 보존됐다고 판정하지 않는다. 수정 전 승인 색 기준, 상품 근거, 수정 후를 비교한다. 단순히 같은 빨강/크림 계열인지가 아니라 실제 색상·채도·명도 변화와 소재 해석을 확인한다.
- 질감이 좋아져도 의류 색이 틀려지면 최종 채택하지 않는다. 이전 색 기준을 보존하고 실패 축만 다음 수정 대상으로 삼는다. 색을 바로잡는 과정에서 표정·구도·원단까지 다시 달라졌는지도 재검수한다.
- 비생성 색/질감 분리 후처리는 아직 검증·승인된 기본 경로가 아니다. 마스크 합성이나 색 전송을 승인 없이 실행하지 않는다.

## 얼굴 false-PASS 재발 방지

fr04-v1의 오류는 긴 머리 교체 및 대략적인 인상 일치를 얼굴 교체 성공으로 인정한 것이었다. 당시 근거 자체에 원본형 좁은 눈매가 남는다는 기록이 있었는데도 PASS를 줬다.

다음 얼굴이 보이는 수정본을 완료로 표시하기 전에 반드시:

1. 생성예시의 인물, 선택 얼굴 시트, 결과물을 별도로 나란히 확인한다. 원본 인물과 비슷하게 남았는지와 선택 얼굴의 특징이 반영됐는지를 모두 묻는다.
2. **얼굴**과 **머리**를 별도 판정한다. 긴 머리·앞머리·피부톤 변경은 얼굴 합격의 대체 근거가 아니다. 보이는 눈·눈꺼풀, 코, 입, 볼·턱의 관계를 실제 시트와 비교한다.
3. 원본 얼굴 잔존이 의심되거나, 근거가 ‘비슷한 느낌/대체로 호환’ 수준이면 얼굴 PASS를 주지 않는다. `REVIEW_REQUIRED`로 두고 사용자 확인이나 별도 얼굴 검수를 요청한다. 불확실하다는 이유만으로 이미지를 자동 반복 생성하지 않는다.
4. 얼굴이 원래 프레임 밖이면 얼굴 전체는 `NOT_APPLICABLE`이다. 일부만 보이면 그 영역만 판단하고, 검수를 위해 머리·눈을 새로 그리거나 구도를 넓히지 않는다. 너무 작아 판단 불가인 얼굴을 정확히 일치한다고 표시하지 않는다.
5. 재검수에는 생성자의 PASS 설명을 정답으로 제공하지 않는다. 수정 후 얼굴뿐 아니라 의류색·구도·손/휴대폰 연결의 회귀도 확인한다.
6. 최종 표시에는 얼굴/헤어/상품/촬영 질감/사용자 수용을 분리한다. 매력적임·자연스러움·웃는 표정만으로 얼굴 실패를 상쇄하지 않는다. 판정 이력과 사용자 수용 범위는 보존한다.

이 절차는 오류를 줄이기 위한 검수 계약이지 얼굴 일치의 무오류 보증이나 신원 확인 시스템이 아니다. 현재 서버의 `modelIdentity` 하드 게이트는 이미 모호함을 UNJUDGEABLE로 처리하도록 작성돼 있다. 이번 실험의 내장 생성 + 수기 QC는 그 서버 런타임을 통과한 것이 아니므로, 서버 경로 재현과 실패 사례 재검수 없이 서버 방어가 검증됐다고 주장하지 않는다.

### 확인된 서버 배선의 별도 문제

현재 체크아웃 `server/app/workers/detail_page_job.py`는 cut QC의 repair 결과를 기록하지만, 수정이 불가능하거나 거절되거나 QC 예외가 나면 stage1을 보존한 뒤 저장·`cut_done` 처리로 진행한다. `copilot/api/manifest.yml`과 `copilot/detail-worker/manifest.yml`은 repair 모드를 선언한다. 이는 코드·manifest 확인이며 실제 배포 런타임을 조회한 결과는 아니다.

따라서 “judge가 FAIL을 말한다”와 “실패 이미지를 완료본으로 전달하지 않는다”는 다른 기능이다. 후속 구현은 얼굴 교체·의류 색 같은 핵심 실패를 저장 전에 보류하는 옵션을 추가했다. 작은 포즈 차이까지 모두 실패 처리하거나 무제한 재생성하는 정책으로 대체하지 않는다. 기본값과 배포 manifest는 유지했다.

## 후속 구현 상태와 범위

- `CUT_OUTPUT_RELEASE_POLICY=off`가 기본값이다. `critical`은 선택된 최종 단계의 modelIdentity, garmentColor, matchingGarmentIdentity를 확인하고 실패·판정불가·손상된 결과를 저장/완료 전에 보류한다. **17개 전체 QC 게이트의 전면 출고 차단 모드는 아니다.** 나머지 구조·소재·장소 실패는 여전히 별도로 해석해야 하며 전체 자동 출시 품질이 확정된 것이 아니다.
- 보이는 얼굴의 기본 QC가 PASS이면 별도 얼굴 대조가 필요하다. MODEL FACE / optional EXAMPLE / 최종 후보만 비교하고, 헤어·옷으로 얼굴을 증명하지 않는다. GPT-only `CUT_IDENTITY_REVIEW_MODEL` 기본은 `gpt-6-astra`다. 후보 해시가 맞고 독립 결과도 PASS여야 하며, NA는 추가 호출하지 않는다. 불확실하면 검수 대기이지 머리를 새로 그리는 명령이 아니다.
- 승인된 로컬 `EDIT_STAGE1` 수정에서 수정 전 조명과 해당 의류색이 PASS였을 때만 색 보존 대조를 추가한다. `CUT_COLOR_REVIEW_MODEL` 기본은 `gpt-6-astra`다. 실제 수정 전/후 바이트와 두 해시를 확인한다. 틀린 기존색을 동결하거나 전역 재생성·조명 수정에 동일 명도 보존을 강요하지 않는다.
- 추가 모델 검수는 정책이 off이면 호출되지 않는다. primary QC를 끈 채 critical만 켜면 증거가 없어 보류된다. 운영 활성화는 primary QC와 추가 지연·비용·보류 흐름을 함께 확인한 뒤 별도 승인으로 진행한다.
- 이 코드의 테스트는 제어 흐름·스키마·해시 바인딩을 검증한다. 실제 얼굴/색 판단의 일반 정확도는 별도다. 단일 실패 사례에서 더 좋은 판정이 나왔다고 모든 사진에서 무오류라고 주장하지 않는다.

## 포즈·표정 허용 범위

- 카메라 거리, 전체 프레이밍, 머리/목 크롭은 핵심이다. 작은 손끝 높이, 팔 각도, 표정 변화는 자연스럽고 전체 행동이 유지되면 허용한다.
- 명백한 팔 반전, 휴대폰을 잡는 팔의 잘못된 연결, 비정상 관절, 달라진 핵심 지지·접촉 역할은 계속 실패다.
- fr02-v1은 사용자가 수용한 결과다. 이전 HOLD의 근거인 약 8–9% 프레임 높이 손끝 차이는 이력으로만 남기며 재생성 조건으로 쓰지 않는다.
- fr05의 미소 개선본 실제 파일명은 fr05-v4다. 생기 개선 선호를 기록하되 모든 상품컷에 웃음을 강제하는 일반 규칙은 만들지 않는다.

## 서버 반영 전 최소 검증의 이력과 후속 실행

지금 명세·검수 계약·회귀 사례를 준비하는 PR과, 검증된 생성 레시피를 서버 기본값으로 켜는 PR은 분리한다. 기존 1·2단계 실험은 종료됐으며 미체크된 과거 matrix를 자동 재실행하지 않는다. 새 레시피의 API 재현, 얼굴 false-PASS 방지, 소프트 스냅의 색 보존을 확인한 뒤 제한 적용과 롤백 가능한 승격을 판단한다. Sunburst는 사용자가 승인 완료를 알릴 때까지 보류한다.

다음10장 묶음은 **실행 전 제안의 역사적 기록**이다: fr01의 원본 직접 치환/성공했던 촬영 보정 방식 두 경로를 각2회로4장, fr06의 색 보존 소프트 스냅2장, 나머지fr02~fr05 각1장으로4장을 생성하고 기존20장을 QC에 재사용하려는 계획이었다. 이후 기존 GPT Image 2 API로 신규10장 생성과 기본 QC30건·집중 검수3건을 완료했다. 실행 결과와 한계는 [착용컷 안전장치 및 API 재현 검증](wearshot_release_validation_2026-09-09.md)에 기록했다. 이 수량은 통계적 품질 보증이 아니며 실패한 레시피를 자동 재실행하거나 무한 연장하는 정책으로 바꾸지 않는다.

fr01 해법의 당시 근거: 예전 성공 보정은 실제 사용자가 준 촬영 사진과 얼굴·상품 회귀 참조를 포함했다. 앞서 만든 fr01-v2/v3는 내장 생성 경로에서 생성된v1과 생성된 성공본 두 장만 사용한 1086×1448 결과이며, 후속 검증의 **API 신규10장에 포함된 출력이 아니다.** 후속 API10장은 사전 고정한 입력·프롬프트·manifest로 새로 생성했고 요청한 native2K 크기를 사용했다. 그 작은 비교로 특정 경로의 우수성이나 모든 상품군의 품질을 독립적으로 입증하지는 않는다.
