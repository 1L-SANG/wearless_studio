# 착용컷 안전장치 및 API 재현 검증 — 2026-09-09

## 실행한 것

- 기존 GPT Image 2 API로 새 이미지10장, GPT5.6 Sol 기반 서버 QC로 기존20장+새10장, 별도 집중 검수3건을 실행했다.
- 생성10장과 기본 QC30건 모두 요청이 성공했다. 생성 결과는 요청한 native2K 크기와 일치하며 후처리 리사이즈를 하지 않았다. 원본 비율 반올림에 따라1536×2048,1664×2048,1520×2048을 사용했다.
- 입력·프롬프트·manifest를 실행 전에 해시로 고정했다. 새 모델 조합2건은 결과를 보고 프롬프트를 재조정하지 않았다.
- 이미지 생성 입력98,954토큰, 출력22,818토큰을 영수증에서 합산했다. QC 비용/토큰은 해당 어댑터가 반환하지 않으므로 추정 총비용을 적지 않는다.

실제 이미지와 사용자 얼굴 자료·로컬 절대경로 영수증은 공개 저장소에 포함하지 않는다. 사용자 작업폴더의 로컬 리뷰가 시각 증빙이다. 이 문서는 공개 가능한 실행 요약이며 공개 벤치마크 데이터셋이 아니다.

## 검증 경계

실험 프롬프트와 수동으로 사전 작성한 사례 관찰 → 실제 서버 이미지 어댑터 → 실제 CutPlan 컴파일러/기본 QC를 사용했다. 카탈로그 바인딩·confirmed 고정 프롬프트·DB·R2·전체 워커 운영 경로를 실제 실행한 것은 아니다. 워커 저장 차단은 네트워크/저장소를 대역 처리한 제어 흐름 테스트로 별도 검증했다.

기본 all-scope QC는 다른 인접 장소를 요구하지만 이번 비교는 같은 장소를 허용했다. 원시 판정의 장소 FAIL을 삭제하거나 사진 품질점수로 오용하지 않는다. 기본 QC에는 별도 촬영 질감 참조와 수정 직전 승인색 기준이 없으므로 해당 질문은 독립 비교로 확인했다. 원래 선택 얼굴 한 모델의 전신 시트는 없고, 부분 얼굴에는 full-face 증명 한계가 있다. 이 문제를 숨기기 위해 모델 선택을 해제하거나 몸 시트를 만들어 넣지 않았다.

## 코드로 반영한 공통 개선

1. 기본값 off인 선택 단계별 critical 출고 정책: 얼굴·상품색·매칭 의류 핵심 판정이 없거나 실패하면 업로드/완료 전에 보류.
2. 기본 얼굴 PASS 뒤 별도 얼굴 대조: 선택 시트와 원본형 특징을 분리, 최종 이미지 SHA와 결합.
3. 정상색/조명 상태에서의 승인된 로컬 편집만 수정 전후 색 대조: 틀린 색이나 새 조명을 무조건 동결하지 않음.
4. OpenAI 출력 크기 명시 옵션: 기존3:4의 legacy2:3 매핑은 호환성을 위해 유지하고, opt-in 크기만 검증해 전송.
5. 로컬 재현 도구: 기본 dry-run, 동시2건, 생성 배치 상한10, 이미지/입력/프롬프트 해시와 시작/완료 영수증, 불명확한 요청 자동 재시도 금지, GPT-only QC.

제품명·사진ID·특정 팔 좌표를 production 분기 조건으로 넣지 않았다. 명세와 실제 테스트가 뒷받침하는 것은 공통 제어 흐름의 개선이지 모든 생성 이미지의 자동 합격이 아니다.

## 승격 판단

안전장치·재현 도구는 검토용 PR로 분리한다. 촬영 레시피는 후보 단계이며 운영 기본값으로 승격하지 않는다. 상품의 고유 구조 유지와 일부 얼굴/가려짐 판정 한계가 남아 있다. 이후 사용자 후보 확인과 제한 적용 시 지연·비용·보류 UX·롤백을 확인해야 한다. Sunburst/Flare와 운영 배포 설정은 변경하지 않았다.

실행 예시(사용자가 로컬 evidence manifest와 API 환경을 준비한 경우):

```sh
cd server
python -m app.experiments.wearshot_replay --manifest PATH --output-dir OUTPUT
python -m app.experiments.wearshot_replay --manifest PATH --output-dir OUTPUT --mode generate --case CASE_ID
python -m app.experiments.wearshot_replay --manifest PATH --output-dir OUTPUT --mode qc --case CASE_ID
```

기본 호출은 검증만 한다. 실제 generate/qc는 외부 API를 사용한다. 시작 영수증이 남은 요청은 실패·시간초과 여부와 관계없이 자동 재제출하지 않는다.
