### 1.2 우리 계약 (ADR-0005 정본)

`핵심 장점(benefit) → 핏·코디(fit) → 제품 확인(product) → 구매 정보`
— 앞의 세 개만 콘티보드에 보이고, 구매 정보는 에디터가 담당한다.

### 1.3 정합 판정

**일치하는 구조 (우리 결정이 시장 통념과 어긋나지 않음)**

- 히어로/메인 비주얼이 맨 앞 → 우리 `hero`(핵심 장점 첫 카드).
- 그 다음이 **혜택·USP**이지 스펙이 아니다 → 우리 `benefit`. 4개 소스 전부 "특징(Feature) 나열 말고 혜택(Benefit)으로 바꿔라"를 반복한다.
- 구체 정보(스펙·소재·사이즈)는 중반 → 우리 `product`.
- **구매 불안 해소(배송·교환·환불·Q&A)가 항상 맨 뒤** → 우리 `구매 정보`가 마지막인 것과 일치.
- 상품 갤러리·가격·옵션·장바구니는 소스에서도 **플랫폼 UI 영역**으로 다뤄진다 → ADR-0005가 "상품 갤러리는 쇼핑몰 껍데기이므로 우리 섹션으로 세지 않는다"고 한 판단과 같다.

**우리 계약에 자리가 정의되지 않은 것 (결정 필요)**

| 항목 | 시장 소스 | 우리 현황 |
|---|---|---|
| **고객 리뷰/사회적 증명** | 5개 소스 **전부** 배치, 대부분 배송·환불보다 **앞** | ADR-0005의 `구매 정보` 열거(사이즈표·소재·세탁법·배송/교환/반품·필수 고지)에 **없음**. 플랫폼 후기 UI에 위임하는지 명시 안 됨 |

**우리가 시장보다 앞서 있는 지점**

소스의 이미지 처방은 "다양한 각도 5~7장", "착용컷도 포함", "360도 뷰" 수준에서 멈춘다. 우리는 컷 종류(`styling|horizon|mirror|product`), 샷(`full|medium_knee`), 핏 축, 같은 장소 세트까지 계약화되어 있다. **이 소스는 우리 컷 taxonomy를 보강하지도 반박하지도 못한다.**

### 2.1 의류 특화로 건질 것 (887 — 사이즈 시각화)

우리 계약에 없는데 의류 상세페이지에서 실제로 쓰이는 항목:

1. **착용 모델 사진에 "모델 키 + 착용 사이즈" 병기** — 우리 콘티에는 모델 신체 정보 표기 계약이 없다. 가상모델을 쓰므로 우리가 값을 알고 있고, 표기만 하면 된다. **백로그 1순위 후보.**
2. 측정 방법 도해(어깨너비·가슴둘레·소매길이·총장을 어디서 재는지) — 이미지 산출물로 만들 수 있다.
3. 체형별(키·몸무게) 추천 사이즈 안내.
4. "비슷한 체형의 구매자가 고른 사이즈" — 데이터가 쌓여야 가능. 장기 백로그.
5. 브랜드마다 사이즈가 다를 수 있다는 고지 명시.

### 2.2 이미 우리가 하고 있어서 검증만 된 것

914의 Feature→Benefit 리라이트 예시가 우리 소재 블록 리프레이즈 트랙과 **정확히 같은 방향**이다:

> 기존: "본 제품은 폴리에스터 80%, 스판덱스 20%로 구성되어 있습니다."
> 개선: "부드러운 착용감과 뛰어난 신축성을 자랑하는 이 제품은 폴리에스터(80%)와 스판덱스(20%)의 완벽한 조화로 만들어졌습니다."

새 정보는 아니지만, [material_audit_findings.md](material_audit_findings.md)의 방향이 시장 통념과 어긋나지 않는다는 확인은 된다.

## 3. 표현 기법 (블록이 아니라 "어떻게 보여줄까")

우리가 이미지를 만들 때 참고할 만한 것만 추린다.

- **재질 표현** (914): 재질 확대 사진(텍스처) → 우리 `detail` 컷과 대응. 부위별 재질을 색상 코딩해 표시하는 일러스트는 신발·가방용이라 의류에는 과함.
- **사이즈 표현** (887): 비교 대상물 병치는 소품용이고, 의류는 **착용 모델 + 키/사이즈 병기**가 정답이라고 같은 글이 말한다(§5.2).
- **리뷰 표현** (12785): 별점 분포 막대그래프, 키워드 강조(긍정 초록·부정 빨강), 사진 리뷰 그리드, AI 요약(장점/단점/총평/키워드). 리뷰를 우리가 다루기로 하면 여기서 시작.
- **신뢰 체크리스트** (10340): 40여 항목 중 우리 산출물에 해당하는 것 — 다각도 고품질 이미지 / 복잡한 정보의 인포그래픽화 / 반품 절차 단계별 시각화 / 전문가 추천을 인용구 형태로. 나머지는 플랫폼·스토어 기능.
- **FAQ UI 선택 기준** (27719): 10개 미만 → 아코디언·확장형 / 20개 이상 → 탭 또는 하이브리드 / 5개 이하 → 전부 펼침. (우리 산출물이 정적 이미지라면 "전부 펼침"만 유효.)
- **배송 표현** (15554): 옵션 비교 테이블(방법·비용·예상일·특이사항), 주문→결제→준비→배송중→완료 타임라인.
