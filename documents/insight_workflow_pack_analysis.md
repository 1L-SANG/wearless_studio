## 1. 자료의 구성 — "공장" 6단계 파이프라인

책 전체가 하나의 조립 라인: **모델 만들기 → 베이스샷 → 포즈 다양화 → 의상 변경 → (필요시) 배경 변경**, 전 단계 공통 작업 방식은 "두 모델 동시 가동 × 여러 장 뽑아 사람이 베스트 선택".

| 장 | 파일 | 하는 일 | 우리 대응물 |
|---|---|---|---|
| 6장 | 모델 생성.json | 6면(2×3) 캐릭터 시트, 얼굴 레퍼런스 선택 첨부 | 가상모델 C방식(원본+그리드) |
| 7장 | 베이스샷 만들기.json | 무드 레퍼런스+모델 얼굴 → 대표 전신샷 | 컷 생성(예시 all 범위) |
| 8장 | 포즈 변경.json | 베이스샷+포즈 레퍼런스 8장 팬아웃 | 포즈만(pose)·누끼 마네킹 |
| 9장 | 의상 변경.json | 슬롯별(TOP/PANTS/BELT/SHOES) 옷 교체 | 상품+매칭 의류 계약 |
| 10장 | 배경 변경 2종.json | 텍스트 지정 / 레퍼런스 무드 배경 교체 | bg 플레이트 편집(ADR-0009) |
| 11장 | 올인원 워크플로우.json | 5단계 한 캔버스 + 베스트컷 수동 연결 + 시드 고정 | 잡 파이프라인+QC 자동화 |

경제 구조(3장): 초기 세팅(모델·베이스샷·포즈 20종) ~75회 생성은 1회성, 이후 **상품당 의상 변경 ~18회(약 2,300원)** 만 반복. "뿌리 하나 세우고 갈아끼우기"가 저비용의 뼈대 — 우리 '가상모델 고정 + 세트 묶음생산' 설계와 같은 결론.

## 2. 인사이트 전체 목록

### A. 프롬프트 기법 (JSON+4장 원리 해설)

1. **"새 사진을 처음부터 찍어라" 역할 선언** (포즈): "NOT an edit of Image 1 — do not copy, reuse, or upscale any pixels." 원본을 살짝 워프해 때우는 게으른 편집 실패 모드를 역할 선언으로 차단.
2. **"카메라가 물리적으로 이동했다" 장치** (포즈): 새 시점에서 원근·스케일·시차(parallax)까지 장면 전체 재렌더 — 크롭 흉내를 구조적으로 금지.
3. **"같은 세션에서 잠시 뒤 찍은 다른 프레임" 장치** (포즈): 표정·고개·시선의 미세 자연 변주 허용 — 복제 인형(frozen duplicate) 방지와 일관성의 균형.
4. **양방향 크롭 경계 규칙** (포즈): "no more, no less — 더 타이트도, 더 와이드도 금지". 크롭 일치를 양방향으로 잠근다.
5. **INTEGRATION 4종 세트** (배경): 조명 방향·부드러움·색온도 일치 + **가장자리만 재조명** + 물리적 접지 그림자 + **노출·WB·심도(DoF) 일치** — 합성 티의 4대 원인 전부 명시.
6. **실제 장비명 선언** (4장 원리 ①): "이미지가 아니라 사진을 주문하라" — Canon 85mm f/2.0, iPhone 15 Pro 같은 실제 장비명이 학습된 실사 사진 분포와 연결돼 렌즈 특유의 심도·질감까지 끌어온다. 컷 성격별로 장비 등급을 갈라 쓴다(시트=85mm 스튜디오, 베이스샷·배경=아이폰 UGC).
7. **태그 수프 금지 + 번호표·역할 지정** (4장 원리 ②): 완전한 문장, [구획] 분리, 이미지마다 "무엇을 가져올지"까지 지정("1번은 색감만, 2번은 얼굴만"). 구글·OpenAI 공식 가이드와 일치. — 우리는 번호 대신 라벨 매니페스트라 한 단계 더 견고.
8. **유지 목록 반복 명시 = 드리프트 방지** (4장 원리 ③): "AI는 방금 한 일을 잊는다" — 매 호출마다 유지 항목(얼굴·체형·옷 색/원단/핏/패턴·프레이밍)을 다시 적는다. 셀러 관점 최우선 유지 항목은 옷의 색·원단·핏·패턴(왜곡 시 곧장 반품).
9. **금지 목록 = AI 티 카탈로그** (4장 원리 ④): airbrushed skin, 3D cartoonish, distorted hands, generic Western features, perfect symmetry, over-processed HDR/cinematic — 사람이 "AI네"라고 알아채는 지점의 목록화.
10. **의도적 불완전 + 물리 정합** (4장 원리 ⑤): 살짝 흐트러진 셀카 느낌·미세 노이즈를 일부러 심고, 대신 조명·그림자·원근은 물리적으로 아귀를 맞춘다.
11. **역할 충돌 해소 규칙** (모델): "이미지와 텍스트가 다르면 **텍스트가 항상 이긴다**" 명문화.
12. **[HAIR STYLE] 스왑 블록** (모델): 헤어만 변수 블록으로 분리(남/녀 예시 제공). 같은 얼굴에 헤어 변주를 갈아끼우는 구조.
13. **6면 시트 구성** (모델): 좌90°·좌45°·정면 / 우45°·우90°·**뒤통수** 2×3 그리드, 각 뷰 head-and-shoulders 고정, 전 뷰 동일 조명·노출. 우리 2×2 시트에는 뒤통수 뷰가 없다.
14. **슬롯별 착장 명세** (의상): TOP/PANTS는 이미지 근거, BELT/SHOES는 텍스트만 — 이미지·텍스트 근거를 슬롯 단위로 혼용. 사진 없는 품목을 텍스트로 통제.
15. **프린트 문구는 철자를 직접 명시** (9장): 옷에 문구가 있으면 `"UNIVERSITY" embroidered in the center` 처럼 프롬프트에 문구를 그대로 적어야 텍스트 재현율이 오른다.
16. **옷 설명 길이는 무의미, 근거 이미지 화질이 지배** (9장 실측): 길게 설명 vs 짧게 설명 차이 없음 — 참고 이미지에서 디테일이 잘 보이는지가 결과를 결정. (우리 소재 블록 간결화·"레퍼런스가 근거" 철학의 외부 실측 방증)
17. **옷 하나에 여러 근거 이미지**(착용샷+디테일컷) 첨부가 정확도를 올린다 — 실착샷이 핏 근거로 최상. (우리 Fit 슬롯 우선 규칙과 일치)

### B. 운영·파이프라인 노하우 (책에서만)

18. **포즈 라이브러리 선구축·조합 로테이션** (8장): 전신 10 + 상반신 10을 미리 만들고 상품마다 다른 조합을 골라 쓴다. 매 상품 같은 포즈면 "찍은 게 아니라 찍어낸" 템플릿 카탈로그가 된다 — 진짜 촬영은 컷마다 무게중심·손 위치가 조금씩 다르기 때문.
19. **하의=전신 크롭 OK, 상의=전용 구도** (8장): 하의 디테일은 전신에서 잘라 써도 어색하지 않지만, **상의 디테일컷은 카메라를 더 가까이+렌즈를 좀 더 높게 잡은 전용 컷**이어야 한다(전신샷은 허리 높이에서 멀리). — 우리 하의 미디움=허리~발·상의 미디움 구도에 직접 대응하는 관찰.
20. **포즈 레퍼런스는 스케치(선화)가 안전** (8장): 실사진을 포즈 참조로 쓰면 배경·모델까지 유출 — 스틱 피규어·라인 스케치 권장(책은 47종 포즈 세트 배포). 우리 누끼 마네킹 자산은 같은 문제의식의 상위 해법.
21. **포즈 변경은 두 모델 품질 차이 없음 → 싼 모델만** (8장 실측): 과업별 모델 라우팅(어려운 과업만 비싼 모델)의 외부 실측 근거.
22. **텍스트만으로 '한국 쇼핑몰 감성' 안 나온다** (7장): "한국 쇼핑몰st 감성"은 말로 백날 외쳐도 안 나옴 — 그 느낌이 담긴 이미지를 직접 넣는 게 유일하게 확실. **우리 생성예시(앵커) 우선 설계의 강력한 외부 검증.**
23. **얼굴은 아직 최난이도** (6장): 얼굴이 화면을 채울수록 아티팩트가 드러나고, 같은 레퍼런스도 뽑을 때마다 이목구비가 흔들림 → 여러 장 뽑아 최유사 선택 + (비용 아끼려면) 얼굴 잘린 크롭 활용. — 우리 하우스 얼굴 하드 게이트·재생성 정책의 방증.
24. **배경만 갈아끼우기의 한계** (10장): 원본 조명(스튜디오 정면광)이 새 배경(야외 노을)과 충돌하면 스티커처럼 보임 — 심하면 **배경 교체가 아니라 새 장면을 처음부터 함께 설계**하는 게 정답. 우리 bg '플레이트 편집'(장면 안에서 인물 조명을 함께 계산)이 바로 그 정답 방식.
25. **확정 컷 보존(시드 고정)** (11장): 베스트 확정 후 뒤 단계 반복 실행에도 앞 컷이 안 바뀌게 시드 고정 + 크레딧 절약. 우리는 잡 결과 저장으로 동일 목적 달성.
26. **셀러 최종 체크리스트** (에필로그): ① 실물과 색·원단·핏·패턴 대조 ② 참고 이미지와 100% 동일한 부분(배경·타투·점) 없는지 검사 ③ 실패한 생성도 과금됨 주의. "도구가 90%, 마지막 10%는 셀러의 눈" — 우리 image_qc·fit QC·sourceDistance 검사가 이 10%를 자동화한 형태.
