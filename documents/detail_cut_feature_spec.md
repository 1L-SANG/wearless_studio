## 1. 해결할 문제와 제품 목표

셀러는 앞면과 뒷면 전체 사진 외에 잘 재현하고 싶은 부분을 앞면 디테일, 뒷면 디테일에 나누어 올린다. 이 사진에는 소맷단, 단추, 레이스처럼 촬영 주제가 명확한 경우도 있고, 원단만 보이거나 안감과 라벨을 찍은 경우도 있다.

디테일 사진이 있다는 이유만으로 그 사진의 내용을 그대로 생성 대상으로 삼으면, 셀러가 보여주려던 상품의 매력보다 우연히 찍힌 부위가 강조된다. 반대로 전체 사진만 보고 극단적으로 확대하면 원단과 부자재가 새로 만들어진다.

이 기능은 실제 상품 근거로 만들 수 있는 매력적인 부위를 추천하고, 그 부위를 새로 접어 배치하거나 각도와 조명을 바꾼 상세페이지용 상품 사진으로 생성한다. 사진 복원이나 단순 선명화가 아니다.

사용자에게 약속할 결과는 “올린 사진을 참고해 상품의 소재와 마감을 돋보이게 보여주는 디테일컷”이다. 실제 미세조직을 완벽히 복원한다고 표현하지 않는다.

## 2. 이번 대화에서 확인된 방향과 권고안

### 사용자 요청으로 확인된 방향

- 실제 근접 사진을 활용하되 원본 구도를 그대로 보정하는 방식은 원하지 않는다.
- 실제 원단을 참고하면서 새 접힘, 배치, 촬영 각도와 빛으로 디테일을 어필한다.
- 브라운 체크 셔츠와 하늘색 레이스 스커트 결과의 연출을 긍정적으로 평가했다.
- 로즈 블라우스의 색상 변화는 문제로 지적됐다.
- 근접 사진이 생성 대상으로 적합한지 판단하고, 부적합하면 전체 사진에서 적절한 부위를 고르는 방향을 검토한다.
- 이를 서비스의 디테일컷 기능으로 등록한다.

### 초기 출시 권고안

- 기존 디테일샷을 고도화한다. 새로운 cutType이나 독립 스튜디오 화면을 만들지 않는다.
- 사용자는 기본적으로 AI 추천을 사용한다. 고급 프롬프트와 입력 역할을 직접 설정하지 않는다.
- 상품당 추천 부위는 최대 3개다. 첫 부위를 기본 선택하고 한 번에 한 장을 생성한다. 자동으로 3장을 생성하거나 과금하지 않는다.
- 근거가 명확한 겉면의 구조와 소재 디테일부터 제공한다. 안감, 기능성, 복잡한 부품 구조의 연출은 초기 자동 추천에서 제외한다.
- 프롬프트와 입력 역할만으로 해결했다고 간주하지 않는다. 생성 뒤 색상, 구조, 무늬와 연출을 별도로 검수한다.
- 모델은 검증 대상 설정값으로 관리한다. 이번 소규모 실험만으로 gpt-image-2를 모든 상품의 운영 기본값으로 확정하지 않는다.
- 세부 정책의 승인과 코드 구현은 다음 단계다. 가격, 자동 재시도 횟수와 운영 공개를 이 문서 등록만으로 변경하지 않는다.

## 3. 권장 접근과 다른 안

| 접근 | 장점 | 한계 | 판단 |
| --- | --- | --- | --- |
| 모든 근접 사진을 생성 주제로 사용 | 단순하고 셀러 사진을 직접 반영한다 | 안감, 라벨과 애매한 접힘이 원치 않는 주제가 된다 | 기본 동작으로 부적합 |
| 카테고리별 정해진 부위만 생성 | 일정한 구도와 결과를 만들기 쉽다 | 실제 상품에 없는 포켓이나 장식까지 만들 수 있고 고유 매력을 놓친다 | 후보 탐색 가이드로만 사용 |
| 전체 사진에서 부위를 확인하고 적합한 근접 근거를 연결 | 부위 선택과 소재 재현을 함께 제어한다 | 사진 내용 분류와 근거 연결이 필요하다 | 권장 |

“일반적으로 잘 나오는 부위”는 생성 허가 목록이 아니라 우선 탐색할 후보 목록이다. 실제 사진에서 확인되지 않으면 추천하지 않는다.

## 4. 사진의 역할

사진마다 역할을 하나로 강제하지 않고 필요한 영역별로 판정한다. 예를 들어 지퍼 사진은 부자재 근거로는 좋지만 주변 천이 충분히 보이지 않으면 원단 근거로는 약하다.

| 역할 | 주된 근거 | 허용되는 사용 |
| --- | --- | --- |
| 상품 위치와 형태 | 목표 색상의 앞면 또는 뒷면 전체 원본 | 해당 부위가 실제로 어디에 붙어 있는지, 크기와 연결 관계 확인 |
| 소재 | 선택 부위와 같은 겉감 또는 같은 트림의 유효한 근접 영역 | 실·직조·무늬·광택·마감 참고 |
| 색상 | 목표 색상에 속한 신뢰 가능한 상품 원본 또는 사용자가 확인한 기준 사진 | 상품색과 배색 보존 |
| 연출 | 발행된 제품 생성예시와 촬영 계획 | 접힘, 카메라, 크롭, 배경과 빛의 방향 |
| 제외 | 라벨만 있는 사진, 다른 원단, 심한 흐림·반사, 관련 없는 내용 | 생성에 넣지 않거나 해당 부위 증거에서 제외 |

전체 원본이 항상 색을 정확히 담는 것도 아니다. 전체와 근접의 같은 원단 영역이 충돌하면 위치 확인용과 색상 확인용 역할을 분리한다. 일반 팔레트의 “레드”나 색상 이름은 정확한 상품색을 대체하지 않는다.

## 5. 입력에 따른 생성 경로

| 입력 판정 | 생성할 주제 | 참고 방식 | 사용자 표시 예시 |
| --- | --- | --- | --- |
| 부위와 구조가 분명한 근접컷 | 그 부위의 새 연출 | 근접으로 디테일 확인, 가능하면 전체로 위치·비율 확인 | 레이스 마감 |
| 원단만 보이고 부위는 불명확한 근접컷 | 같은 면 전체 사진에서 확인되는 부위 | 전체로 구조, 같은 겉감 근접으로 소재 | 소맷단과 원단 |
| 유효한 근접이 없지만 전체에서 구조가 확인됨 | 넥라인, 여밈, 밑단 등 확인 가능한 구조 | 전체 원본 기준, 과도한 매크로와 미세조직 재구성 제한 | 넥라인 |
| 근접이 라벨·안감·심한 흐림 등으로 부적합 | 다른 유효 후보가 있으면 해당 부위 | 부적합 영역은 겉감 표본으로 전용하지 않음 | 다른 부위 추천 |
| 전체와 근접 모두 근거 부족 | 생성하지 않음 | 필요한 부위의 추가 사진 또는 명시적인 원본 사용 안내 | 소맷단이 보이는 사진을 추가해 주세요 |

전체 사진의 작은 부자재가 흐릿하면 “전체로 대체” 경로에서도 그 부자재를 크게 만들지 않는다. 더 넓은 구조 컷이나 다른 부위로 바꾼다.

근접컷이 자체적으로 부위를 분명히 증명하는데 전체에서는 작아서 확인되지 않는 경우, 전체에서 안 보인다는 이유만으로 해당 부위가 없다고 판정하지 않는다. 다만 보이지 않는 연결이나 주변 장식으로 화면을 확장하지 않는다.

## 6. 앞면·뒷면과 원단 구역

- 기존 Front, Back, Detail, BackDetail 슬롯을 유지한다.
- 슬롯은 셀러의 면 선언이다. 사진 내용 분석은 소재와 부위의 적합성을 판단하며 업로드 슬롯을 조용히 앞뒤로 재분류하지 않는다.
- 앞면 컷에 뒷면의 자수·포켓·등판·백넥 구조를 전달하지 않는다. 초기 버전은 소재만 같아 보인다는 이유로 반대 면 디테일도 함께 넣지 않는다.
- 같은 면 안에서도 겉감, 안감, 골지, 레이스, 자수와 부자재를 구분한다. 골지를 몸판 전체에 적용하거나 안쪽 데님 조직을 겉면에 덮어쓰지 않는다.
- 서로 같은 소재인지 불확실한 영역은 연결하지 않는다. “같은 옷 사진”이라는 사실만으로 모든 천이 같다고 가정하지 않는다.
- 추가 색상 근거는 목표 색상 사진을 우선한다. 타색 상세 근거의 재사용은 같은 상품·버전·해당 부위의 일치가 확인된 경우에만 구조·소재로 한정한다.
- 타색 사진의 원단색과 부자재색을 목표색 이름 하나로 일괄 치환하지 않는다. 확인되지 않는 배색이나 버튼색은 생성 대상에서 제외한다.

## 7. 후보 선택

카테고리별로 다음 위치를 먼저 찾되 반드시 원본 근거로 확인한다.

| 의류 | 우선 찾을 부위 |
| --- | --- |
| 셔츠와 블라우스 | 칼라·넥라인, 여밈, 커프스, 셔링 연결 |
| 니트 | 소맷단·밑단과 몸판 연결, 넥 마감, 실제 골지·아일릿·배색 |
| 바지 | 포켓 입구, 허리·밴딩, 실제 지퍼·단추, 밑단 |
| 스커트와 원피스 | 레이스·프릴 연결, 셔링·주름, 허리 연결, 밑단 |
| 아우터 | 칼라·라펠, 여밈, 포켓, 실제 퀼팅·트림 |

후보 평가는 실제 디테일의 식별 가능성, 사진 해상도, 대상 소재 영역 일치, 색상 근거, 구조의 모호함, 셀러가 확인한 강조 특징, 후보끼리의 중복 여부를 함께 본다.

고유하고 예쁜 부위여도 재현 위험이 높으면 자동 추천 우선순위를 낮춘다. 반대로 무지 상품도 실제 소맷단과 몸판의 연결처럼 설명 가치가 있는 부분을 추천할 수 있다. 모든 상품에 장식적인 디테일 3개를 억지로 채우지 않는다.

초기 자동 추천에서 제외할 대상은 브랜드 라벨·세탁표시만 보이는 사진, 안감·안쪽 솔기만 보이는 사진, 가려진 여밈의 전체 작동 구조, 손으로 늘려야 드러나는 신축성, 방수·두께 같은 성능을 추측해야 하는 장면이다. 해당 정보가 필요하면 원본 사진을 명시적으로 쓰는 별도 선택지로 다룬다.

## 8. 사용자 흐름

1. 입력 화면은 기존 4개 업로드 칸을 유지한다. 디테일 칸 안내에 “소재나 마감이 보이게, 주변 모양도 조금 포함해 가까이 찍어 주세요”를 제안한다.
2. 분석 시 각 디테일 사진의 활용 영역과 생성 가능한 부위 후보를 만든다. 업로드 사진 전체를 매번 이미지 모델에 넘기지 않는다.
3. 콘티보드의 의류 확인에서 디테일샷을 선택하거나 에디터의 새 이미지 추가에서 디테일컷을 선택한다.
4. 같은 면과 목표 색상으로 가능한 후보를 최대 3개 보여준다. 기본은 추천 1개다. 기존 생성예시 갤러리는 구도 참고로 유지한다.
5. 후보에는 “단추 여밈”, “소맷단”, “레이스 마감” 같은 쉬운 이름과 근거 원본의 미리보기만 보여준다. 내부 모드나 신뢰도 숫자는 노출하지 않는다.
6. 부위를 바꾸면 해당 부위와 맞지 않는 예시는 해제하고 호환 가능한 연출만 제공한다. 기존에 예시가 결정한 방향을 조용히 뒤집지 않는다.
7. 생성 장수와 기존 크레딧 비용을 보여준 뒤 한 장을 만든다. 단순히 추천 목록을 여는 것으로 이미지 생성 비용이 발생해서는 안 된다.
8. 결과는 기존 의류 탭과 이미지 추가 흐름에 넣는다. 기존 블록을 자동 교체하지 않는다.

최초 버전에서 후보 UI 범위를 줄여야 한다면 자동 추천 한 부위와 “다른 부위” 선택만 제공하는 축소안도 가능하다. 본문은 최대 3개 후보를 보여주는 권고안이다.

## 9. 색상 문제를 별도로 해결한다

로즈 블라우스 실험에서는 프롬프트가 색을 dusty brick-rose로 해석하고 따뜻한 빛을 요구했다. 결과의 갈색 이동은 입력 근접도만으로 설명할 수 없다. 소재 묘사와 미적 연출 문구가 색에 영향을 준 문제도 있다.

- 목표 색상의 실제 사진을 COLOR_AUTHORITY로 명시한다. 소재 사진은 색상을 덮어쓰지 못한다.
- 조명은 방향과 부드러움으로 설계한다. warm rose, cinematic orange grade처럼 상품색을 움직이는 표현을 기본 레시피에 넣지 않는다.
- 따뜻한 배경이 필요해도 상품 자체는 중립 화이트밸런스를 유지하도록 한다.
- 파란 레이스, 대비 스티치와 버튼은 몸판과 분리한 색 관계로 보존한다.
- 화면의 원형 팔레트나 색상명 하나로 정확한 색을 맞췄다고 간주하지 않는다.
- 전체·근접 사진의 같은 소재 영역에서 심한 색 불일치가 확인되면 기준 사진을 확인하도록 한다. 이때만 사용자 개입을 요청한다.
- 결과 색상 검수는 상품 마스크 안의 같은 소재 영역을 비교한다. 배경이나 깊은 그림자를 섞은 전체 이미지 평균색으로 판단하지 않는다.
- 색차 계산은 보조 신호로 쓰고 조명·그림자 영향을 고려한다. 보정되지 않은 휴대폰 사진만으로 실제 상품색의 절대 일치를 보장하지 않는다.

## 10. 생성과 검수

생성 계획은 네 역할을 명시한다. COLOR_AUTHORITY, STRUCTURE_AUTHORITY, MATERIAL_EVIDENCE, ART_DIRECTION.

생성기는 선택 부위 하나를 주제로, 실제 구조를 유지하면서 접힘과 겹침 및 카메라를 새로 설계한다. 매장 손·옷걸이·가격표는 제외한다. 상품 자체의 영구적인 로고·자수·라벨은 실제 보이는 범위에서 보존하며 임시 행택과 구분한다. 근거 없는 장식은 만들지 않는다.

검수는 다음을 독립적으로 판단한다.

- 상품색과 배색 관계.
- 선택 부위의 위치, 여밈, 버튼·지퍼·레이스의 실제 구조.
- 패턴 색 순서와 상대적 반복 크기, 조직 크기, 트림과 몸판 구분.
- 포개진 원단의 연결과 물리적으로 가능한 접힘.
- 원본 단순 복사에 머무르지 않고, 요청한 부위가 잘 드러나는 새 연출인지.
- 원본 사진 삽입, 손과 태그 잔여물, 과도한 샤프닝이나 거친 가짜 조직이 없는지.

검수기가 같은 잘못된 생성 계획을 정답으로 반복하지 않도록 실제 원본 영역도 직접 대조한다. 검수 실패는 사용자에게 성공 결과처럼 내보내지 않는다. 다른 후보로 바꾸거나 원본 사용을 선택하게 하는 처리는 명시적으로 한다. 몰래 원본을 그대로 반환하고 연출 생성이 됐다고 표시하지 않는다.

자동 재생성과 비용 상한, 검수기 장애 시 처리와 환불은 기존 작업·과금 계약을 검토해 구현 단계에서 정한다. 이 기획은 무한 자동 재생성이나 새로운 환불 정책을 허용하지 않는다.

체크와 스트라이프는 이번 결과의 연출이 좋았다는 이유만으로 정확성 검사를 완화하지 않는다. 현재의 미세 패턴 원본 통과 규칙을 전역으로 끄지 않는다. 새 연출 경로를 켜려면 해당 패턴의 별도 검수와 명시적 폴백 처리를 먼저 검증한다.

기존 PRD §8.4와 새 이미지 추가 설명에는 Detail이 있어야 한다는 옛 조건이 남아 있다. 2026-08-07 확정 슬롯 스펙과 현재 코드에는 같은 면 전체 사진을 사용하는 구조 확대 경로가 있다. 이 차이는 구현 전 정본·UI·런타임 계약을 함께 맞추는 후속 작업으로 등록한다.

초기 데이터 설계는 기존 kind, cutType=product, shot=detail, contentRole=detail을 유지한다. 후보 선택에 필요한 필드만 공통 데이터 계약을 검토한 뒤 추가한다. 별도 상세페이지 저장 체계를 만들지 않는다.

생성 근거에는 assetId, 업로드 면, 색상 그룹, 부위, 소재 구역, 사용 목적, 필요 시 원본의 정규화된 영역 좌표, 제외 사유를 기록한다. 좌표와 파일은 서버가 검증한다. 사용자가 보내는 파일 경로나 후보 설명을 그대로 신뢰하지 않는다.

후보 선택 ID와 생성 당시 상품 입력 버전을 연결한다. 색상·업로드·부위가 달라지면 이전 계획을 재사용하지 않는다. 같은 선택의 단순 재요청과 다른 부위의 추가 생성이 혼동되지 않도록 기존 중복 방지·크레딧 계약을 검사한다.

실행 기록에는 실제 선택 원본, 역할 목록, 선택 부위와 경로, 모델·프롬프트 버전, 검수 결과와 대체 사유를 남긴다. 다른 프로젝트나 사용자의 자산을 참고할 수 없게 기존 소유 검증을 유지한다.

## 12. 구현 단계와 검증 계획

1. 입력 근거 분석과 후보 선택을 먼저 구현한다. 생성 모델을 호출하지 않는 테스트에서 면·색상·소재 구역 혼동을 차단한다.
2. 같은 색상의 명확한 겉면 디테일로 새 연출 경로를 연결한다. 기존 product/detail 저장 의미를 유지한다.
3. 일괄 상세페이지와 에디터 단건 생성에 같은 근거 선택과 검수를 연결한다.
4. 기존 UI 안에서 추천 부위와 대체 이유를 보여준다. 별도의 프롬프트 입력이나 새로운 촬영 용어는 추가하지 않는다.
5. 모델별 실물 대조 평가를 거쳐 범위를 확대한다. 체크·레이스·다색·안쪽 구조의 위험을 따로 기록한다.

필수 검증 시나리오:

- 앞면 디테일만 있고 뒷면 컷 요청: 앞면 장식을 등에 만들지 않는다.
- 라벨 확대만 존재: 라벨 천을 몸판 소재로 사용하지 않는다.
- 안쪽 데님 확대와 겉면 전체: 안쪽 조직을 겉면에 적용하지 않는다.
- 레이스 확대: 레이스를 몸판 전체로 확대하지 않는다.
- 무지 원단 확대만 존재: 전체 사진의 실제 소맷단에 소재만 연결한다.
- 유효 근접 없음: 전체에서 보이는 구조를 합리적인 확대 정도로만 만든다.
- 목표색과 근접 색이 다름: 다른 색이 목표색을 덮지 않는다.
- 로즈색·민트색·아이보리·중청: 생성의 색 이동을 실제 기준 사진으로 검수한다.
- 체크와 줄무늬: 예쁜 결과라도 선 간격·색 순서가 바뀌면 통과시키지 않는다.
- 같은 사진에 여러 소재: 영역을 구분해 사용하고 애매하면 추천에서 제외한다.
- 참조를 내려받지 못함: 다른 옷이나 원본 삽입으로 대체하지 않는다.
- 원본 그대로인 결과: 새 연출 성공으로 표시하지 않는다.
- 존재하지 않는 후보, 오래된 입력 버전, 타인 자산 요청: 서버에서 거부한다.
- 재시도와 중복 요청: 기존 과금·실패 처리와 결과 저장이 일치한다.

정량 품질 기준과 평가 표본은 구현 전 별도 검증 계획으로 정한다. 위 시나리오는 아직 자동화하거나 통과시킨 테스트 목록이 아니다.
